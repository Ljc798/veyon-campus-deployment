## 1. 目标流程

任何人都可在教师端或网站 `/publish` 提交校区配置包，无需登录。服务器只接受启用校区，并验证包内校区名称、ZIP 内容、清单、文件摘要及命名规则；通过后将 ZIP 写入私有 CloudBase 存储并登记 PostgreSQL。学生可搜索已发布包的目录信息，通过下载接口取得文件；学生客户端继续使用已有 `PackageManifest` 校验与部署预检。

本次数据库范围对应当前桌面程序的校区配置 ZIP：仅 `schemaVersion=3`、Windows x64，ZIP 最大 64 KiB、解压后的单文件最大 16 KiB、HTTP 请求最大 128 KiB。它不是教师/学生 App 安装包发布表，也不保存教师私钥、学生密码或任意可执行脚本。

网站中部署包的发布时间、校区更新时间等时间戳按 UTC+8（`Asia/Hong_Kong`）展示。数据库使用 `timestamptz` 保存绝对时间点；现有匿名遥测按 `day_utc` 做 UTC 日去重的口径保持不变。

## 2. 严格命名规则

### ZIP 文件名

唯一接受的文件名格式：

```text
veyon-campus-config-v3-<manifest.packageId 去掉连字符后的小写32位GUID>.zip
```

示例：

```text
veyon-campus-config-v3-018f2c7aa2da7ebf9a3247d8edca5012.zip
```

规则细节：

- `manifest.json` 必须是当前受支持的 `schemaVersion=3`，`packageId` 必须是有效 GUID。
- 云端目录名和下载 ZIP 名由数据库生成列根据 `packageId` 生成；上传者不能指定云端文件名。服务端忽略上传时的源文件名，先重新验证并重建规范 ZIP，再只以生成的规范名称存储和提供下载。
- 该规则对 ZIP 上传和文件夹上传一致：对象键固定为 `deployment-packages/v3/<32位小写GUID>.zip`，下载名固定为上面的规范格式；用户提交的路径和文件名不会成为存储路径。
- CloudBase 私有存储对象键由包 ID 派生：`deployment-packages/v3/<32位小写GUID>.zip`。对象键不对学生开放，也不接受用户提供的路径。
- `artifact_sha256` 使用 64 位大写十六进制 SHA-256；数据库拒绝其他格式。
- 数据库列的兼容性硬上限为 524288 字节；发布 API、教师端与 PG Storage 桶共同将新包限制为 65536 字节。

### 电脑名前缀

部署包必须包含来自当前命名规则的 `computerPrefix`：首字符为 ASCII 字母或数字，之后只允许 ASCII 字母、数字和连字符；必须包含至少一个英文字母，不得以连字符结尾，最长 12 个字符。该限制为电脑编号追加 `1–150` 后仍留出最多三位数字，并确保最终 Windows 主机名不超过 15 个字符。比如 `PC-`、中文前缀、含空格/下划线的前缀都会被拒绝。

### `public.deployment_package_publishers`

教师身份到校区的授权映射。主键为 `(user_id, campus_id)`；只有 `is_active=true` 的授权可以发布该校区包。只有服务端可以创建、停用或调整映射；教师浏览器只能读取自己的有效映射。现有 `owner` / `admin` 角色可代表任意活跃校区发布，普通教师必须有对应校区授权。

### `public.deployment_packages`

每个已发布 ZIP 一行，以清单里的 `packageId` 为主键。数据库保存校区 ID 与名称快照、电脑名前缀、固定 schema/平台、ZIP 大小与 SHA-256、发布者、发布时间、下载计数和撤回状态。`display_name` 与 `artifact_file_name` 是生成列；发布后内容不可改，修订时须生成新 `packageId` 并发布新行。撤回使用软状态，不删除历史元数据。

学生 `anon` 与 `authenticated` 角色只能 SELECT 已发布目录列，不能读发布者身份或修改任何字段。Row Level Security 会隐藏草稿/撤回包；当前 schema 只接受校区配置 `v3`、Windows x64。

### `public.deployment_package_artifacts`

每个目录条目一行，仅保存私有对象存储的确定性 `storage_key`。数据库的延迟约束触发器要求发布包在事务提交前已有该对象记录。对象本身仍需上传到私有存储；SQL 约束不能代替存储端的真实对象核验。

`record_deployment_package_download(package_id)` 只授予 `service_role` 执行。下载 API 读取已发布包、验证对象长度与 SHA-256 后调用，用于原子增加计数；学生端不能直接调用计数函数或获取存储对象键。

### 私有 CloudBase PG Storage 桶

- 桶 ID：`deployment-package-artifacts`。
- `public=false`；`20260929041500` 迁移应用后单对象上限为 65,536 字节；MIME 白名单仅 `application/zip`。
- 对象键由服务端生成：`deployment-packages/v3/<packageId去连字符>.zip`。
- 远端已核对：桶记录存在且为私有，大小和 MIME 限制正确；`storage.buckets` / `storage.objects` 没有给 `anon` 或 `authenticated` 的对象策略。只有服务端持有 `service_role` API Key 才能读写对象。
- CloudBase 静态网站托管桶与该 PG Storage 桶用途不同，部署包不会写入网站静态文件桶。

## 4. 上传和下载的安全校验

### 教师上传

1. 发布不要求 CloudBase Auth；用户只能选择启用校区，且配置包内校区名必须与所选校区完全一致。客户端不能直接插入 PostgreSQL。
2. ZIP 不得超过 64 KiB，单个文件不得超过 16 KiB，整个 multipart 请求不得超过 128 KiB；限制 ZIP entry 数和解压总大小，拒绝重复文件名、路径穿越、绝对路径、链接和嵌套包。
3. 只接受 `manifest.json`、`campus.json`、校区公钥 PEM、网站策略公钥 PEM 这四项固定内容；拒绝 README、私钥、密码、未知文件、非 v3、非 Windows x64 及非空 `telemetryEndpoint`。
4. 重新计算清单中资源大小和 SHA-256；检查清单校区与教师授权校区一致，`computerPrefix` 符合本页规则。
5. 服务器根据 manifest UUID 生成文件名和对象键，写入私有对象存储；一个 PostgreSQL RPC 事务同时新增 package 元数据和 artifact 记录。只有两者都成功，目录行才提交为 published。
6. 文件上传失败、数据库提交失败或对象核验失败时，删除未引用的暂存对象并返回具体错误；不要留可公开访问的半成品。

### 学生搜索和下载

- 搜索只查询已发布目录信息，可按校区名称和电脑名前缀进行不区分大小写的子串筛选，也可按校区 ID 过滤，并按发布时间倒序分页。
- 下载请求传 `packageId`，服务器再次检查 published 状态，读取私有对象并比对数据库长度与 SHA-256，然后以规范文件名返回 ZIP。
- 下载响应文件名只使用数据库生成的 `artifact_file_name`；API 不接受客户端传入的本地文件名或存储路径。
- 学生收到 ZIP 后继续调用现有清单、路径、摘要、公钥及部署预检验证。TLS、数据库 SHA-256 和 ZIP 内资源摘要分别解决传输、归档和清单校验问题；未来若要求离线证明发布者身份，还需在包上增加教师/发布服务数字签名。

当前包只允许包含公钥与普通配置，且发布前应有真实教师账号授权。若需要限制“学生只能下载本校包”，需要再设计学生身份或一次性校区注册码；当前表只实现公开已发布目录和下载语义，不做学生身份认证。

## 5. 两种分发方式

学生端现在保留 Windows 共享文件夹入口，并新增网站云端目录入口。共享文件夹适合局域网内手动读取；云端目录支持教师通过网站上传 ZIP 或选择配置包文件夹，学生按校区名称/电脑名前缀检索后下载并载入，或将已校验 ZIP 另存到本机。载入后仍需核对电脑编号、生成预览并运行只读检查，部署操作继续由学生端现有确认流程执行。

教师发布入口为网站 `/publish` 和教师控制台的首次设置页，均无需登录。服务端返回启用校区，任何人都可发布符合规则的校区公开配置。学生桌面端默认通过 CloudBase HTTP 网关域名访问 `/v1/deployment-packages`，可用环境变量 `VEYONCAMPUS_DEPLOYMENT_PACKAGES_API_BASE_URL` 覆盖 API 基地址。

发布校区授权仍由 owner/admin 调用 `POST /v1/deployment-package-publishers` 管理，当前没有单独的授权管理页面。部署 CloudRun 时需配置服务端 `CloudBase__ApiKey`（service_role key）以及现有遥测所需密钥，并把网站 `/api` 路径转发至 CloudRun；学生 App 直接使用 CloudBase 网关地址。云端分发端到端验收仍需覆盖教师上传、学生搜索/下载、撤回、服务断网和下载中断。共享文件夹选项不依赖这些云端服务。

## 7. 后端 API 契约

接口源码位于 `src/VeyonCampus.Telemetry.Server/DeploymentPackageEndpoints.cs`，完整 OpenAPI 3.1 契约位于 [`src/VeyonCampus.Telemetry.Server/openapi/deployment-packages.yaml`](../../src/VeyonCampus.Telemetry.Server/openapi/deployment-packages.yaml)，复用已有遥测服务与 Dockerfile。所有服务端数据库和对象存储调用使用 CloudBase `service_role` key；公开发布不接触该密钥，浏览器和桌面端都不需要 Auth 会话。

| 方法与路径 | 权限 | 用途 |
| --- | --- | --- |
| `GET /v1/deployment-packages?query=&campusId=&limit=20&offset=0` | 公开只读 | 搜索已发布目录，最多每页 49 项，返回 `hasMore`；不包含对象键 |
| `GET /v1/deployment-package-campuses` | 公开只读 | 返回启用校区的 ID 与名称 |
| `GET /v1/deployment-package-publishers/me` | 登录用户（兼容管理） | 保留旧授权查询接口；公开发布页面与桌面端不调用 |
| `POST /v1/deployment-packages` | 公开写入 | `multipart/form-data` 上传。必需文本字段 `campusId`；文件字段选 `archive`（单个 ZIP）或 `files`（目录内文件，多项）之一；命名和大小由服务器校验 |
| `GET /v1/deployment-packages/{packageId}/download` | 公开，仅已发布 | 服务端校验对象 SHA-256 与大小后返回 ZIP；文件名由数据库生成 |
| `POST /v1/deployment-packages/{packageId}/withdraw` | owner/admin | 撤回已发布包，JSON 可带 `reason`（最多 500 字）；公开发布的包由管理员撤回 |
| `POST /v1/deployment-package-publishers` | owner/admin | JSON `{ "userId": "CloudBase Auth 用户 ID", "campusId": 1, "isActive": true }`，新增或停用教师校区授权 |

文件夹上传时，浏览器可通过 `webkitdirectory` 收集配置目录，并把同一目录下的文件以 `files` 字段重复加入 `FormData`；可带一个共同根目录名，服务器会去掉该层。拒绝子目录、路径穿越、重复文件名、超过 5 个文件、单文件超过 16 KiB 或总内容超过 64 KiB。ZIP 上传字段最多一个，ZIP 内容最多 64 KiB；整个 HTTP 请求上限为 128 KiB。服务端按 `CampusConfigurationArchive` 重建规范 ZIP，所以无论上传文件夹还是 ZIP，云端只保存一个经过验证的 ZIP 对象。

请求示例（无需认证令牌；示例不包含任何密钥）：

```js
const form = new FormData();
form.set("campusId", String(campusId));
form.append("archive", zipFile); // 或将目录里的文件逐项以 files 字段加入

const response = await fetch("/api/v1/deployment-packages", {
  method: "POST",
  body: form,
});
```

学生目录通过 `GET /v1/deployment-packages?query=...` 查询；响应中的 `packageId` 用于 `GET /v1/deployment-packages/{packageId}/download`。浏览器使用同源 `/api/v1` 路径。对象键、`service_role` 密钥和数据库写入 RPC 都不返回给浏览器。网站 `/api` 前缀和学生端网关地址只有在 CloudRun 与 HTTP 网关路由部署后才会工作。

公开发布过程先校验活跃校区、校区名称与包清单一致性，再验证 schema v3、Windows x64、清单资源摘要、公钥 PEM、无私钥/密码/额外文件及空遥测地址；服务端从清单读取 packageId，生成对象键和下载名，并以固定 `public` 发布标记记录。对象上传成功后，PostgreSQL 单事务新增目录及对象映射；数据库失败时服务端尝试回滚未引用对象。只有服务端 service_role 能执行数据库写入与私有桶操作。

API 的 `publishedAt` 为绝对时间戳；网站显示时使用 `Asia/Hong_Kong`（UTC+8）。应用尚未创建 CloudRun 部署和网关映射；当前代码接口仅在本地项目内，不能通过 CloudBase 默认域名调用。
