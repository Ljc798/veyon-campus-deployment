# 网站开发规范

本规范适用于 website/ 下的公开站点与管理员工作区。网站独立于 src/VeyonCampus.App 中的 Windows 桌面程序开发和发布。

## 1. 目标与边界

- 公开页面介绍 Veyon Campus 的实际定位、版本、使用文档和隐私边界，不显示管理员后台入口。
- /admin 是单独的管理员工作区。访问时先由 CloudBase Auth 验证身份，PostgreSQL admin_profiles 与 RLS 决定数据权限。
- 浏览器只能使用 CloudBase publishable key。CloudBase service API key、数据库密码和 `Telemetry__DailyHashKey` 只能放在 HTTP 云函数的服务端环境密钥配置，不得进入静态网站或浏览器构建。
- API 后端只使用 CloudBase HTTP 云函数 `veyon-api`，网站和桌面客户端经 HTTP 网关调用；CloudRun/云托管后端方案已弃用。CloudBase 静态网站托管仍可用于网站文件，不承担 API 计算。
- CloudBase PG 已有校区和按日心跳汇总表。空表应展示空状态，不得用本地虚构数据冒充真实记录。
- App 当前状态统一见 [任务主表](../../docs/开发路线与任务清单.md)，云端实施范围见 [云端指南](../../docs/网站与云端指南.md)。

## 2. 技术约定

- 使用 Vite 提供开发服务器和生产构建；依赖版本及用途写在 website/package.json。
- 公开页面保持轻量；CloudBase SDK 和管理模块只在用户直接进入管理员路由时加载。
- 所有站内页面采用同一域名和路径路由；链接使用以 / 开头的站内路径，支持浏览器前进、后退和刷新。
- 表单、按钮和导航具备语义标签、键盘焦点和窄屏布局。
- CSS 设计变量集中在 styles.css 的 :root 中。品牌色优先使用深蓝 #132E46、青绿 #187B70 和浅色背景。
- 不从未经审核的第三方 CDN 加载脚本、字体或图片。新增依赖须记录用途、版本和许可证。

## 3. 页面与内容

- 公共页面说明产品、项目背景、部署步骤、反馈入口与隐私原则。
- 管理页面包含数据总览、校区、按日匿名汇总、趋势与账号状态；不得加入公共导航、首页 CTA 或页脚直达链接。
- /admin 直接访问不代表获得权限。页面隐藏、前端按钮和路由判断都不能替代 CloudBase Auth、数据库 grants 与 RLS。
- 角色由受控管理渠道维护。浏览器不可修改 admin_profiles 或自行提权；不要增加公开注册到管理员角色的流程。
- 所有客户名称、校区信息、用户反馈、统计数字与连接状态应准确标记数据来源。PG 无记录时应显示空状态。
- 产品能力以根目录 README.md 与 docs/README.md 为准。未经桌面 App 实现和验收的能力应写成规划或待验收事项。

## 4. 数据与隐私

- 校区资料只保存名称、地区、城市、状态和系统时间，不加真实联系人或学生个人资料。
- 匿名心跳默认关闭；启用后只携带随机安装标识、StudentSetup 版本和 manifest packageId。API 按 UTC+8 日 HMAC，服务端从已发布包映射校区；数据库不保存原始标识，也不接收用户、电脑名或 IP 字段。
- 逐日摘要保留目标 90 天，每日聚合保留目标 400 天。每日活跃数不能跨日去重，不可累加成周期独立设备数。
- 需清楚说明统计用途、启用方式和留存期限；学生包遥测地址默认为空。
- 地区由授权管理员录入，不采集精确定位。不要采集课堂屏幕、浏览历史、文件内容或统计目的无关信息。
- 浏览器本地存储不是管理数据存储或权限边界；真实管理资料只经 Auth 会话和 RLS 访问 PostgreSQL。
- CloudBase /api/health 仅检查遥测进程状态，不验证管理员认证、PostgreSQL 写权限或 App 是否已接入。
- 公开网站不直接访问数据库；管理数据使用登录会话和 RLS。心跳写入使用服务端 REST RPC，不开放匿名 SQL 写入。

## 5. 前端行为

- 路由变化后更新页面标题和选中导航，支持浏览器历史记录。
- 搜索、筛选、区间切换、导出和表单操作需有可见反馈；空结果显示清晰空状态。
- 校区列表初始最多查询 200 条，同时呈现数据库总数。若数据规模增长，增加游标分页，不扩大整表查询。
- 表格适配窄屏并允许表格容器内横向滚动；颜色不能作为唯一状态提示。
- 用户输入插入 HTML 前必须转义。数据库错误消息不可原样显示给浏览器用户，以免暴露表结构和服务信息。

## 6. 修改与发布流程

1. 修改前确定属于公开网页、管理前端、API 或 PostgreSQL 的哪一层。
2. 数据结构变化创建新的 14 位 CloudBase 迁移文件，完成 plan、apply 和对象/策略核对后再更新应用代码。
3. 本地首次运行使用 npm ci；启动 npm run dev，打开公开路由和 /admin 登录页。
4. 变更后运行 npm run build 与必要的 JavaScript 语法检查；按任务要求决定是否执行测试。
5. 发布前核对前端构建中无 service API key、公开页无后台入口、静态托管回退与上传范围正确。
6. HTTP 云函数发布、静态网站发布、自定义域名和 HTTPS 绑定须先完成部署预检及回滚方案，并通过 CloudBase 发布门禁。后端只能发布为云函数；静态网站托管与 API 云函数分别验收。

## 7. 路由清单

| 路由 | 页面 | 数据来源 |
| --- | --- | --- |
| / | 首页 | 静态介绍，无管理员入口 |
| /product | 产品能力 | 静态产品状态与数据边界 |
| /about | 关于项目 | 静态内容 |
| /docs | 使用指南 | 静态内容与仓库文档链接 |
| /contact | 联系与反馈 | 表单只提示本地预览，不上传反馈 |
| /privacy | 隐私说明 | 当前 Auth、PG 和心跳字段说明 |
| /admin | 登录 / 数据总览 | CloudBase Auth 与 PostgreSQL |
| /admin/campuses | 校区管理 | PostgreSQL campuses |
| /admin/usage | 匿名汇总 | PostgreSQL telemetry_daily_hkt_stats |
| /admin/analytics | 趋势分析 | PostgreSQL 日汇总和实际校区资料 |
| /admin/settings | 账号和连接说明 | Auth 会话、角色和保留策略 |
