# P3-04/05 受限 Worker 与按需 UAC

## 问题与范围

当前 Windows 应用清单要求整个 App 以管理员权限运行。P3-04/05 要求普通权限界面仅在用户确认系统修改后启动短生命周期高权限 Worker，并通过受控本机协议执行固定操作。本规格覆盖 StudentSetup 与 TeacherConsole 中需要本机管理员权限的系统修改：账户/电脑名、Veyon 安装/配置/密钥库/机房目录，以及学生网站策略 Agent 安装/卸载；不把 Teacher 的云端发布、策略推送、文件浏览、用户证书中的网站签名私钥或更新下载移入高权限进程。

## 用户故事

- 作为学校管理员，我希望日常使用、浏览和准备计划时不提升整个界面的权限，只有确认本机系统修改时才收到 UAC 提示。
- 作为管理员，我希望提升进程只能执行产品定义的操作，不能把任意命令、脚本或路径交给高权限进程。
- 作为操作者，我希望 UAC 取消时没有系统改动；Worker 中断或身份校验失败时看到“需核对”，且后续步骤停止。

## 验收条件（EARS）

1. 当应用正常启动时，StudentSetup 和 TeacherConsole 必须以 `asInvoker` 运行；只读浏览、导入和计划预览不得请求 UAC。
2. 当操作者确认一项需要管理员权限的固定步骤时，UI 必须启动受保护安装目录中的匹配版本 Worker 并按需触发 UAC；UAC 取消必须在任何系统修改前返回取消状态。
3. 当 Worker 收到请求时，它必须验证协议版本、枚举操作、参数边界、请求关联 ID、调用 UI 的 PID/SID/会话/映像路径/版本和目标 SID；未知字段、未知操作或不匹配身份必须拒绝执行。
4. 当 UI 与 Worker 通信时，协议必须使用仅限本机的单次随机命名管道；DACL 只允许发起 UI SID、Administrators 和 SYSTEM；限定一客户端、帧大小和超时；密码仅经管道传递，不能放入进程参数或运行日志。
5. 当 Worker 执行操作时，它只能调用预先注册的适配器；不得接收可变命令行、脚本正文、任意可执行文件路径或可由请求指定的工作目录。
6. 当 UAC 使用另一管理员凭据时，系统必须分别记录发起 UI 身份和 Worker 管理员身份；账户目标继续按预检时冻结的本地 SID 复核。
7. 当 Worker 断连、超时或返回身份/协议错误时，UI 必须将当前步骤标记为需核对、停止后续步骤且不得自动重试。
8. 当软件安装在用户可写目录、Worker 与 UI 版本不一致、无法确认文件身份或 IPC 安全属性时，系统必须拒绝提权执行并说明原因。

## 约束与非目标

- 不安装常驻高权限服务；Worker 每次操作短生命周期运行。
- 不改变现有计划顺序、预检、备份和读回语义；Worker 不能替代这些保护。
- 本机管理员始终可控制本机；本功能不宣称抵御本机管理员或恶意内核组件。
- `VeyonTeacherKeyProvisioner` 只允许创建/复用校区密钥并把公钥回传给普通 UI；绝不把 Veyon 私钥传出受控密钥库。机房电脑清单请求限制为现有 1–150 台校验规则。
- 在 Windows 10/11 实机完成 ACL、UAC、跨账户凭据、假 Worker、崩溃恢复和真实修改验收前，不将 P3-04/05 标为完成。
