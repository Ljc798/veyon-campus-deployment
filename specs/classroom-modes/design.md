# 课堂模式设计

## 交互与默认值

- 活动课堂卡片只显示一个当前模式和一个切换按钮：“开始练习”或“恢复正常”。讲解与休息都使用“恢复正常”，减少重复选择；“下课”保持独立。
- 练习模式固定选择当前校区最近更新的网站和应用预设，系统策略预设不显示为候选。页面展示实际采用的预设名称及逐台结果；老师不再逐次挑选策略和目标。
- 手机 PWA 在课堂区复用相同模式和当前状态；策略页继续作为高级入口，课堂首页不重复暴露预设选择。

## 组件边界

- `VeyonCampus.Core/ClassroomModes.cs` 定义固定 `ClassroomMode`、本地状态/拥有版本模型、严格 JSON 与原子有界存储。状态以随机 session target ID 关联逐台 revision，不存 IP/主机名；活动和未完成清理 session 有明确数量上限。
- Teacher 的课堂协调器作为唯一模式执行者：从活动会话获取目标地址和 session target ID 映射，读取签名 Agent 状态，调用现有策略编译器/签名传输，再更新模式及拥有版本状态。
- Teacher Mobile HTTPS 服务对已配对手机提供模式读取和切换接口；手机不能持有私钥，不能提交目标、profile ID、任意规则或命令。服务器根据活动 session 和本校最近 profile 决定动作。
- Classroom status command v2 携带固定模式枚举；Agent 同时读取旧 v1 状态以兼容已安装学生端。签名 Agent snapshot 仅在当前课堂带模式字段；Companion 继续验证 Agent 签名后显示该状态。
- AppLocker Enforce 使用与现有手机流程相同的短期审核票据：绑定配对设备、本课堂、预设指纹、审核版本/统计和目标；使用前重新核验且单次消费。

## 状态与恢复

| 触发 | 课堂模式 | 网站/应用操作 | Session 生命周期 |
| --- | --- | --- | --- |
| 开始 | 正常课堂 | 不写入策略 | Active |
| 练习 | 练习 | 选最新网站/应用预设；只处理当前 Disabled 或本 session 拥有版本 | Active |
| 恢复正常 | 正常课堂 | 按签名状态读回仅解除拥有版本仍匹配的策略 | Active |
| 下课 | 结束 | 先尝试恢复；失败项写入本机待恢复记录 | Ended |

状态读回未响应时保留拥有记录；若 Agent 当前 revision 与拥有 revision 不同，视为外部接管，记录待核对并清除本课堂的撤销权限，不覆盖外部值。成功解除后删除对应拥有项。待恢复项按随机 session ID 保留，最多 31 条记录（最多 30 条已结束记录加 1 条活动记录），每 session 最多 150 个目标、两类策略共 300 条拥有项；本机文件拒绝重复/未知字段、重解析点与超限内容，原子替换。下课后桌面和手机列出电脑编号与策略类别，并提供一个自动重试入口。重试只使用本机校区/机房档案及当前 Veyon 目录，在机房、编号范围和目标唯一吻合时临时解析现行地址；地址不写入课堂恢复账本或手机待恢复列表。逐台签名读回确认仍由原课堂拥有的 revision 后才解除；离线、外部修改、档案不符或目标歧义均保留记录。

## 安全与验证

- 只接受 `normal/practice` 两个有界模式；“下课”走既有 Session end 操作，不作为任意命令或持久模式值。
- 模式状态命令绑定校区、session、随机消息 ID 和两分钟有效期，继续使用 RSA-PSS；v1 仍只接受无模式的旧 status payload，v2 必须含有效 mode。下课状态不带 active session 或 mode。
- 每种策略在发送前读取签名状态并按校区/目标固定 Agent 身份。只有失败/未知/外部版本才标记需复核；不把 HTTP 200 或 Agent 接受当作策略效果验证。
- 自动检查覆盖模式映射、profile 默认排序、session target 绑定、签名版本、状态回读与外部 revision 拒绝、Enforce 审核确认/失效、稳定标签与当前目录的唯一匹配、持久待恢复、校区隔离和长期系统策略不变；真实策略效果仍待 Windows/手机实机验收。
