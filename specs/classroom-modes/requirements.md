# 课堂模式需求

## 背景与范围

课堂会话、Student Companion、教师手机事件通道和网站/应用策略已经各自存在，但教师仍须在不同页面自行组合。课堂模式提供一个低选择的工作流：开始课堂默认为“正常课堂”；老师只在“练习”和“恢复正常”之间切换；“练习”自动复用本校最近更新的网站/应用临时预设；“下课”先尝试同样的安全恢复，再结束课堂。

系统策略是长期基线，不属于课堂临时模式，任何课堂模式不得自动修改它。AppLocker 执行模式保留现有“先审核、教师阅读、确认前重新核对”的门槛。

## 用户故事

- 作为教师，我可以从课堂页或已配对手机用一个固定入口切换正常课堂与练习，不再逐次选择目标电脑或策略类型。
- 作为教师，我可以看到系统使用了哪些默认预设，以及每台电脑的 Agent 确认、离线、待核对或失败结果。
- 作为学生，我可以在 Student Companion 看到当前课堂模式；课堂模式随签名状态同步。
- 作为学校管理员，我希望恢复正常/下课只撤销本堂课创建且当前版本仍匹配的临时网站/应用策略；长期系统基线和外部修改保持不变。

## 固定产品规则

1. 新课堂默认为“正常课堂”，不额外询问模式、目标范围或保存位置；讲解和休息共用恢复正常动作。
2. “练习”按本校最近更新时间选择一份网站预设和一份应用预设；没有某一类预设时只应用存在的类别。系统策略预设不参与排序或执行。两类均不存在时拒绝切换，保持当前模式。
3. 练习模式自动使用当前课堂的全部固定目标，不提供第二份目标选择。
4. 网站/应用策略启用前，逐台读取签名状态。目标当前策略为 Disabled，或其版本等于本堂课记录的拥有版本时才允许替换；未知状态、身份待核对或外部版本均保留原值并报告。
5. AppLocker Audit 可作为练习预设应用；Enforce 必须先对本次预设和本堂课目标推送 Audit、读取每台签名审核回执，并由教师明确确认。确认前重新读取的版本/统计不匹配时，旧确认失效。
6. “恢复正常”只尝试解除本堂课记录拥有且 Agent 当前读回版本仍匹配的临时网站/应用策略。解除失败或离线目标保留为有界待恢复项；外部版本变化不覆盖并从本堂课拥有记录中移除。
7. “下课”执行同样的恢复尝试后结束课堂事件/授权。无法确认解除的拥有记录保存在本机，不阻止下一堂课开始，也不得被静默丢弃。下课后在桌面和已配对手机显示待恢复项；教师无需选择电脑或策略，系统只按原机房和稳定电脑编号匹配当前目录，签名读回确认拥有版本后才尝试解除。
8. 每项策略结果逐台显示，Agent 接受不等于浏览器/AppLocker 实际效果已实机验证。
9. 当前模式、策略预设 ID 和 Agent 策略版本仅保存在教师本机；不保存网络地址、学生身份/姓名、策略正文、聊天内容或私钥，不上传 CloudBase。

## 验收条件

- 当开始一堂新课时，教师端应保存“正常课堂”作为默认模式，并通过签名课堂状态同步给兼容的 Student Agent/Companion。
- 当教师选择“练习”时，系统应自动用当前课堂目标和最新网站/应用预设执行；没有预设、校区不匹配或目标无法唯一匹配时必须安全拒绝，不扩大目标。
- 当目标 Agent 当前签名状态未知、策略 revision 非本课堂拥有或身份未固定时，系统不得覆盖其网站/应用策略，并应逐台标记待核对。
- 当应用预设为 Enforce 时，教师未确认同一策略和同一目标的最新审核结果前，系统不得启用阻止。
- 当教师恢复正常或结束课堂时，系统只解除拥有版本仍匹配的课堂策略；长期系统策略和已被外部改写的策略不得被课堂流程修改。
- 当恢复设备离线或签名状态无法读取时，系统应保留不含网络地址的本机待恢复记录；更新已被外部替换的版本时系统应删除其拥有记录并保留外部值。下课后桌面和手机应显示电脑编号、策略类别及结果，并提供一个自动匹配当前机房目录的重试动作；无法唯一匹配的项目不得发出命令且继续保留。
- 当手机模式操作或逐台策略操作被审计时，日志应只保存动作/预设 ID、时间、目标分类和结果，不保存策略正文或配对凭据。

## 非目标

- 不把六项长期系统策略映射到课堂模式，不自动改变任何系统基线。
- 不新增自定义模式编辑器、每模式目标选择、规则编辑或 CloudBase 中继。
- 本功能的代码/签名回执检查不能替代 Windows、浏览器和 AppLocker 的实机效果验收。
