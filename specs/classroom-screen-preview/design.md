# 手机课堂屏幕巡视：设计

## 数据路径

```text
已配对手机 --HTTPS/配对令牌--> Teacher Mobile API
   |                                | 校验活动课堂、座位目标与权限
   |                                +--> Veyon 已认证 Screenshot 单帧
   |                                          |
   +-- no-store 缩略图 <--- 内存缩放 <--- 教师机临时原图（精确删除）
```

- 目标从活动课堂和本机座位映射构造；`/api/session` 为每个可巡视座位返回本课堂目标 ID、座位号、姓名和电脑名，不返回用于采集的主机地址。浏览器只提交目标 ID 和短期巡视租约，Teacher 每次请求都从当前课堂座位映射重新解析主机地址；改写 URL 不能查询任意主机。
- Teacher 按目标运行受限的 Veyon `Screenshot` 采集，验证唯一输出文件与最大输入字节后缩放为内存 JPEG 母图，再删除本次精确匹配原图。
- 手机端按座位号排序，默认只请求可见区域；屏幕巡视开关拥有统一轮询调度器，停止/后台/课堂变化取消请求。

## 资源预算与控制

- 移动端只有三个用户选项：画质“省流/标准/清晰”，刷新“3/5/10/15/30/60 秒”。默认省流、10 秒；解释文案使用“画面更清楚会多用流量”这类普通语言。
- 服务端把三档固定映射为 320×180/JPEG 48、640×360/JPEG 68、960×540/JPEG 84；Veyon 原图先限制在 1280×720，再编码成最多 1 MB 的短期内存母图。未知画质回到省流；刷新范围夹在 3 至 60 秒，并归到最近的预设。
- 单个座位截图最短间隔 3 秒；截图采集最多并发 2 个，手机接口按设备每分钟最多 120 次、全局最多 600 次限流；教师机母图缓存总量不超过 10 MB。图片响应使用 `Cache-Control: no-store`。
- 只有在屏幕巡视明确开启且学生卡片可见时请求单帧；单个目标失败独立显示状态并允许下轮重试。普通屏幕巡视遵循所选刷新间隔；Veyon 原生窗口单座位画面保持约每秒更新。
- 逐台目标可渐进采集，任何时间都不将 150 台截图一次性并发运行；当前硬限制为两路采集和 10 MB 母图缓存，扩展规模前仍需实机测量。

## 安全与生命周期

- Teacher Mobile API 复用现有配对 Bearer token 和 HTTPS；每次图片读取核对 session、座位目标、认证设备和租约。
- 同一座位按服务端最短间隔限速；进入等待队列的请求可取消，取消后不得启动 CLI。
- 内存图片按课堂 session 和稳定目标隔离，课堂变化时清空。响应禁止缓存；Service Worker 明确绕过图片端点。
- 审计只记时间、会话设备、座位标签、用户画质预设和结果代码；不记内部目标 ID、主机地址、画面或屏幕文字。

- Windows Veyon 4.11.2 实测原图路径、文件匹配、删除、图像处理、资源预算与故障输出。
