# 课堂即时测验：设计

> 教师进程内存状态机、签名消息契约、教师服务端首批 API 和 Session 生命周期清理已有代码；Agent/Companion 客户端传输、桌面/手机可视界面和现场验收仍未完成。本功能不属于稳定发布候选。

## 组件边界

- Teacher Console 是题目生命周期的唯一写入口；当前活动 Session 和目标列表来自现有本机课堂会话。
- Student Companion 仅显示当前题目并提交选项。Student Agent 使用既有教师证书固定、校区身份和目标授权校验学生请求；不能信任 Companion 自报的目标。
- Teacher Console 通过本地管理器调用教师服务端的创建、关闭、揭晓和取消方法。配对手机只有只读 API，可读取状态和揭晓后的汇总结果。
- 课堂题目和答案沿 Teacher HTTPS 局域网服务传输，不经过 CloudBase、发布 API 或网站策略执行器。

## 协议与状态

- 使用单独、版本化且严格校验的 Classroom Quiz 消息用途，不复用求助消息中的自由文本字段，也不把题目塞入通用 ClassroomNotice。
- 题目绑定 CampusId、SessionId、随机 QuizId、创建时间和状态；答题绑定 QuizId 与选项 ID。服务端从已验证的 Agent 授权中解析目标。
- 状态为 Open、Closed、Revealed 或 Cancelled。创建后进入 Open；教师关闭后停止接受答案；揭晓只开放汇总结果；结束课堂或取消进入终态并清理。
- 开放期间内存保存每个授权目标最后一次选择和对应选项计数。相同目标重复请求幂等；更改选项时更新旧计数与新计数。
- 关闭时丢弃目标到选项的映射，只保留本 Session 的汇总计数供教师桌面和配对手机显示。终态题目在 Session 结束或教师进程退出时清除。
- 已实现的 `ClassroomQuizStore` 只负责上述教师进程内存状态：每题最多 150 个目标、4 小时有效期、每目标最多 256 个唯一提交 ID；达到提交上限时不改变答案。取消、过期和 Session 结束会移除当前题目。
- 教师服务端已提供学生测验读取和答案提交路由：问题仍由教师密钥签名，答案由 grant 中固定的 Agent 公钥验证，目标仅从授权 grant 解析。配对手机只读路由返回教师汇总 DTO，不返回目标级答案。

## 签名、授权与数据最小化

- Teacher 发布的题目由校区教师密钥签名；Student Agent/Companion 校验当前 CampusId、SessionId、题目状态、字段大小及有效期。
- 学生答案必须使用由教师授予的短期目标授权，并由 Agent 身份密钥签名。客户端 payload 不得包含可选择的电脑名、目标 ID、教师地址或校区 ID。
- Core 已定义 `VeyonCampus.ClassroomQuizQuestion.v1` 和 `VeyonCampus.ClassroomQuizAnswer.v1` 两种 purpose：题目用教师固定公钥验证，答案用当前授权目标的 Agent 固定公钥验证；答案正文不含目标标识。签名封装限制为 16 KiB/8 KiB，答案有效期最多 2 分钟。
- Teacher API 在提交时固定目标归属并校验当前课堂集合。一个目标只能对当前 QuizId 有一份有效答案。
- 未揭晓前，教师手机接口只返回题目摘要与响应数量；揭晓后仅增加各选项聚合计数。移动端和学生端响应都不得包含目标级答案。
- 不写课堂事件历史、答题内容或会话题目日志；错误日志只记稳定错误码，不记题目正文和答案。

## 可靠性与故障恢复

- 提交请求带随机 SubmissionId；重试保持相同 ID。服务器按 SessionId、QuizId 和已认证目标去重，并明确返回 accepted、duplicate、closed 或 expired。
- 学生客户端只在收到教师服务确认后显示已提交；超时或断线显示待确认，重连后查询当前题目及本机目标的当前选择。
- Teacher 进程重启后不恢复开放题；桌面 UI 需明确提示本堂课的测验已结束。旧消息因 Session/Quiz ID 不匹配而拒绝。
- 所有内存集合、并发数、请求体大小和提交频率均有上限；满载时返回可读错误，不阻塞其他课堂事件或策略操作。

## 页面范围

- Teacher Console 在活动课堂卡片内提供题目编辑、发布、关闭、揭晓和汇总结果，不新增顶级导航。
- Student Companion 仅添加一个清楚的单选题卡片和提交状态；不增加账号或网络设置。
- 已配对手机只读显示活动状态和教师已揭晓的汇总结果，不保存本地历史，也不展示逐台答案。

## 实施前必须核对

1. 已复核现有 ClassroomEvent、Student Agent 授权刷新与 Mobile API；教师端独立 quiz 路由和两种签名 purpose 已落地。仍需把客户端接入这些路由。
2. 确认 Teacher 重启后活动 Session 的恢复语义，确保题目能显式结束且不会被恢复。
3. 确认手机页面只接收汇总 DTO，并检查日志、异常和诊断事件不带题目/选项正文。
4. 完成代码检查后仍需另行做 Windows 双机、手机证书、断网重连和 10/24 台课堂验证。
