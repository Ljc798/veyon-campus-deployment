# 手机端教师控制设计

> 本文中有关课堂练习模式的部分属于旧实现。TeacherConsole 1.1.23 不再启用临时课堂预设；保留的兼容路径只用于恢复旧状态，见[停用记录](../../docs/records/2026-10/classroom-practice-mode-removal-20261022.md)。

## 当前手机限制页范围（2026-10-20）

手机电脑限制页不再加载或选择策略预设，只读取教师端当前校区已保存的网站阻止/允许名单，并向选定电脑推送或解除网站限制；应用与系统策略仍只在教师桌面端操作。桌面手机控制窗口保留的预设维护只供课堂练习模式读取，不能作为手机电脑限制页的方案来源。旧 `/api/profiles` 接口继续服务课堂模式和兼容客户端。

## 目标与实现边界

教师控制台是控制面的唯一签名者。教师 Windows 进程持有现有校区私钥，并在校园 LAN 内向学生 Agent 推送命令；手机端只保存可撤销的配对凭据。CloudBase 不转发控制或学生状态数据。

首期以教师控制台进程内的 ASP.NET Core/Kestrel HTTPS 服务托管同源移动网页。只在教师控制台的私有 IPv4 地址监听 TCP 39176，防火墙规则限定 `LocalSubnet`、Domain/Private 网络配置。教师端安装程序建立该规则；卸载时删除自己创建的规则。StudentSetup 不启动此服务。

## 连接与配对

1. 首次启动时，教师控制台生成本机专用 CA 和 HTTPS 服务证书。私钥仅保存在教师 Windows 用户的受保护本地密钥存储中；服务证书 SAN 包含教师电脑当前可用的私有 IPv4 地址。根证书由控制台导出供手机一次性安装/信任，桌面控制台同时显示证书 SHA-256 指纹及 LAN 地址。
2. 教师在桌面端开启配对窗口后，控制台生成短时、单次使用的配对码，并在本机生成 LAN HTTPS 配对二维码。二维码把配对码放在 URL 片段中，避免随 HTTP 请求发送；手机打开页面后清除片段并预填配对码，用户提交设备昵称后，桌面教师必须核对设备名和来源 LAN 地址，在控制台显式批准或拒绝待配对设备。配对码五分钟过期，请求两分钟未处理即失效。二维码只减少地址/配对码输入步骤，不安装或绕过证书信任。
3. 批准后服务签发随机 256-bit bearer 凭据，服务仅持久化凭据哈希；手机将凭据写入 IndexedDB。控制台允许按设备撤销，撤销后立即拒绝该凭据。配对窗口关闭、超时或服务停止时，未完成请求失效。
4. 手机网页以 HTTPS 和浏览器原生证书信任验证服务身份；接口要求 bearer 凭据、严格同源、JSON 内容类型、请求大小上限、限速及防重放 nonce。API 不使用跨域共享资源，不接收任意命令、文件路径或 URL。

证书首次信任是 PWA 的浏览器安全边界：页面不提供绕过证书错误的按钮。服务地址变化时控制台应显示新的地址/证书指纹；若 CA 轮换，必须重新信任并重新配对。

## 移动网页与桌面集成

- `TeacherMobileControlServer` 只在 TeacherConsole 角色启动，在 Avalonia 桌面程序退出时停止；服务启动失败不影响桌面端其他工作，并在桌面端显示具体原因。嵌入页面和脚本由教师端按 no-store 提供；Service Worker 不缓存页面/API，在教师端重启或手机恢复网络后获取当前资源并尝试重连，避免要求用户清浏览器缓存。
- 移动网页以嵌入资源随教师安装包交付；同源路由提供配对、当前会话、机房、预设、状态和操作 API。配对设备批准/拒绝/撤销及本机记录查看都在教师桌面端完成。首期不从 CDN 加载脚本或字体。
- 新增桌面“手机控制”设置区，显示服务状态、LAN URL、TLS 根证书下载/指纹、按网络地址切换的一次性配对二维码和配对码、待批准/已配对设备及本机操作记录，并提供批准/拒绝、撤销、查看记录和保存策略预设入口。无法扫码时保留手动输入方式。
- 房间和目标从 `VeyonNetworkObjectDirectory.ReadLocations()` 读取。课堂练习预设由桌面端编辑器保存，含校区、练习策略、逐电脑学生 SID 映射和时限；移动端只负责选择目标和启动课堂练习，不读取 SID。电脑限制页不使用网站预设。旧版共用 SID 预设只允许单台目标；新预设须完整覆盖每个待启用目标。
- 电脑策略页增加地点浏览模式：从 `/api/rooms` 读取 Veyon 当前地点目录，将 `TargetDisplayNames` 作为电脑显示名，将 `Targets` 仅作为内部连接/校验键。显示名缺失时用“未命名电脑”，界面和操作结果不暴露地址。一个目标若在多个地点重复出现，显示目录冲突并禁用该目标的单机操作，要求先修复 Veyon 清单。
- 每个地点的电脑目录使用两列响应式卡片；每张卡片预留统一尺寸的电脑图标槽，首期仅保留中性占位，不下载图片。点卡片进入单机详情，点返回回到原地点与滚动位置。详情只请求该目标的签名状态，并用日常中文显示当前模式、到期时间和系统六项开关；不向手机用户展示内部版本号、Agent 名称或服务器原始错误。未知/离线/需核对状态明确保留，不渲染成已解除。操作结果区分“电脑已回应”和实际限制效果核验。
- 详情中的应用/解除操作始终只提交一个目标，并在确认中同时显示电脑名、状态读取时间、当前策略摘要、预设名称/类型和期限。原有多目标批量操作保留在独立的范围选择入口；单机卡片动作不复用用户可能遗留的批量选择集合。
- 多个教师控制台没有共同的本机互斥锁或共享审计文件。手机确认时提交此前已签名读回的逐台、逐策略版本；Teacher 在签名前重新读取 Agent 状态，若版本与手机所见不同就拒绝并要求刷新、重新确认。签名策略继续绑定该预期版本，Agent 在本地事务锁内核对，只有与当前版本相同才接受并应用，因此也覆盖预检后并发到达的写入。Agent 对新版本仍执行现有单调递增/防重放校验；桌面端不带期望版本的旧协议调用继续遵循其现有兼容语义，后续迁移可再逐步统一。
- Veyon 列表与策略状态均按需读取，不为手机目录新建云端数据表或学生身份数据库。既有本机审计记录继续用于操作追溯；它按教师控制台本机保存，只代表该台教师电脑发起的请求。
- `/api/session` 返回当前校区活动课堂的目标快照。网页只在每个目标与 Veyon 清单完整、唯一匹配时默认选中并收起目标清单；不匹配时保持空选并展开范围供教师核对。首次加载不展示手动列表，确认目标缺失或未匹配后才展开。这个默认值只改变选择状态，不会触发策略操作。
- 同一响应中的座位资料来自本机可编辑座位网格，只包含存在稳定 Veyon 电脑/地点 ID、主机地址命中本堂活动目标的座位，并返回座位号、行列、学生姓名和电脑名。手机在课堂事件、学生列表和屏幕卡片中优先显示学生姓名；筛选仍允许使用 Veyon 电脑名。没有新网格时暂时兼容旧的只含行列位置数据。
- 电脑限制页不显示方案选择器；当前校区的教师端名单自动读取并展示阻止/允许数量和更新时间。教师可在手机按行编辑名单、增加或删除域名、保存到教师端，然后设置默认一小时的截止时间并推送；推送会先保存未提交修改。保存携带读取到的更新时间，冲突时拒绝覆盖并保留手机编辑内容。活动课堂目标与电脑目录完整匹配时仍自动作为范围；推送前需教师确认。
- 课堂模式作为主要快捷操作；独立电脑限制页只处理当前校区网站名单，不编辑复杂应用规则、账户或签名内容。应用/系统策略仍由教师桌面端处理。
- 预设 JSON 有严格 schema、字段/总大小上限、唯一 ID、原子替换写入与路径链接拒绝；不包含私钥或访问 token。

## 策略操作

- 服务调用 `WebsitePolicyCompiler`、`ApplicationPolicyCompiler` 和对应签名/传输组件，不调用 Avalonia 控件、不启动 shell 命令。每次操作重新验证校区、目标、策略期限及 schema，再生成新的单调递增版本和签名消息。
- 写入前 Teacher 服务重新读取每台电脑的已签名状态；Agent 运行版本须为 0.4.50 或更高，该版本开始支持策略原子版本比较。缺少电脑名、Agent 身份未固定、状态不可读或 Agent 版本较旧时，不发送任何该次操作的策略。
- 长期系统策略若报告状态待复核（`Pending`）或版本缺失，服务端拒绝启用或解除；手机界面的禁用状态不能替代服务端检查。
- 网站模式沿用现有黑名单/白名单与自动到期语义。应用模式沿用审核/执行模型、学生 SID 与规则约束；执行模式必须先对相同目标/规则推送审核策略、读取全部目标审核回执并由教师在手机明确确认。执行前服务会重新读取相同审核版本和统计；版本/统计变化、待核对或不匹配的目标都会使原确认失效，必须重新审核。
- 解除限制生成签名 Disabled 策略；多目标结果逐台返回，失败设备可单独重试。策略接收 HTTP 成功回执标记为“Agent 已确认”，通过签名身份核验的状态读回标记为“签名身份已验证”；二者均不表示浏览器页面或启动拦截行为已在实机验证。
- 学生 Agent 使用 SYSTEM 专属持久 RSA 身份密钥签署状态、策略、审核和应用清单回执。状态绑定教师一次性签名随机数；其他成功回执绑定教师请求随机数、校区和请求正文摘要。TeacherConsole 按校区和目标电脑固定公钥；首次使用或换钥时显示指纹并要求教师明确批准，未核对的回执一律为“需复核”。超时、未支持和响应校验失败显示为未知/待核对，不推断为解除。
- 移动端的每个 mutating request 由教师服务写入本机审计日志：配对设备 ID、UTC 时间、动作、预设 ID、目标和逐台响应分类。禁止记录 bearer token、签名策略正文、应用目录/学生个人名称或私钥。

## 本地持久化与保护

- TLS CA/服务身份使用 Windows CurrentUser 证书库和不可导出的 CNG/RSA 私钥；仅导出 CA 公共证书。私钥只用于签发 HTTPS 服务证书，不用于签名校园策略。
- 配对设备只保存 bearer 凭据哈希，配对码/限速/二阶段审核票据仅驻内存；预设与审计日志写入 `%LOCALAPPDATA%/VeyonCampus/MobileControl`。拒绝重解析链接、重复 JSON 字段和未知字段；使用有界反序列化和临时文件原子替换。数据沿用当前 Windows 用户配置文件的访问控制；根证书私钥使用当前用户不可导出的 CNG 密钥。
- 服务严格拒绝公网/环回/链路本地以外的监听地址；防火墙限制 LAN 入站。配对码按来源 IP 和当前邀请总量限速，已配对 API 每台设备每分钟最多 60 次，并验证时间戳和单次 nonce。服务无互联网依赖、无云端写入和无手机私钥。

## 验证策略

- 可移植检查覆盖配对码一次性/过期/限速、凭据哈希存储/撤销、请求校验、防重放、预设校验、目标白名单、状态未知处理、逐台结果与审计脱敏。
- 电脑名映射需覆盖主机名/IP 目标、空电脑名、中文名和重复目标；移动网页检查 390px/窄屏下每行两张卡片、图标占位及卡片标题/结果不含 IP。详情操作检查必须证明请求仅携带当前卡片目标。
- Agent 端并发版本检查需用两个独立 Teacher 服务针对同一目标的并行和先后请求验证：教师页面所见版本已变化时应在签名前拒绝；两个相同期望版本的并行写入中，第一个成功后第二个应由 Agent 冲突拒绝；旧版本和重放仍应拒绝；状态未知时界面不得把策略显示为已解除。
- API 合同测试需覆盖未配对拒绝、教师批准/拒绝、同源策略、认证成功、权限不足、超大/无效请求及配对撤销。
- 构建角色检查确保 StudentSetup 不包含/不启动手机控制服务，TeacherConsole 嵌入网页资源并包含端点。
- 2026-10-16 本机 macOS 使用 .NET SDK 10.0.401 运行完整可移植检查 **78/78**；TeacherConsole、StudentSetup 和 Agent Release 构建均为 **0 警告、0 错误**；`app.js` 与 `service-worker.js` 的 Node 语法检查通过。这些检查覆盖本次目录、单目标操作和条件版本比较的代码路径，不等于 Windows/手机现场验收。390px 窄屏下的显示、Android/iOS 证书信任、真实 Windows 防火墙/网络隔离、两台教师电脑的并发冲突恢复和策略效果仍需按[任务清单](tasks.md)验收。

## 手机界面视觉规范（2026-10-19）

- **用途**：让教师在手机上快速查看课堂、学生电脑状态和画面，并完成已有授权范围内的策略操作。
- **视觉方向**：工业控制台风格。用清晰分区、紧凑状态和克制强调色呈现教学现场信息，保持 Veyon Campus 的识别度。
- **品牌配色**：深海军蓝 `#102A3B`、青绿 `#087F78`、雾灰底色 `#F1F5F7`、白色 `#FFFFFF`、蓝灰正文 `#173044`；状态继续使用既有的绿、琥珀和红色语义。
- **字体**：沿用静态页面现有系统中文字体栈 `-apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans SC", sans-serif`，不加载外部字体。此项是对设计技能字体默认限制的窄范围覆盖，依据是产品现有视觉基础及手机系统中文字体的可读性。
- **布局**：四个主页面继续使用底部导航。课堂页优先显示课堂状态和主要操作；限制页依次呈现地点/电脑、方案、状态和操作；画面页让当前预览占主要可视空间；设置页将低频说明收起。标题左对齐，使用侧边色条和不等宽层级建立重点；控件保持适合触屏的尺寸，并避开设备安全区。
- **改动边界**：只调整移动页面结构、样式和用户文案，不改变控制 API、权限校验、签名策略或操作行为。浏览器视觉回放、窄屏和实机结果分别记录，不以代码构建替代。
