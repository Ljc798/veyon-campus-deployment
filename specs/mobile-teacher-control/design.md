# 手机端教师控制设计

## 目标与实现边界

教师控制台是控制面的唯一签名者。教师 Windows 进程持有现有校区私钥，并在校园 LAN 内向学生 Agent 推送命令；手机端只保存可撤销的配对凭据。CloudBase 不转发控制或学生状态数据。

首期以教师控制台进程内的 ASP.NET Core/Kestrel HTTPS 服务托管同源移动网页。只在教师控制台的私有 IPv4 地址监听 TCP 39176，防火墙规则限定 `LocalSubnet`、Domain/Private 网络配置。教师端安装程序建立该规则；卸载时删除自己创建的规则。StudentSetup 不启动此服务。

## 连接与配对

1. 首次启动时，教师控制台生成本机专用 CA 和 HTTPS 服务证书。私钥仅保存在教师 Windows 用户的受保护本地密钥存储中；服务证书 SAN 包含教师电脑当前可用的私有 IPv4 地址。根证书由控制台导出供手机一次性安装/信任，桌面控制台同时显示证书 SHA-256 指纹及 LAN 地址。
2. 教师在桌面端开启配对窗口后，控制台生成短时、单次使用的配对码，并在本机生成 LAN HTTPS 配对二维码。二维码把配对码放在 URL 片段中，避免随 HTTP 请求发送；手机打开页面后清除片段并预填配对码，用户提交设备昵称后，桌面教师必须核对设备名和来源 LAN 地址，在控制台显式批准或拒绝待配对设备。配对码五分钟过期，请求两分钟未处理即失效。二维码只减少地址/配对码输入步骤，不安装或绕过证书信任。
3. 批准后服务签发随机 256-bit bearer 凭据，服务仅持久化凭据哈希；手机将凭据写入 IndexedDB。控制台允许按设备撤销，撤销后立即拒绝该凭据。配对窗口关闭、超时或服务停止时，未完成请求失效。
4. 手机网页以 HTTPS 和浏览器原生证书信任验证服务身份；接口要求 bearer 凭据、严格同源、JSON 内容类型、请求大小上限、限速及防重放 nonce。API 不使用跨域共享资源，不接收任意命令、文件路径或 URL。

证书首次信任是 PWA 的浏览器安全边界：页面不提供绕过证书错误的按钮。服务地址变化时控制台应显示新的地址/证书指纹；若 CA 轮换，必须重新信任并重新配对。

## 移动网页与桌面集成

- `TeacherMobileControlServer` 只在 TeacherConsole 角色启动，在 Avalonia 桌面程序退出时停止；服务启动失败不影响桌面端其他工作，并在桌面端显示具体原因。
- 移动网页以嵌入资源随教师安装包交付；同源路由提供配对、当前会话、机房、预设、状态和操作 API。配对设备批准/拒绝/撤销及本机记录查看都在教师桌面端完成。首期不从 CDN 加载脚本或字体。
- 新增桌面“手机控制”设置区，显示服务状态、LAN URL、TLS 根证书下载/指纹、按网络地址切换的一次性配对二维码和配对码、待批准/已配对设备及本机操作记录，并提供批准/拒绝、撤销、查看记录和保存策略预设入口。无法扫码时保留手动输入方式。
- 房间和目标从 `VeyonNetworkObjectDirectory.ReadLocations()` 读取。策略预设由桌面端当前编辑器保存，含校区、策略类型、规则、学生 SID、时限和审计说明；移动端可选预设与目标，不能编辑复杂规则。
- 预设 JSON 有严格 schema、字段/总大小上限、唯一 ID、原子替换写入与路径链接拒绝；不包含私钥或访问 token。

## 策略操作

- 服务调用 `WebsitePolicyCompiler`、`ApplicationPolicyCompiler` 和对应签名/传输组件，不调用 Avalonia 控件、不启动 shell 命令。每次操作重新验证校区、目标、策略期限及 schema，再生成新的单调递增版本和签名消息。
- 网站模式沿用现有黑名单/白名单与自动到期语义。应用模式沿用审核/执行模型、学生 SID 与规则约束；执行模式必须先对相同目标/规则推送审核策略、读取全部目标审核回执并由教师在手机明确确认。执行前服务会重新读取相同审核版本和统计；版本/统计变化、待核对或不匹配的目标都会使原确认失效，必须重新审核。
- 解除限制生成签名 Disabled 策略；多目标结果逐台返回，失败设备可单独重试。策略接收 HTTP 成功回执标记为“Agent 已确认”，通过签名身份核验的状态读回标记为“签名身份已验证”；二者均不表示浏览器页面或启动拦截行为已在实机验证。
- 学生 Agent 使用 SYSTEM 专属持久 RSA 身份密钥签署状态、策略、审核和应用清单回执。状态绑定教师一次性签名随机数；其他成功回执绑定教师请求随机数、校区和请求正文摘要。TeacherConsole 按校区和目标电脑固定公钥；首次使用或换钥时显示指纹并要求教师明确批准，未核对的回执一律为“需复核”。超时、未支持和响应校验失败显示为未知/待核对，不推断为解除。
- 移动端的每个 mutating request 由教师服务写入本机审计日志：配对设备 ID、UTC 时间、动作、预设 ID、目标和逐台响应分类。禁止记录 bearer token、签名策略正文、应用目录/学生个人名称或私钥。

## 本地持久化与保护

- TLS CA/服务身份使用 Windows CurrentUser 证书库和不可导出的 CNG/RSA 私钥；仅导出 CA 公共证书。私钥只用于签发 HTTPS 服务证书，不用于签名校园策略。
- 配对设备只保存 bearer 凭据哈希，配对码/限速/二阶段审核票据仅驻内存；预设与审计日志写入 `%LOCALAPPDATA%/VeyonCampus/MobileControl`。拒绝重解析链接、重复 JSON 字段和未知字段；使用有界反序列化和临时文件原子替换。数据沿用当前 Windows 用户配置文件的访问控制；根证书私钥使用当前用户不可导出的 CNG 密钥。
- 服务严格拒绝公网/环回/链路本地以外的监听地址；防火墙限制 LAN 入站。配对码按来源 IP 和当前邀请总量限速，已配对 API 每台设备每分钟最多 60 次，并验证时间戳和单次 nonce。服务无互联网依赖、无云端写入和无手机私钥。

## 验证策略

- 可移植检查覆盖配对码一次性/过期/限速、凭据哈希存储/撤销、请求校验、防重放、预设校验、目标白名单、状态未知处理、逐台结果与审计脱敏。
- API 合同测试需覆盖未配对拒绝、教师批准/拒绝、同源策略、认证成功、权限不足、超大/无效请求及配对撤销。
- 构建角色检查确保 StudentSetup 不包含/不启动手机控制服务，TeacherConsole 嵌入网页资源并包含端点。
- 当前已使用 .NET 10.0.401 完成 TeacherConsole/StudentSetup/Agent 构建、53 项可移植检查、21 项 Node/API 契约检查和 HTTPS API 合同测试；移动浏览器证书信任、真实 Windows 防火墙/网络隔离、安装包更新与策略效果仍需单独实机验收。
