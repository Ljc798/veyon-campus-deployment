# 手机端教师控制需求（评审稿）

## 背景与范围

教师希望在校园 Wi‑Fi/LAN 内通过手机查看学生电脑状态，并启用或解除网站、应用限制。首期是手机控制入口，不替代教师桌面端，也不包含学生系统策略或软件更新控制。

当前教师端通过 TCP 39174 向学生 Agent 直连推送策略。学生 Agent 在 `LocalSubnet` 上监听；网站和应用策略由教师 Windows 用户证书库中的私钥签名。学生端已有 `/health` 和应用策略审核读取接口，但没有网站策略状态读取接口，也没有手机配对或教师侧移动控制服务。手机不能持有校区签名私钥，也不能绕过教师端直接向学生 Agent 发控制命令。

因此首期需让手机在校园 LAN 上连接一台已运行的教师控制台，由该教师电脑校验手机身份、签署策略并转发至选定学生电脑。控制流不得依赖 CloudBase 中继、互联网可达性或公网端口转发。

## 用户故事

- 作为教师，我可以在手机上确认教师控制台和学生电脑是否在线，以及网站/应用限制当前状态。
- 作为教师，我可以选定一个或多个已配置地点/学生电脑，启用预先保存的网站或应用限制，或签名解除限制。
- 作为教师，我可以区分“Agent 已确认”“设备离线”“结果待核对”等状态，不会把送达回执误认为浏览器或应用行为已验证。
- 作为校园管理员，我可以撤销已配对手机的访问权，并查看本机保留的操作记录。

## 验收标准

1. 当教师控制台在校园 LAN 运行时，手机端应能通过配对流程绑定到该教师电脑；配对需经教师电脑上的教师主动确认，并且配对凭据可撤销。
2. 当手机与教师电脑不在同一校园 LAN，或教师电脑未运行时，手机端应明确显示不可连接；系统不得将控制命令转发到 CloudBase 或公网。
3. 当配对手机请求状态时，系统应显示已配置地点/目标电脑的在线性、最后响应时间、网站策略模式/到期时间及应用策略模式/版本。设备不可达或 Agent 不支持某类查询时，应显示“未知/不可用”，不得显示为“已解除”。
4. 当教师在手机选择限制预设并确认操作时，教师电脑应重新验证当前校区、预设内容、目标列表和签名权限，再通过现有学生 Agent 通道发送经过签名的策略。
5. 当教师在手机解除网站或应用限制时，教师电脑应为每个目标生成校区签名的解除策略；部分目标失败时，应逐台展示结果并允许只重试失败目标。
6. 当应用限制会启用实际阻止模式时，手机流程应保留现有执行前审核/确认要求；没有有效审核状态时不得绕过该保护直接启用阻止。
7. 当 Agent 接受策略或返回应用审核/清单时，TeacherConsole 应验证 Agent 身份签名，并核对本次请求随机数、校区和请求正文摘要；身份未核对、密钥变化或回执无效时标为“需复核”，不得报告成功。只有独立的签名状态读取确认后才能标为“状态已读回”，不得宣称浏览器页面效果已验证。
8. 当手机控制服务接受请求时，服务应验证已配对身份、请求授权、有效期与防重放信息；请求只能包含允许的网站/应用策略操作，不得执行任意命令、路径或 URL。
9. 校区私钥应只留在教师 Windows 控制台受保护的密钥存储中；手机端、网页资源和学生 Agent 均不得接收私钥。移动链路应使用认证加密通道，并限制为校园 LAN 可达。
10. 当教师在手机执行查看、启用、解除或重试时，教师电脑应记录配对身份、时间、目标和逐台结果；日志不得包含私钥或不必要的学生个人信息。
11. 首期手机端应适配常见 iOS/Android 手机屏幕，并支持单台及多台目标的操作确认和逐台结果查看。

## 暂定产品约束（请一并确认）

- 首期采用手机浏览器/PWA，不要求上架 App Store 或 Google Play；教师电脑需保持开机并运行教师控制台。
- 手机端只启用/解除教师端预先保存的网站和应用策略预设，不在手机编辑复杂规则。当前桌面端可编辑规则，但没有可供手机重新启用的持久化预设，因此需要新增本地预设保存/选择能力。
- 只有网站与应用策略进入首期；学生端系统策略及软件更新仍由各自桌面流程处理。
- TeacherConsole 逐台策略、审核和清单回执使用 SYSTEM Agent 身份密钥签名，并绑定一次性教师随机数、校区和请求正文摘要；每个目标的身份须先经教师明确核对并固定。手机展示逐台回执和身份状态。

## 不在首期范围

- 校园网外的远程控制、CloudBase/互联网命令中继和公网暴露。
- 手机完整替代教师桌面控制台，包括配置部署包、密钥管理、地点配置、策略规则编辑、应用清单维护和版本发布。
- 学生端系统限制策略的实现，以及真实 Windows 设备上的验收；实机验收仍单独保留为后续阶段。
