# 手机端教师控制需求

## 背景与范围

教师希望在校园 Wi‑Fi/LAN 内通过手机查看学生电脑状态，并启用或解除网站、应用限制及六项长期系统策略。手机是教师控制台的局域网遥控入口，不替代桌面端，也不持有签名密钥。手机控制范围已确认包含长期系统策略；其六项具体定义见[手机端长期系统策略控制需求](../mobile-system-policy-control/requirements.md)。

TeacherConsole 在校园 LAN 内通过 HTTPS 提供配对、状态、预设和策略操作 API，再使用现有签名通道与学生 Agent 通信。手机不持有校区签名私钥，也不能绕过教师端直接向学生 Agent 发控制命令。

因此首期需让手机在校园 LAN 上连接一台已运行的教师控制台，由该教师电脑校验手机身份、签署策略并转发至选定学生电脑。控制流不得依赖 CloudBase 中继、互联网可达性或公网端口转发。

## 用户故事

- 作为教师，我可以在手机上确认教师控制台和学生电脑是否在线，以及网站、应用和六项长期系统策略的当前状态。
- 作为教师，我可以按 Veyon 地点浏览学生电脑，并通过电脑名识别具体设备，而不必记住 IP 地址。
- 作为教师，我可以点开一台学生电脑，单独查看它当前的策略状态并只对这台电脑应用或解除策略。
- 作为教师，我可以选定一个或多个已配置地点/学生电脑，启用预先保存的网站、应用或长期系统策略，或签名解除限制。
- 作为教师，我希望手机默认选择本堂课电脑并收起完整机房清单，需要时再展开调整范围。
- 作为教师，我可以区分“Agent 已确认”“设备离线”“结果待核对”等状态，不会把送达回执误认为浏览器或应用行为已验证。
- 作为校园管理员，我可以撤销已配对手机的访问权，并查看本机保留的操作记录。

## 验收标准

1. 当教师控制台在校园 LAN 运行时，手机端应能通过配对流程绑定到该教师电脑；配对需经教师电脑上的教师主动确认，并且配对凭据可撤销。
2. 当手机与教师电脑不在同一校园 LAN，或教师电脑未运行时，手机端应明确显示不可连接；系统不得将控制命令转发到 CloudBase 或公网。
3. 当配对手机请求状态时，系统应显示已配置地点/目标电脑的在线性、最后响应时间、网站策略模式/到期时间、应用策略模式/版本及六项系统策略状态/版本。设备不可达或 Agent 不支持某类查询时，应显示“未知/不可用”，不得显示为“已解除”。
4. 当教师在手机选择限制预设并确认操作时，教师电脑应重新验证当前校区、预设内容、目标列表和签名权限，再通过现有学生 Agent 通道发送经过签名的策略。应用和系统预设须为每台目标电脑匹配各自保存的学生 SID；旧版共用 SID 预设仅允许单台操作，映射缺失时不得发送。
5. 当教师在手机解除网站、应用或长期系统限制时，教师电脑应为每个目标生成相应校区签名的解除策略；系统策略解除遵循长期基线的冲突检查和恢复规则。部分目标失败时，应逐台展示结果并允许只重试失败目标。
6. 当应用限制会启用实际阻止模式时，手机流程应保留现有执行前审核/确认要求；没有有效审核状态时不得绕过该保护直接启用阻止。
7. 当 Agent 接受策略或返回应用审核/清单时，TeacherConsole 应验证 Agent 身份签名，并核对本次请求随机数、校区和请求正文摘要；身份未核对、密钥变化或回执无效时标为“需复核”，不得报告成功。只有独立的签名状态读取确认后才能标为“状态已读回”，不得宣称浏览器页面效果已验证。
8. 当手机控制服务接受请求时，服务应验证已配对身份、请求授权、有效期与防重放信息；请求只能包含允许的网站、应用或系统策略操作，不得执行任意命令、路径或 URL。
9. 校区私钥应只留在教师 Windows 控制台受保护的密钥存储中；手机端、网页资源和学生 Agent 均不得接收私钥。移动链路应使用认证加密通道，并限制为校园 LAN 可达。
10. 当教师在手机执行查看、启用、解除或重试时，教师电脑应记录配对身份、时间、目标和逐台结果；日志不得包含私钥或不必要的学生个人信息。
11. 首期手机端应适配常见 iOS/Android 手机屏幕，并支持单台及多台目标的操作确认和逐台结果查看。
12. 当教师生成配对邀请时，桌面端应本地生成对应 LAN HTTPS 地址的二维码；二维码只包含短时配对码的 URL 片段。手机扫码后应清除地址栏片段并预填配对码，仍需手机提交请求和教师端批准；证书首次信任不得由二维码绕过。
13. 当活动课堂中的电脑目标与 Veyon 清单逐台且唯一匹配时，手机应默认选择这些目标并折叠手动范围；没有活动课堂、目标未完整匹配或目标重复时，应保持未选择并提示教师核对。默认选中不得自动启用或解除策略。
14. 当手机加载多个策略预设时，系统应默认选择最近更新的网站或应用预设，并将长期系统预设排在其后；教师仍可展开列表改选。该默认选择不得自动执行策略。
15. 当配对手机读取电脑名单时，TeacherConsole 应从 Veyon 当前地点目录读取地点、电脑目标和电脑显示名；电脑显示名用于手机界面，IP/主机地址只用于连接与目标校验，不得作为卡片标题或学生名称显示。没有有效显示名时显示“未命名电脑”，不得回退显示 IP/主机地址。
16. 当教师打开手机电脑策略页时，每个 Veyon 地点应能单独浏览；选中地点后，学生电脑以每行两张卡片的网格显示，卡片包含预留的电脑图标位置和电脑显示名。图标位置首期保持空白占位，不加载学生照片、电脑截图或外部图片。
17. 当教师点开一张电脑卡片时，手机应进入该电脑的详情视图并读取最新的签名状态，包括网站模式/版本/到期时间、应用模式/版本/到期时间、支持情况及六项系统策略值/版本。离线、签名身份未核对、Agent 不支持或状态过期时应显示未知/待核对，不得推断为解除。
18. 当教师从电脑详情应用或解除策略时，请求只能包含该卡片对应的一个 Veyon 目标。操作确认应显示电脑名、当前可验证策略状态、拟应用预设及期限；逐台结果和操作记录应使用电脑名展示，后台仍以 Veyon 目标地址校验和传输。
19. 当不同教师通过手机控制页并发修改同一学生电脑的同一类策略时，策略操作应绑定教师确认时看到的目标 Agent 签名版本，并在签名前重新读取；若版本已改变，旧确认应失效并要求刷新状态、重新确认。签名策略还须由 Agent 在策略事务锁内再次核对版本，较旧手机请求不得覆盖已接受的较新手机请求；发生冲突时明确报告，不得显示为成功。Agent 版本低于 0.4.50 或状态不可验证时，手机端应阻止写入并提示更新或核对 Agent。旧桌面策略协议继续兼容，但不具备这项跨手机版本比较保证。
20. 当教师在桌面手机控制窗口保存应用或系统预设时，窗口应显示可用电脑映射数量及电脑名称、已选账户数和覆盖电脑数，并允许展开核对已选的电脑名与账户名；无电脑名称时显示“未命名电脑”，不得显示 IP/主机地址或 SID。启用应用页高级手动 SID 模式时，窗口应说明应用预设和系统预设使用的账户来源及多目标限制。

## 已确认产品约束

- 采用手机浏览器/PWA，不要求上架 App Store 或 Google Play；教师电脑需保持开机并运行教师控制台。
- 连接范围限校园 Wi‑Fi/LAN。不得经 CloudBase 中继或公网端口转发；教师服务仅在教师显式启动时开放受限局域网入口。
- 手机只选择桌面端保存的网站、应用或长期系统策略预设，不在手机编辑复杂规则、学生 SID 或签名内容；应用/系统预设的学生 SID 按电脑保存在教师端，所有目标映射通过后才可发送；系统策略没有自动期限，必须由教师另行解除。
- 手机可查看状态并启停网站限制、应用限制和六项长期系统策略；Teacher/Student 更新、校区资料发布、密钥管理仍由桌面流程处理。
- 手机只在活动课堂目标和 Veyon 清单完整、唯一匹配时默认选中本堂课范围；无活动课堂或匹配失败时不扩大范围。启停策略仍需教师主动操作和确认。
- TeacherConsole 逐台策略、审核和清单回执使用 SYSTEM Agent 身份密钥签名，并绑定一次性教师随机数、校区和请求正文摘要；每个目标的身份须先经教师明确核对并固定。手机展示逐台回执和身份状态。
- 手机显示的身份名称以 Veyon 电脑显示名为准；不把 IP/主机地址当作学生姓名。电脑名缺失或地点中出现重复目标时，应提示目录问题并阻止有歧义的单机操作。
- 当前手机审计日志保存在发起操作的教师电脑上；多教师之间没有共享审计账本。跨教师冲突以目标 Agent 的签名当前状态和策略版本为准，不依赖本机操作历史，也不向 CloudBase 上传策略或学生状态。
- 当前跨教师条件版本保护覆盖更新后的手机控制写入；尚未携带预期版本的桌面旧策略写入按兼容协议运行，若需统一保护桌面写入，应另行迁移并更新 Agent 兼容策略。

## 不在首期范围

- 校园网外的远程控制、CloudBase/互联网命令中继和公网暴露。
- 手机完整替代教师桌面控制台，包括配置部署包、密钥管理、地点配置、策略规则编辑、应用清单维护和版本发布。
- 手机端发布应用版本、编辑复杂规则或配置学生账户和 SID。
- 以手机 Agent 回执替代真实 Windows 策略效果、Android/iOS 浏览器证书信任或校园网络隔离验收。

## 实施与验收边界

配对、状态读取、策略操作、Veyon 地点 API、本机审计、按地点两列电脑卡片、电脑详情、单目标操作和 Agent 端条件版本检查已有代码。2026-10-16 本机 macOS 的 .NET SDK 10.0.401 完整可移植检查 **78/78**；TeacherConsole、StudentSetup 和 Agent Release 构建均为 **0 警告、0 错误**，两个 MobileWeb JavaScript 文件的语法检查通过。真实 Windows 教师机、390px 窄屏、Android/iOS 浏览器证书信任、防火墙、校园 VLAN、双教师并发冲突恢复和逐台策略效果仍需设备验收，见[手机控制任务](tasks.md)及项目[任务主表](../../docs/开发路线与任务清单.md)。
