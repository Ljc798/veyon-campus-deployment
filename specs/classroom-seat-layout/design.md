# 自定义教室座位网格与换座：设计

## 本机数据与座位交互

- 使用有界矩形网格，默认 15 行 × 15 列，编辑上限 30 行 × 30 列；每格为 `aisle` 或 `seat`。空白格不建记录，座位包含稳定格坐标、当前连续座位号和可空的学生姓名。
- “添加座位”是编辑页内的模式开关。模式开启时，点按格子增删桌位；按住鼠标左键拖过多个格子，可按起点状态连续添加或移除。模式关闭时，点已有桌位编辑姓名。名字可留空，且没有关联电脑的编辑控件。
- 只有非空姓名桌位用于建立学生电脑清单。桌位添加、删减、姓名更改都只写教师机本地布局；教师明确执行“创建地点和学生电脑”时才写 Veyon。
- 新建地点先写入教师机的本地档案。Veyon 写入成功后再读取新地点，按读回的电脑名、规范化地址和地点 ID 唯一匹配已填写姓名的桌位，并一次性保存关联。空姓名桌位不匹配、不生成电脑。
- 移除桌位时删除该桌位的本地记录和关联；不会自动删除 Veyon 电脑对象，避免移除座位时误删仍在使用的设备。
- 每个机房布局以教师本地稳定的 `CampusProfileId/RoomId` 绑定；学生名单和座位映射存于 LocalAppData 的 Teacher 目录，使用 schema 版本、大小上限、严格解析、文件锁和原子替换。
- 座位号按 row-major 顺序重算，过道不占号。打印座位表显示学生名；空姓名的实体桌位标记为空桌位，不显示推测的电脑名或地址。

## 换座事务

- 换座模式只允许选择两个已有姓名的座位，交换学生归属；取消模式不更改名单或 Veyon。
- 预检读取 Veyon 当前 Computer 记录，固定每台目标的 hostAddress/IP 和认证身份，并构造只包含 `oldName → newName` 的差异计划。
- Veyon CLI 没有单对象改名入口时，教师端通过固定 Worker 导出配置、校验计划指纹，并只修改选中 Computer 对象的 `Name` 字段后导入；导入前再次核对原配置指纹。
- 执行前在教师机本地用当前用户 DPAPI 保存完整配置和逐台计划。改名后重新导出配置，确认完整配置差异只有目标对象的 `Name` 字段。
- 完成后重新读取 Veyon Computer 目录，核对名称变化、原 IP 未变、映射唯一。超时、目录重复、IP 变化或结果不确定均标记“需核对”。
- 移动目标的身份绑定使用稳定 Veyon ID/原始地址记录，显示名称不作为主键。

## 手机读取

- 已配对手机只读取本机座位表中带稳定 Veyon 电脑/地点 ID 且地址命中当前活动课堂目标的座位号、学生显示名和电脑名。
- `/api/session` 的 `activeClassroomSeatLocations` 只返回授权目标的 `target`、行列、座位号、`studentName` 和 `computerName`；客户端确认目标属于同一活动课堂后才用于卡片标题和座位说明。
- 预览请求仍由教师端按活动课堂目标和短时租约校验，不接受任意主机/IP 查询，也不上传至云端。

## 检查与现场验证

- Core/Teacher 检查覆盖网格上限、行优先编号、空姓名桌位、已填姓名电脑清单、本地原子保存、损坏文件、换座差异和不可变 IP 字段。
- Veyon 适配器检查覆盖只改名称、超时读回、部分失败、备份与重试边界；Windows 实机需验证 Veyon 目录操作及读回格式。
- TeacherConsole 与 MobileWeb 构建后，桌面/手机真实可用性、150 台机房性能与 LAN 画面需单独验收；本地构建不能代替现场验证。
