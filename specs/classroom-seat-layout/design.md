# 自定义教室座位网格与换座：设计

## 数据模型与本机保存

- 使用有界矩形网格，默认 15 行 × 15 列，编辑上限 30 行 × 30 列；单元格为 `aisle` 或 `seat`。默认全部为空，教师逐格添加座位；过道无需额外对象。旧版 25×25 默认布局读取时缩到 15×15，并保留范围内已有座位。
- 座位包含稳定格坐标、当前连续座位号、学生姓名、可选 Veyon 目标标识及对应已读回的 IP/hostAddress。座位号在每次布局保存时按 row-major 顺序重算，过道不计数。
- 桌位是否关联电脑是座位已有 Veyon 目标字段的派生显示状态，不新增存储字段：过道用浅灰显示，未关联 Veyon 目标的桌位用白色与深边框显示，已关联电脑的桌位用浅青绿显示；教师端网格和打印表均有文字图例，悬停提示也说明关联状态。此状态表示教师端映射，不推断桌上是否有实体电脑。只有已绑定目标才显示读回的电脑名，不展示地址或推测的电脑名。换座选中状态优先于三种网格底色。
- 每个机房布局以教师本地稳定的 `CampusProfileId/RoomId` 绑定；学生名单、座位图和目标映射存于 LocalAppData 的 Teacher 目录，使用 schema 版本、大小上限、严格解析、文件锁和原子替换。
- 新建地点先写入零台电脑的本机档案，让教师只输入校区/地点名称即可打开空白网格。此状态保留有效的电脑名前缀/起始编号默认值，但不生成课堂目标；课堂会话入口和 `ClassroomSession.Start` 都拒绝零台电脑的档案。添加 Veyon 电脑时，规划数量由座位数决定，只有写入及读回成功后才更新档案电脑范围。
- 添加成功后重新读取 Veyon 稳定对象 ID，要求每个计划目标的电脑名、规范化地址和所属地点都唯一匹配；全部匹配后由 `ClassroomSeatGridStore.AssignVeyonTargets` 在一次原子写入中按行优先座位号绑定。部分匹配、目录并发变化或本地保存失败时不应用任何新关联，现有手动逐台关联流程保留。
- 保存仅能保留当前 Veyon 目录中已唯一读回的目标。删除/移动一个已绑定座位时先产生待确认计划，任何冲突都阻断执行。

## 换座事务

- 换座模式将交互限制为选择两个已分配学生的座位，交换两人的座位归属；取消模式不更改名单或 Veyon。
- 预检读取 Veyon 当前 Computer 记录，固定每台目标的 hostAddress/IP 和认证身份，并构造仅包含 `oldName → newName` 的差异计划。
- Veyon CLI 没有单对象改名入口时，教师端通过固定 Worker 导出配置、校验计划指纹，并只修改选中 Computer 对象的 `Name` 字段后导入；导入前再次核对原配置指纹。
- 执行前在教师机本地用当前用户 DPAPI 保存完整配置和逐台计划；改名后重新导出配置，确认完整配置差异只有目标对象的 `Name` 字段。任何命令都不得写系统网络设置或 Windows 机器名。
- 完成后重新读取 Veyon Computer 目录，核对名称变化、原 IP 未变、映射唯一。超时、目录重复、IP 变化或结果不确定均标记“需核对”，不继续批量覆盖。
- 部分改名只在读回确认所有其他配置字段未变时自动导入原备份；若发现并发或其他字段变化，保留备份并标记“需核对”，避免覆盖外部更改。
- 移动目标的身份绑定使用稳定 Veyon ID/原始地址记录，显示名称不作为主键；名称交换后教师仍能匹配原 IP 设备。

## 普通编辑与手机读取

- 在地点/机房管理流程中提供“教室座位图”编辑器：只填校区与地点名即可新建空白网格；电脑前缀、起始编号和逐台主机/IP 覆盖放在选填项中，电脑数量随座位数自动生成。教师可添加/移除座位、编辑姓名；过道通过空格表达。
- 网格过大时允许滚动和平移，不把 625 个格子压缩成难以点击的桌面小图；手机只读简化显示当前课堂有座位的学生卡片。
- 已配对手机只读取本机座位表中带有稳定 Veyon 电脑/地点 ID 且地址命中当前活动课堂目标的座位号、学生显示名和电脑名。手机界面优先显示学生姓名，其次显示 Veyon 电脑名；预览请求仍由教师端按活动课堂目标和短时租约校验，不接受任意主机/IP 查询，也不上传至云端。
- `/api/session` 的 `activeClassroomSeatLocations` 只返回授权目标的 `target`、行列、座位号、`studentName` 和 `computerName`；客户端逐项确认目标属于同一活动课堂后才用于卡片标题和座位说明。
- “换座模式”有醒目的进入/退出状态，完成前展示影响目标数量和保留 IP 的确认摘要；无需额外的常用地点模板。

## 检查与现场验证

- Core/Teacher 检查覆盖网格上限、行优先编号、过道、重名/多目标拒绝、本地原子保存、损坏文件、换座差异和所有不可变 IP 字段。
- Veyon 适配器检查覆盖只改名称、超时读回、部分失败、备份与重试边界；Windows 实机需验证 Veyon CLI/API 的 Computer 名称修改入口和读回格式。
- TeacherConsole 与 MobileWeb 构建后，桌面/手机真实可用性、150 台机房性能与 LAN 画面均需单独记录；模拟检查不代替现场验收。
