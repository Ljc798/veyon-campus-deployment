# 机房座位图：设计

## 数据与存储

- 新增 Core 本地模型，以 `CampusProfileId` 与 `RoomId` 作为键；每个布局只保存 schema 版本、每排列数和按行排列的电脑标签。电脑范围继续由现有 `TeacherRoomProfile` 派生，不复制主机/IP 或学生名单。
- 独立保存于 `%LOCALAPPDATA%\VeyonCampus\Teacher\classroom-seat-layouts.json`，不改动既有校区档案 schema。使用大小上限、严格 JSON/重复字段拒绝、路径链接检查、文件锁和原子替换；损坏时读取失败且不自动覆盖。
- 初始顺序采用现有 `MachineNaming.CreateRange` 的数字顺序，列数取接近方形的默认值，调整范围为 1 到电脑数量。布局重载时保留仍存在的标签顺序，再按数字顺序追加新标签；电脑数减少时丢弃已不在机房范围内的标签。
- 交换电脑会持久化新的行优先顺序；调整列数只影响位置计算，不改变电脑顺序。座位行列由 `index / columns + 1`、`index % columns + 1` 推导，避免冗余存储。

## UI 与活动课堂

- 在现有“地点与学生名单”页的机房档案下加入座位网格，不新增导航。教师点击一台电脑、再点击另一格即可交换；选中格使用现有薄荷色焦点，修改立即保存。只提供一个“每排座位”数值控制。
- TeacherViewModel 从活动 `ClassroomSession` 的稳定校区/机房 ID 和目标标签解析位置，并在教师求助卡片中显示行列。
- 配对手机 `GET /api/session` 增加当前课堂的只读座位位置数组（目标标签、行、列）；无活动课堂或布局无法读取时返回空数组，不能影响既有会话状态/策略 API。
- 手机 PWA 仅将位置补充到匹配目标的求助卡片；它不接收可编辑布局，也不把座位信息发送到 CloudBase。

## 验证

- Core 检查覆盖默认顺序、稳定 ID 隔离、列数边界、交换持久化、机房范围变更、原子文件与损坏/越界拒绝。
- Teacher API 检查验证活动课堂返回匹配的目标行列、无课堂返回空数组、坏布局不会泄漏部分映射；旧会话字段保持可读。
- TeacherConsole Release 构建、完整 .NET 检查及 MobileWeb JavaScript 检查通过；API 检查覆盖活动位置、无活动课堂和损坏布局回退。Windows 桌面交互、手机浏览器显示和真实 LAN 端到端仍由实机验收。
