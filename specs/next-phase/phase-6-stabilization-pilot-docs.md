# 下一阶段 Phase 6：稳定化、灰度和文档

实施日期：2026-10-22
状态：代码级轮询和 UI 更新稳定化、快捷管控构建灰度门、教师及管理员手册已加入；10–70 台性能、Win10/11、手机证书和断网恢复仍待用户统一现场验收。

## 本轮实现

- 设备健康页持续轮询时，只有当前分页设备对象或排序真正变化才替换 `DeviceHealthPageRows` 绑定源。异常集合按新增、移除和排序移动增量更新，不再每轮清空重建；异常严重程度随最新签名状态更新。
- 异常重复采集继续刷新最近时间，但不会重复增加发生次数；有新设备进入同类异常时仍重置“已知悉”状态。
- 轻量健康状态现在在教师端本地显示每轮总耗时、成功数、超时数、首波并发窗口外的排队目标数、当前有效设备数、通信耗时、视图模型更新耗时和全局并发上限。所有到期设备一次提交给共享的 12 路传输闸门，在有界并发下分批读回；避免每个 5 秒 UI 轮询只额外处理 12 台。视图模型计时包含列表/告警整理和绑定通知，不冒充操作系统合成器的真实绘制时间；现场仍需观察布局抖动和响应。数据来自本地 LAN 请求，无需 CloudBase 逐机心跳。
- “地点与学生名单”和“首次设置向导”已从主侧栏移入底部“遇到问题？”折叠区；默认收起，展开后仍能进入，两项入口不再因校区签名密钥状态而消失。抽屉内容可滚动，避免内容较多时挤出其他选项。
- 新课堂快捷管控由 TeacherConsole 编译开关控制，默认构建关闭新的启用/锁定操作；已有状态仍可读，解除操作仍允许。教师桌面和手机 UI 都按同一试点能力显示/禁用按钮，服务层也再次拒绝未开放的新命令。
- 教师端快捷管控卡片按“当前网站预设、管控方式、当前选择和进度、统一解除”重做，并提供可展开的逐台状态；教室名、选中数量和完成状态一目了然。
- 两种管控方式已做成等宽等高卡片，分别带盾牌和鼠标指针线框图标，标题与说明居中排列。
- 课堂控制卡片移除重复的会话说明和静态帮助句，仅保留本堂课地点/电脑数量及通知、连接状态；逐台推送进度折叠栏横向拉伸，与卡片内容等宽。
- 网站限制遇到暂时离线或 Agent 尚未连接的电脑时，会保留待执行意图。课堂仍有效时，教师端以有界并发等待 Agent 回来，重新核对设备身份和签名状态后自动应用最新保存的网站策略，并更新逐台进度；不要求电脑在开始课堂时在线。键鼠锁定不加入此自动重试队列。
- 课堂结束时未送达的网站策略会取消；已送达的课堂策略进入恢复重试。恢复队列在 TeacherConsole 保持运行时重试；若教师端关闭，网站策略现有的一小时租约作为兜底。
- 桌面进度约每 2 秒刷新，手机进度随课堂事件读取约每 5 秒刷新；两者展示等待 Agent、执行中、成功、失败/待处理等逐台状态。
- `scripts/package-windows-offline.ps1 -ClassroomQuickControlManualTest` 为 TeacherConsole 显式构建课堂快捷管控试点包，并将 `CLASSROOM-QUICK-CONTROL-PILOT.txt` 放入载荷。StudentSetup 不接受此标志。
- 新增[教师端课堂快捷管控使用指南](../../docs/教师端课堂快捷管控使用指南.md)和[管理员部署、软件保护与灰度试点手册](../../docs/管理员部署、软件保护与灰度试点手册.md)。手册分别说明课堂操作、租约和结果语义、配置部署、长期开启/恢复以及灰度范围。

## 发布门与限制

- 普通构建不能开启新快捷策略；试点必须显式构建教师端带标记的安装器。试点构建不是正式版，不应向非测试教师分发。
- 无论构建开关如何，解除本工具现有管控始终保留；这是试点结束、回退到普通构建或需要安全恢复时的操作路径。
- 屏幕/音频持续、键鼠恢复、网站实际阻止、AppLocker 命中、手机证书及断网行为都没有在本轮环境实测。代码构建和界面回执不能替代这些现场证据。
- 本轮没有运行测试套件或启动测试设备；只进行 Release 编译和本地离线安装包构建。

## 待用户统一验收

1. 在 10–24 台设备规模打开健康页，确认 12 台有界并发、单目标 1.5 秒超时、故障退避、排队目标计数准确，页面滚动与选择不会因重复刷新跳动。
2. 在 60–70 台规模重复运行，观察所有到期目标是否在一次轮询中按有界并发排空、一轮耗时、请求队列、网络重试和课堂控制响应；记录教师端窗口是否卡顿、内存或 CPU 是否持续增长。
3. 让同一设备出现多个异常，确认列表不重置、级别变化能及时反映、同一故障不会因每轮读取重复计数/通知，新设备加入后会重新要求确认，恢复后异常归档。
4. 用最新试点教师包确认主侧栏不再显示“配置与部署”；展开“遇到问题？”后能找到“地点与学生名单”和“首次设置向导”，且抽屉滚动不遮挡其他帮助选项。
5. 用 1 台在线和 1 台关机/断网的可恢复测试学生机开始课堂并启用网站限制。确认在线设备进入执行和成功状态；离线设备显示等待 Agent，电脑开机并连接 Agent 后自动应用当前网站策略，逐台状态跟进；身份未核对的目标不得应用策略。再逐步扩到 2–5 台。
6. 在可恢复设备上验证键鼠锁定与解除；锁定操作不应在设备稍后上线时被自动补发。结束课堂时，确认离线且尚未执行的网站策略被取消，已经应用的策略进入恢复流程；可在课堂仍结束的情况下让设备重新上线，观察 TeacherConsole 自动重试恢复。若关闭教师端，确认网站限制最多由现有一小时租约兜底。
7. 检查课堂摘要只显示一次地点/设备数，通知与消息连接状态简短清晰；逐台推送进度展开栏应与卡片等宽。再检查网站预设摘要、管控方式切换、“一键解除所有设备管控”和手机状态，之后逐步扩到整间测试教室。
8. 用普通教师构建确认新启用/锁定命令被禁用，已有管控状态仍可读且可解除。
9. 按教师和管理员手册分别演练一次日常课堂流程及软件保护启用/解除；在 Win10、Win11 和 Android/iPhone 上记录版本、逐台回执、恢复耗时及连接问题。
