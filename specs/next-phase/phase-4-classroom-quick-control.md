# 下一阶段 Phase 4：课堂两模式互斥与一键执行

实施记录：2026-10-22  
当前状态：桌面端、手机端共用课堂快捷管控服务；教师端与学生端 Release 编译及 Windows x64 离线测试包构建完成。尚未安装测试包或进行 Windows / 浏览器 / 手机现场验收。

## 已实现

- `DeviceControlMode` 独立记录 `None / WebsiteRestriction / InputLocked` 三种快捷管控状态；新版课堂状态不使用旧课堂策略模式字段。
- TeacherConsole 按稳定设备 ID 记录所有权、期望网站修订、InputGuard 租约、阶段和逐台结果；账本不保存网络地址或学生姓名。TeacherConsole 重启后不会恢复旧键鼠锁定或自动续租。
- 网站限制使用本校已保存名单生成一小时有效的课堂策略，并通过期望修订号 compare-and-set 下发；解除只会清理本工具拥有的修订，不会覆盖其他教师或长期策略。
- 键鼠锁定使用最多 20 秒的 InputGuard 租约，教师端每 5 秒续租；TeacherConsole 关闭或失联后不再续租，Agent 侧租约自行到期。
- 网站与键鼠之间切换前先解除当前拥有的另一模式，并等待 Agent 签名读回；未核验、归属冲突、设备身份变化或状态未知时停止后续操作并显示逐台结果。
- Agent 端用同一串行执行门保护网站策略和 InputGuard Activate/Renew。普通网站策略写入不依赖 InputGuard 状态；课堂快捷管控的模式切换由教师端服务先核验并解除本工具拥有的旧模式。已有网站限制时，Agent 仍拒绝新建或续租键鼠锁；解除动作可用于恢复。
- 桌面和手机都必须确认操作；手机通过已配对的 Teacher HTTPS API 调用同一控制服务，不直接签名连接 Agent。结束课堂时，TeacherConsole 会先尝试解除课堂快捷管控，并保留逐台结果。
- 桌面侧栏不再使用“高级设置”折叠入口收纳常用配置：`地点与学生名单`、`首次设置向导` 已提到“配置与部署”组顶部，常驻显示并附带用途说明。
- 手机课堂页新增网站限制、限时键鼠锁定和解除课堂管控操作、课堂状态摘要和逐台回执列表。旧浏览器缓存版本已递增。

## 2026-10-24 追加：按学生电脑恢复网站访问

- 在桌面课堂页与手机课堂页增加独立的“恢复全班网站访问”操作。它不依赖“解除课堂管控”的本机归属账本，也不要求学生电脑的原策略相同。
- 每台电脑先读取当前已签名的网站状态；只对身份可信且 Agent 支持版本比较（0.4.50+）的设备签发一个更高版本、预期版本绑定、黑名单/白名单为空的网站停用策略，并读回验证。失败、离线、旧 Agent 和并发版本变化逐台显示；不会自动重放。
- 该恢复操作保留键鼠租约和应用/系统限制，也保留教师电脑上保存的网站名单。原“解除课堂管控”仍只清理本快捷管控能证明归属的网站策略和键鼠租约。
- 当前工作区没有 .NET SDK，未编译教师端；本次手机/Windows 真实设备验收仍未完成。该追加只记录源码功能，不提升专项或项目总体验收状态。

## 尚待现场确认的边界

- 代码核验的是 Agent 签名状态、策略版本和 Guard 租约；浏览器是否真实拦截指定网站、Windows 输入恢复时序和手机网络行为仍需人工实测。
- 当前操作范围是开始互动时冻结的整堂课电脑集合；逐台结果会显示成功、失败、冲突或未知。不会因设备离线自动重放危险命令。
- 未取得可信回执时，UI 保留未知或待核对状态。TeacherConsole 重启后不会重新锁定；曾有快捷锁定的设备需要人工重新读状态并解除。
- 安装器未配置 Developer Release PEM 公钥，因此应用内更新安全停用。这些安装器只供本地测试，不是正式 Release。

## 之后统一进行的人工验收

仅使用可恢复的 Windows 测试教师电脑、学生电脑和手机；不要用正式课堂设备。先确认学生电脑可通过 Veyon 本地恢复，并留出安全桌面恢复途径。

1. 安装教师端测试包并打开“课堂控制”。确认侧栏顶部直接显示“地点与学生名单”和“首次设置向导”，不需要展开设置入口；检查窗口缩放后名称和说明没有裁切。
2. 在“地点与学生名单”确认当前教室、编号和学生显示名正确；选择一间独立测试机房，准备 2–4 台可恢复测试机。先完成 Agent 身份核对，再启动课堂互动。
3. 无活动课堂时确认快捷操作禁用；点击“开始互动”后确认页面显示实际课堂电脑数。“恢复全班网站访问”和“解除课堂管控”在活动课堂内可用；启用网站限制和锁定键鼠还要求教师端开放试点。执行前取消确认框，确认设备状态没有变化。
4. 在学生 Setup 中安装对应测试包并确认 Agent 版本更新、InputGuard / Companion 部署完成。登录学生桌面，确认 Guard 空闲运行，不会自行阻止输入。
5. 在教师端保存一组明确的测试网站名单。启用网站限制，逐台核对操作回执、策略版本和到期时间，并在学生浏览器中人工确认阻止效果；同时确认课堂在线状态与快捷管控状态分别显示。
6. 对同一台电脑从网站限制切换到键鼠锁定。确认先读回网站策略已解除，键鼠只在签名回执和状态读回成功后显示为已锁定；使用教师端解除后确认输入恢复。再从键鼠切换回网站限制，确认先解除原租约。
7. 人工制造策略归属冲突、断网或 Agent 不支持 InputGuard 的情况。确认其他电脑仍各自返回结果，出问题的设备显示冲突/失败/未知，不显示为成功，不会覆盖其他教师策略。
8. 在键鼠锁定时断开 TeacherConsole 连接或关闭教师端，等待最多 20 秒后确认输入恢复；重新启动教师端，确认不会自动重锁，并按页面状态重新读回。单独验证 Windows `Ctrl+Alt+Del` 恢复路径。
9. 结束互动，确认系统先尝试释放本工具拥有的快捷管控，再结束课堂；若某台未确认，记录显示未确认设备及其原因。复查其他来源的网站长期策略仍保留。
10. 将已配对手机连接到 TeacherConsole，重复取消、全课堂启用、切换和解除流程；确认手机走教师端 API、显示逐台结果，与桌面端共享状态。再验证手机断网和课堂结束后的状态。
11. 为不同学生电脑分别准备黑名单、白名单和综合名单，再执行“恢复全班网站访问”；逐台确认策略停用且黑/白名单为空，并确认键鼠状态、应用限制和系统限制没有变化。另验证离线、未核对身份、旧于 Agent 0.4.50 及操作并发导致版本变化时只显示待核对、不覆盖新策略。

验收时记录 Windows 版本、学生 Agent / Setup 版本、设备数、每步逐台结果和恢复耗时。未完成上述人工验收前，不发布正式版本或部署到正式机房。
