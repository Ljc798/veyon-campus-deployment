# 一对一课堂聊天：需求

## 问题与目标

当前课堂事件通道支持学生一键求助、教师针对该求助回复、学生确认解决，以及教师向全班发布短通知；它不支持双方连续多轮聊天。教师需要能与活动课堂中的单名学生建立私密对话，学生收到消息时能在屏幕右下角看到聊天入口，同时继续操作当前应用。

## 用户故事

- 作为教师，我可以从当前课堂中的某名学生打开一对一会话，并与该学生连续收发文字消息。
- 作为学生，我可以从 Student Companion 主动开启与教师的会话，也可以在收到教师消息时查看和回复。
- 作为学生，我希望新消息显示在屏幕右下角但不抢键盘焦点，避免打断正在进行的作业。
- 作为已配对手机的教师，我可以从当前课堂的学生名单选择一名学生，加入与教师电脑相同的一对一会话。
- 作为校区管理员，我希望消息只属于本堂课和对应电脑，不进入 CloudBase，也不写入磁盘聊天记录。

## 范围与默认规则

1. 会话只允许当前 Teacher 与当前活动课堂中一个已授权、身份已固定且声明支持聊天的 Student Agent 通信；教师可从 Teacher Console 或已配对手机的当前课堂名单选择目标开启会话，学生也可从 Companion 主动开启会话。
2. 同一活动课堂中的同一台学生电脑只对应一条一对一会话；不论由 Teacher Console、已配对手机还是学生先发送，双方都加入同一条对话，Teacher Console 与手机显示相同的会话内容和送达状态。
3. 学生 Companion 支持从托盘进入沟通窗；课堂通知、教师回复和一对一私聊显示在同一右下角非模态窗口。后台新消息到达时不自动激活窗口、不改变键盘焦点；学生从托盘主动打开或点击输入区后，可以正常激活并输入。
4. Teacher Console 在当前课堂互动区提供按学生进入的会话视图；收到学生消息时更新会话内容，不强制切换教师正在使用的页面或输入焦点。
5. 一对一会话支持连续多轮纯文字消息；消息有序显示。首版不支持群聊、附件、图片、语音、已读回执或聊天记录导出。
6. 消息和当前会话只保存在教师端和 Companion 的有界内存中；下课或 Teacher/Companion 重启后清除，不写磁盘、不上传 CloudBase。Teacher API 接受消息只表示已提交，不表示对方已读。
7. 复用现有教师 HTTPS、Student Agent 身份签名、短期课堂授权和长轮询通道；不开放新端口，不允许按任意 IP 建立对话。
8. 消息正文有固定长度和速率上限。目标离线、授权失效或请求被拒绝时，发送方看到明确的失败状态，消息不能静默丢失。
9. Agent 必须在签名授权回执中声明当前 `classroom-chat.v1` 能力；未声明、缺少能力或未实现当前授权端点的旧 Agent 不得获得课堂事件授权，也不能接入求助、教师回复、通知或私聊通道。Teacher 应提示更新学生端后重试；配对手机的通用课堂事件接口不得返回私聊消息。
10. 教师端收到学生消息时显示座位表中的学生姓名；未填写姓名时使用该学生电脑名称。两端输入框都支持 Enter 发送、Shift+Enter 换行。
11. 已配对手机只能读取当前选中学生的私聊线程，且只能向当前活动课堂、当前聊天能力已确认的目标发送；手机通用课堂事件列表不得因此包含私聊正文。
12. 当教师在手机选择学生时，读写请求都应绑定当前课堂 Session ID 和稳定学生目标 ID；服务端必须重新校验活动 Session、目标 ID 与聊天能力，不接受旧课堂请求或手机提交的任意主机地址。
13. 配对手机可在当前课堂期间查看该线程最近 200 条内存消息；下课或教师服务进程重启时清除。手机页面不得把聊天正文写入 localStorage、IndexedDB、Service Worker 缓存或其他磁盘存储。

## 验收条件

1. 当且仅当课堂处于活动状态且目标设备属于当前课堂、Agent 身份已固定时，Teacher 或该目标的 Student Companion 才能开启对应的一对一会话；学生端不能指定其他电脑或主机地址。
2. 当 Teacher 或该学生任一方先发送文字后，通道必须将消息绑定到当前 Session、唯一目标和会话标识；另一方后续加入同一会话，其他学生及其他课堂不能读取或回复该会话。
3. 当学生 Companion 收到新聊天消息时，系统应在屏幕右下角显示非模态面板，但不得通过程序化激活窗口、置入键盘焦点或打开模态对话框来打断学生。
4. 当用户点击面板或输入框时，用户应能主动查看上下文并继续发送消息；教师端应在当前会话中显示同一消息顺序。
5. 当课堂结束、授权过期或任一端重启时，旧会话必须关闭；旧消息和授权不得在新课堂恢复。
6. 当请求超时、目标离线或消息不符合限制时，发送端必须显示失败原因并提供重试；不得把“Teacher 已接收”显示为“学生已读”。
7. 通道不得通过 CloudBase、磁盘聊天历史、新监听端口或未授权主机转发消息。
8. 当课堂通知、教师回复或私聊消息到达时，Companion 使用同一沟通窗；后台弹出不激活窗口、不抢键盘焦点，学生主动打开后可以继续输入。
9. 当学生发送聊天消息时，Teacher 消息项应显示该学生姓名；姓名为空时显示电脑名。当 Teacher 或学生在输入框按 Enter 时，系统应发送消息；按 Shift+Enter 时应插入换行且不发送。
10. 当教师从已配对手机选择一名支持聊天的学生时，系统应显示与 Teacher Console 同一条会话；手机发送或学生回复后，两端应在当前课堂会话中收到同一消息，且重复提交应沿用原 EventId 去重。
11. 当手机请求另一台学生电脑的线程、伪造目标 ID、访问旧课堂或访问不支持聊天的 Agent 时，服务端应拒绝请求，且不得返回其他线程的私聊正文。
12. 当教师手机请求通用课堂事件页时，返回结果仍不得包含私聊消息正文或私聊送达回执。

## 非目标

- 多人群聊、跨课堂对话、离线消息投递、消息搜索/导出和长期聊天历史。
- 文件、图片、屏幕画面、语音、表情或富文本附件。
- 由后台消息自动聚焦、持续强制置顶抢占操作或系统级强制提示；学生主动打开窗口后的正常焦点交互除外。
