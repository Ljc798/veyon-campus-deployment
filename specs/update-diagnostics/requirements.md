# 更新诊断：需求

## 问题与范围

教师控制台和学生部署工具已有在线、离线与局域网更新流程，但失败提示直接拼接异常文本，容易暴露本机路径且难以跨角色判断。此功能为更新流程统一稳定错误码，并提供本机限量保存、由用户主动导出的 JSON 诊断。

本轮涵盖 Teacher 在线/离线更新、StudentSetup 在线/离线更新，以及教师发起的学生端批量更新汇总。诊断只保存在本机；不增加云端 API、自动上传、后台统计页或新的更新选择。

## 用户故事

- 作为教师或管理员，我希望失败时看到稳定错误码和下一步建议，以便快速重试或定位问题。
- 作为支持人员，我希望用户能主动导出结构化诊断，而不需要复制异常堆栈或设备清单。
- 作为学校管理员，我希望诊断默认留在本机，只有我手动选择导出位置时才生成文件。

## 验收条件

1. 当更新操作成功或失败时，系统应记录模块、错误码、版本、严重性和可重试标记，以及 UTC 时间、操作、结果和随机事件 ID。
2. 当在线或离线更新失败时，界面应显示稳定错误码与适当的重试建议，不显示异常原文。
3. 当教师批量更新部分成功时，诊断应只记录成功、需核对、失败的汇总数量，不记录单台目标。
4. 当用户主动选择导出时，系统应生成可读 JSON；未主动导出时，系统不得将诊断发送到网络或云端。
5. 系统应将记录保存于当前用户本机应用数据目录，保留最多 128 条、总量不超过 512 KiB；单条记录不得超过 4 KiB。
6. 诊断记录与导出不得包含 IP 地址、主机名、校区名、用户名、文件路径、发布者/Agent 指纹、密钥、异常消息或堆栈。
7. 当本机诊断保存或清理失败时，更新和安装行为应保持原样继续；只有显式导出失败才向用户显示导出失败。
8. 当文件内容或目录异常、超出大小限制或为重解析点时，诊断存储应安全跳过或拒绝该内容，不影响更新流程。
9. 当更新助手已启动但尚未得到安装回执时，系统应将结果记为“已启动”，不得记为安装成功。

## 非目标

- 本轮不上传单条诊断或每日汇总到 CloudBase。
- 本轮不增加远程诊断、教师可配置保留期、诊断级别或自动清理设置。
- 本轮不改变更新签名验证、回滚、权限或发布流程。
- 代码与自动化检查完成不等于 Windows 实机更新验收完成。
