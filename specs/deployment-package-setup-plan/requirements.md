# 校区配置包部署建议需求

## 目标

让教师在生成学生校区配置包时记录建议执行的首次部署操作；StudentSetup 将建议呈现为可编辑的操作选择和执行计划。配置包只提供建议，不能替学生确认、授权或执行系统更改。

## 用户故事

- 作为教师，我可以为一批学生机选择建议的 Veyon 配置、电脑改名、创建学生账户和管理员密码维护操作。
- 作为学生机维护人员，我可以看到建议来源与具体影响，在执行前取消任一操作或取消整个计划。
- 作为设备管理员，我不会因为导入通用校区包而自动更改一台身份尚未确认的电脑的管理员密码。
- 作为维护者，我可以让旧 schema v1–v5 包保持原有解析行为，同时通过新 schema 明确表达建议操作。

## 验收条件

1. 当配置包的 `schemaVersion=6` 时，系统必须要求 `recommendedOperations` 严格包含四个布尔字段（`installVeyon`、`renameComputer`、`createStudentAccount`、`changeAdminPassword`），并拒绝未知、重复、缺失或非布尔字段。
2. 当 TeacherConsole 生成配置包时，系统必须在明确标注“建议”的区域提供四项设置，默认只勾选安装/配置 Veyon，并在读回时确认建议值与用户选择一致。
3. 当 StudentSetup 载入有效 v6 配置包时，系统必须把前三项建议显示为可编辑的操作选择，并要求先完成环境检查、完整计划预览和显式确认；导入、预览及下载不得执行操作。
4. 当包内 `changeAdminPassword` 为 true 时，系统必须显示醒目的提示，但不得自动勾选该操作。由于校区包不绑定已验证的单台设备，维护人员必须先核对本机账户，再手动选择此操作并重新确认计划。
5. 当维护人员取消单项操作或整个计划时，系统必须在预检刷新、页面导航及重读同一配置包后保留其选择。当载入另一个配置包时，系统必须说明建议来源已变化，且不得静默覆盖用户已作出的选择。
6. 当系统读取或生成 v1–v5 配置包时，必须保持其已有字段、兼容范围、文件摘要和行为。当发布 v6 支持时，StudentSetup、TeacherConsole、Node API、OpenAPI 与数据库约束必须一致支持 v6，CloudBase 必须使用独立的 v6 对象路径。
7. 当声明代码级验收完成时，必须通过覆盖 v6 生成、严格解析、往返读回、建议编辑/取消和异常包拒绝的可移植 .NET 检查、Node/API 合同检查及双角色 Release 构建。共享 CloudBase v6 写入型 E2E 与 Windows/手机效果必须分别记录，不得从本地检查推定通过。

## 范围与边界

- 建议不构成校区签名命令或管理员授权；签名、环境预检、计划预览和执行确认仍沿用现有 StudentSetup 工作流。
- 第一版不将通用配置包绑定到机器名、设备身份或管理员账户；因此任何包都不能自动选中管理员密码修改。
- 不改变网站、应用、系统策略签名流程，也不新增学生资料或密码到配置包。
- 详细组件和 schema 方案见 [设计](design.md)；项目级状态以 [P7-11](../../docs/开发路线与任务清单.md) 为准。
