# 原生 Mac 教师端与跨端课堂体验：需求

> 状态：实施基线。按用户已提出的 Mac 教师端、手机状态/策略和课堂屏幕缩略图目标继续推进；平台边界按当前设备与项目现状设定。

## 首期范围假设

- 教师 Mac 目标为当前 Apple Silicon 设备（`osx-arm64`）。
- 学生端首期沿用项目现有 Windows Agent 和 StudentSetup 部署流程；Linux 学生端暂不纳入首期验收。
- Mac 教师端优先提供课堂资料/座位编辑、手机服务、学生 Agent 状态和已有签名策略；依赖 Veyon CLI、Windows 安装器、注册表或 Windows 配置器的操作，须由真实平台适配器支持后才开放。
- 已部署学生 Agent 只接受学生包中固定的教师策略公钥。Mac 上新建的 Keychain 私钥不能直接替代现有 Windows CNG 私钥；在完成受信任的签名密钥迁移或学生包更新前，Mac 必须逐台显示“未信任/待迁移”，不得把策略发送显示成成功。

## 目标

让教师可以在 Mac 本机运行教师端并管理校园 LAN 内的学生电脑，无需通过 Windows 远程桌面。完善教师端、学生部署端和手机端页面；让配对手机能够读取学生状态、发送获准的策略并查看课堂学生屏幕缩略图。

## 用户故事

- 作为教师，我可以在 Mac 上启动教师端、选择课堂地点、管理座位和学生名单，并从本机查看学生状态和执行课堂策略。
- 作为教师，我可以在课堂持续进行时修改地点或座位配置，不必先结束课堂；确认应用修改后，课堂目标范围会同步更新。
- 作为已配对教师，我可以在手机上读取逐台学生状态、发送策略，并看到每台设备的接受、失败或待核对结果。
- 作为教师，我可以在手机上按座位查看本堂课学生的屏幕缩略图，并随时停止查看。
- 作为教师，我可以在桌面端和手机端使用一致、适合各自屏幕尺寸的界面；学生部署端和教师端沿用项目主题及适合各页面的 SukiUI、Flowery 组件。

## 验收条件

1. **Mac 本机教师端**：当教师在受支持的 macOS 设备启动 TeacherConsole 时，应用须在 Mac 本机运行并承担教师服务，不要求 Windows RDP、Windows 虚拟桌面或把教师操作转发到 Windows 主机。教师手机可在同一校园 LAN 配对并连接该 Mac。
2. **教师工作流**：在 Mac 教师端，教师须能读取课堂地点和学生名单、管理座位、查看可用的学生 Agent 状态，并对支持的学生目标发送既有签名策略。每台设备的结果须区分已验证、失败、离线、身份待核对和不支持；不得把发送成功等同于 Windows 实际效果已验证。
3. **课堂期间编辑配置**：当课堂会话保持活动时，教师仍可编辑地点、座位及学生关联。未确认的修改不得静默改变正在执行的目标；教师确认应用后，系统须校验新范围、更新课堂绑定，并停止或撤销依赖旧座位绑定的移动巡视租约。
4. **手机状态与策略**：当已配对手机请求所选学生状态或发送支持的策略时，教师端须返回逐台结果。状态未知、签名身份不匹配、版本冲突、目标离开当前地点或平台能力缺失时，界面须说明原因且不得显示为成功；Mac 教师端不得因非 Windows 平台而对本可通过学生 Agent 执行的状态读取或策略操作统一返回 501。
5. **手机屏幕缩略图**：当教师在手机明确开启课堂屏幕查看时，页面须按当前课堂座位展示可授权学生的缩略图；教师可查看全部座位或单台画面。暂停、离开页面、手机进入后台、课堂/座位绑定变化、配对撤销或教师服务关闭时，系统须停止采集并清除临时画面。
6. **屏幕数据边界**：屏幕查看须使用已认证且限于当前课堂座位的采集路径；图片只短暂经教师端传输，不写入持久存储、不上传 CloudBase、不记录到审计、不提供录像或鼠标键盘远控。页面须标明这是间隔更新的缩略图，不称为视频流。
7. **Veyon 平台边界**：当某项能力依赖当前平台不支持的 Veyon 程序或 Windows 系统接口时，系统须提供可理解的能力状态，不得假报成功。Mac 端屏幕采集和课堂控制的设计须明确说明其认证与数据路径，不得假设 Windows `veyon-cli` 可在 macOS 运行。
8. **桌面界面**：TeacherConsole 与 StudentSetup 的页面须沿用 `docs/ui_design.md`、`docs/ui_rule.md` 和现有教师主题；在当前 Avalonia/SukiUI 基础上统一常用交互和状态展示，并在适合的场景使用 Flowery 组件。课堂座位图、策略确认、错误恢复和设备身份等既有业务语义须保留。
9. **手机界面**：手机 PWA 须针对窄屏和触控优化课堂、策略、学生状态和屏幕查看页面；重要操作、范围、逐台结果和未知状态须在不横向滚动的情况下可见。手机页面不得把桌面控件缩小后直接照搬。
10. **平台能力提示**：Mac 端须明确列出可用、受限和仅 Windows 可执行的教师功能；受限功能不得被渲染为可成功操作的按钮。StudentSetup 的 Windows 学生部署能力须保持可用。

## 约束与非目标

- Veyon 官方文档当前列出的受支持桌面平台为 Windows 和 Linux，macOS 暂未列为受支持平台。因此 Mac 教师端必须采用经验证的兼容路径；不可把 Veyon Master/CLI 的 macOS 支持当作前提。
- 教师签名私钥、手机配对凭据和学生身份固定仍由教师端管理；私钥不得发送到手机或 CloudBase。Mac 端须使用适合 macOS 的本机安全存储。
- 不新增公网中继、端口转发或将课堂控制流量转经 CloudBase；课堂控制继续限于可信校园 LAN。
- 首期不做持续视频流、录像、远程键鼠控制，也不承诺在 Mac 上运行 Windows 配置器、安装器或注册表工具。
- UI 实施只迁移和改善展示交互，不改变策略签名协议、学生身份、策略所有权、课堂数据格式或恢复边界，除非后续设计明确提出并经审查。

## 当前实现基线

- SukiUI 已用于 Avalonia 主题，Flowery.NET 已用于教师端部分课堂组件。
- 手机屏幕巡视已有 TeacherConsole 单帧采集、配对 HTTPS API、座位卡片、限流及短期内存缩略图；现有采集器依赖 Windows Veyon CLI。真实 Windows/Veyon、Android/iOS 浏览器和校园 LAN 验收仍未完成。
- 教师页面现在提供当前地点名称、电脑编号范围和主机地址编辑器；课堂持续时保存前确认，并触发已有课堂范围协调流程。座位图编辑仍不以活动课堂作为禁用条件。真实运行界面和并发失败路径仍待验收。
- 手机服务现在可在非 Windows 教师端启动；`/api/rooms`、`/api/status`、网站/应用/系统策略路由不再因平台统一返回 501。Mac 房间目标从本机地点档案读取，策略私钥和手机 TLS 证书使用当前用户证书库，版本及启动偏好使用本机状态文件。
- Mac 新密钥与现有 Windows 学生包固定的 CNG 教师公钥不同。完成教师策略公钥迁移或更新学生包前，现有学生仍须显示未信任/待核对；端到端状态读取和策略应用尚未完成验收。
- 首次设置向导现提供 Mac 路径：选择原 Windows 学生配置包后，校验包内容并保留 Veyon 公钥/电脑前缀，使用 Mac 本机策略密钥生成更新包；需用最新 StudentSetup 在学生机管理员授权下重新应用。Mac 教师桌面上的策略、状态、预设和课堂 HTTP Agent 流程不再被 Windows-only 条件统一禁用；Keychain、真实学生机重部署和逐台身份读回仍待验收。
