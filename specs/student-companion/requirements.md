# Student Companion：登录会话入口需求

## 问题与范围

StudentSetup 是管理员维护工具，SYSTEM Agent 负责系统策略；学生需要一个独立的普通用户课堂入口。本里程碑交付独立托盘 App、简洁的课堂状态卡、学生登录后自动启动和干净卸载。它不复用管理员向导，也不把 Agent/SYSTEM 权限暴露给学生。

S1-02 先交付默认显示“等待教师端连接”的独立入口；S1-03 已将只读状态接通：Teacher 签名推送到 Student Agent，Companion 自动读取本机 Agent 的签名快照。只有验证通过且未过期的状态才显示为已连接或课堂中；双向课堂互动另行设计。

## 用户故事

- 作为学生，我可以在登录后从系统托盘打开课堂助手，并看到当前连接/课堂状态。
- 作为学生，我可以关闭窗口把助手收回托盘；退出入口保持可找到。
- 作为教师，我可以在学生安装包中统一交付该助手，不需要逐台手工安装额外运行时。
- 作为学校管理员，我希望 Companion 以登录用户身份运行，不请求 UAC、不启动 SYSTEM Agent 控制面，也不包含 TeacherConsole。

## 验收条件

1. Student 安装包包含独立 `VeyonCampus.StudentCompanion.exe`，不与 StudentSetup 或 Student Agent 共用入口程序。
2. 应用清单声明 `asInvoker`；普通启动、托盘打开/隐藏和关闭流程不请求管理员权限。退出菜单能完全退出进程；关闭窗口只隐藏到托盘。
3. Student 安装器默认创建所有学生用户可用的登录启动快捷方式，参数使用最小化到托盘模式；卸载时移除该快捷方式。无需额外安装选项或配置向导。
4. 界面只展示由本机 Agent 签名状态快照提供的标题、教室和电脑数；未连接时显示明确等待状态，不把未知说成“课堂中”或“已连接”。
5. UI 不展示学生姓名、IP、身份密钥、管理员状态或策略编辑器；Companion 项目不引用 Worker 或 Student Agent 项目。
6. Companion 和托盘功能不调用 CloudBase、不监听网络端口；固定间隔读取只允许 loopback 的 Agent 状态端点，状态源不可用或过期时回到未连接。
7. TeacherConsole 发布物不包含 Student Companion；Student 发布物包含并通过角色清单/哈希校验。
8. 布局沿用现有 Fluent/品牌颜色，优先显示一个状态卡和必要操作，不新增保留期、服务器地址或登录选项。

## 非目标

- 本里程碑不实现 WSS、求助、通知、答题或移动端控制；只读教师状态经已存在的 Agent LAN 通道传送，双向事件另立任务。
- 不以隐藏窗口替代进程身份/权限边界；Student Agent 仍为单独 SYSTEM 组件。
- 不向 CloudBase 上传课堂内容，不接入移动端。
- macOS 预览与可移植构建不等同于 Windows 托盘、启动项或 UAC 实机验收。
