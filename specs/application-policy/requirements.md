# 学生机应用限制需求

## 目标

教师可以按校区、学生本地账户和目标电脑发布课堂应用阻止策略；Student SYSTEM Agent 验证签名后由 Windows AppLocker 执行，并提供审核、撤销和恢复。长期软件安装限制与课堂阻止规则共用一个 AppLocker EXE 策略所有者，避免两套功能互相覆盖。

应用限制用于课堂秩序管理，不替代杀毒软件、Windows 安全基线或设备管理平台，也不承诺抵御本机管理员。

## 用户故事

- 作为教师，我能从目标学生机的已登记程序中搜索并选择软件，或手动建立发布者/哈希规则，再先审核影响、确认后执行。
- 作为机房管理员，我能看到逐台已应用、已撤销、失败、离线、冲突或待复核状态，并知道 Agent 回执只证明 Agent 已处理，不证明程序在 Windows 上实际被拦截。
- 作为学生机管理员，我能在断网或 Teacher 不在线时保留已确认策略，并在期限结束、教师撤销或 Agent 卸载时恢复本工具仍拥有的原值。
- 作为维护者，我能在长期软件限制启用时更新和恢复 Veyon、Teacher、Student Agent 与维护组件；不兼容更新不得替换受保护设备上的现有版本。

## 验收条件

1. 策略使用独立于网站、系统策略和 Developer Release 的 RSA-PSS purpose/key；签名内容绑定校区、策略版本、目标学生 SID、审核/执行模式、规则、时间范围和内容摘要。拒绝错误校区、无效签名、重复/倒退版本、过期策略、重放和超出限制的输入。
2. 目标账户必须是规范 SID 且 RID 不低于 1000 的启用本地学生账户。策略编译、运行时预检和持久状态读回均拒绝内置 Administrator RID 500；直接或经嵌套本地组取得 Administrators 权限的账户不得成为目标。组 SID 读回不完整或无法解析时失败关闭。
3. Teacher 可从所选目标机的受限程序清单搜索/选择条目，并可手动输入发布者或 SHA-256 规则。发布者规则限定产品/应用名称和可选版本范围；哈希规则绑定文件内容，升级后须重新核验。目录扫描有界，当前最多检查 400 个已登记 EXE 候选并返回 200 项；不能把它描述为完整软件盘点。
4. 规则不得以学生可写路径作为信任依据。发布者和哈希 Deny 规则必须经过受保护文件名检查，避免误阻 Windows 登录、外壳、设置、安全、维护、恢复及本工具组件。当前 Veyon、Agent、Worker、Teacher 和更新恢复组件的动态哈希保护须与每次策略编译一起核验。
5. 没有长期软件限制时，课堂审核使用 AppLocker AuditOnly 事件；长期 EXE allowlist 启用时，EXE 集合保持 Enabled，审核改为基于已登记程序清单的影响模拟，并明确这不是实际启动历史。Teacher 只能在相同目标和规则的审核策略已读回一致后确认执行。
6. 执行只阻止之后的新启动，不自动结束已运行程序。默认 Deny 只作用于选定学生 SID，不影响 Teacher、本机管理员、SYSTEM、Agent 或明确保留的非学生本地账户。
7. 长期软件限制开启时，单一 EXE 集合须合并受信任 Windows/Program Files 放行基线、拒绝学生可写目录/可移动盘 PE 文件的长期规则和课堂 Deny；AppLocker Appx 集合维持已签名包放行，MSI 与 Script 集合不由本功能配置。MSI/Store/Appx 安装入口由学生系统策略按用户范围控制。
8. 写入前核验 Windows 版本与版次、AppLocker 支持、域/MDM 和现有有效策略、AppIDSvc、目标身份与本机组成员、放行目录 ACL 和重解析点。存在不支持版本、外部策略冲突、路径不安全或检查结果不完整时，不启动 AppIDSvc、不写 AppLocker 策略并给出可复核原因。AppIDSvc 只能在全部预检和 Pending 状态持久化后、紧邻策略写入时启动。
9. 应用和撤销跨 AppLocker、注册表及本机状态使用持久事务和逐项读回。中断后只接受原值或工具目标值；外部修改、损坏状态或读回不一致均保留现场并报告冲突，不覆盖、不误报成功。
10. Teacher 的成功回执须由固定的 Student Agent 身份密钥签名，并绑定校区、目标指纹、nonce、请求摘要和策略版本。首次身份信任或换钥需要教师明确审批；未经固定/验签的回执只能标为待复核。审核事件、清单和状态数据留在授权的本机教师端，不采集应用使用内容、浏览历史或学生文件。
11. 手机控制只能操作 Teacher 桌面预先保存的应用策略预设，继续调用同一审核、确认、签名推送、逐台回执和审计路径；手机不得持有策略私钥或绕过身份固定。
12. 校区配置包通过 schema v4/v5 提供独立应用策略公钥和客户端兼容范围；v5 另含系统策略信任和 Student Agent 兼容信息。Node/ASP.NET API、OpenAPI、数据库约束及发布清单能力须一致。更新器验证 Developer 签名、角色、版本、摘要、兼容范围和活动策略能力；候选版本能力不足时在替换前拒绝。
13. 可移植检查、API 合同检查、角色构建和 Windows 实机验收分别记录。代码回执、CI 或策略 XML 读回不能单独作为 Windows 实际拦截、账户范围和恢复效果的验收证据。

## 范围与边界

- 首版使用 Windows AppLocker EXE 策略；AppLocker MSI/Script 集合、WDAC 强防篡改白名单、便携程序完整盘点、已运行程序结束和行为监控不在范围内。
- Windows SKU、补丁、AppLocker/CSP/MDM 状态及学校策略必须现场确认；未知或冲突时停止自动写入。
- 具体实现、协议与当前代码边界见[应用限制设计](../../docs/应用程序限制设计.md)；项目级完成状态以[开发路线与任务清单](../../docs/开发路线与任务清单.md) P13 为准。
