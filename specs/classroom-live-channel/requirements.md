# 课堂状态同步：需求

## 目的与范围

让学生登录会话里的 Student Companion 自动显示教师是否在线、课堂是否开始，以及机房名称和电脑数量。首版只同步只读状态，不实现求助、聊天、通知、答题或远程策略控制。

状态更新复用已部署的教师→学生 Agent 签名 LAN 通道，但使用单独的课堂状态端点、消息用途和内存状态，不调用网站、应用或系统策略处理器。Companion 只读取本机 Agent 的 loopback 状态端点。未来双向课堂互动再使用专门的实时事件通道。

## 用户需求

1. 教师在课堂页通过一个明确的开始/下课入口，使用已保存的校区与机房默认值；签名校区身份在本机固定到该 session，不用再次输入目标电脑、连接地址或课堂参数。
2. 开始课堂后，教师向该机房电脑发送已签名的状态快照；下课后发送结束快照。网络失败只影响失败设备，不回滚本地课堂生命周期。
3. Student Companion 自动读取本机 Agent 状态；不显示配置表单、连接地址、重试按钮或重复的状态徽章。
4. 最近一次状态超过两分钟、Agent 重启、签名无效、校区不匹配或负载异常时，显示“等待教师端连接”，不保留过期课堂信息。
5. 状态只含校区 ID、消息 ID、UTC 时间、活动 session ID、机房显示名和目标数；不含学生姓名、IP、浏览内容、消息正文或策略内容。
6. 课堂状态消息必须由已配置的校区教师私钥签名；学生 Agent 仅以该校区公钥验证，并由自身身份密钥签署回执。
7. 学生端本机状态查询仅允许 loopback；不得从 LAN 或公网读取。
8. 断网或 CloudBase 不可用不影响状态过期规则；课堂状态不上传云端。

## 验收条件

- 无有效状态、过期状态和错误状态均回到断开显示；有效无课堂与活动课堂正确呈现。
- 伪造签名、错误校区、重复/旧消息、超出有效期、超大请求、无效字段和远程访问本机查询端点均被拒绝。
- 状态更新不会调用或修改任何策略后端；教师端每 30 秒刷新活动快照，学生 Agent 在两分钟后自动过期。
- 单机检查、Teacher/Student 角色构建通过；真实 Windows LAN、重启、断网恢复和卸载边界单独标记为实机验收。
