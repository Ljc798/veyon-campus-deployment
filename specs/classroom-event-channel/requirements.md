# 双向课堂事件通道：需求

## 目标

为 Student Companion、Teacher Console 和已配对教师手机提供校区局域网内的课堂事件通道，作为求助、教师回复和课堂通知的共同基础。首个版本使用固定间隔的 HTTPS 长轮询，验证端到端身份、会话隔离、事件确认与重连；后续仅在实测表明有必要时再切换 WebSocket。

## 用户故事

- 作为学生，我可以从登录会话中的 Companion 发出一条课堂求助，不需要输入教师电脑地址或配置网络。
- 作为学生，我收到教师回复后可以用一个明确操作确认本次求助已解决，不需要再次选择原因或设备。
- 作为教师，我可以在教师电脑和已配对手机上及时收到当前课堂的事件，并能回复对应设备。
- 作为教师，我可以看到学生是否确认解决，从而区分“已回复”和“已闭环”。
- 作为教师，我可以发送一条课堂通知给当前课堂内所有已授权学生，不用逐台选择设备。
- 作为校区管理员，我希望事件留在教师电脑和校园 LAN 内，断开互联网时课堂互动仍可工作。

## 范围与默认值

1. 复用 Teacher HTTPS `39176`、Student Agent 签名 TCP `39174`、现有教师校区密钥和 Agent 身份；不新增端口、服务发现、CloudBase 中继或用户连接设置。
2. 教师只为本次活动课堂中已固定 Agent 身份的目标签发临时通道授权。授权包含校区、session、目标设备、教师 LAN 地址、证书指纹和有效期，由校区私钥签名，经 Agent 验证后只保存在内存中。
3. Companion 仅通过 loopback 向 Agent 读取课堂授权和提交/读取事件；网络身份由 Agent 签名的目标授权限定，不向 Companion 暴露 Teacher 私钥或 SYSTEM 能力。
4. 移动端沿用配对设备凭据，并通过现有 API 请求随机数和速率限制。教师端可以订阅当前课堂事件并向指定目标回复。
5. 事件带唯一 ID、session、发送者角色、目标、类型和 UTC 时间。学生端消息大小、每设备速率和教师端队列容量均使用固定上限。
6. 事件只在内存中暂存；课堂结束、授权到期或 Teacher 服务重启后失效。重连使用事件 ID 去重，不回放旧课堂事件。
7. 通道只传课堂交互事件，不承载策略命令、屏幕画面、学生浏览数据或 CloudBase 数据。
8. 学生端只显示一个求助动作；系统自动带入当前课堂、学生设备身份和默认求助类型，不要求学生选择原因、输入地址或设置连接方式。
9. 教师回复后，学生端同一位置的动作变为“标记已解决”；等待教师回复时只显示状态，不提供额外操作选项。
10. 学生只能用当前签名授权提交 `HelpResolved`；事件必须关联当前 session、相同目标、已存在的学生求助及教师回复，每个求助最多接受一次解决事件。
11. 教师可以在桌面或手机用同一个消息输入框发送全班通知；目标自动绑定当前课堂，内容最多 500 字符、两分钟后失效，不保存聊天历史。

## 验收条件

- 当活动课堂的目标 Agent 身份已固定时，Teacher 应能签发并推送仅对该校区、session 和目标有效的授权；未固定身份、结束课堂或其他 session 的请求必须失败关闭。
- Student Companion 应只接受 Agent 本机签名且未过期的授权，并验证教师 HTTPS 证书指纹后连接；不允许向非私有地址或非本机 Agent 端点发送事件。
- 学生请求必须经过 Teacher HTTPS API 的令牌、校区、session、目标、事件类型、正文大小、去重和速率校验；教师手机只能读取其配对权限范围内的当前课堂事件。
- 事件确认和教师回复必须绑定原始事件与同一 session；下课或服务重启后旧事件和旧凭据不得生效。
- 当学生确认解决时，Teacher 必须验证 Agent 固定身份、当前 session、目标设备、原始求助和已发送的教师回复；Teacher 桌面与手机网页应显示“已解决”，且不得把重复确认显示为新的求助。
- Teacher 的全班通知必须由当前校区密钥签名并绑定活动 session；事件队列仅保存一条 class-wide 事件，Student Agent 只可通过自身当前有效的逐台授权读取；下课或过期后不可继续投递。
- 教师桌面和手机均可通过一个输入框发送通知；页面不得增加目标电脑选择或网络设置，并明确反馈“已提交”而不声称学生已读。
- 教师手机网页只显示仍有效的课堂通知和当前求助；本地事件缓存按签名事件有效期自动清理。已回复求助保留到关联回复/解决事件的最新有效期，不增加手动清理历史的操作。
- 断网时客户端应退回等待连接并自动恢复；无 CloudBase 时通道照常工作。
- 自动检查覆盖签名篡改、目标/校区/session 错配、过期与重放、令牌撤销、大小与速率限制、队列边界、断线恢复和 Agent loopback 限制。
- 本地 HTTPS API 集成检查以 24 个独立 Agent 身份同时长轮询和提交事件；客户端取消请求后使用原游标重连，每台只能读到自己的事件，教师课堂流不得丢失或重复 48 条事件，下课后所有旧授权失效。该模拟检查不替代 Windows 双机、真实 LAN 或校园网并发验收。
- .NET Release 构建、完整检查集及 Teacher/Student Windows x64 发布构建通过。真实 Windows 双机、手机、VLAN、防火墙和并发容量另列实机验收，不由构建结果替代。

## 非目标

- 本规格不实现在线屏幕流、视频、群聊历史、云端消息存储或后台推送。
- 本规格不加入学生求助原因菜单、快捷回复菜单或第二个解决按钮；学生仍使用一个上下文动作完成求助与确认。
- 本规格不实现通知回复、群聊或消息历史；通知只用于当前课堂短期公告。
- 本规格不承诺 60–70 台同时互动的性能；自动化先验证 24 台规模，现场再测峰值。
