# 双向课堂事件通道：实施任务

- [x] 1. 定义事件、授权和回执协议
  - 固定事件字段、允许的首批事件类型、大小/时间/重放边界和严格 JSON 规则。
  - 为教师签名授权、角色/目标绑定、短期事件和有界内存缓冲添加协议检查。
- [x] 2. 在 Student Agent 加入独立课堂授权与 loopback 接口
  - 仅活动 session 接受授权；进程重启、下课、过期时清除。
  - Agent 不调用网站、应用或长期系统策略处理器。
  - 课堂事件授权单独验签，Companion 事件只经 loopback 转发。
- [x] 3. 在 Teacher HTTPS API 增加事件授权、提交、订阅与确认
  - 学生身份只由固定 Agent key、目标绑定与短期授权确定。
  - 复用配对手机认证，保持队列内存有界、事件短期、断网可恢复。
  - 已实现逐台短期授权、学生签名事件提交、配对手机长轮询和回复；原始签名封装按发送者原样转发，结束课堂会取消等待请求。
- [x] 4. 接入 Teacher 的课堂生命周期
  - 开始/刷新时只向已固定身份的目标签发短期授权；下课立即撤销。
  - 桌面和手机均读取同一课堂事件流。
  - 活动课堂自动启动服务并续签；教师桌面每 2 秒读取本机事件队列，手机网页通过 HTTPS 长轮询读取。
- [x] 5. 接入 Student Companion 通道客户端
  - 固定读取 loopback 授权、固定 HTTPS 证书指纹和请求重试节奏。
  - 网络配置不暴露为用户选项；失联时自动回到等待状态。
  - 学生窗口只提供一个求助按钮；课堂、目标、网络和求助原因均自动确定。
- [x] 6. 添加协议、API、重连和安全边界检查
  - 覆盖篡改、错校区/目标/session、重放、过期、撤销、越权、大小/速率与队列边界。
  - 检查教师桌面事件关联、学生回复关联、重复消息去重、过期消息过滤和求助状态恢复。
- [x] 7. 更新架构、使用说明、路线索引和实施记录；完成验证后单独提交
- [x] 8. 完成学生确认解决的求助闭环
  - Companion 收到本次教师回复后，在原有单按钮位置显示“标记已解决”；等待回复期间不增加额外操作项。
  - Agent 通过独立 loopback 请求生成并签名 `HelpResolved`；Teacher 拒绝无原求助、错误目标/session、未回复或重复解决事件。
  - Teacher 桌面与配对手机把原求助更新为“已解决”，而不是新增第二条求助。
  - _Requirement: 9–10_
- [x] 9. 完成 Teacher 全班通知
  - Teacher 桌面和 PWA 使用单一消息输入，将一条校区签名的 class-wide `ClassroomNotice` 发给当前课堂。
  - Agent 只能通过当前 session 的逐台有效授权读取通知；事件只入队一次，不按每台设备复制。
  - Companion 收到后显示通知，不覆盖尚未确认的教师求助回复；通知两分钟后失效。
  - _Requirement: 11_
- [x] 10. 增加 24 目标本地 HTTPS 并发集成检查
  - 24 个独立 Agent 身份同时长轮询和提交；断开请求后沿原游标重连。
  - 验证逐目标隔离、教师流完整接收 48 条唯一事件，下课后旧授权与等待请求失效。
  - 此项验证 Teacher API 和内存事件服务，不代表 Windows/真实 LAN 现场验收。
- [ ] 11. Windows 双机、手机、真实断网、防火墙/VLAN 与 24 台实机并发验收

第 8–10 项代码与自动检查完成；第 11 项现场验收仍未完成。
