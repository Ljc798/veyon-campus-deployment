# 管理员下载页版本同步：需求

## 目标

站点 owner/admin 可在管理员后台一键读取 GitHub 与 GitCode 的最新正式发行，并更新公开 `/download` 页的版本号、发行页地址和教师端/学生端安装包地址。

## 用户故事

- 作为站点管理员，我希望从一个按钮同步两个下载来源，不必手工改网页或重建静态站点。
- 作为下载页访客，我希望清楚看到每个来源当前对应的版本，并直接下载对应角色的安装程序。
- 作为管理员，我希望任一来源缺少所需安装包或返回错误时，原有页面配置保持不变，并显示能处理的错误信息。

## 验收条件

1. 只有已登录且角色为 `owner` 或 `admin` 的账号可以读取后台同步状态或触发同步；令牌和上游凭据不进入浏览器。
2. Cloud Function 服务端分别读取固定 GitHub、GitCode 仓库的最新正式 Release；浏览器不直接请求上游 API。
3. 服务端验证发行 tag 为 `vX.Y.Z`，并确认该版本同时有名称精确匹配的 TeacherConsole 和 StudentSetup Windows x64 EXE 附件。
4. 服务端只接受固定仓库的 HTTPS 发行页和已验证附件；不允许管理员提交任意下载 URL。
5. 两个来源都通过验证后才原子保存全部记录。任一来源失败、版本标签无效或缺少附件时不改变现有配置，并返回按来源说明的错误。
6. 配置按来源保存版本、tag、发行页 URL、教师端 URL、学生端 URL、更新时间和操作者；页面不要求两个托管源同时发布同一版本。
7. 公共只读 API 只返回下载页所需字段；公开 `/download` 页从该 API 读取动态数据，并分别显示 GitHub 与 GitCode 的版本。读取失败时保留可读页面并明确标出暂时无法刷新下载信息。
8. 手工打开两个发行页的链接和逐角色直链仍可用；安装程序免责声明和角色说明保留。
9. 不上传配置包、校区数据、设备信息或私钥；该功能不触发构建、签名或 Release 发布。

## 非目标

- 不在后台构建、发布或签名安装器；仍使用现有受保护发布工作流。
- 不向公开站点展示 CloudBase 对象存储地址、凭据或管理员资料。
- 不要求 GitHub 与 GitCode 的版本相同；镜像延迟时各显示各自实际 Release 版本。
