# 本地课堂会话：需求

## 问题与范围

路线图中的学生求助、课堂通知和后续测验需要共享一套教室、课堂和目标电脑身份。该功能从 TeacherConsole 已保存的本机校区/机房档案生成课堂快照，并记录课堂开始与结束状态。它是本机数据，不是 CloudBase 校区 ID、登录凭据或设备认证。

本轮完成 `Session / Room / Target` 的本地模型、单活动会话生命周期、受限历史存储及未来课堂事件的授权契约。暂不提供 Student Companion、WSS、聊天页面或课堂控制 UI。

## 用户故事

- 作为教师，我可以用已保存的机房清单开始一堂课，无需再次输入电脑或学生名单。
- 作为教师，我可以结束课堂；重复请求不会重复生成结束记录。
- 作为维护人员，我可以从本机结构化会话摘要检查开始/结束时间、机房和目标电脑范围。
- 作为学校管理员，我希望学生姓名、消息内容、IP 地址和主机名不进入课堂会话历史，也不会被上传到 CloudBase。

## 验收条件

1. 当教师从本机校区档案的某个机房开始课堂时，系统应生成随机 `sessionId`、稳定的本机 `campusProfileId`/`roomId`，并按现有电脑编号规则快照 1–150 个目标。
2. 每个目标应取得仅在本堂课内有效的随机 `targetId`；目标显示标签来自电脑编号。会话创建不得把学生姓名、IP、DNS 主机名、Agent 指纹或密钥作为会话 ID。
3. 同一 TeacherConsole 本机数据目录最多只有一个活动会话。已有活动会话时，新建必须安全拒绝，不隐式结束旧会话或替换目标。
4. 结束操作只能将 `Active` 转为 `Ended`；重复结束应保持最初结束时间，早于开始时间的结束时间无效。
5. 会话历史仅写入当前用户本机应用数据目录；保留最近 30 条已结束会话及最多 1 条活动会话，单文件不超过 1 MiB。写入采用原子替换，未知字段、重复 JSON 字段、损坏文件、超限数据和重解析点均拒绝；拒绝时不得覆盖原文件。
6. 本轮模型只保存校区/机房显示名快照、稳定档案 ID、开始/结束时间、状态和电脑编号。不得保存学生姓名、终端地址、身份指纹、举手/消息正文、屏幕或课堂行为明细。
7. 会话创建、读取和结束不调用网络、手机服务或 CloudBase；没有会话事件、更新、心跳或诊断数据上传。
8. 未来事件必须带版本、随机事件 ID、活动 `sessionId`、目标范围和 UTC 时间；只接受固定事件类型及有界负载。目标 ID 仅用于会话内路由，不能当作认证凭据；每个事件仍须由已认证教师或经过机器身份核验的学生会话授权。
9. 授权矩阵限制教师和学生可发出的事件；超出当前会话、目标不在快照、重复/过期事件、超限文本或未知事件必须拒绝。课堂消息不经 CloudBase 中继。

## 非目标

- 本轮不实现 Student Companion、举手队列、教师回复、测验、WSS、长轮询或 PWA 页面。
- 本轮不将学生名录、Agent 公钥、目标 IP/DNS、课堂消息、浏览/屏幕数据写入会话存储。
- 本轮不上传课堂状态或互动事件到 CloudBase，也不增加保留期、房间或目标范围设置。
- 可移植检查通过不代表 Windows UI、LAN、并发规模或手机/Agent 身份实机验收完成。
