## 1.1.95：四个问题合并 + DNS 强制误伤正常网站

1.1.94 的四个修复（课堂自动解除、失败设备重试误报、Maintenance 卡更新、网络层下沉）
一直只在本地，未提交未发布；这次合并成一版，并追加 DNS 修正。

### DNS 误伤：两个真实缺陷

1. **DoH 名单封了本机自己的解析器**。`223.5.5.5` / `119.29.29.29` 既在国内常见 DNS 名单里，
   又是 DoH 端点。学校直接把它们当普通 DNS 用时，53 放行了、443 被自己封掉；Windows 11 把已知
   解析器升级成 DoH 后，解析走上 443 → 被切断。缓存命中的站点能开、其余超时 = "有的网站能开有的不能"。
   → `WebsiteDnsLockdown.Build` 现在把 `configuredServers` 从 DoH 名单里剔除。
2. **黑名单模式封了整个公网 53**。黑名单按目标地址执行，换解析器不能让已封地址变可达；
   全封只会误伤软件自带的解析器。
   → `Build(servers, restrictAllPublicResolvers)`：白名单仍全封（靠解析结果执行），
      黑名单/组合只封 `KnownPublicResolversV4`（Google/CF/Quad9/OpenDNS/AdGuard/Control D/
      AliDNS/DNSPod/腾讯/百度/114DNS + 电信联通移动常用）。
3. **新增解析器探测**：`AnyResolverRespondsAsync` 直接用 UDP 53 向本机解析器发 `www.msftconnecttest.com`
   的 A 查询（`BuildQuery` 手写报文，internal 可测）。没有任何一台响应就不启用 53 封锁，
   只保留 DoH 封锁，并把原因写进 `ResolverLockError`。旧锁已生效时探测仍能通过（目标就是被放行的解析器），不会抖动。

### 四个既有修复（本轮一起进包）

- 课堂范围：`HasPendingClassroomScopeChange` 拆成"确实换了教室/校区"与"名单可读且确实不一致"，
  快照过期只算"无法核对"；`IsClassroomDirectoryScopeVerified` 在已有活动会话时忽略
  `_classroomDirectorySelectionPending`；`ClassroomQuickControlBlockedReason` 补两条分支 + 兜底，禁用必有原因。
- 失败设备重试：`FillFailedWebsiteTargets` 清掉目录快照要求；推送入口用 `DescribeWebsiteTargetTrustBlocker`
  区分"真没选"和"快照过期"。
- Maintenance：ACL 判定 + 先修复再校验（1.1.92/1.1.93 的结论保留）。
- 网络层：地址封禁 + 53/853/DoH 三层，状态独立上报。

## 1.1.96：重启后解除要等几分钟 + 空悬浮框

用户实测 1.1.95：抖音客户端也被拦住（网络层与浏览器无关，符合预期）。但学生机重启后，
教师端“一键恢复全部”报失败、状态停在“等待上线”，几分钟后才自己恢复；同期 Veyon 消息仍可互通。

### 根因

快捷管控失败退避是**指数**的：60s → 120s → 240s → 480s …（上限 30 分钟）。
重启后 Agent 未起来的几十秒里，前几次尝试失败就把下一次推到 2/4/8 分钟后；
Agent 早就起来了，教师端还在梯子上等。而 Veyon 消息走的是另一条通道，因此“看起来可达”。
“关机时推送、开机就好”是因为那次由 Agent 启动后领取，没走退避。

### 改动

- `ClassroomQuickControlDeviceState.UpdateRetry(..., bool awaitingAgent = false)`：
  `WaitingForAgent` 时 10s → 20s → 30s（封顶）；真实失败仍走原来的长梯子。
- `TeacherClassroomQuickControlService.RecordCatchUpFailure(..., awaitingAgent)`，
  三个调用点按设备 `Phase` 传入；`WebsiteCatchUpInterval` 30s → 15s。
- `IsCatchUpDue` 对 `WaitingForAgent` 再加读侧上限（`UpdatedUtc + 30s`），
  旧状态文件里“几十分钟后再试”升级后会被就地纠正。
- 汇总文案：全员离线时改为“已排队：N 台设备暂未上线，约半分钟内自动重试，上线后自动完成，无需重复点击。”
- 空悬浮框：`ClassroomQuickControlBlockedReason` 无原因时返回 `null`（原为空字符串，
  Avalonia 对空字符串也画气泡，于是出现“只有框没有文字”）。
- 测试：`--classroom-quick-control-revision-fixtures` 增加离线 10s/30s 断言。

## 1.1.97：已经开着的应用拦不住

用户实测：抖音设了开机自启动、或课间就打开，上课推送后照样能刷；"关机时推送、开机生效"却正常。

### 根因

防火墙规则只决定**新连接**能否建立；Windows 不会因为出现阻止规则而拆掉**已建立**的 TCP 会话。
所以策略下发前就连上 CDN 的客户端会一直保持会话。规则没错，缺"让旧连接立刻失效"。

### 改动

- 新增 `src/VeyonCampus.Core/TcpConnectionReset.cs`：
  - `ResetTo(prefixes)`：枚举 `IPGlobalProperties.GetActiveTcpConnections()`，远端地址落在封禁集合内的
    IPv4 会话用 `SetTcpEntry` + `MIB_TCP_STATE_DELETE_TCB`（12）重置；
  - `Parse` / `Covers`：前缀解析与匹配，纯函数、可测；IPv6 跳过（`SetTcpEntry` 只有 MIB_TCPROW）；
  - 地址按网络字节序写入（`b0 | b1<<8 | b2<<16 | b3<<24`），端口低 16 位交换字节。
- `WebsiteNetworkBlock.Apply(revision, plan)`（Windows 公开重载）在写入成功后调用重置；
  只在 `AddressCount > 0` 时执行，测试用的三参重载不受影响。
- 客户端随后重连：连被封 IP 被防火墙拒；重新解析命中 hosts（0.0.0.0）。
  hosts 写入本来就有 `DnsFlushResolverCache`，所以已开着的程序重新解析也能看到新映射。
- 测试：`--website-network-block-fixtures` 新增 `MatchesOnlyBlockedPrefixes`（/32、/16、不误伤相邻地址、不匹配 IPv6）。

## 1.1.98：学生端“移除学生端限制”后身份对不上（入口难找）

`TeacherMobileControlServer` 抛“学生 Agent 身份已撤销或轮换”。

2. `设备与更新` → 勾选设备 → “同步教师连接配置”/“一键静默更新全部学生端”

## 1.1.109：总根因——Guard 租约线程每秒误判过期

1.1.108 的命令结果日志（input-guard-command）一次定位真正的总根因。现场日志：
```
09:16:36.77 input-guard-state  phase=Locked, lease=fdc5ee2a
09:16:36.78 input-guard-command Activate: Succeeded, phase=Locked
09:16:36.83 input-guard-sessions s2=Locked/lease:fdc5ee2a/up
09:16:41.84 input-guard-state  phase=Expired, lease=null   ← 仅 5 秒后（租约应 20s）
```
整段只有 Activate、无 Renew——续租在读回时已被判 Expired，没发出去。用户问"是不是虚拟机问题"，
答案：不是。

### 根因（确定性 bug，从第一版就存在）
`StudentInputGuardServer.RunLockThread`：
- `GetLeaseWaitMilliseconds()` 把等待封顶 1000ms（本意每秒醒一次保持响应）；
- 但 `TryTake` 因这个 1s 上限超时后，**无条件调用 `ExpireLease()`**，把租约当到期释放；
- 于是每次 Activate/Renew 后约 1 秒租约就被误判过期、键鼠被解锁。5 秒才出现 Expired 是因为
  期间续租/状态请求让线程没走到超时分支，第一次空档才释放。

### 改动
- `RunLockThread`：TryTake 超时后先判断绝对到期时间 `_leaseExpiresTimestamp` 是否真的过了，
  没到就 continue 继续等，只有到点才 ExpireLease()。
- 保留之前所有加固（epoch、双会话快照、命令日志、移除网站策略互斥）。
- Agent 0.4.73→0.4.74；发布说明 `docs/releases/v1.1.109.md`。
