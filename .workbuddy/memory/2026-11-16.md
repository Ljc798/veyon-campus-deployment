## 13:20–13:40 网站策略覆盖 360 等不读策略的浏览器（hosts 兜底）

### 调研结论（决定了方案）
- 360 社区版主官方回复：**安全浏览器个人版不支持策略**，要管控得用 360 企业浏览器（browser.360.net）。
- 360 极速浏览器只有 `HKLM\SOFTWARE\WOW6432Node\Policies\360Chrome` 这类厂商自定义项（首页、扩展），
  没有证据表明支持 URLBlocklist；360 企业版走自己的 `SOFTWARE\Policies\360\Browser`。
- QQ/搜狗同理。结论：**注册表策略无法覆盖国产浏览器**，必须另找机制。

### 实现（提交 `eca56f4` + `ca2ac36`）
新增 `src/VeyonCampus.Core/HostsFileWebsitePolicy.cs`：
- 在 `%SystemRoot%\System32\drivers\etc\hosts` 维护带标记区块
  （`# BEGIN VeyonCampus Website Policy` / `# END ...`），把黑名单域名指向 `0.0.0.0`。
- hosts 无通配符，每个域名同时写 `x.com` 与 `www.x.com`；深层子域仍依赖浏览器策略。
- 只对 Blocklist/Combined 写条目；Allowlist 无法用 hosts 表达。
- 幂等：先剥离旧块再写；`Clear` 用于解除/到期/卸载。
- 写入失败**不阻塞策略**（注册表事务已提交，回滚反而丢掉 Edge/Chrome/Firefox 的覆盖），
  结果写入注册表 `AgentKey\HostsRevision` / `HostsError`，并在设备摘要上报。
- 失败文案点名 360 安全卫士/腾讯电脑管家锁 hosts 的处置办法。
- **编码保留**：严格按 UTF-8 解码，失败回退 Latin-1（字节级往返），避免把 GBK 注释写成乱码。

集成点：`WebsitePolicyRegistryStore.Apply`（写）、`ExpireIfDue`（清）、`RemoveOwnedState`（清）；
所有权白名单加 `HostsRevision`/`HostsError`（`ReadSnapshot` 与 `ValidateOwnedState` 两处）。
状态穿透：`WebsitePolicyReportedState` + `StudentAgentRuntimeSummary` 各加两个可选字段，
教师端 `PolicySummary` 显示「hosts 兜底 rN（覆盖 360 等不读策略的浏览器）」或失败原因。

### 验证
- Core / App 编译 0 错误。
- 新增 `tests/VeyonCampus.Checks/HostsFilePolicyChecks.cs`，`--hosts-policy-fixtures` 通过：

- 本机实测 hosts 可写（35 行 → 加一行 → 恢复 35 行）。

## 13:40–14:30 CloudBase 过期 → 更新来源迁移到发布目录（1.1.81）

### 现场
- `veyon-api` 返回 402 `ENV_ISOLATED`；`kidscode.fun`（CNAME → `*.tcbaccess.tencentcloudbase.com`）同样 402。
  不只是一个接口不可用，网站、数据库、云函数整体离线。
- GitCode 直连 0.22s（`gitcode.com/{owner}/{repo}/raw/{branch}/{path}` 200），
  `api.gitcode.com` 0.54s，资产 GET 206 → 302 到 `file-cdn.gitcode.com`。GitHub raw 直连失败。

### 约束（决定了实现方式）
`ApplicationReleaseClient.Verify` 原来要求 `manifest.downloadUrl` 与 API 基址同源且路径为
`/v1/releases/{guid}/artifact`，而签名本身覆盖 `downloadUrl`。换来源必须重新签名 + 放开同源校验。

### 方案（用户确认：GitCode 发布页 + 网站一起迁）
- 每个 Release 增加资产 `release-catalog.json`（`schemaVersion 1`，`tag`，`roles`），
  内含每个角色的签名清单 + StudentSetup 的 Agent 目标 sidecar + `mirrors`。
- 客户端：`api.gitcode.com/.../releases/latest` → 取资产 → 按角色取 → 验签 → 下载。
  GitHub API 为第二来源，每源 20s 超时；全部失败报“版本目录暂时不可用”而不是“已是最新”。
- `downloadUrl` 允许两种形态：旧 `/v1/releases/{guid}/artifact`（自建/测试），
  或 `https://gitcode.com|github.com/{owner}/{repo}/releases/download/{tag}/{fileName}`（文件名必须与签名一致）。
- 镜像仅在主地址失败时尝试；摘要被签名覆盖，完整性错误仍抛 `InvalidDataException`（不包装成网络错误）。
- 复用 `publish-application-release.cjs` 的 `canonicalPayload` 签名，保证 JS 与 .NET 字节一致；
  固件里把 .NET `CreateCanonicalPayload` 的输出与 JS 产出写成字面量断言，防跨语言漂移。

### 代码
- 新增 `src/VeyonCampus.Core/ReleaseCatalogSources.cs`（来源、env `VEYONCAMPUS_RELEASE_CATALOG_SOURCES`）
  与 `ApplicationReleases.Catalog.cs`（索引读取、目录解析、镜像过滤）。
- `ApplicationReleases.cs`：partial 类、`_catalogSources`/`_legacyApiEnabled`、镜像重试循环、
  `ValidateDownloadUrl`、`MirrorDownloadUrls` 贯通到 5 处下载调用点。
- `scripts/build-release-catalog.cjs`：CI 生成并签名目录；重发版本时从旧目录继承 Agent sidecar。
- `windows-installers.yml`：CloudBase 发布步骤换成“生成目录 + `gh release upload`”；
  同时去掉发布前的 CloudBase 凭据要求。
- `publish-existing-cloudbase-release.yml` → `rebuild-release-catalogue.yml`（contents: write）。
- `website/src/public-download-data.js`：下载页直接读两个发布站的 `releases/latest`。
