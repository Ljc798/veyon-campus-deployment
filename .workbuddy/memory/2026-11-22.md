# 2026-11-22

## 网络层网站策略：DNS 强制 + DoH 封锁（1.1.90 / Agent 0.4.59）

背景：用户判断「学生会下载各种浏览器，浏览器策略没用，必须改网络层」。原有实现只把黑名单域名解析成 IP、在 Windows 防火墙封出站地址，三个缺口：改 DNS、浏览器自带 DoH、白名单模式没有网络层。

### 新增文件

- `src/VeyonCampus.Core/WebsiteDnsLockdown.cs`
  - `WebsiteDnsLockdownPlan(ResolverAddresses, DohEndpoints, AllowedServers, Error)`
  - `Build(IReadOnlyList<IPAddress>)`：纯函数。`0.0.0.0/0` 减去保留段与「本机 DNS 服务器」，得到要封的 53 目标前缀；IPv6 用 `2000::/3` 同法处理。
  - `ReadConfiguredServers()`：读所有 Up 网卡的 `DnsAddresses`（跳过链路本地/多播）。
  - 保留段：`0/8, 10/8, 100.64/10, 127/8, 169.254/16, 172.16/12, 192.0.0/24, 192.0.2/24, 192.88.99/24, 192.168/16, 198.18/15, 198.51.100/24, 203.0.113/24, 224/4, 240/4`。
  - DoH 端点表：Cloudflare、Google、Quad9、OpenDNS、AdGuard、CleanBrowsing、Control D、AliDNS、DNSPod、腾讯、百度（IPv4 + IPv6）。
  - `ToCidrs` 分解对齐前缀；`UInt128` 版本对 `start==0 && end==MaxValue` 特判（`1<<128` 会回绕成 1）。
  - 读不到 DNS 时不封 53（避免断网），只封 DoH 并返回 Error。

### 改动

- `WebsiteNetworkBlock.cs`
  - `WebsiteNetworkBlockPlan` 增加可空 `DnsLockdown`。
  - `WebsiteNetworkBlockResult` 增加 `ResolverLocked / ResolverCidrCount / DohEndpointCount / AllowedServers / ResolverLockError`。
  - `IWebsiteBlockRuleBackend` 改为 `Write(addresses, resolverCidrs, dohEndpoints)`，新增 `ReadResolverLockCidrs / ReadDohEndpoints`。
  - `Apply` 三方比对（地址、53 段、DoH 端点），任一不符就整体重写并重新校验；地址为空但锁定非空时不再 `Clear()`。
  - `WindowsWebsiteBlockRuleBackend` 新前缀 `VeyonCampus Resolver Lock`（53）与 `VeyonCampus DoH Block`（443），TCP+UDP，`CidrsPerRule=32`。
- `WebsitePolicyRuntime.cs`
  - `QueueNetworkBlock`：Allowlist 模式也进入网络层（只写 DNS 锁定）。
  - `ApplyNetworkBlockInBackground`：`plan with { DnsLockdown = WebsiteDnsLockdown.Build(ReadConfiguredServers()) }`。
  - 注册表新增 `ResolverLockCidrs / DohBlockEndpoints / ResolverLockServers / ResolverLockError`，并同步两处「允许值」白名单（否则事务会报「未知内容」）。
- 协议：`WebsitePolicyReportedState`、`StudentAgentRuntimeSummary` 末尾追加 5 个可空字段；`Validate` 增加非负与长度校验。
- 教师端 `TeacherViewModel`：新增「DNS 强制已生效（仅放行 …；封 N 段公网 53、M 个 DoH 端点）/ 未生效 / 未上报」。
- 版本：App `1.1.90`，Agent `0.4.59`；`docs/releases/v1.1.90.md`。
- 测试：`tests/VeyonCampus.Checks/WebsiteDnsLockdownChecks.cs`（CIDR 分解、私网放行、公网解析器封禁、本机公网 DNS 扣除、IPv6、空 DNS 时只封 DoH、写回校验），已注册到主套件与 `--website-dns-lockdown-fixtures`。

### 关键陷阱

- 测试里判断 CIDR 包含时必须按地址族分别用 32/128 位掩码；用 128 位掩码套 IPv4 会让所有地址都「命中」。
- `package-windows-offline.ps1` 的 `-InstallerPath` 是**输出**安装包路径，不是 Inno Setup 安装器路径；传错会覆盖输入文件。
- 本机 Inno Setup 在 `%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`（winget 安装，6.7.3），脚本的候选路径已经包含它。
- 新增注册表值必须同时加进 `WebsitePolicyRegistryTransactions.ReadSnapshot` 与 `WebsitePolicyRuntime` 卸载校验的两份允许值列表。
