- 20:00 定位"安装成功但弹窗报 Maintenance 安装失败"的**真正根因**（1.1.46 起一直存在，1.1.66 未修）：

  后果：服务被创建但没启动，安装器判定失败并把整次安装报成中止。
  修复（v1.1.67）：
  - `LocalFree` 改 kernel32。
  - `MaintenanceServiceRecoveryTask.Register` 包 try/catch（恢复任务是可选兜底，不能决定安装成败）。
  - `.iss` 随包把 `VeyonCampus.UpdateHelper.exe` 放进
    `MaintenanceService\Versions\<ver>`（开机恢复任务与服务自更新的固定助手位置）。
  - `.iss` 安装判定改为"以 `--verify-running` 的服务状态为准"，退出码非 0 但服务在跑也算成功；
    失败提示带 control/state 与 `C:/ProgramData/VeyonCampus/MaintenanceServiceHost/service.log`。
  - `--uninstall-service` 先释放服务句柄再轮询删除（持句柄时已删除的服务不消失，原先必然等满 20s
    抛 TimeoutException）；`TimeoutException` 纳入 Main 的统一 catch（原先直接 CLR 崩溃）。
  验证：本机受管目录 `Versions\1.0.0` 安装 exit=0 且服务 Running，`--verify-running`=0。
  注意 CI 冒烟测试一直通过（runner 是 Windows Server 2025 26100），说明该平台上
  advapi32 碰巧能解析 LocalFree；本机 Win10 19045 必崩。今后此类 P/Invoke 需在客户端系统上验。

## 01:00 1.1.77 遗留问题盘点（代码级确认）
- `StudentUpdateAtomicTransaction.MoveInstallationDirectory` 只做一次 750ms 重试，**不处理目标目录已存在**；
  Win32 183「当文件已存在时，无法创建该文件」仍会在“上一轮回滚没走完”的机器上复现。
  `CleanupStagingDirectory` 只清暂存安装包目录，不清 Versions/恢复目录。
- 统计口径：`alreadyCurrent = State==Completed && !StudentSetupUpdateAttempted`，
  只做了 ConfigurationSync 的机器会被算成“已完成”（pc-15 那种），需按版本号复核。
- `TeacherMaintenanceWorkflow` 仍无“未开机/不可达”独立状态，未开机设备计入预检失败。
- `RunStudentUpdateAsync` 已有 try/catch（IOException/UnauthorizedAccessException 等），单台异常基本不再污染整批。
