## 现场故障：时钟差导致「回执时间无效 / 锁定后无法解除 / 认证失败」

**现象**：学生机课堂助手「等待教师端连接 · 课堂状态本机回执时间无效」；教师端该机画面区「认证失败」+「网站待核对」；更早一次是锁定键鼠后无法推送、连不上、只能等锁定到期。

**根因（代码级）**：三条协议都把「另一台机器的时间戳」与「本机 now」直接比较，学生机时钟比教师机慢几秒就全线失败：
- 课堂状态：`ClassroomStatusAgentState` 把教师端绝对截止时间与本地接收时间混算，`expires - received > 2min` 一触即发 → 课堂助手整个课时显示回执无效。
- 键鼠：`ValidateStatus` 要求 Agent 的 `CollectedUtc` 在教师端 ±2 分钟；`Validate(command)` 要求 `IssuedUtc` 在 Agent 端 [-30s,+5s]；`ValidateReceipt` 要求 `CompletedUtc` 在教师端 [-2min,+1min]。锁定能写进去（那一刻恰好通过），解除/续租时校验不过 → 教师端只会显示「状态无法核验」，没有任何解除入口，只能等 `ReleaseUtc`。

**修复（本轮）**
- `ClassroomStatusAgentState`：用「剩余有效期 = ExpiresUtc - IssuedUtc」锚定本地接收时间，快照时间全部变成本机时钟；`ToSnapshot` 新增可选 `expiresUtc`。
- `StudentInputGuardTransport`：`ReadStatusAsync` 用签名状态测出 `ClockOffset`，把状态时间换算成教师端时钟并把差值写进提示；`ExecuteAsync` 用同一差值换算 `IssuedUtc/ExpiresUtc/LeaseExpiresUtc/LockReleaseUtc`，回执校验也用 `now + offset`。`ValidateStatus` 的窗口放宽到 12 小时（nonce 已防重放）。
- `StudentCompanionStatusPoller`：提示改为「本机与教师端时钟相差约 N 秒，请对齐时间并启用自动同步」。
- 教师端身份固定：`StudentAgentIdentityTrustStore.FindTrustedPins`（同一指纹多个名称），Agent 通道与 Maintenance 通道不再要求「指纹唯一」，并把这些名称都注册到同一连接上；否则改名后两条通道都会 `untrusted agent`。

**产物/工具**：`scripts/release-input-lock.ps1`（学生机管理员运行：停任务→杀 Agent→杀 Guard→删 `input-guard-lock-intent.json`→启任务）。
**环境坑**：F 盘曾 100% 满（仅 6.9MB），`dotnet build` 报 CS2012/MSB3021；清 `src|tests/*/obj|bin` 后剩 1.4GB。`artifacts/teacher.vmcz` 占 5.9GB。

## 屏幕墙「认证被拒绝：密钥不匹配」定位（10:50）

- 文案来源：`ScreenWall/ScreenWallConnection.cs:202`，即遍历本机所有 Veyon 私钥后全部被 401/400 拒绝。
- 链路：屏幕墙固定走 `http://127.0.0.1:11080/api/v1/authentication/{host}`（本机 veyon-service 代理连学生机），私钥来自 `C:\ProgramData\Veyon\keys\private\<keyId>\key`。Veyon 的 KeyFile 认证要求 keyname 与学生机 authkeys 里的同名 public 匹配，所以 `keyId` 必须一致。
- 校区 keyId 算法：`SHA-256(campusId)` 前 16 字节，每字节拆两个字母（高/低 4 位 → A..P），前缀 `C`，共 33 字符（`VeyonAuthKeyId.ForCampus`）。本机实测用座位表 GUID `ecea2d26-…` 算出 `CBGBEK…`，而本机唯一私钥是 `CDPPL…`，说明本机私钥属于别的校区。
- 公钥导入只发生在 `WindowsVeyonAdapter.ConfigPublicKey`（经 `PrivilegedWorkerDispatcher` 推送配置包时）：切 `Authentication/Method=1` → `authkeys import <keyId>/public` → 重启 VeyonService。**同名公钥指纹不一致时返回 NeedsReview 且不覆盖**，这是「学生机有旧公钥 → 新教师机永远认证失败」的隐藏路径。
- 新增只读诊断脚本 `scripts/diagnose-screen-wall-auth.ps1`（pwsh 运行）：列私钥/公钥、算校区 keyId、探测 WebAPI、逐台逐把私钥真实认证，输出判读结论；`-OutputPath` 落盘。
- 「网站待核对」是 `ClassroomScreenTileViewModel` 的 `reported` 状态（Agent 已上报待教师核对），不是故障。

## 现场取证：keyId 相同、认证方式=1，故障落在「同名不同钥匙」
- 学生机 `authkeys list` = `CDBPDCGNJHEMBDFGAME3FHWLLJNGOEFH/public`，`Authentication/Method` = 1；教师机 `keys\private` 与 `authkeys list` 都是同一个 keyId，且 private+public 齐全。→ 名字层面对齐；Veyon 只按名匹配、不校验内容，唯一剩下的解释是两边密钥材料不同（教师端密钥被重建过）。
- 新增 `scripts/compare-veyon-key.ps1`（只读，UTF-8 带 BOM，兼容 Windows PowerShell 5.1）：打印每个 keyId 的私钥/公钥存在性与**规范指纹**。指纹 = SHA256(SPKI DER)，与 Veyon 配置器显示、`package.PublicKeyFingerprint` 完全一致（已用 RSA.ImportFromPem 交叉验证）。支持 `-ExpectedFingerprint` 直接给「一致/不一致」结论、`-OutputPath` 落盘。
- veyon-cli 4.11.2 实测语法：`authkeys export <keyId>/public <file>`（必须带 /public）、`authkeys delete <keyId>/public`、`authkeys import <keyId>/public <file>`、`authkeys extract <两个库内密钥名>`（不接受文件路径）。密钥库布局：`C:\ProgramData\Veyon\keys\{private,public}\<keyId>\key`，PEM，store 文件与 export 内容哈希相同。
- 现场修复路径：学生机 `authkeys delete <keyId>/public` → 重启 VeyonService → 教师端重推该机配置包（不删则 `ConfigPublicKey` 遇同名不一致会 NeedsReview 且不覆盖，永远自愈不了）。

- 现场截图：PC-15 与教师机 TEACHER 的 `authkeys list` 公钥指纹**完全相同**（`E5CF4D60 7870 1879 BA3F DD5D C191 4CF7…`），student 私钥=无、public=有，Method=1 → 「同名不同钥匙」假设被排除，学生机信的正是教师机这把公钥。
