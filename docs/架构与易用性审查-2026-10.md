# 架构与易用性审查：2026-10-24

本次对照仓库说明、部署边界、UI 规范、教师端/手机端操作、课堂策略和 CloudBase 管理站代码，整理实际组件关系与可以逐步简化的地方。这里记录的是代码审查结论；没有把设备实测或未执行的编译写成已验收。

## 系统结构

| 部分 | 当前职责 | 主要边界 |
| --- | --- | --- |
| TeacherConsole 桌面端 | 教师/校区资料、课堂名单、Veyon 操作、签名策略、设备状态、更新、手机服务 | Avalonia 桌面进程；调用 Core 协议和课堂服务。教师管理界面及主要状态仍集中在约 13,000 行的 `TeacherViewModel.cs`。 |
| StudentSetup | 学生端首次安装、配置导入、维护操作 | 独立 Windows 管理员界面；由固定 Worker 处理少量需提升权限的系统操作。 |
| Student Agent 与 InputGuard | Agent 验证教师签名策略并读回状态；InputGuard 处理短时输入锁 | Agent 以 SYSTEM 计划任务运行；InputGuard 使用短时租约；Companion 在普通学生会话中运行。 |
| Teacher Mobile PWA | 已配对手机使用课堂互动、逐台策略、屏幕巡视 | 同一校园 LAN 连接教师机 HTTPS；请求经教师机校验后再访问学生 Agent/Veyon。策略和截图不经过 CloudBase。 |
| CloudBase 服务与网站 | 管理员登录、校区资料、匿名使用汇总、分析、数据库只读视图、API 目录、下载页和版本发布 | 网站静态前端调用 CloudBase Auth/PostgreSQL 与公开 API；API 与数据读写在 `admin-data.js`/`cloudbase.js`，页面呈现在 `cloud-admin.js`。 |
| UpdateHelper | 校验安装请求、替换和回退 | 固定的更新流程；不执行任意命令或路径。 |

## 本次修复

### 课堂网站恢复

旧“解除课堂管控”只移除教师端可证明自己创建的课堂策略，因而不会处理各学生电脑原本就不同的名单。课堂页现在有两种含义分明的操作：

- **恢复全班网站访问**：桌面端和手机端均逐台读取签名状态，用当前网站策略版本作比较条件，下发版本更高且黑名单/白名单为空的“停用”策略，再读回确认。不同学生策略不需要相同；身份无法核实、离线、Agent 低于 0.4.50、策略版本已变化时保持原状并单独报告。
- **解除课堂管控**：仍只清理本快捷管控账本能证明归属的网站策略和键鼠租约。

恢复网站访问不触碰 InputGuard 租约、应用限制、系统限制或教师电脑保存的网站名单。离线电脑不会自动收到延迟写入，教师恢复连接后可重新执行。

### 管理后台

- 增加顶栏页面搜索，可用按钮或 `Ctrl/⌘+K` 打开、筛选、方向键选择和回车跳转。搜索结果按账号角色过滤，不能导航到该账号看不到的管理页面。
- 接通已有的手机侧栏样式，增加可见的菜单按钮与关闭遮罩，避免窄屏看不到管理导航。
- 首页突出新增校区、匿名使用、趋势、服务检查和有权限的下载管理入口；连接和角色说明使用普通中文。
- 页面渲染与数据读取保持分开，页面导航搜索新建为独立模块。没有改 CloudBase 认证、数据库表、行级权限、API 或部署环境。

## 手机看 Veyon 学生屏幕

该能力在当前代码中已经实现。手机 PWA 底部的“画面”页打开“学生屏幕”，可开始查看全部座位，也可打开单台实时画面。TeacherConsole 在教师电脑上运行经过认证的 Veyon `Screenshot` 单帧采集，缩放为短时 JPEG，再通过现有配对 HTTPS 返回手机。手机只提交活动课堂目标 ID，教师机重新核对座位和设备绑定；响应禁止缓存，切页、课堂变化、停止或撤销配对时会撤销巡视租约。

详细的文件清理、限流、并发和缓存约束见[手机屏幕巡视设计](../specs/classroom-screen-preview/design.md)与[API 契约](../specs/classroom-screen-preview/api.md)。代码实现不能代替现场验证：该专项第 9 项仍未完成，需在 Windows + Veyon、Android/iOS 浏览器和真实校园 LAN 检查清晰度、后台/前台切换、断线取消及多座位 CPU/内存/带宽。

## 结构简化方向

| 观察到的结构 | 风险 | 后续按边界拆分的顺序 |
| --- | --- | --- |
| `TeacherViewModel.cs` 约 13,000 行 | 页面状态、操作编排和多种领域功能都聚在一个文件，日常改动难以判断影响面 | 继续让 `TeacherClassroomQuickControlService` 等领域服务拥有业务动作；优先把课堂巡视/策略、设备健康、更新分别提取到功能 ViewModel 或 presenter，再减小主 ViewModel。每一步保持已有接口和 UI 绑定，不做一次性重写。 |
| `TeacherMobileControlServer.cs` 约 4,200 行 | 同一个 HTTP 服务承载认证、中间件、课堂/策略/更新/巡视路由、租约和审计 | 先按 API 领域拆路由处理器（课堂、设备策略、屏幕巡视、更新），共享认证、目标绑定、审计与租约生命周期留在服务层；保留同源 HTTPS 和现有端口。 |
| `cloud-admin.js` 约 970 行 | 管理页面、共享状态和事件绑定集中在单个入口 | 页面导航已经提取；下一步按概览、校区、数据、发布拆 renderer，再把 API 逻辑留在 `admin-data.js`。保持每页数据来源和角色过滤显式。 |
| Mobile PWA `app.js` 约 3,200 行 | 手机功能已经按区域组织，但事件和渲染仍在一个脚本 | 以课堂、策略、屏幕巡视为界分模块；共用认证、课堂绑定和轮询生命周期留在小型公共层，避免各模块复制计时器或状态。 |
| CloudBase SDK 管理 chunk 较大 | 网站构建出现超过 500 KB 的 Vite chunk 提示；公开站点已动态加载管理模块 | 先按使用情况拆 SDK 依赖或进一步延后加载管理资源，再检查生产网络加载，不单为消除提示引入难维护的分包规则。 |

这些方向是增量计划，不意味着本次已拆分上述大型模块。Student Agent、InputGuard、Companion 和 Worker 目前已有各自进程/协议边界，继续保留。
