# 学生电脑应用程序限制设计

状态（2026-10-08）：Teacher/StudentSetup 当前源码支持配置包 schema v1–v6；Teacher 生成 v2–v6，Node、ASP.NET 对照契约、OpenAPI 和迁移源码支持 v3–v6。v6 在 v5 信任载荷上增加首次部署建议，不改变应用策略签名流程。学生 SYSTEM Agent、网站/应用/长期系统策略签名推送、状态读取、到期与撤销已接通。应用 Deny 规则编译器现同时保留 Windows 登录/外壳/设置/维护/安全与恢复组件名称；Publisher 与文件哈希规则都经过同一保护校验，当前及候选 Veyon/Agent/更新器仍由动态 AppLocker 文件哈希清单保护。应用和系统策略预检递归展开本机嵌套组成员关系；AppIDSvc 仅在环境、身份、嵌套组、软件放行目录 ACL 预检及 Pending 状态保存后、紧邻 AppLocker 写入时启动。当前本地 .NET 检查 53/53、Node/API 合约 21/21、v6 一次性 PostgreSQL 迁移检查通过；TeacherConsole 与 StudentSetup Release 构建均为 0 警告、0 错误。公开 GitHub/Gitee 发布和 GitHub 受保护 Environment secret + 离线加密备份的私钥保管方式已确认，密钥/凭据设置和许可审查仍未完成。CloudBase 与线上 E2E 的当前状态以[任务主表 P13-05](开发路线与任务清单.md)和[2026-10-08 续作记录](records/2026-10/续作核查记录-20261008.md)为准。Windows AppLocker/桌面策略、浏览器和校园网手机效果仍待 Windows 实机验收。

本文件保留实现细节；规范化的需求、组件设计和细分任务见[应用限制专项规格](../specs/application-policy/requirements.md)。项目级 P13 状态仍以[开发路线与任务清单](开发路线与任务清单.md)为准。

## 目标

教师按校区和学生账户设置应用阻止规则；学生部署工具从可信配置包读取规则，Windows 在启动应用时执行限制。教师离线或网络中断时，已经安装的规则继续有效，并能按设定时间恢复原值或由教师撤销。限制不结束已运行程序。

应用限制用于课堂秩序管理。它不代替杀毒软件、Windows 安全基线或设备管理平台，也不声称可以抵御拥有本机管理员权限的用户。

## 首版交互范围

- Teacher UI 可从所选学生电脑读取已登记桌面程序，按名称、发布者、文件名、路径和电脑搜索并多选，自动生成发布者精确版本规则或文件哈希规则；仍可手工输入规则。每台最多检查 400 个注册 EXE 候选并返回 200 项，未覆盖便携或未登记程序。成功的局域网回执已由固定的 Agent 身份密钥签名，并绑定本次请求；首次信任或身份变化仍需教师核对。发布前还须人工核对目标机的文件路径和签名者。
- 课堂应用规则仍采用“明确阻止少数应用”。学生系统软件限制开启时，则同时启用长期执行 allowlist：学生可从受信任 Windows/Program Files 路径启动程序，学生可写目录和可移动盘上的 PE 程序默认拒绝；管理员、SYSTEM 和其他已启用本地账户保留不受该 allowlist 限制的启动能力。
- 无长期软件限制时，课堂审核使用真实 AppLocker AuditOnly 事件。长期执行 allowlist 启用时，EXE 集合必须保持 Enabled，课堂审核改用已登记程序清单进行影响模拟，不切换整套集合到 AuditOnly。模拟不代表启动历史，也不覆盖未登记/便携程序；教师需核对模拟结果后，才可发布课堂执行规则。
- 发布者和哈希 Deny 规则共用受保护文件名校验，拒绝指向 Windows 登录/外壳/设置/维护/安全/恢复组件；当前交付的 Veyon、Student Agent、Teacher、Worker 与 UpdateHelper 还由运行时 AppLocker 哈希清单保护。此保护减少课堂规则误伤，不能代替 Windows 目标版本、外部策略冲突和更新恢复实测。
- 执行模式只阻止后续新启动。默认不强制结束已经打开的应用，避免学生正在编辑的文件丢失；Teacher 要先对相同规则和目标成功推送审核策略、读回同一版本后，才可勾选执行确认。
- 规则默认只作用于学生账户 SID，不影响教师、本机管理员、Veyon、VeyonCampus Agent、Windows 登录和恢复工具。
- 学生目标必须是规范账户 SID，且 RID 不低于 1000；内置 Administrator 的 RID 500 会在策略编译、运行时入口和持久状态校验中被拒绝。非学生例外 SID 单独从启用的本机账户清单读取，格式校验允许 RID 500，以免长期 allowlist 锁住管理员。该校验保护账户范围输入，不替代 Windows 上的账户枚举与策略效果验收。

## 规则身份

1. 首选签名发布者、产品名称和应用名称，可按版本设置最低/最高范围；应用更新后在允许范围内继续匹配。
2. 无签名应用使用文件 SHA-256，更新后需教师重新核验并发布新版本。
3. 安装路径只作为受控目录的补充条件；学生可写目录中的路径不能单独作为 allow 依据。
4. 不以进程显示名作为安全标识，也不通过隐藏窗口、改进程名或循环结束进程实现限制。
5. 规则需展示安装位置和签名者，教师可在发布前确认选中的是目标软件。

## Windows 执行方案

### 明确阻止规则的必要基线

课堂“只阻止选中的应用”会在没有长期软件限制时生成 Everyone `*` Allow，再把具体 Deny 限定到教师选定的学生 SID。打开长期软件限制时，单一 AppLocker composer 改为生成 Enabled EXE 集合：允许 `%WINDIR%\System32`、`SysWOW64`、`Microsoft.NET`、`SystemApps`、`WinSxS`、Windows Explorer 和 `%PROGRAMFILES%`；另加对学生 SID 的 `%WINDIR%\Temp\*` 拒绝，避免 Windows 临时目录中的可写 PE 文件借宽路径启动。SYSTEM、管理员组和 Agent 读取到的其他启用本地账户有独立 Allow `*`。`%PROGRAMFILES%` 是 AppLocker 路径变量，覆盖 Program Files 与 x86 Program Files。启用长期限制前，Agent 会递归检查这些允许目录的目录和文件 ACL，合并学生直接/本地嵌套组及常见交互用户 SID；目录或文件由学生拥有、可由学生写入、存在重解析点、ACL 读取失败或审查超过两分钟时，策略在 Windows 写入前失败关闭。工具不自动修改系统 ACL；管理员需先修复不安全目录。参见 [AppLocker 路径条件](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/applocker/understanding-the-path-rule-condition-in-applocker)。

课堂 Enforce Deny 与上述长期 Allowlist 合并进同一 EXE 集合；课堂 Audit 文档保存在策略状态中，但不下发到已强制执行的集合。Appx 集合继续允许所有已签名包。EXE 集合匹配 PE 程序，不只看 `.exe` 后缀；AppLocker MSI 和 Script 集合保持未配置。MSI 安装改由 Windows Installer 的 `DisableMSI=1`、`DisableUserInstalls=1` 与 Appx 用户安装限制处理；`RemoveWindowsStore=1` 只写入目标学生的用户配置，不整机禁用教师管理员的 Store。微软说明 `DisableMSI=2` 会禁用所有 Windows Installer 安装，而 `DisableMSI=1` 保留受管理部署等维护路径；Store 策略亦支持按用户范围限制。参见 [DisableMSI](https://learn.microsoft.com/en-us/windows/win32/msi/disablemsi)、[Windows Store Policy CSP](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-windowsstore)。

AppLocker 的可执行文件集合实际匹配 PE 可执行文件，不完全等同于 `.exe` 扩展名。此限制通过系统策略与课堂规则组合，不代表强防篡改白名单，也不限制脚本、MSI 规则集合或所有浏览器网站访问。Windows Installer/Appx 安装入口是独立的系统策略。当前网站策略管理 Microsoft Edge、Google Chrome 和 Firefox：Edge 与 Chrome 的 URL-list filter 用裸域名匹配根域名和子域名，Firefox 用 `*://*.domain/*` match pattern；便携浏览器、其他浏览器和全设备 DNS/网络过滤不在当前实现范围。详见[网站访问限制设计](网站访问限制设计.md)。

### 六项长期系统策略与双端更新边界

六项策略均已实现为独立签名、长期有效的学生机基线，默认值如下；代码检查已完成，实际 Windows UI/权限效果仍需实机验收。

| 学生机策略 | 默认值 | 实施与验收约束 |
| --- | --- | --- |
| 锁定桌面壁纸 | ON | Student Agent 携带 SHA-256 固定的统一 JPEG，验证后安装到 ProgramData 内容寻址路径并设置只读 ACL；实际 Windows 10/11 显示、裁切与策略读回应在现场验收，公开分发许可归 P9-02 |
| 禁止修改系统时间 | ON | 对学生 SID 精确移除修改日期/时间和时区两项 LSA 权限；不改系统同步服务账户权限 |
| 禁止修改网络设置 | ON | 限制网络属性、组件、高级 TCP/IP 和新连接入口；拒绝网络配置操作组中的学生账户，保留 Agent/Veyon 联网 |
| 禁止安装软件 | ON | 学生 hive 隐藏 Store；系统 MSI/Appx 策略保留管理员维护路径；AppLocker 单一 EXE allowlist 拦截学生可写目录和可移动盘上的 PE 程序，并与课堂 Deny 合并 |
| 禁止修改用户账户 | ON | 学生账户保持本地标准账户；禁止本人改登录密码，学生不能借管理员/账户操作组管理本机账户；教师管理员保留维护/重置能力 |
| 禁止访问控制面板 | OFF | 允许打开 Control Panel/Settings；OFF 恢复本工具拥有的禁止值，不覆盖学校外部策略 |

系统策略与课堂限时策略分开签名、保存和到期，但 EXE/Appx XML 由一个 AppLocker owner 维护。跨系统注册表和 AppLocker 的操作使用持久 pending 日志；中断时 Agent 重试目标状态，不能把部分写入报告为完成。每项系统值和 AppLocker XML 都保存原值与工具值，恢复前核对所有权；遇到外部变更停止覆盖并报告冲突。普通账户是权限边界，不能靠隐藏设置页面证明限制有效。

TeacherConsole、StudentSetup、Agent 和 UpdateHelper 必须保留更新能力。系统策略不得禁用 SYSTEM 安装与服务维护、教师管理员修复、开发者签名清单校验或更新恢复目录。应用规则发布前对当前及候选新版的更新、Veyon 和修复组件进行命中检查；拒绝会阻断这些组件的 Deny。不能用学生可写的路径放行更新。候选版本缺少必需策略能力时，在安装前明确拒绝；失败回滚保留校区信任、公钥、策略版本和原值备份，不重置防重放计数。两个角色均须验证在线和离线更新，并覆盖已开启上述策略时的安装、恢复和重启。

协议升级顺序是先发布兼容新策略的双端程序，再允许教师发布新策略；旧学生客户端必须报告不支持，不能显示已应用。生产 Developer Release 公钥必须嵌入起始安装包；未嵌入公钥的旧客户端需要管理员手动安装可信版本完成引导，不能通过未验证的在线下载补信任。

实机验收仍须按目标机房 Windows 版本和补丁测试 AppLocker 规则命中、完整 PE 启动、用户范围、系统程序兼容、策略合并、离线恢复和卸载。AppLocker 属于较轻量的应用控制和纵深防御能力；若需求升级为强防篡改白名单，再评估 App Control for Business（WDAC）及其策略签名/补充策略能力。

Microsoft 当前文档说明，Windows 10 2004 及以后版本（安装 KB5024351 或更新补丁）和所有 Windows 11 版本均可在所有版本 SKU 上执行 AppLocker 策略。Windows 10 Build 19044 本身不足以确定支持生命周期：它可能是普通 Windows 10 21H2，也可能是 LTSC 2021；普通 21H2 Enterprise/Education 已于 2024 年停止更新，而 Enterprise LTSC 2021 仍有不同的生命周期。因此必须核对实际 SKU、EditionID、servicing channel、完整 build/UBR、补丁及 ESU 状态，不能只凭 build number 把设备列为受支持。参见 [Windows 10 21H2 servicing 状态](https://learn.microsoft.com/en-us/windows/release-health/status-windows-10-21h2) 和 [Windows 客户端支持版本](https://learn.microsoft.com/en-us/windows/release-health/supported-versions-windows-client)。

执行前还必须核对 Application Identity (`AppIDSvc`) 服务状态，并盘点已有本机策略、组策略和设备管理策略。运行时先检查域加入、MDM 登记、学生账户是否为启用的本地标准账户以及是否属于 Administrators，全部通过后才启动 `AppIDSvc`；拒绝的设备不会仅因预检而启动该服务。只读采集器会汇总 `Get-AppLockerPolicy -Effective` 返回的本机与组策略集合，但此 cmdlet 不读取 AppLocker CSP/MDM 策略；所以未读到组策略规则不能证明 MDM 没有配置。MDM 登记状态需由现场负责人确认后写入采集摘要，不采集租户、设备或账户标识。AppLocker CSP 是设备范围；本工具不能借此假定能够按学生 SID 做用户范围控制，而且策略应用或删除可能要求重启。发现学校 MDM 策略或作用范围无法确认时，应停止原型修改并请管理员复核，不覆盖管理端策略。参见 [AppLocker CSP](https://learn.microsoft.com/en-us/windows/client-management/mdm/applocker-csp) 和 [Get-AppLockerPolicy](https://learn.microsoft.com/en-us/powershell/module/applocker/get-applockerpolicy)、[Get-AppLockerFileInformation](https://learn.microsoft.com/en-us/powershell/module/applocker/get-applockerfileinformation)。

没有长期软件限制时按 AppLocker AuditOnly 观察启动日志；长期 allowlist 已开启时，审核查询明确显示为登记程序影响模拟，不能伪称已观测真实启动。两条流程均要求教师核对结果并确认，执行策略只阻止后续启动，不结束已运行程序。

## 配置包与云端接口

- StudentSetup/Teacher 当前代码支持 schema v1–v6 读取和 v2–v6 生成；Node `veyon-api`、ASP.NET 发布 API、OpenAPI 与 SQL 迁移源码支持 v3/v4/v5/v6。v5 包包括独立应用及系统策略公钥；v6 沿用该信任载荷并增加严格的首次部署建议字段。包内不放教师私钥或课堂规则。课堂规则使用 RSA-PSS 签名信封、固定 JSON、限大小/规则数、校区绑定、递增版本与最多 24 小时有效期。共享环境与线上合成 E2E 当前状态以[项目任务主表 P13-05](开发路线与任务清单.md)为准。
- 为应用策略使用独立签名用途/密钥，避免网站策略公钥被复用到不同控制域。学生安装后只信任首次受验证的校区公钥；策略更新必须验签、核对校区 ID、版本递增和过期时间。
- Teacher UI 生成并签名策略；学生 v5/v6 包在本机校验兼容范围、独立应用/系统公钥、完整清单文件 SHA-256 和规范 ZIP 集合。Teacher 审核事件、应用清单与策略状态回执使用 SYSTEM Agent 的设备身份密钥签名，并绑定当前请求；教师端固定目标密钥后才报告已验证，首次信任或轮换需人工确认，Windows 端命中效果仍待实机核对。
- 发布端需同时更新教师生成器、`PackageManifest`、学生解析和快照、云端 ZIP 校验、目录 schema 支持、学生 Agent、OpenAPI 文档及迁移。v3 包继续可读可用。

## 安全、恢复与验收

- 策略包包含策略版本、校区 ID、目标学生账户 SID、审核/执行模式、规则数、创建时间、开始时间、结束时间、签名和内容摘要。
- 过期/撤销需要有本机恢复流程。教师网络离线时不能依赖在线心跳来解除本机策略。
- 发布前先生成设备现有应用清单；确认设备长期 allowlist 状态，再区分真实启动日志与安装清单模拟。Windows 系统、登录、更新、Veyon、远程修复、安全软件和本工具自身始终要纳入回归。
- 单机测试覆盖已签名/无签名应用、应用升级、学生/管理员账户、规则冲突、策略损坏、过期、续期、断网、重启、卸载和恢复；确认策略不会导致无法登录或失去远程修复能力。
- 小范围机房试点观察一周后再扩大。每次发布记录策略摘要、目标设备、结果和回滚状态，不上传应用使用内容或学生文件。

## 0.4.55 教师端简化入口

默认按“核对身份 → 读取并选择学生账户 → 读取并勾选软件 → 检查影响 → 禁用”操作。账户清单只在学生机本地读取，经校区签名请求和已固定 Agent 签名回执返回，不上传云端；排除禁用、内置、域账户及通过嵌套组获得管理员/账户或网络操作员权限的账户。教师仍需勾选实际上课账户，不能把所有普通账户自动认作学生。新增只读 /v1/student-accounts 需要 Agent 0.4.43；旧 Agent 不支持时提示更新学生包，高级 SID 入口仍保留。原应用清单响应不输出空的新字段，旧教师读取新 Agent 的原清单保持原格式。

勾选自动生成现有精确发布者/哈希规则，不采用名称或通配符直接拦截。每台目标使用自己的 SID 独立签发同一轮版本，避免同名账户被当成同一 SID。取消勾选并重新通过审核后应用，会用新的课堂清单替换旧清单；列表展示库存和本次选择，不声称已读取当前禁用状态。恢复按钮撤销全部课堂应用限制，长期软件安装策略及学校管理策略仍需分别解除。

改变软件、账户、校区或目标会使审核回执失效。自动账户模式的手机应用/系统预设暂要求单台目标，避免将设备 SID 绑定丢失；批量手机预设的设备账户映射尚未实现。现场步骤见[第三轮修复记录](records/2026-10/实机问题第三轮修复-20261008.md)。
