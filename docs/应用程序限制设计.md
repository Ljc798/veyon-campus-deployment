# 学生电脑应用程序限制设计

状态：方案，尚未实现。本文是网站策略之外的下一阶段设计依据。

## 目标

教师按校区和学生账户设置允许/禁止运行的应用规则；学生部署工具从可信配置包读取规则，Windows 在启动应用时执行限制。教师离线或网络中断时，已经安装的规则继续有效，并能按设定时间结束或由教师撤销。

应用限制用于课堂秩序管理。它不代替杀毒软件、Windows 安全基线或设备管理平台，也不声称可以抵御拥有本机管理员权限的用户。

## 首版交互范围

- 教师能搜索并添加应用、查看规则条件、选择阻止或允许、选择作用账户、设置有效期、预览影响并发布。
- 首版从“明确阻止少数应用”开始，默认不使用整机默认拒绝。Allowlist/默认拒绝要等完成设备软件清单、Windows 关键程序白名单和恢复演练后再启用。
- 设置默认先进入审核模式：Windows 记录将被阻止的启动，学生电脑不立即拦截。教师核对事件清单后，才发布执行模式。
- 执行模式只阻止后续新启动。默认不强制结束已经打开的应用，避免学生正在编辑的文件丢失；教师可在发布说明中选择“需重启应用后生效”。
- 规则默认只作用于学生账户 SID，不影响教师、本机管理员、Veyon、VeyonCampus Agent、Windows 登录和恢复工具。

## 规则身份

1. 首选签名发布者、产品名称和应用名称，可按版本设置最低/最高范围；应用更新后在允许范围内继续匹配。
2. 无签名应用使用文件 SHA-256，更新后需教师重新核验并发布新版本。
3. 安装路径只作为受控目录的补充条件；学生可写目录中的路径不能单独作为 allow 依据。
4. 不以进程显示名作为安全标识，也不通过隐藏窗口、改进程名或循环结束进程实现限制。
5. 规则需展示安装位置和签名者，教师可在发布前确认选中的是目标软件。

## Windows 执行方案

实现时先按目标机房的 Windows 版本和补丁实测 AppLocker 与 App Control for Business。AppLocker 可基于文件属性、签名、产品、名称和版本制定规则，并提供审核模式；它适合较轻量的应用控制，但 Microsoft 将它定位为纵深防御能力。需要强应用控制时，应评估 App Control for Business（WDAC）及其策略签名/补充策略能力。

Microsoft 当前文档说明，Windows 10 2004 及以后版本（安装 KB5024351 或更新补丁）和所有 Windows 11 版本均可在所有版本 SKU 上执行 AppLocker 策略。Windows 10 Build 19044 本身不足以确定支持生命周期：它可能是普通 Windows 10 21H2，也可能是 LTSC 2021；普通 21H2 Enterprise/Education 已于 2024 年停止更新，而 Enterprise LTSC 2021 仍有不同的生命周期。因此必须核对实际 SKU、EditionID、servicing channel、完整 build/UBR、补丁及 ESU 状态，不能只凭 build number 把设备列为受支持。参见 [Windows 10 21H2 servicing 状态](https://learn.microsoft.com/en-us/windows/release-health/status-windows-10-21h2) 和 [Windows 客户端支持版本](https://learn.microsoft.com/en-us/windows/release-health/supported-versions-windows-client)。

执行前还必须核对 Application Identity (`AppIDSvc`) 服务状态，并盘点已有本机策略、组策略和设备管理策略。只读采集器会汇总 `Get-AppLockerPolicy -Effective` 返回的本机与组策略集合，但此 cmdlet 不读取 AppLocker CSP/MDM 策略；所以未读到组策略规则不能证明 MDM 没有配置。MDM 登记状态需由现场负责人确认后写入采集摘要，不采集租户、设备或账户标识。AppLocker CSP 是设备范围；本工具不能借此假定能够按学生 SID 做用户范围控制，而且策略应用或删除可能要求重启。发现学校 MDM 策略或作用范围无法确认时，应停止原型修改并请管理员复核，不覆盖管理端策略。参见 [AppLocker CSP](https://learn.microsoft.com/en-us/windows/client-management/mdm/applocker-csp) 和 [Get-AppLockerPolicy](https://learn.microsoft.com/en-us/powershell/module/applocker/get-applockerpolicy)。

当前路线建议先做 AppLocker 审核与明确阻止规则原型，在 Windows 10 Build 19044 和实际 Windows 11 设备上确认服务、学生账户作用域、策略合并、日志读回、恢复和卸载。先以 Audit only 观察，再由教师确认规则影响后启用阻止；Microsoft 指出审核日志可用于发现规则会影响的程序。只有需求升级为强防篡改控制时，再采用 App Control for Business（WDAC）；不要把两种机制同时写入首版。

## 配置包与云端接口

- 当前学生配置包和上传接口严格接受 `schemaVersion=3`。应用限制需要新协议版本，建议 `schemaVersion=4`，不要在 v3 文件中偷偷追加必需字段。
- v4 清单新增独立的 `applicationPolicy` 摘要、版本、有效期和签名信息；规则内容采用固定 JSON 结构、限大小与规则数、校验重复 ID、文件哈希、签名条件和过期时间。
- 为应用策略使用独立签名用途/密钥，避免网站策略公钥被复用到不同控制域。学生安装后只信任首次受验证的校区公钥；策略更新必须验签、核对校区 ID、版本递增和过期时间。
- Teacher UI 生成并签名策略；配置包 API 校验协议和签名元数据；私有对象桶保存经验证的包；Student 搜索/下载后仍需在本机再次验证清单、签名和内容摘要。
- 发布端需同时更新教师生成器、`PackageManifest`、学生解析和快照、云端 ZIP 校验、目录 schema 支持、学生 Agent、OpenAPI 文档及迁移。v3 包继续可读可用。

## 安全、恢复与验收

- 策略包包含策略版本、校区 ID、目标学生账户 SID、审核/执行模式、规则数、创建时间、开始时间、结束时间、签名和内容摘要。
- 过期/撤销需要有本机恢复流程。教师网络离线时不能依赖在线心跳来解除本机策略。
- 发布前先生成设备现有应用清单，在审核模式观察真实启动日志；Windows 系统、登录、更新、Veyon、远程修复、安全软件和本工具自身始终要纳入回归。
- 单机测试覆盖已签名/无签名应用、应用升级、学生/管理员账户、规则冲突、策略损坏、过期、续期、断网、重启、卸载和恢复；确认策略不会导致无法登录或失去远程修复能力。
- 小范围机房试点观察一周后再扩大。每次发布记录策略摘要、目标设备、结果和回滚状态，不上传应用使用内容或学生文件。

## 依赖和顺序

先完成 `veyon-api` 首次部署以及教师上传、学生搜索/下载验收；之后再升级配置包协议。应用限制不可被旧 API、旧 v3 学生端或教师网站页面静默忽略。
