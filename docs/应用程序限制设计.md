# 学生电脑应用程序限制设计

状态：教师端、schema v4 信任包、Node 与 ASP.NET v3/v4 发布契约、学生 SYSTEM Agent、签名推送、审核读取、到期与撤销已接通；数据库迁移 `20261005100000` 已应用。解决方案构建 0 警告/错误，48 项核心检查和 13 项 Node 合约测试通过。CloudBase 函数尚未部署，AppLocker 适配器和局域网链路尚无 Windows 实机验收，因此还不能对真实机房宣称可用。

## 目标

教师按校区和学生账户设置应用阻止规则；学生部署工具从可信配置包读取规则，Windows 在启动应用时执行限制。教师离线或网络中断时，已经安装的规则继续有效，并能按设定时间恢复原值或由教师撤销。限制不结束已运行程序。

应用限制用于课堂秩序管理。它不代替杀毒软件、Windows 安全基线或设备管理平台，也不声称可以抵御拥有本机管理员权限的用户。

## 首版交互范围

- Teacher UI 可从所选学生电脑读取已登记桌面程序，按名称、发布者、文件名、路径和电脑搜索并多选，自动生成发布者精确版本规则或文件哈希规则；仍可手工输入规则。每台最多检查 400 个注册 EXE 候选并返回 200 项，不覆盖便携或未登记程序。局域网回执未签名，教师须核对目标机的文件路径和签名者；实际命中需先推送审核模式。
- 首版从“明确阻止少数应用”开始，默认不使用整机默认拒绝。Allowlist/默认拒绝要等完成设备软件清单、Windows 关键程序白名单和恢复演练后再启用。
- 设置默认先进入审核模式：Windows 记录将被阻止的启动，学生电脑不立即拦截。教师核对事件清单后，才发布执行模式。
- 执行模式只阻止后续新启动。默认不强制结束已经打开的应用，避免学生正在编辑的文件丢失；Teacher 要先对相同规则和目标成功推送审核策略、读回同一版本后，才可勾选执行确认。
- 规则默认只作用于学生账户 SID，不影响教师、本机管理员、Veyon、VeyonCampus Agent、Windows 登录和恢复工具。

## 规则身份

1. 首选签名发布者、产品名称和应用名称，可按版本设置最低/最高范围；应用更新后在允许范围内继续匹配。
2. 无签名应用使用文件 SHA-256，更新后需教师重新核验并发布新版本。
3. 安装路径只作为受控目录的补充条件；学生可写目录中的路径不能单独作为 allow 依据。
4. 不以进程显示名作为安全标识，也不通过隐藏窗口、改进程名或循环结束进程实现限制。
5. 规则需展示安装位置和签名者，教师可在发布前确认选中的是目标软件。

## Windows 执行方案

### 明确阻止规则的必要基线

首版的“只阻止选中的应用”必须显式生成对应规则集合的放行基线：AppLocker 的集合一旦有规则，未匹配允许规则的文件会被隐式拒绝；不能只写几条 Deny 就认为其他程序仍能启动。原型使用可执行文件集合，加入 Everyone 的 `*` Allow，然后将具体 Deny 限定到已确认的学生 SID；不启用 DLL、脚本或 MSI 集合。AppLocker 在可执行文件集合执行时会连带阻断打包应用，因此还会加入 Appx 集合的 Everyone “允许全部已签名包”默认规则，保持此首版不控制打包应用。宽泛 Allow 只服务于显式黑名单模式，不作为未来白名单的安全基线。Deny 优先于 Allow，因此系统及修复组件不能靠额外 Allow 来抵消误加的 Deny；发布前必须拒绝命中这些组件的规则。参见 [AppLocker 规则行为](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/applocker/understanding-applocker-rule-behavior)、[规则集合与默认规则](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/applocker/working-with-applocker-rules) 和 [打包应用管理](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/applocker/manage-packaged-apps-with-applocker)。

AppLocker 的可执行文件集合实际匹配 PE 可执行文件，不完全等同于 `.exe` 扩展名。此限制不等于禁止安装所有软件，也不能阻止其他浏览器的所有网站访问；脚本、MSI 与网站不由此首版控制。教师预览会说明未扫描安装清单和实际命中数量需先审核。安装限制需要独立设计和 Windows 验收。

### 后续学生机系统策略与更新边界

目标默认值如下；这些是后续要求，当前没有实现或实机验收。

| 学生机策略 | 默认值 | 实施与验收约束 |
| --- | --- | --- |
| 锁定桌面壁纸 | ON | 针对学生 SID 设置壁纸与禁止更改策略；离线用户配置单独处理，记录原值及归属 |
| 禁止修改系统时间 | ON | 学生使用普通账户，核对时间与时区两项权限；保留系统时间同步及服务账户权限 |
| 禁止修改网络设置 | ON | 核对普通账户及网络配置操作组成员；覆盖设置、控制面板及命令行修改入口，保留 Agent/Veyon 联网 |
| 禁止安装软件 | ON | 同时评估机器安装、用户安装、MSI、EXE、Store 与便携程序；仅禁止 MSI 或要求 UAC 不能证明本项完成 |
| 禁止修改用户账户 | ON | 覆盖创建/删除账户、组成员及学生密码变更的具体范围；教师管理员和恢复账户保留可用 |
| 禁止访问控制面板 | OFF | 允许打开控制面板；各受限制设置仍应拒绝修改。OFF 表示撤销本工具拥有的禁止值，不覆盖学校外部策略 |

系统策略与课堂限时策略分开保存、分开签名和撤销，不能因为课堂策略到期就撤销长期基线。每项策略保留部署前原值、工具写入值与目标 SID，恢复前核对仍为工具拥有；遇到外部变更停止覆盖并报告冲突。普通账户是权限边界，不能靠隐藏设置页面证明限制有效。

TeacherConsole、StudentSetup、Agent 和 UpdateHelper 必须保留更新能力。系统策略不得禁用 SYSTEM 安装与服务维护、教师管理员修复、开发者签名清单校验或更新恢复目录。应用规则发布前对当前及候选新版的更新、Veyon 和修复组件进行命中检查；拒绝会阻断这些组件的 Deny。不能用学生可写的路径放行更新。候选版本缺少必需策略能力时，在安装前明确拒绝；失败回滚保留校区信任、公钥、策略版本和原值备份，不重置防重放计数。两个角色均须验证在线和离线更新，并覆盖已开启上述策略时的安装、恢复和重启。

协议升级顺序是先发布兼容新策略的双端程序，再允许教师发布新策略；旧学生客户端必须报告不支持，不能显示已应用。生产 Developer Release 公钥必须嵌入起始安装包；未嵌入公钥的旧客户端需要管理员手动安装可信版本完成引导，不能通过未验证的在线下载补信任。

实现时先按目标机房的 Windows 版本和补丁实测 AppLocker 与 App Control for Business。AppLocker 可基于文件属性、签名、产品、名称和版本制定规则，并提供审核模式；它适合较轻量的应用控制，但 Microsoft 将它定位为纵深防御能力。需要强应用控制时，应评估 App Control for Business（WDAC）及其策略签名/补充策略能力。

Microsoft 当前文档说明，Windows 10 2004 及以后版本（安装 KB5024351 或更新补丁）和所有 Windows 11 版本均可在所有版本 SKU 上执行 AppLocker 策略。Windows 10 Build 19044 本身不足以确定支持生命周期：它可能是普通 Windows 10 21H2，也可能是 LTSC 2021；普通 21H2 Enterprise/Education 已于 2024 年停止更新，而 Enterprise LTSC 2021 仍有不同的生命周期。因此必须核对实际 SKU、EditionID、servicing channel、完整 build/UBR、补丁及 ESU 状态，不能只凭 build number 把设备列为受支持。参见 [Windows 10 21H2 servicing 状态](https://learn.microsoft.com/en-us/windows/release-health/status-windows-10-21h2) 和 [Windows 客户端支持版本](https://learn.microsoft.com/en-us/windows/release-health/supported-versions-windows-client)。

执行前还必须核对 Application Identity (`AppIDSvc`) 服务状态，并盘点已有本机策略、组策略和设备管理策略。只读采集器会汇总 `Get-AppLockerPolicy -Effective` 返回的本机与组策略集合，但此 cmdlet 不读取 AppLocker CSP/MDM 策略；所以未读到组策略规则不能证明 MDM 没有配置。MDM 登记状态需由现场负责人确认后写入采集摘要，不采集租户、设备或账户标识。AppLocker CSP 是设备范围；本工具不能借此假定能够按学生 SID 做用户范围控制，而且策略应用或删除可能要求重启。发现学校 MDM 策略或作用范围无法确认时，应停止原型修改并请管理员复核，不覆盖管理端策略。参见 [AppLocker CSP](https://learn.microsoft.com/en-us/windows/client-management/mdm/applocker-csp) 和 [Get-AppLockerPolicy](https://learn.microsoft.com/en-us/powershell/module/applocker/get-applockerpolicy)、[Get-AppLockerFileInformation](https://learn.microsoft.com/en-us/powershell/module/applocker/get-applockerfileinformation)。

当前路线建议先做 AppLocker 审核与明确阻止规则原型，在 Windows 10 Build 19044 和实际 Windows 11 设备上确认服务、学生账户作用域、策略合并、日志读回、恢复和卸载。先以 Audit only 观察，再由教师确认规则影响后启用阻止；Microsoft 指出审核日志可用于发现规则会影响的程序。只有需求升级为强防篡改控制时，再采用 App Control for Business（WDAC）；不要把两种机制同时写入首版。

## 配置包与云端接口

- StudentSetup/Teacher 代码已支持 schema v4；CloudBase PostgreSQL 迁移已允许 v3/v4。Node `veyon-api` 与 ASP.NET 发布 API 都按版本生成对象键并传递 RPC 版本号，OpenAPI 与合约测试支持两版；Node 在线函数尚未部署。v4 清单新增独立 `applicationPolicyPublicKey`，不把教师私钥或课堂规则装入包。课堂规则使用单独 RSA-PSS 签名信封、固定 JSON、限大小/规则数、校区绑定、递增版本与最多 24 小时有效期。
- 为应用策略使用独立签名用途/密钥，避免网站策略公钥被复用到不同控制域。学生安装后只信任首次受验证的校区公钥；策略更新必须验签、核对校区 ID、版本递增和过期时间。
- Teacher UI 生成并签名策略；学生 v4 包在本机校验兼容范围、独立应用公钥、完整五文件 SHA-256 清单与规范 ZIP 集合。Teacher 审核读取回执目前是未签名的局域网 HTTP 响应；CloudBase 在线发布仍待部署验收。
- 发布端需同时更新教师生成器、`PackageManifest`、学生解析和快照、云端 ZIP 校验、目录 schema 支持、学生 Agent、OpenAPI 文档及迁移。v3 包继续可读可用。

## 安全、恢复与验收

- 策略包包含策略版本、校区 ID、目标学生账户 SID、审核/执行模式、规则数、创建时间、开始时间、结束时间、签名和内容摘要。
- 过期/撤销需要有本机恢复流程。教师网络离线时不能依赖在线心跳来解除本机策略。
- 发布前先生成设备现有应用清单，在审核模式观察真实启动日志；Windows 系统、登录、更新、Veyon、远程修复、安全软件和本工具自身始终要纳入回归。
- 单机测试覆盖已签名/无签名应用、应用升级、学生/管理员账户、规则冲突、策略损坏、过期、续期、断网、重启、卸载和恢复；确认策略不会导致无法登录或失去远程修复能力。
- 小范围机房试点观察一周后再扩大。每次发布记录策略摘要、目标设备、结果和回滚状态，不上传应用使用内容或学生文件。

## 依赖和顺序

数据库迁移已应用；仍需部署更新后的 `veyon-api`，然后验收教师 v4 发布、学生搜索/下载与本机复验。应用限制不可被旧 API、旧 v3 学生端或教师网站页面静默忽略。
