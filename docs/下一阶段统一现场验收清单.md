## 现场验收顺序

请从单台可恢复测试机开始，快捷管控先扩至 2–5 台，再考虑整间测试教室。性能项目可在 15、24 台进行；60–70 台只在设备和网络允许时开展。下列详细步骤分别见[Phase 2 健康中心](../specs/next-phase/phase-2-runtime-health.md)、[Phase 3 InputGuard](../specs/next-phase/phase-3-inputguard.md)、[Phase 4 快捷管控](../specs/next-phase/phase-4-classroom-quick-control.md)、[Phase 5 软件管控](../specs/next-phase/phase-5-application-policy-ux.md)、[Phase 6 稳定化](../specs/next-phase/phase-6-stabilization-pilot-docs.md)。

### 1. 页面入口、教室和学生姓名

- 安装教师包后，检查常用导航、课堂控制、设备健康、策略与预设、更新与运维，以及“遇到问题？”里的地点/学生名单和首次设置入口。
- 桌面和手机课堂页不应再有旧课堂临时策略入口；课堂互动和快捷管控仍可用，独立“策略与预设”页的数据与操作保留。
- Student Companion 课堂状态只显示地点和电脑数量，不应显示“练习”。新版开始互动不应自动套用网站或应用预设。
- 检查零个、一个和多个教室的页面；单教室不显示多余选择器，多教室可以切换。切换教室后，已开始课堂仍绑定开始时的目标。
- 对已有 Veyon 地点执行读取/同步，核对电脑名称、连接地址和学生姓名关联；新建空地点时，空桌位不应自动编号，填写姓名后新编号应从本机已登记地点的最大编号后续排。切换地点和增删其他桌位都不应重排已有编号。
- 使用 TeacherConsole 1.1.32 检查换座计划与逐台执行结果：只显示学生姓名、座位位置和结果状态，不显示 PC-01 类电脑名或连接地址；没有唯一映射时显示“未填写姓名”。
- 用已填写姓名和未填写姓名的设备检查教师端健康、策略名单、更新进度、策略执行结果、待恢复列表、课堂消息、快捷管控进度、手机设备/聊天/屏幕页面、手机待恢复列表及打印座位表。所有设备标签应显示学生姓名；无姓名或设备别名有映射冲突时显示“未填写姓名”，不回退到 PC 编号或 Veyon 名称，也不把其他学生姓名串到设备上。
- 找两个教室都含有 `PC-01` 的机房档案，并为两台设备配置不同学生姓名。开始其中一间教室的互动，查看聊天和求助显示的姓名；切换教师端当前选中的教室后检查已开始互动仍显示原教室学生姓名。结束互动并检查待恢复列表，确认姓名仍来自原课堂教室；无法唯一关联时显示“未填写姓名”，不显示 `PC-01` 或误用另一间教室的姓名。

### 2. 设备健康与状态刷新

- 检查正常、需关注、离线/未知状态的颜色区分；展开诊断，核对搜索、状态过滤、分页和长名单布局。
- 点击某条设备异常提醒，搜索框应定位到学生姓名；健康列表可按学生姓名、状态和异常原因搜索，不要求输入电脑编号或主机名。
- 在 10–24 台打开设备健康页，首次请求发出时应立即显示所选设备行和“等待读取”数量，不应出现空列表。至少观察 30 秒（覆盖多轮自动刷新），确认名单持续显示；离开或最小化时暂停。Agent 未回执的前两轮应显示待确认，连续 3 次失败后才计入“未收到回执”；Agent 已签名响应但键鼠状态未知应计入“需关注”。手动重新读取同一电脑名单时，已显示设备不应清空；切换教室或设备选择确实变化时，旧请求结果应作废，稳定后新名单应持续显示。
- 在至少一台教师电脑上读取成功后关闭并重新打开教师端：同一校区和名单应先恢复灰色“本地缓存 · 待更新”行，再自动刷新成实时状态。断开 Agent 或网络时，名单仍应保留；缓存行不得显示为在线/正常，启动 Veyon 或同步 Edge 等修复操作必须保持不可用。切换校区时不得显示其他校区同名电脑的缓存。确认缓存文件位于 `%LocalAppData%\VeyonCampus\Teacher\device-health-cache.json`，只含状态摘要，不含密钥或完整诊断，并会在 30 天后过期。
- 制造单机多个异常并观察异常去重、确认、恢复；状态无新签名回执时应保持未知，不能被显示为正常或确定关机。
- 检查逐台设备健康卡片和手机状态页中的 InputGuard 状态颜色与文字：锁定、未锁定、切换中、已退出、未知；旧 Agent 应明确显示未提供该状态，不能推断为已解锁。
- 用 TeacherConsole 1.1.32 / StudentSetup 1.1.32 验证重启识别：只重启学生 Agent 服务不应触发 Windows 重启提醒；在有效锁定租约期间重启学生 Windows 后，应按学生姓名显示“学生电脑已重启”，明确锁定不会自动恢复，也不能自动重锁。教师知悉后提醒应从当前异常列表移除；旧 Agent 缺少 BootId 时不应误报。
- 检查 Windows 时间同步或小幅校时后重复读取：正常校时和 Agent 重启不应触发重启提醒；若出现误报，记录调整时间及前后状态供修正 BootId 生成逻辑。
- 可选在 60–70 台观察 12 路有界并发、排队排空、窗口响应和 CPU/内存趋势。详细的 5 秒轮询、1.5 秒单目标超时、退避和 45 秒过期行为参照 Phase 2 清单记录。

### 3. Agent 上线后自动加入课堂策略

- 准备一台 Agent 在线设备和一台关机或断网设备，开始课堂并启用已保存的网站名单。
- 在线设备应进入执行并显示逐台结果；离线设备显示等待 Agent，而不是显示已关机或误报失败。
- 在课堂仍有效时启动离线设备并等待 Agent 连接。确认系统重新核对设备身份和签名状态后，自动应用当前保存的网站策略，逐台进度从等待更新到执行/结果。
- 在学生浏览器实测名单效果。Agent 回执只证明报告状态，不能代替浏览器访问验证。
- 另做一次离线设备尚未上线就结束课堂：旧策略不得在之后上线时补发。对已应用策略检查恢复；TeacherConsole 退出时现有一小时网站租约是兜底。
- 确认离线键鼠锁定不会在 Agent 后续上线时自动补发。

### 4. 快捷管控与恢复

- 在教师端开始/结束互动，分别取消和确认网站限制、键鼠锁定及解除操作；核对冻结的目标范围和逐台结果。
- 在可恢复设备上验证“网站限制 → 键鼠锁定 → 网站限制”切换。只有上一模式被签名读回确认解除后，下一模式才应执行；冲突、身份变化、未知状态应停止该设备后续步骤。
- 观察锁定期间画面、视频和耳机声音；验证正常解除、20 秒租约到期、Agent/Teacher 断线、Guard 退出、Ctrl+Alt+Del、UAC、锁屏/切换用户及重启后的输入恢复行为。
- 让一台设备断网或使用不支持的 Agent，确认其他目标仍能独立完成；失败/未知设备不得显示成功，离线危险命令不得排队重放。
- 结束课堂后，确认快捷管控只释放本工具持有的策略，不删除长期软件保护或其他管理员策略。
- 对曾有旧版课堂临时策略的可恢复测试机，结束互动时核对安全恢复：只解除本工具仍拥有且版本未变化的旧策略；离线、身份未核实或版本冲突的项目必须留在“待恢复项”，设备上线后再人工重试。不要在无恢复方案的教学机上做此项。

### 5. 长期软件保护

- 从教师端直接开启长期软件运行保护，不先扫描并勾选整台电脑上的软件；核对目标学生账户、影响确认和逐台签名读回。
- 核对教学软件、Windows Shell、Veyon、Agent、Companion、更新/恢复工具是否可运行和更新；在受控测试机检查学生可写目录中的 EXE 行为。
- 检查快速软件目录、按产品选择、仅对选中项目生成详细信息/哈希；管理员完整扫描保留为高级工具并显示其范围限制。
- 关闭长期保护并读回本机/有效策略恢复。测试不支持系统版次、外部策略冲突、ACL 审查失败时应失败关闭。详细恢复步骤见 Phase 5 手册。
- 查看系统限制逐台结果、设备健康及手机状态：状态必须写明“Agent 已报告/已读回，实际效果待现场核验”；Windows 或浏览器实际拦截结果须单独实测，不能只凭签名回执判定通过。

### 6. 手机配对、课堂沟通和屏幕巡视

- 在活动课堂中分别测试教师端给学生发送、学生 Companion 回复：输入消息后按 Enter 应只发送一次；Shift+Enter 应换行；点击发送按钮仍可用。用中文输入法确认候选字时按 Enter，不应把尚未提交的候选词提前发出；测试空消息和连续快速发送。
- 用手机重新配对，核对证书安全码、教师批准、断开/撤销；确认手机通过教师端 LAN 服务工作。
- 在手机完成课堂状态刷新、通知、求助回复、一对一聊天、设备姓名显示、屏幕巡视和课堂管控进度核对。
- 检查单教室和多教室切换、手机后台/断网恢复；手机连接丢失时应显示断开，不能假报后台已送达。
- 核对屏幕读取停止、手机离开页面/切后台后租约清理，以及手机端和教师端显示的学生姓名一致。
