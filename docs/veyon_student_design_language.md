# Veyon Campus Student Setup — Design Language & Interaction Specification

> 本文定义 Student Setup 的视觉语言、Wizard 结构、组件规则和交互原则。  
> 设计依据：当前生成的 Student Setup UI 草图与后续确认的 5 步 Wizard 方案。

视觉草图集中在[Student Setup 参考图](assets/student-setup-concepts/README.md)。它们用于追溯 2026-09-29 的设计方向，不是当前产品截图或功能验收凭据；界面现状以代码和[任务主表](开发路线与任务清单.md)为准。

---

## 1. 产品体验目标

Student Setup 是一个**一次性、关键、不可出错的部署工具**，不是日常设置中心。

设计目标：

- 让第一次使用的老师不需要理解内部技术细节
- 清楚知道“我现在在哪一步”
- 清楚知道“下一步要做什么”
- 重要操作前有明确检查
- 部署过程有可见反馈
- 失败时知道问题在哪
- 完成后 GUI 退出普通使用路径，只保留管理员维护能力

核心体验关键词：

```text
清晰
克制
可信
低学习成本
低技术感
强流程感
强状态反馈
```

## 2. 整体设计语言

### 2.1 视觉方向

整体采用：

```text
Windows 现代桌面应用
+
浅色背景
+
蓝色主色
+
轻卡片
+
明确状态色
+
低装饰、高信息层级
```

整体观感应接近：

- Windows 11 Fluent 风格
- 简洁企业级部署工具
- 不使用“黑客工具”“运维面板”式复杂视觉

### 2.2 页面结构

主窗口固定布局：

```text
┌──────────────────────────────────────┐
│ Title Bar                            │
├──────────────────────────────────────┤
│ Stepper                              │
├──────────────────────────────────────┤
│                                      │
│ Main Content                         │
│                                      │
├──────────────────────────────────────┤
│ Footer Actions                       │
└──────────────────────────────────────┘
```

原则：

- 页面本身尽量**不出现整页滚动**
- 主体区域一次只展示当前步骤
- 底部按钮固定
- 顶部 Stepper 固定
- 复杂细节使用 Modal / Drawer / Popover

---

## 3. 主 Wizard 结构

最终推荐 5 步：

```text
[1 配置来源] → [2 部署内容] → [3 环境检查] → [4 执行部署] → [5 完成]
```

这 5 步表达的是用户心中的主流程。

复杂子任务不继续增加顶层 Step，而是使用弹层处理。

---

## 4. Stepper 设计

顶部采用连续箭头 / Chevron Stepper。

示例：

```text
[✓ 配置来源] → [2 部署内容] → [3 环境检查] → [4 执行部署] → [5 完成]
```

状态：

### 未开始
- 浅灰背景
- 深灰文字
- 数字圆点

### 当前步骤
- 蓝色背景
- 白色文字
- 当前数字高亮

### 已完成
- 浅灰或淡蓝背景
- 绿色 ✓
- 可显示已完成状态

### 错误状态
如果某一步存在阻断性错误：
- 红色 / 橙色小状态标识
- 不建议整个 Stepper 变红

Stepper 的目的不是导航菜单，而是告诉用户当前位置和总体进度。

默认不允许随意点击跳过未完成步骤。

## 5. Step 1 — 配置来源

### 5.1 页面目标

只解决一个问题：

> “这台学生机应该使用哪一份校区配置？”

主页面保持简洁：

```text
配置来源

当前配置
尚未选择

[从云端获取]
[导入本地配置]

说明：
配置中包含校区信息、公钥和部署参数。
```

选择成功后：

```text
当前配置

柴桑校区一教室
Campus ID：VC-000001
配置版本：0.5.0
来源：云端

[更换配置]
[查看详情]
```

### 5.2 从云端获取 — Modal

点击：

```text
[从云端获取]
```

打开 Modal：

```text
获取校区配置

搜索
[ 校区名称 / 电脑名前缀 ]

────────────────────────

○ VC-000001  柴桑校区一教室
○ VC-000002  柴桑校区二教室
○ VC-000003  浔阳校区一教室

────────────────────────

教师手机号后四位：
[____]

[取消]                  [下载并使用]
```

规则：

- Modal 是阻断式任务
- 完成或取消后才能回到主页面
- 不在主 Wizard 页面堆叠搜索、验证、列表等内容

### 5.3 本地导入 — Modal

点击：

```text
[导入本地配置]
```

打开：

```text
导入本地配置

[选择配置包]

Campus-001.zip

✓ 文件格式有效
✓ SHA-256 校验通过
✓ Campus ID：VC-000001
✓ 校区：柴桑校区一教室
✓ 配置版本：0.5.0

[取消]                  [使用此配置]
```

如果失败：

```text
✕ 配置包无效
原因：缺少 campus.json
```

不要只弹 MessageBox。

## 6. Step 2 — 部署内容

### 6.1 页面目标

告诉用户：

> “这台电脑具体要改什么？”

内容建议：

```text
部署内容

校区
柴桑校区一教室
Campus ID：VC-000001

电脑编号
[ 03 ]

目标电脑名
PC-03

需要执行的操作

☑ 配置 Veyon
☑ 修改电脑名称
☑ 创建学生普通用户
☑ 安装 Student Agent
```

### 6.2 配置项设计

每个选项使用：

```text
☑ 标题
  简短说明
```

例如：

```text
☑ 配置 Veyon
  导入校区公钥并设置认证配置
```

不要直接展示 Veyon CLI 参数。

### 6.3 高风险操作

例如：

- 覆盖已有密码
- 修改已有电脑名
- 覆盖已存在 Agent

使用警告卡片：

```text
⚠ 已检测到现有学生账户
继续可能修改现有配置。

[查看详情]
```

复杂说明放 Drawer，不放在页面中间。

---

## 7. Step 3 — 环境检查

### 7.1 页面目标

确认：

> “现在是否安全地开始部署？”

检查结果必须页面内展示。

每项检查在标题下方显示一句简短提示，字号小于标题；具体失败原因、系统信息和处置步骤放在“查看检查详情”中。提示只说明这项检查的用途或通过条件，不重复长错误信息。

示例：

```text
环境检查

✓ 配置包有效
✓ Veyon 已安装
✓ 当前具有管理员权限
✓ 电脑名称可用
✓ 学生账户可创建
✓ Agent 安装资源可用
✓ 网络通信正常
```

### 7.2 状态视觉

#### 成功
```text
✓ 通过
```
使用绿色。

#### 检查中
```text
◌ 检查中...
```
使用蓝色旋转指示。

#### 警告
```text
! 需要注意
```
使用橙色。

#### 失败
```text
✕ 未通过
```
使用红色。

### 7.3 页面操作

顶部或右上：

```text
[重新检查]
```

底部：

```text
[上一步]                     [下一步]
```

如果存在阻断失败项：

```text
[下一步]
```

禁用。

---

## 8. Step 4 — 执行部署

### 8.1 页面目标

让用户知道：

> “系统现在正在做什么？”

不要只显示一个 Spinner。

应逐项展示：

```text
正在部署

[1/5] 配置 Veyon              ✓
[2/5] 修改电脑名称            ✓
[3/5] 创建学生账户            进行中
[4/5] 安装 Student Agent      等待
[5/5] 测试网站策略通信        等待
```

### 8.2 状态层级

任务状态：

```text
等待
进行中
成功
失败
已跳过
```

当前任务高亮。

已完成任务降低视觉权重。

失败任务明显但不要整个页面变红。

### 8.3 进度条

顶部可以使用总进度：

```text
3 / 5
60%
```

但进度条只是辅助。

真正关键的是任务列表。

### 8.4 详细日志

右侧或底部：

```text
查看详细日志 >
```

推荐 Drawer：

```text
详细日志
────────────────
10:23:11 开始部署
10:23:12 Veyon 配置成功
10:23:16 修改电脑名成功
...
```

默认关闭。

### 8.5 失败处理

如果失败：

```text
✕ Student Agent 安装失败

原因：
Windows Service 注册失败

[查看详情]
[重试失败项目]
```

不要强迫用户从 Step 1 重新开始。

---

## 9. Step 5 — 完成

### 9.1 页面目标

给出一个明确结论：

> “这台学生机现在是否已经部署完成？”

示例：

```text
部署完成

✓ Veyon 配置成功
✓ 电脑名称修改成功
✓ 学生账户创建成功
✓ Student Agent 安装成功
✓ 网站策略通信测试成功
```

### 9.2 状态摘要

推荐展示：

```text
电脑名称
PC-03

Campus
VC-000001

Veyon
正常

Student Agent
运行中

Agent Version
0.5.0

网站策略通信
已连接教师端
```

### 9.3 重启提示

如果需要重启：

使用橙色提示卡：

```text
部分更改将在重启后生效

- 电脑名称修改需要重启
- 建议现在重启以完成部署
```

按钮：

```text
[稍后重启]              [立即重启]
```

## 10. Modal / Drawer / Popover 使用规则

### 10.1 Modal

用于：

- 从云端获取配置
- 导入本地配置
- 高风险确认
- 需要用户完成后才能继续的任务

特点：

```text
阻断式
完成 / 取消后才能回主流程
```

### 10.2 Drawer

用于：

- 查看配置详情
- 查看部署日志
- 查看 Veyon 详细状态
- 查看 Agent 信息
- 查看错误详情

特点：

```text
信息量大
但不应该打断主流程
```

建议从右侧滑出。

### 10.3 Popover

用于：

- “Campus ID 是什么？”
- 字段说明
- 简短提示

特点：

```text
轻量
短文本
不承载复杂操作
```

## 11. 卡片设计

主要信息使用轻卡片：

```text
┌──────────────────────┐
│ 校区信息             │
│ 柴桑校区一教室       │
│ VC-000001             │
└──────────────────────┘
```

卡片规则：

- 浅灰或白色背景
- 轻边框
- 小圆角
- 少量阴影
- 不要大面积渐变

---

## 12. 颜色语义

### 主色
蓝色：
- 当前步骤
- 主按钮
- 当前任务
- 链接

### 成功
绿色：
- ✓
- 已通过
- 已完成
- 服务正常

### 警告
橙色：
- 需要重启
- 可继续但需注意
- 已存在配置

### 错误
红色：
- 阻断部署
- 配置无效
- 安装失败

颜色必须表达状态，不做装饰。

---

## 13. 按钮层级

### Primary

用于当前页面最重要操作：

```text
[下一步]
[开始部署]
[立即重启]
```

蓝色实心。

### Secondary

```text
[上一步]
[重新检查]
[稍后重启]
```

浅色描边。

### Tertiary

```text
查看详情
查看日志
帮助
```

文字按钮。

### Danger

```text
卸载
清理 Agent
删除配置
```

红色。

危险按钮不要和普通 Primary 并列得过于接近。

---

## 14. 文案规则

主界面文案必须：

```text
短
明确
动作导向
```

不推荐：

```text
由于系统目前检测到若干配置，因此在继续下一步之前需要...
```

推荐：

```text
检测到已有 Veyon 配置。
继续部署可能覆盖部分设置。
```

---

## 15. 技术信息展示原则

普通用户默认不需要看到：

- CLI 参数
- JSON
- 文件路径
- 端口
- SID
- Hash
- Registry 路径

这些放到：

```text
查看详细信息
```

里。

主界面只说：

```text
配置成功
Agent 已启动
网站策略通信正常
```

## 16. Student GUI 完成后的状态

部署完成后：

```text
Student Setup
→ 不删除
→ 不作为普通学生日常入口
→ 不自动启动
→ 不创建或移除桌面快捷方式
→ 保留管理员维护入口
```

管理员以后重新打开：

```text
此设备已完成部署

Veyon：正常
Agent：运行中
版本：0.5.0

[查看状态]
[修复部署]
[卸载]
```

## 17. 与 Teacher 端设计语言统一

Teacher 和 Student 应共享：

- Logo
- 主色
- 字体
- Button 样式
- Card 样式
- 状态色
- Modal / Drawer 样式

但信息密度不同：

```text
Student
→ 强流程
→ 低复杂度
→ 大按钮
→ 明确步骤

Teacher
→ 管理工具
→ 更高信息密度
→ 列表 / 状态 / 批量操作
```

## 18. 最终设计原则

1. **主 Wizard 保持 5 步，不因子流程复杂无限拆分。**
2. **复杂任务使用 Modal / Drawer / Popover。**
3. **页面不再依赖长滚动。**
4. **每一步只解决一个用户问题。**
5. **技术细节默认隐藏。**
6. **状态必须清晰可见。**
7. **失败要支持恢复，而不是强制重来。**
8. **部署完成是“Veyon + Agent + 策略通信”全部成功。**
9. **Student GUI 最终进入管理员维护模式，而不是删除。**
10. **整体风格保持 Windows 原生感、克制、可信。**

## 19. 建议开发 Agent 按此顺序实现

```text
1. 搭好固定窗口布局
2. 实现顶部 Stepper
3. Step 1 配置来源
4. 云端配置 Modal
5. 本地导入 Modal
6. Step 2 部署内容
7. Step 3 环境检查
8. Step 4 部署任务状态
9. 日志 Drawer
10. Step 5 完成页
11. 部署完成后的维护模式
12. 统一状态色、按钮、卡片
```

## 20. 一句话设计定义

> **Student Setup 应该像一个可信、清晰、不会让老师迷路的 Windows 安装向导，而不是一个堆满技术选项的运维工具。**

## 21. 固定布局与部署内容页修订

- 主窗口固定尺寸，主页面不滚动。内容区域采用固定网格；只有超出容纳能力的编辑区、结果列表和详情抽屉纵向滚动。
- 优先让常规摘要、标题和提示完整显示，不为短文本创建过小的滚动框。
- 步骤条首项左侧平直，后续步骤采用连续箭头。当前步骤与已完成状态互斥，当前步骤及悬停时始终保持蓝底白字。
- 配置来源页加高当前配置摘要；来源标题突出显示，两个来源入口并列，避免无意义的大段留白。
- 部署内容页顶部横向显示校区、电脑名前缀和来源。左侧列出四项操作，复选框决定是否执行，点击项目切换编辑内容；中间大卡片编辑当前项目，右侧显示全部已选操作的结果预览，不显示密码。
- 环境检查页标题区域完整显示，结果列表占用剩余主体高度。成功、失败、警告使用矢量图标，并保留悬停提示及无障碍名称。
- 检查页采用左侧简短列表、右侧结论卡，区分全部通过、阻断和需注意；详细原因放入检查详情。
- 执行页进度卡不滚动，任务列表只展示短名称与状态，技术说明进入执行详情。
- 完成页只保留执行结论、简短任务结果和紧凑设备摘要；默认不展示路径、端口、指纹或实现原理。
