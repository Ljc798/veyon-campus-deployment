# 学生端更新可靠性计划：先原子更新，再增量更新

日期：2026-10-21（Asia/Hong_Kong）

状态：原子事务与匿名批次性能报告源代码已实现；TeacherConsole、StudentSetup（含 Agent）Release 构建通过。Windows 10/11 故障注入、双机验收与真实性能基线仍未完成。文件级增量更新和二进制差分尚未开始。

## 1. 决策摘要

学生端开始文件级增量更新前，先把 Teacher 推送链路做成一个可恢复的更新事务。一次更新包含 StudentSetup 安装目录与 SYSTEM Student Agent 两部分；新版本只有在安装目录读回正确、Agent 使用目标版本启动并通过本机健康检查后才提交。任一步失败或设备在更新期间重启，都保留并恢复上一版 StudentSetup、上一版 Agent、校区配置和 Agent 身份。

正式切换沿用当前的完整签名 StudentSetup 安装包和 Teacher 局域网传输。只替换变化文件属于下一阶段。二进制差分要等文件级增量更新通过现场验收后再立项实施。

## 2. 目前实现与发现的缺口

### 已有保护

- StudentSetup 和 Teacher 的手动自更新通过 `ApplicationReleaseUpdateHandoff` 暂存、验证安装包；管理员助手把旧角色目录移入 `UpdateRecovery`，安装失败或版本读回不符时恢复旧目录。
- Teacher 推送的安装包经过 Teacher 下载校验、开发者签名验证、Teacher 校区签名、Student Agent 二次验证和 SHA-256 校验。
- Agent 文件按版本复制到受 SYSTEM 保护的 ProgramData 目录。更新时旧 Agent 文件保留；SYSTEM helper 等新进程退出旧进程，启动新 Agent 并核对版本及校区配置指纹；失败时恢复旧计划任务并验证旧 Agent。
- 教师端只在签名回执、设备身份和目标版本读回通过后报告成功。
- 2026-10-20 增加了更新耗时观测：教师端分别显示发布查询与本机签名缓存准备；Student Agent/UpdateHelper 按 commandId 记录局域网传输、完整性摘要、StudentSetup 安装、Agent 暂存/切换、健康提交和回滚。学生端记录保存在 SYSTEM 私有的有界 sidecar，不进入事务 journal；教师只通过新鲜校区签名请求读取，并核对已固定 Agent 身份。计时失败不会改变事务结果。该提交仅通过 macOS Release 构建，尚无 Windows 现场耗时或 P50/P95 基线。
- 2026-10-21 增加教师端本机匿名批次性能报告：每次 rollout 完成后仅在内存保留报告，可手动导出 JSON；包括整批准备/总时长、结果计数、阶段与端到端 P50/P95/最大值、失败率、批次规模、来源版本和网络/Windows 版本类别。Teacher 进程最多在内存保留 128 条批次级观察值，按 1、2–9、10–19、20+ 分组计算缓存就绪和整批时长分布；应用退出后清空。导出不包含设备逐行记录、电脑名、IP、校区 ID、更新命令 ID、路径或下载 URL，也不会自动上传。网络类别由学生端按局域网下载路由匹配的接口类型推导，只保存 `wired`/`wifi`/`other`/`unknown`；Windows 类别只保存 `windows10`/`windows11`/`other`/`unknown`。类别通过独立签名 `/v2/update-timings` 返回；v1 端点和协议保留兼容。TeacherConsole 与 StudentSetup（含 Agent）macOS Release 构建通过；Windows 基线仍待现场采集。

### 当前原子事务实现与验收边界

- Teacher 推送代码现在先验证签名包、旧版本、路径、磁盘余量和 Agent 任务，再创建 SYSTEM/Administrators 私有 journal；旧 StudentSetup 目录在同卷重命名保存后才运行 Inno。
- Agent 文件暂存和任务激活已拆开。完整任务动作与受限 DACL 读回成功后才启动候选 Agent；启动助手按命令 ID 绑定 journal，候选版本及配置指纹健康读回通过后才写入 `Committed`。
- SYSTEM 开机恢复任务和每分钟 watchdog 在活动目录变更前注册，调用仍保留在 ProgramData 版本目录中的旧 Agent 恢复入口。恢复任务先取得全局更新锁，再核对或停止超时更新助手；这样不会与持锁的正常更新并发。更新助手 10 分钟仍未结束才会按 PID、启动时间和固定安装助手路径核验后停止。
- StudentSetup 安装器最多运行 10 分钟。事务记录绑定签名清单中的固定安装器文件名；若 Agent 在安装器仍运行时崩溃，恢复入口只会查找本事务受保护暂存目录中的同名安装器，确认其映像路径后停止并等待退出，再恢复活动目录。安装器未能确认退出时不移动目录，事务保留为 `RecoveryRequired`。
- StudentSetup Inno 文件不再使用 `restartreplace` 延迟替换锁定文件。若某文件不能立即替换，安装必须失败并让事务回滚，不能将“等重启后替换”当作安装成功。
- 源代码和角色构建通过不等于 Windows 原子更新已验收。SYSTEM、任务计划程序 ACL、重启恢复、失败注入、Agent 恢复和 Teacher 新鲜签名读回仍须在 Windows 10/11 现场逐项验证；这项门槛通过前仍禁止文件级增量。

## 3. 原子更新的保证范围

一次 Teacher 推送更新必须满足以下不变量：

1. **先校验，后改动**：命令、发行签名、包大小、摘要、角色、架构、版本、策略能力、磁盘空间、当前 Agent 任务与 ACL 都检查通过后，才创建恢复点。
2. **旧版始终可启动**：在新 Agent 健康读回前，旧 Agent 可执行文件、原 SYSTEM 任务、校区配置、签名身份私钥和旧 StudentSetup 文件不得删除或覆盖。
3. **先暂存，再激活**：安装包下载到受保护临时目录；Agent 安装到版本隔离的 ProgramData 目录。激活只改变受保护的任务动作，不原地覆盖运行中的 Agent。
4. **一致提交**：StudentSetup 角色标记与关键可执行文件版本读回正确、候选 Agent 以预期版本和配置指纹通过 loopback 健康检查后，才提交事务并清理恢复点。
5. **失败整体回退**：失败时恢复旧任务和旧 StudentSetup 目录，启动旧 Agent 并核对旧版本与同一配置指纹。若任何恢复步骤失败，保留所有恢复材料并标记 `needs-review`，不得报告成功。
6. **断电可恢复**：每次活动目录或任务动作变化前，先把下一阶段写入 SYSTEM 保护的原子事务记录；开机恢复入口能根据记录检查当前状态并继续提交或恢复旧版。
7. **成功依赖读回**：Agent 本机健康通过不等于教师端已确认。教师仍须验证新 Agent 的签名状态、命令 ID、校区、目标电脑和原有身份指纹。
8. **单设备串行**：同一学生电脑同一时刻只能运行一个更新事务；相同命令重放不会重新安装或删除恢复材料。

原子不表示 Windows 更新过程中完全没有停机。Agent 切换期间允许短暂服务中断；保证是旧版可恢复、没有半套状态被误报为成功。

## 4. 事务状态与落盘记录

建议状态只向前推进；回退使用单独的状态，不把未知状态猜成成功。

| 状态 | 含义 | 允许的下一步 |
| --- | --- | --- |
| `Prepared` | 签名安装包已验证，受保护事务记录已落盘，旧版仍活动 | 注册恢复任务、备份旧安装目录、取消事务 |
| `PreviousSetupPreserved` | 旧 StudentSetup 目录恢复点正在建立或已读回 | 开始安装候选版或恢复旧目录 |
| `SetupInstallationPending` | 旧 StudentSetup 已保存；完整签名安装器即将运行或仍在运行 | 读回并完成安装，或终止安装器后恢复旧目录 |
| `SetupInstalled` | 新 StudentSetup 角色和版本读回正确；旧 Agent 仍活动 | 暂存 Agent 或直接提交 |
| `AgentStaged` | 候选 Agent 已复制到版本目录并通过树校验；任务仍指向旧 Agent | 激活候选任务或回退 |
| `ActivationPending` | SYSTEM 任务切换即将开始或已发生；旧文件和安装目录恢复点仍保留 | 重新核对任务和健康状态后提交，失败时恢复 |
| `Committed` | 新 StudentSetup 和 Agent 已通过本机核验；教师端继续做签名网络读回 | 清理恢复点、保留最小结果记录 |
| `RollbackPending` | 已确定更新失败，恢复流程尚未完成 | 恢复旧任务、恢复旧目录 |
| `RolledBack` | 旧 StudentSetup、旧任务和旧 Agent 均读回；保留失败摘要 | 清理临时下载，不自动重试 |
| `RecoveryRequired` | 自动恢复至少一步失败；旧文件与事务记录全部保留 | 由 SYSTEM 恢复入口再次核对或人工处理 |

事务记录写在 `ProgramData/VeyonCampus/StudentUpdateTransactions/<campus-hash>/student-update-transaction.json`。记录包括 schema、命令 ID、旧/目标版本、签名清单绑定的安装器文件名、阶段时间、配置指纹、发行摘要、更新助手进程 ID/启动时间和恢复结果；路径均由固定根目录与命令 ID 推导，不接受 journal 内的任意路径。不存私钥、管理员凭据、签名正文或个人资料。写入采用同目录临时文件、Flush 到磁盘、原子替换，并在读取时核对 SYSTEM/Administrators 专属 ACL。

事务状态字段表示“下一阶段已持久化，操作可能尚未开始或已经中断”，不能单独作为操作完成证据。每次恢复都会重新读 StudentSetup 角色标记、Agent 任务动作、DACL、进程健康、版本及配置指纹，并按物理读回决定继续还是回退。每次 journal 状态迁移都必须与磁盘上的完整当前记录一致；回滚入口先刷新记录并识别已持久化的终态，旧的内存快照不能覆盖较新的状态。

活动安装目录恢复点位于同一 Program Files 卷的 `Veyon Campus/UpdateRecovery/Student/<command-id>/Previous`，使目录重命名在同一卷内完成。候选 Agent 位于独立版本目录；原身份文件和策略数据留在现有 ProgramData 配置目录，不随二进制替换。

## 5. 正常更新顺序

1. Agent 验证 Teacher 签名命令、有效期、开发者签名清单、目标角色/架构/版本/策略能力和局域网下载来源。
2. 获取本机全局更新互斥锁；先恢复任何上次未完成的事务并确认没有活动事务，再读取旧 StudentSetup/Agent 版本、任务动作、受限 ACL 和配置指纹。恢复前不依赖活动安装目录存在或版本有效；版本或任务状态不能确定时停止。若已是目标版本则返回，不下载重复安装包。
3. 释放互斥锁后将完整安装包下载到受保护临时目录，校验字节数和 SHA-256，并再次核对命令有效期。异步下载期间不持有线程相关的系统互斥锁，也不修改活动安装目录或任务。
4. 下载完成后重新获取互斥锁，再恢复并核对事务/版本，防止下载期间本机状态变化；检查 Program Files 与 ProgramData 所在卷空间、路径重解析点、Agent 二进制树和保留旧版所需空间。消费命令重放 ID，写入 `Prepared` 事务记录，并注册、读回 SYSTEM 开机任务与每分钟 watchdog。到这里为止，任务创建失败不会改安装目录或主 Agent 任务。
5. 写入 `PreviousSetupPreserved` 阶段意图，将旧 StudentSetup 目录同卷重命名到受保护恢复路径并读回旧角色标记。接着写入 `SetupInstallationPending`，运行固定参数的完整签名安装包；Inno 在替换文件前停止学生端交互进程，等待上限为 10 分钟。退出码和版本标记缺一不可；超时后先终止并确认安装器退出，异常时恢复 `Previous` 并读回。
6. 新 StudentSetup 角色与版本读回后写入 `SetupInstalled`。若无需升级 Agent，先核对当前 Agent 健康再提交。
7. 将 Agent 从新 StudentSetup 复制到版本隔离 ProgramData 目录，逐文件核对候选/来源树，应用 ACL 和防火墙规则；完成后写入 `AgentStaged`，此时旧任务仍指向旧 Agent。
8. 写入 `ActivationPending` 后切换 SYSTEM 任务到候选 Agent，读回任务命令和 DACL。启动更新 helper 后，旧 Agent 在 HTTP 202 回执送出后退出。
9. Helper 有界等待旧进程退出，启动候选任务，并通过 loopback `/health` 核对目标 Agent 版本和原配置指纹。通过后写 `Committed`；失败时恢复旧任务、旧 StudentSetup 目录和旧 Agent 健康状态。
10. StudentSetup 与 Agent 都健康提交后才删除旧版恢复目录；旧 StudentSetup 与 Agent 都读回回滚成功后才删除失败候选目录。清理失败保留受保护材料和终态 journal，并阻止下一次更新覆盖记录，不把已验证的提交/回滚误判为安装失败。
11. Teacher 对同一设备发起新鲜签名状态查询；确认目标版本、命令绑定和原固定设备身份后才显示成功。新 Agent 身份变化仍需教师明确审核。

## 6. 故障处理矩阵

| 失败点 | 必须执行 | 教师端结果 |
| --- | --- | --- |
| 签名、摘要、角色、架构或策略能力无效 | 不创建恢复点、不执行安装器 | 拒绝，显示验证失败 |
| 下载中断、过期、磁盘空间不足 | 删除未完成临时文件；旧目录、旧任务不变 | 可重新发起；不能显示已安装 |
| 旧安装目录无法安全重命名 | 不运行安装器；删除空事务或记 `RolledBack` | 该设备更新失败，旧 Agent 继续运行 |
| 安装器非零退出、崩溃或版本读回不匹配 | 隔离候选目录，恢复 `Previous`，核对旧角色和版本 | 失败，不发送成功回执 |
| 安装器运行超过 10 分钟或 Agent 在安装中崩溃 | 最多等待 30 秒终止本事务安装器；仅在固定暂存映像已退出后回滚；无法确认退出则保留安装包暂存目录、旧目录和 journal，标记需核对 | 不显示成功；恢复未完成时 `needs-review` |
| 候选 helper 复制或恢复任务注册失败 | 恢复 StudentSetup 目录；Agent 任务保持旧版 | 失败，旧 Agent 继续运行 |
| Agent 文件复制、ACL、防火墙或任务写入失败 | 旧任务保持或立即恢复；回退 StudentSetup | 失败；恢复失败时 `needs-review` |
| 旧 Agent 无法退出 | 不启动候选 Agent；恢复旧任务和 StudentSetup | 超时/需核对，不能成功 |
| 候选 Agent 未启动或健康超时 | 恢复旧任务，启动并健康核对旧 Agent，恢复旧 StudentSetup | 更新失败，旧 Agent 已恢复或明确需人工核对 |
| helper 在候选健康后、提交前退出 | 开机恢复任务或每分钟 watchdog 读取 journal；目标健康则提交，否则回退 | 暂不报告成功，直到新鲜签名读回 |
| 断电发生在 StudentSetup 改动期间 | 预先注册的旧 Agent 恢复任务根据 journal 恢复旧目录；旧 Agent 任务未提前切换 | Teacher 下次连接看到旧版本/失败 |
| 断电发生在 Agent 任务切换后 | 临时 SYSTEM 开机恢复任务检查候选健康；成功提交，失败恢复旧任务和安装目录 | 需等设备恢复联网读回，不能预报成功 |
| 回退任务、ACL、旧目录或旧健康读回失败 | 保留旧二进制、备份、日志和 journal；不做破坏性清理 | `needs-review`，展示具体恢复阶段 |
| 相同命令再次到达 | 命令 ID/事务互斥判重；返回已有状态，不重复安装 | 显示原结果或需核对 |

所有自动等待必须有上限。失败报告包含阶段、旧/目标版本、错误类别和恢复是否验证；不记录签名命令、校区私钥、学生姓名、手机号或下载 URL 中的临时凭据。

## 7. 兼容策略与发布门槛

- Agent 更新保持当前稳定命令协议、开发者签名清单和完整 StudentSetup 安装包。文件级增量包使用单独 schema 和签名类型，不能被旧 Agent 当成安装器执行。
- 首次安装原子事务能力属于迁移更新。设备必须先通过完整签名安装包更新；旧 Agent 在迁移事务期间不能运行新恢复代码，因此迁移版的 Windows 首次升级仍需单独现场观察。只有后续由新 Agent 执行的更新才具备本文件描述的 watchdog/journal 自动恢复保证。
- 文件级增量实现前，必须在签名状态中增加可验证的更新能力与事务 schema，并让 Teacher 按设备状态识别能力。未知、旧版或 capabilities 不匹配的设备继续使用完整包。
- 不跨多个差分包逐步串接。每个旧版本到当前最新版有一个可验证的直接文件包，或者回退完整安装器；每设备更新前固定目标版本和已验证内容摘要。
- 原子更新必须先通过 Windows 10/11 SYSTEM、计划任务 ACL、权限、故障注入、重启恢复和一教师一学生端到端验收。未通过之前，文件级增量更新开关保持关闭。
- 文件级增量稳定后，才评估二进制差分；二进制差分仍要先重建完整目标文件并验证 Developer Release 的完整目标摘要，然后走同一暂存、备份、激活和回滚事务。

## 8. 文件级增量更新后续设计

原子更新门槛通过后，增量包面向 `role + architecture + sourceVersion + targetVersion`，携带规范清单、路径、文件大小、SHA-256、新增/替换/删除操作和目标 StudentSetup/Agent 版本。包签名绑定 base/target 版本和文件清单。文件写入先进入隔离 staging；每个最终文件在替换前验证，活动目录修改由同一事务 journal 记录并能逐文件恢复。

Teacher 读取每台设备签名状态，将不同源版本的设备按 `sourceVersion -> targetVersion` 分组。缓存键必须包含源版本、目标版本、角色、架构和 manifest 摘要；一台机器的临时下载内容不能冒充另一版本的差分包。相同源版本组复用同一缓存；版本组合太多、旧版缺少基线文件或差分包无法验证时，直接使用完整安装包。安装完成并获健康签名读回后才清理该组缓存。更新期间有新的最新版发布时，不改变已冻结的目标；下一轮再统一升级。

## 9. 严格实施顺序与完成门槛

## 10. Windows G0 现场快照

`scripts/collect-student-update-g0-evidence.ps1` 提供 Windows 10/11 学生机更新前后的只读快照。它用于缩短人工核对时间，不执行更新、恢复、重启或任务修改；报告中的 `g0Acceptance` 永远为 `false`，不能代替故障注入或教师—学生双机验收。

Windows installer workflow 会用 Windows PowerShell 5.1 的语言解析器检查该脚本。解析通过只证明语法可读，不代表脚本在 Windows 10/11 上成功采集或证明更新恢复正确。

现场成功、失败注入、重启恢复和性能基线的逐场景记录要求见[Windows 原子更新现场 G0 验收矩阵](records/2026-10/Windows原子更新现场G0验收矩阵-20261021.md)。矩阵中的案例默认均未运行；每个案例必须用实际 Windows 快照、Teacher 签名终态和对应 artifact 填写。

用管理员 PowerShell 在同一台学生机对同一场景采集更新前、更新后的快照。两次使用相同的 `CaseId`，每个阶段使用不同输出文件：

```powershell
$case = [guid]::NewGuid()
.\scripts\collect-student-update-g0-evidence.ps1 -CaseId $case -Phase before -OutputPath .\evidence\before.json
# 完成一次受控的学生端更新
.\scripts\collect-student-update-g0-evidence.ps1 -CaseId $case -Phase after -OutputPath .\evidence\after.json
```

故障注入时将阶段写为 `failed` 或 `rolledBack`，并将快照和对应的 Teacher 回执、CI artifact、人工步骤记录放在同一验收案例中。采集器会读取 StudentSetup 角色标记、Agent 任务动作和受限 ACL、恢复/watchdog 任务动作与触发器、loopback Agent 健康读回、事务 journal 的安全字段、恢复目录存在性、Program Files/ProgramData 可用空间及配置/身份连续性标签。报告不写电脑名、用户名、校区标识、配置路径、命令 ID 原文、配置正文或密钥内容。

配置、身份密钥、Agent 健康指纹和事务命令 ID 的连续性标签使用每台电脑本地生成的随机盐计算 HMAC。同一用户在同一台机器使用同一 `CaseId` 时，标签可用于前后比较；盐保存在用户本机 `LOCALAPPDATA` 下的 G0Evidence 目录，不随 JSON 报告提供。不能把盐文件复制到其他机器，也不要将它作为验收附件。

快照中的 `unavailable`、`null`、缺少任务或缺少 journal 都只是采集结果，不自动代表通过或失败；验收人员必须按本计划的故障矩阵结合 Windows 版本、实际操作步骤、Teacher 新鲜签名回执和恢复结果逐项判定。当前 Mac 环境未运行此 PowerShell 脚本，必须先在 Windows 10/11 上检查解析和采集结果，再将真实快照纳入 G0 证据。
