## 1. 测试原则与当前证据

当前源码与验收状态统一见[任务主表](开发路线与任务清单.md)。原 0.4.18 构建、31/31 主检查与 4/4 专项结果已作为历史材料保留在[原验收清单](archive/2026-09-29/测试验收与发布清单.md)，不证明当前版本通过。学生现场验收顺序已合入本文第 14 节，原始审阅见[历史归档](archive/README.md)。本轮文档整合未执行构建或 Windows 系统验收。

验证顺序：规则 → ViewModel／执行器契约 → Windows 系统集成 → 教师学生连接 → 小批试点 → 发布包验收。每层只能证明其覆盖范围；150 条记录不能替代 150 台连接证据。公钥独立导出并核对指纹的代码已接入，仍需在 Windows 10/11 实机确认；完整 UI 与恢复验收仍缺。普通权限可拖放，管理员窗口使用文件选择器（Windows 不允许普通 Explorer 向提升权限窗口 OLE 拖放），其他拖放来源和异常路径尚未覆盖。

所有 16 种布尔组合可以在计划层验证依赖与不越界；真实 Windows 测试至少覆盖上述独立与风险组合，再按发现的问题增加集成用例。不要为每种组合重复运行所有无关测试。

执行前状态快照已加入学生部署流程；P3-08 未通过 Windows 验收前不得依赖它扩大部署。快照采用 Windows 当前用户 DPAPI 加密。学生端结果页现在可在创建快照的同一用户下检查快照摘要、只读比对当前 Veyon 配置 SHA-256，并将原配置另存到新 JSON 文件；程序不自动导入或覆盖配置。以下仍需在 Windows 实机验证，不能只凭界面和 Release 构建判定恢复可用。

- [ ] BACKUP-01：选中改名时，快照包含当前活动名称和待生效名称；选中账户时包含目标账户 SID、来源、启用状态及组成员状态，不含密码。
- [ ] BACKUP-02：已有固定版本 Veyon 时，导出配置并记录 SHA-256；没装 Veyon 时记录“无现有配置”，未知版本、CLI 缺失、导出失败或文件写入失败均在首项系统修改前阻断整份计划。覆盖组合部署和“仅安装 Veyon”入口。
- [ ] BACKUP-03：实现了当前用户 DPAPI 解密与结构／摘要校验、当前电脑名／账户状态只读对照、当前 Veyon 配置哈希比对及不覆盖式 JSON 另存；schema v2 保存计划电脑名并继续读取 v1。Windows 上验证同一用户成功读取、另一用户拒绝读取、v1/v2 均可读；分别确认名称／账户及 Veyon 哈希一致／不同的结果；导出后由管理员检查差异并手动恢复，不自动导入或覆盖。以上实机验收仍未完成。
- [ ] BACKUP-04：DPAPI 或落盘读回校验失败、运行目录无权限／磁盘满时，Veyon、改名和账户操作均未开始，执行记录写明阻断原因；表单输入密码与 Veyon 私钥文件不被快照／日志／结果保存；原 Veyon 配置若含敏感设置，仅处于 DPAPI 保护的快照中，只有用户明确选择后才另存明文文件，并验证临时导出清理。
- [ ] BACKUP-05：结束正常执行后临时明文配置导出已删除；在可恢复测试机强制中断进程后，下一次启动或执行会删除遗留临时导出文件，之后快照失败仍阻断修改。

## 5. Windows 身份与权限（P2–P6）

- [ ] SEC-01：普通 UI 可浏览资料和生成计划；未开始修改时不要求 UAC。
- [ ] SEC-02：UAC 取消时系统无修改，UI 能继续编辑，不显示成功或永久忙碌。
- [ ] SEC-03：使用不同管理员提权时，仍针对原来明确选中的本地账户 SID，不误改提权人的密码。
- [ ] SEC-04：域账户与本地账户同名，不能仅通过名称匹配；不支持身份时阻断对应操作。
- [ ] SEC-05：已有 User 是管理员、禁用账户或有数据，不自动降权、启用、删除或重建。
- [ ] SEC-06：密码首尾空格保留原意；两次输入不一致和策略拒绝有明确提示，不打印实际密码。
- [ ] SEC-07：假 Worker、错误会话、其他用户进程、过大请求不能驱动高权限操作。
- [ ] SEC-08：参数含引号、分号、换行、PowerShell 特殊字符不变成命令；可执行文件路径不能由任意请求指定。
- [ ] SEC-09：部署包、日志、异常、运行记录、进程参数、回传消息无密码或私钥内容。

| FAIL-10 | 在组合任务首项或中间项运行时请求停止；同时尝试关闭窗口 | 当前账户／安装器命令不被强杀；返回后不启动后续修改，未开始步骤记为已取消／已跳过，窗口在流程结束前不关闭 |

| FAIL-14 | 还原机制在重启后恢复旧状态 | 报告实际回退，停止扩大部署，现场核对维护模式 |
| FAIL-15 | 最新运行日志缺失、截断、损坏或无法枚举 | 结果页显示需核对并阻止新修改，不得回退到较早的成功记录；管理员核对状态后才能确认继续 |

## 11. 试点顺序与停止条件

| 批次 | 范围 | 进入下一批的条件 |
| --- | --- | --- |
| T0 | 可恢复 Windows 实验环境 | 规则、权限、故障与单项操作通过 |
| T1 | 一教师＋一学生 | 所选操作、重启、日常教师身份连接和恢复路径通过；若包含账户修改，另需账户人工登录验收 |
| T2 | 5–10 台 | 个体差异可解释、无误改、日志足够诊断 |
| T3 | 一个真实机房，最多 150 台 | 逐批完成，设备台账和问题记录完整 |
| T4 | 其他机房／不同环境 | 在既有矩阵之外新增环境，重新做必要兼容性验证 |

发生下列任一项立即停止扩大范围：改错账户、非选中操作发生修改、凭据泄露、错误密钥导致原环境失联、不可解释的数据损失、失败却显示整体成功。先修复并验证，再决定恢复试点。

停止扩大部署不等于自动撤销已完成修改。现场根据每台运行记录和已核对备份分别恢复。

## 13. 缺陷分级与完成定义

| 等级 | 示例 | 处理要求 |
| --- | --- | --- |
| S0 | 改错账户、敏感资料外泄、执行任意命令、数据损失 | 停止相关操作和扩大部署，修复后重新审查边界 |

模板化测试名、固定 PASS 字样和截图不能替代真实检查；对系统修改必须能说明检查了哪个系统状态以及得到什么结果。

## 14. 学生现场验收与新生命周期

本节合并原学生自测清单的现场顺序。上文同类任务共用结果，不重复计数。

7. 更新功能交付后验证角色/版本/架构、篡改签名、下载中断、重复命令、默认拒绝降级、安装失败、重启后版本读回及 Teacher 恢复查询。
