## 1. 测试原则与当前证据

截至 2026-09-26 审阅修复记录，0.4.4 Release 构建通过（0 警告 / 0 错误），29 组 Windows 本地检查通过。本轮加入跨进程命名管道锁后重新构建通过，但未重跑本地检查；Windows 双实例及系统验收仍缺。当前工作区验收 ZIP 摘要见 [工作进度报告](工作进度报告-2026-09-26.md)，历史验证记录见 [验证与变更记录](reviews/2026-09-25-验证与变更记录.md)。本清单维护验收规格，不把代码存在或模拟检查当作系统验收。

验证顺序：规则 → ViewModel／执行器契约 → Windows 系统集成 → 教师学生连接 → 小批试点 → 发布包验收。每层只能证明其覆盖范围；150 条记录不能替代 150 台连接证据。当前公钥独立读回、Windows 10/11 矩阵、原生拖放、完整 UI 与恢复验收仍缺。

## 4. 独立操作与组合测试（P3–P7）

在测试前记录本机名称、账户 SID 与组状态、Veyon 版本／配置和服务。验证“没有更改密码”应依靠调用边界检查与必要的人工登录验证，不能从系统读取旧密码来比较。

| ID | 选择项 | 必须发生 | 必须保持 |
| --- | --- | --- | --- |
| OP-01 | 只部署 Veyon | 安装／配置／验证所需组件 | 电脑名、账户、已有密码 |
| OP-02 | 只改电脑名 | 改名及待重启状态 | Veyon、账户、密码；无需部署包 |
| OP-03 | 只创建学生账户 | 新建明确指定的普通账户 | 管理员密码、电脑名、Veyon |
| OP-04 | 只修改指定管理员密码 | 修改选中 SID 对应的本地账户 | 其他账户、电脑名、Veyon |
| OP-05 | Veyon＋改名 | 按依赖执行两项，记录待重启 | 所有账户与密码 |

所有 16 种布尔组合可以在计划层验证依赖与不越界；真实 Windows 测试至少覆盖上述独立与风险组合，再按发现的问题增加集成用例。不要为每种组合重复运行所有无关测试。

## 5. Windows 身份与权限（P2–P6）

- [ ] SEC-01：普通 UI 可浏览资料和生成计划；未开始修改时不要求 UAC。
- [ ] SEC-02：UAC 取消时系统无修改，UI 能继续编辑，不显示成功或永久忙碌。
- [ ] SEC-03：使用不同管理员提权时，仍针对原来明确选中的本地账户 SID，不误改提权人的密码。
- [ ] SEC-04：域账户与本地账户同名，不能仅通过名称匹配；不支持身份时阻断对应操作。
- [ ] SEC-05：已有 User 是管理员、禁用账户或有数据，不自动降权、启用、删除或重建。
- [ ] SEC-06：密码首尾空格保留原意；两次输入不一致和策略拒绝有明确提示，不打印实际密码。
- [ ] SEC-07：假 Worker、错误会话、其他用户进程、过大请求不能驱动高权限操作。
- [ ] SEC-08：参数含引号、分号、换行、PowerShell 特殊字符不变成命令；可执行文件路径不能由任意请求指定。
- [ ] SEC-09：部署包、日志、异常、运行记录、进程参数、回传消息无密码或私钥内容。
- [ ] SEC-10：文件选择和拖放在普通 UI 下可用；提权后不意外变成永远高权限运行的下载界面。

## 6. 安装、配置、教师端连接（P4、P7）

- [ ] INST-01：只接受 `veyon-4.11.2.0-win64-setup.exe`、16,782,856 字节及固定 SHA-256；Windows 预检和执行入口均验证 WinVerifyTrust 和固定签名者证书。用真实官方资产验证通过，改名、改字节、错误大小、未签名及其他签名者全部阻断；旧版、新版和无法确认版本的现有 Veyon 也应阻断安装/配置。记录 Win10/11 信任链结果。macOS 只校验发布摘要，不代表已验证 Authenticode。
- [ ] INST-02：固定版本在可恢复 Windows 上运行 `/S /NoMaster /NoInterception /NoStartMenuFolder`；确认学生不安装 Master、无交互提示、目标路径和返回码，并区分 NSIS 管理员错误码 740、成功以及实际待重启行为。不要仅以外层退出码 0 代替服务与文件读回。

- [ ] VEY-01：未安装 → 离线安装 → 读回版本和组件；学生端无不需要的 Master，教师端具备 Master。
- [ ] VEY-02：同版正常安装重复运行不破坏配置；同版损坏进入明确修复计划。
- [ ] VEY-03：已知旧版先备份后升级；未知新版不自动降级或全量覆盖。
- [ ] VEY-04：安装器出错、被锁、返回待重启，不误当作一般成功；显示后续步骤为何停止或延期。
- [ ] VEY-05：公钥导入失败或同名异指纹，不改成其他校区，不自动删除重建密钥。
- [ ] VEY-06：服务启动验证有超时与错误信息；端口不可达与服务未启动能区分。
- [ ] VEY-07：仅修改需要的防火墙规则，无全局关闭；已有无关规则保持。
- [ ] TEA-01：创建与复用校区密钥分别测试；导出失败后重试不创建第二套身份。

## 8. 故障注入与恢复（P3、P8）

故障注入先使用假执行器或受控测试资源，再在可恢复 Windows 环境验证。每例记录最后完成步骤和实际系统状态。

| ID | 注入位置 | 预期结果 |
| --- | --- | --- |
| FAIL-01 | 第一次修改前预检失败 | 无系统修改，不创建误导性成功记录 |
| FAIL-02 | 备份目录无权限或磁盘满 | 必须备份的修改不开始，明确原因 |
| FAIL-03 | 安装器非零返回／超时 | 停止依赖步骤，保留输出摘要和状态 |
| FAIL-04 | 安装完成后公钥配置失败 | 显示部分完成，说明 Veyon 已安装 |
| FAIL-05 | 配置完成后服务启动失败 | 不能显示可连接；允许诊断与有界重试 |
| FAIL-06 | 改名完成后后续步骤失败 | 明确名称已更改／待重启，不隐去事实 |
| FAIL-07 | 密码修改后日志落盘失败 | 标为需核对，不盲目重复改密或声称已回滚 |
| FAIL-08 | UI 退出／Worker 断连 | 展示或恢复到真实状态；不能启动第二个冲突任务 |
| FAIL-09 | 系统修改与结果记录之间断电 | 重启后重新读回系统，识别已完成步骤 |
| FAIL-10 | 用户在长操作中取消／关闭窗口 | 在安全点停止；不随意强杀安装器 |
| FAIL-11 | 备份恢复遇到新配置变更 | 先比较并提示冲突，不覆盖后来人工配置 |
| FAIL-12 | 拔 U 盘或替换资料 | 不执行未验证资源；已完成步骤有记录 |
| FAIL-13 | 重复运行同一包／新包 | 不重复创建密钥、目录或账户；不因重试自动改密 |
| FAIL-14 | 还原机制在重启后恢复旧状态 | 报告实际回退，停止扩大部署，现场核对维护模式 |

## 11. 试点顺序与停止条件

| 批次 | 范围 | 进入下一批的条件 |
| --- | --- | --- |
| T0 | 可恢复 Windows 实验环境 | 规则、权限、故障与单项操作通过 |
| T1 | 一教师＋一学生 | 所选操作、重启、日常教师身份连接和恢复路径通过；若包含账户修改，另需账户人工登录验收 |
| T2 | 5–10 台 | 个体差异可解释、无误改、日志足够诊断 |
| T3 | 一个真实机房，最多 150 台 | 逐批完成，设备台账和问题记录完整 |
| T4 | 其他机房／不同环境 | 在既有矩阵之外新增环境，重新做必要兼容性验证 |

发生下列任一项立即停止扩大范围：改错账户、非选中操作发生修改、凭据泄露、错误密钥导致原环境失联、不可解释的数据损失、失败却显示整体成功。先修复并验证，再决定恢复试点。

停止扩大部署不等于自动撤销已完成修改。现场根据每台运行记录和已核对备份分别恢复。

## 13. 缺陷分级与完成定义

| 等级 | 示例 | 处理要求 |
| --- | --- | --- |
| S0 | 改错账户、敏感资料外泄、执行任意命令、数据损失 | 停止相关操作和扩大部署，修复后重新审查边界 |
| S1 | 不能安装、错误成功状态、无法登录或连接、恢复记录缺失 | 阻断对应功能正式交付 |
| S2 | 有清楚绕行办法的非核心失败、个别路径或显示问题 | 明确范围、修复计划与已知限制 |
| S3 | 不影响操作理解的间距、文案或装饰问题 | 归入后续体验修复，不伪装成核心阻断 |

单项完成定义：代码实现、相关正常与失败验证、日志／错误行为、文档与状态更新齐备。阶段完成定义：前置阶段条件和本阶段所有发布必需项通过；延期项目说明不影响当前交付目标。

模板化测试名、固定 PASS 字样和截图不能替代真实检查；对系统修改必须能说明检查了哪个系统状态以及得到什么结果。
