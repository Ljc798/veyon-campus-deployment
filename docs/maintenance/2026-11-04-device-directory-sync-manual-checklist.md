# 设备目录同步 · Windows 手动验收清单

本清单对应本轮代码修改。当前没有运行自动化测试、构建或 Windows 实测；请等教师机和隔离测试环境开机后再执行。

## 测试前准备

- [ ] 使用可还原的 Windows 10/11 虚拟机或备用教师机，不要先在正式教室目录操作。
- [ ] 建立虚拟机快照；另行导出并保存当前 Veyon 配置。记录教师端版本、Veyon 版本和系统版本。
- [ ] 选一个已有测试地点，记录现有电脑的 Veyon Name、Host、UUID、所属地点和数量。
- [ ] 在策略与预设中读取该地点；记录当前电脑勾选项，确认不发送任何新策略。
- [ ] 选中两台现有测试电脑，并确保至少一台现有电脑未选中；这样才能检查新增后原选择是否保持。
- [ ] 确认测试电脑有固定且唯一的 Windows 计算机名（如 PC-19），并确认无需配置 IP 或 Host 覆盖映射。

## A. 已有地点新增座位

- [ ] 在 Veyon Campus → 地点/座位图中进入已有地点的编辑模式。
- [ ] 在空座位填写新学生姓名和编号并保存；不要再打开 Veyon 手工添加。
- [ ] 观察 Veyon 写入流程和结果提示；若出现管理员权限提示，在测试机上确认。
- [ ] 打开 Veyon Configurator，确认原地点新增一台电脑，Veyon Host 为固定电脑名（例如 PC-19）；Veyon Name 为学生姓名，无姓名时回退 PC-19。
- [ ] 确认已有电脑 Name、Host、UUID 和地点都没有被重命名、移动或删除。
- [ ] 回到座位图，确认新座位已关联到读回的 Veyon 对象；学生姓名仍显示在 Campus 座位资料中。
- [ ] 添加第二个新座位，确认编辑仍可继续；第一台电脑没有重复创建。
- [ ] 在空姓名座位手动填写电脑编号并保存；确认预览、冲突检查、Veyon 写入和读回绑定均包含该电脑，姓名显示为“未填写姓名”。
- [ ] 添加一个既无姓名也无编号的桌位；确认它仍只作为桌位，不被创建为 Veyon 电脑。

## B. 策略名单刷新和默认勾选

- [ ] 确保策略页此前已从同一地点载入完整电脑清单，再新增一台电脑。
- [ ] 检查策略名单自动刷新并出现新电脑；现有勾选状态保持原样。
- [ ] 确认新电脑默认未勾选；本步骤只检查名单，不推送黑白名单或其他策略。
- [ ] 如果之前手工编辑过策略目标文本，新增完成后确认程序没有覆盖这段手工文本，并提示需要重新选择/载入地点。

## C. 已在 Veyon 手工补录的设备

- [ ] 在测试快照中准备一个已存在于同一地点、Host 唯一的 Veyon 电脑，但 Campus 座位尚未绑定。
- [ ] 在 Campus 为该 Host 对应的座位填写姓名并保存。
- [ ] 确认不会创建第二个 Veyon 对象，并且座位只关联到原对象 UUID。
- [ ] 确认已有 Veyon Name 按绑定 UUID 与 Campus 姓名同步，Host 和 UUID 不变。
- [ ] 若原 Veyon Name 与 Campus 学生姓名不同，确认关联完成后座位图立即显示姓名同步差异，并要求教师确认方向；未确认前两侧名称都不被静默覆盖。

## D. 冲突与失败处理

- [ ] 仅在可还原的测试快照中，制造同 Host 位于其他地点的冲突；确认操作被阻止，两个地点都未变化。
- [ ] 仅在隔离测试机上拒绝管理员权限请求；确认座位可保留为本机待处理资料，界面不显示“已同步”。
- [ ] 遇到 Veyon 读回失败或状态需核对时，不要再次重复点写入；先按界面提示刷新目录，检查是否已新增。
- [ ] 如果测试中 networkobjects export 自然返回 255，记录 dump、export、config export 的退出码与提示；不要运行 networkobjects clear 或 config clear 来制造/修复故障。

## E. 手工关联已有 Veyon 电脑

- [ ] 在测试快照中准备一台已在当前地点的 Veyon 电脑，以及一个尚未关联的 Campus 座位。
- [ ] 在座位图明确选择座位和 Veyon 电脑后关联；确认界面重新读取并核对 UUID、Name、Host 和父地点。
- [ ] 确认绑定只写入 Campus 座位资料，没有新建 Veyon 对象；原有绑定未被静默覆盖。
- [ ] 尝试选择 Host 重复或来自其他地点的对象，确认操作被拒绝并保持原绑定。

## F. 固定电脑名与独立学生资料

- [ ] 修改座位上的学生姓名和编号；确认 Veyon Name 按绑定 UUID 更新；Host、Windows Hostname、电脑编号和 UUID 均不变。
- [ ] 交换两个已绑定电脑座位上的学生姓名；确认对应 UUID 的 Veyon Name 同步交换；电脑编号、Host、UUID 和座位设备绑定不变。
- [ ] 交换一个已绑定学生与空座位；确认绑定电脑的 Name 同步为空座位对应的姓名；若姓名为空则回退为该 Host，电脑编号与绑定不动。
- [ ] 确认 Veyon Host 始终是固定电脑名（如 PC-19）；Veyon Name 与学生姓名一致，空姓名时回退为 PC-19。
- [ ] 在可还原快照中将 Veyon Name 改成与学生姓名不同的值并刷新；确认出现按 UUID 确认同步方向的提示。单独修改 Host 时确认设备标为连接冲突且不能作为策略目标。

## G. 目录投影、冲突和只读回退

- [ ] 通过 Veyon 原生配置只修改 Name，再读取当前地点；确认出现 UUID 绑定差异，人工确认后 Campus 学生姓名更新且 Host/编号/座位绑定不变。单独修改 Host 时确认标为连接冲突，不能作为策略目标。
- [ ] 移动同一 UUID 到另一个地点后刷新；确认设备 UUID 保留并提示核对座位归属。
- [ ] 从 Veyon 删除一台测试电脑并刷新；确认旧投影标为缺失，座位资料没有自动删除。
- [ ] 清除一台设备的座位 UUID 绑定后重新读取完整目录；确认投影清除旧 SeatId/电脑编号/学生姓名关联，不影响其他设备。
- [ ] 制造重复 Host 或缺失父地点的测试数据；确认冲突设备不会成为策略目标；确认重复 Veyon Name 仅作为显示名，不触发身份冲突。
- [ ] 让投影中的设备分别发生外部 Name 修改、Host 修改和 UUID 不变的跨地点移动；每次刷新后确认该目标在姓名差异/连接/归属冲突被核对前不能用于策略或维护操作，解决冲突并重新完整读取后才恢复。
- [ ] 让 Veyon 完整读取失败并触发只读回退；确认界面提示回退，旧可信投影不被覆盖，也不能用回退结果执行关联/策略操作。

## H. 结果记录

请记录以下内容，便于修复未通过项：

- Windows 版本、Veyon 版本、Veyon Campus 版本。
- 新增前后的电脑数量，以及新设备 Name、Host、UUID、父地点 UUID。
- 管理员权限提示是否出现；每一步界面显示的成功/失败文本。
- 策略名单新增设备是否出现、已有选择是否保留、新设备是否未勾选。
- 是否有重名、重复 Host、遗漏绑定、错误重命名或错误成功提示。

任何一步出现重复创建、误删/移动既有对象、或新设备默认被选中，请立即还原快照并保留日志，不要在正式校区继续操作。
