# 设备目录同步 · Windows 手动验收清单

本清单对应 TeacherConsole 1.1.56 座位编辑测试包。Release 构建和离线打包已成功，清理构建 0 错误、103 警告；自动化测试未运行。用户此前已确认同名地点冲突时能恢复旧座位图，但最新截图仍显示维护/课堂页面使用旧本机电脑、保存后目录未同步、右键删除无效。1.1.56 针对这些问题改为从 Veyon 实际名单刷新，并增加旧 UUID 安全恢复、冲突档案入口和右键菜单；请在教师机或隔离测试环境执行。测试包位于 `artifacts/seat-editor-test-20261104-1.1.56/VeyonCampus-TeacherConsole-SeatEditor-1.1.56-win-x64.exe`，SHA-256 `576F06EC5977537CB377341166F0530500D727166494B777982BE1F43F7D312B`。

## 测试前准备

- [ ] 使用可还原的 Windows 10/11 虚拟机或备用教师机，不要先在正式教室目录操作。
- [ ] 建立虚拟机快照；另行导出并保存当前 Veyon 配置。记录教师端版本、Veyon 版本和系统版本。
- [ ] 选一个已有测试地点，记录现有电脑的 Veyon Name、Host、UUID、所属地点和数量。
- [ ] 在策略与预设中读取该地点；记录当前电脑勾选项，确认不发送任何新策略。
- [ ] 选中两台现有测试电脑，并确保至少一台现有电脑未选中；这样才能检查新增后原选择是否保持。
- [ ] 记录一台 Veyon Host 不等于本机 `PC-编号` 的现有设备，确认它的 UUID、Host 和所属地点唯一；新增设备另用固定 `PC-编号` 测试。

## A. 已有地点新增座位

- [ ] 在 Veyon Campus → 地点/座位图中进入已有地点的编辑模式。
- [ ] 在空座位填写新学生姓名和编号并保存；不要再打开 Veyon 手工添加。
- [ ] 观察 Veyon 写入流程和结果提示；若出现管理员权限提示，在测试机上确认。
- [ ] 打开 Veyon Configurator，确认原地点新增一台电脑，Veyon Host 为固定电脑名（例如 PC-19）；Veyon Name 为学生姓名，无姓名时回退 PC-19。
- [ ] 确认已有电脑 Name、Host、UUID 和地点都没有被重命名、移动或删除。
- [ ] 回到座位图，确认新座位已关联到读回的 Veyon 对象；学生姓名仍显示在 Campus 座位资料中。
- [ ] 添加第二个新座位，确认编辑仍可继续；第一台电脑没有重复创建。
- [ ] 在空姓名座位手动填写电脑编号并保存；确认预览、冲突检查、Veyon 写入和读回绑定均包含该电脑，姓名显示为“未填写姓名”。
- [ ] 新增座位时确认默认建议下一个电脑编号（例如 PC-09），可手动修改；新座位即使暂未填写姓名也会带编号进入待同步清单。
- [ ] 编辑已有未绑定座位，清空姓名和编号后保存；确认该座位不再生成新电脑，已有 Veyon 电脑对象也不会被删除。

## A2. 表格式布局编辑

- [ ] 进入编辑模式，将鼠标移到座位网格右边缘和底边，分别用悬浮“+”新增一列和一行；预览模式不显示这些控件。
- [ ] 悬浮行号/列号，确认数字切换为 `−`；点击空行/空列并在确认框中删除。对含座位的行/列点击 `−`，确认弹出提示且删除被阻止。
- [ ] 点击空白格添加座位，点击已有座位修改姓名/电脑编号；用座位自身菜单删除座位，确认删除不影响行列，也不删除 Veyon 对象。
- [ ] 编辑模式下在已有座位上右键，选择“删除此座位”；确认弹出二次确认并移除所选座位，其他座位和 Veyon 电脑对象不变。预览模式下座位上下文菜单不出现。
- [ ] 在已有绑定座位上右键，选择“解除本机电脑关联”；确认学生姓名、电脑编号和 Veyon 对象均保留，只有本机 UUID/Host 对应关系解除；保存前 Ctrl+Z 能恢复关联。
- [ ] 连续添加多个姓名和电脑编号都留空的空座位；确认允许保存，电脑编号保持空白，Veyon 不新增电脑且同步名单中不包含这些占位桌位。
- [ ] 将一个已绑定座位拖到空格，再拖到另一个座位上交换；确认学生姓名、编号和 UUID 绑定随座位位置移动，Host 不变。
- [ ] 执行几项编辑后按 Ctrl+Z、Ctrl+Shift+Z，确认撤销和重做正确；点击“取消”确认所有未保存改动消失。
- [ ] 保存后确认只经过一次本机保存和 Veyon 同步流程；姓名冲突时分别选择“采用本机姓名”和“采用 Veyon Name”，验证 Host/UUID 不变。
- [ ] 在可恢复测试环境制造权限或目录读回失败；确认页面区分本机保存成功与 Veyon 同步失败，并出现重试入口，不显示虚假成功。
- [ ] 使用“打印座位表”导出 HTML 并打开浏览器打印预览；确认打印功能仍可用。

## A3. 空地点首次导入与拖动反馈

- [ ] 选择本机尚无座位记录、但 Veyon 中已有同名地点的测试地点；进入“地点与学生名单”后确认自动只读导入全部电脑和 Veyon Name 中的学生姓名，包括 Host 不等于 `PC-编号` 的电脑。
- [ ] 确认导入期间 Veyon 配置未被写入；本机座位记录保留每台设备 UUID、原 Host 和地点；只有能安全识别的本地固定编号才写入座位编号。
- [ ] 拖动并保存导入座位，确认 Veyon 中原 UUID、Host 和地点不变，学生姓名只按确认流程同步。
- [ ] 已有 Campus 座位少于 Veyon 设备时，不覆盖原有座位和姓名；确认不确定的设备不会按列表顺序自动配对。
- [ ] 增加一个有新电脑编号的本地座位并保存，确认只把未绑定的新电脑写入 Veyon，已有导入设备不重复创建。
- [ ] 拖动座位时确认目标格实时高亮、网格下方的行列提示随鼠标立即更新；拖到空格后确认只移动座位，拖到另一个座位后确认交换两边的姓名、编号和设备关联。
- [ ] 制造同名地点重复、UUID/Host 冲突或权限错误；确认不会部分导入或覆盖本机数据，并出现可重试诊断。
- [ ] 在一个本机机房座位先绑定某台 Veyon 电脑，再从同名的另一份空本机地点档案触发首次导入；若冲突座位都属于一个档案且地点 UUID 相同，确认自动切回原座位图，原数据和 Veyon 均不更改。
- [ ] 若冲突座位分属多个本机档案、地点 UUID 不同或原档案不可用，确认仍阻止导入，列出可识别的原地点与行列位置，不改数据且提示教师按诊断处理。
- [ ] 若界面显示“打开已有的冲突座位图”，点击后确认打开的是原有本机档案；没有发生自动删除、导入或 Veyon 写入。
- [ ] 在冲突座位图中编辑并右键解除本机电脑关联，保存后确认该座位仍保留姓名和固定电脑编号；Veyon 原电脑对象不被删除，保存流程按 Host 唯一核对后重新建立或恢复关联。
- [ ] 恢复测试目录后使用失败提示中的重试入口，确认空座位表导入成功。

## B. 策略名单刷新和默认勾选

- [ ] 确保策略页此前已从同一地点载入完整电脑清单，再新增一台电脑。
- [ ] 在策略与预设页面确认恢复学生复选名单、全选和清空选择；逐个勾选学生并确认所选数量即时更新。
- [ ] 在策略页修改选择后切换到设备概览和维护页，确认继续使用同一份学生勾选范围。
- [ ] 不进行手工刷新；保存完成后确认策略与课堂控制名单自动重新读取并出现新增电脑。
- [ ] 刷新后检查新电脑出现在策略名单，现有勾选状态保持原样。
- [ ] 确认新电脑默认未勾选；本步骤只检查名单，不推送黑白名单或其他策略。
- [ ] 保存座位后在“策略与预设”“设备与更新”“课堂控制”分别确认名单和数量来自当前 Veyon 目录，不显示仅存在于旧本机地点资料中的电脑。
- [ ] 在可恢复测试环境模拟 Veyon 读取或 UUID 核对失败；本机保存成功但同步失败时确认页面明确显示部分成功和重试入口，不显示虚假同步成功。
- [ ] 恢复目录读取后重试同步；确认当前地点名单自动刷新，新设备默认未勾选，旧地点/旧电脑不会混入当前课堂控制范围。

## C. 已在 Veyon 手工补录的设备

- [ ] 在测试快照中准备一个已存在于同一地点、Host 唯一的 Veyon 电脑，但 Campus 座位尚未绑定。
- [ ] 在 Campus 为该 Host 对应的座位填写姓名并保存。
- [ ] 确认不会创建第二个 Veyon 对象，并且座位只关联到原对象 UUID。
- [ ] 确认已有 Veyon Name 按绑定 UUID 与 Campus 姓名同步，Host 和 UUID 不变。
- [ ] 若原 Veyon Name 与 Campus 学生姓名不同，确认关联完成后座位图立即显示姓名同步差异，并要求教师确认方向；未确认前两侧名称都不被静默覆盖。

## D. 冲突与失败处理

- [ ] 仅在可还原的测试快照中，制造同 Host 位于其他地点的冲突；确认操作被阻止，两个地点都未变化。
- [ ] 仅在隔离测试机上拒绝管理员权限请求；确认座位可保留为本机待处理资料，界面不显示“已同步”。
- [ ] 遇到 Veyon 读回失败或状态需核对时，不要再次重复点写入；先按界面提示刷新目录，检查是否已新增。
- [ ] 如果测试中 networkobjects export 自然返回 255，记录 dump、export、config export 的退出码与提示；不要运行 networkobjects clear 或 config clear 来制造/修复故障。

## E. 手工关联已有 Veyon 电脑

- [ ] 在测试快照中准备一台已在当前地点的 Veyon 电脑，以及一个尚未关联的 Campus 座位。
- [ ] 在座位图明确选择座位和 Veyon 电脑后关联；确认界面重新读取并核对 UUID、Name、Host 和父地点。
- [ ] 确认绑定只写入 Campus 座位资料，没有新建 Veyon 对象；原有绑定未被静默覆盖。
- [ ] 尝试选择 Host 重复或来自其他地点的对象，确认操作被拒绝并保持原绑定。

## F. 固定电脑名与独立学生资料

- [ ] 修改座位上的学生姓名和编号；确认 Veyon Name 按绑定 UUID 更新；Host、Windows Hostname、电脑编号和 UUID 均不变。
- [ ] 交换两个已绑定电脑座位上的学生姓名；确认对应 UUID 的 Veyon Name 同步交换；电脑编号、Host、UUID 和座位设备绑定不变。
- [ ] 交换一个已绑定学生与空座位；确认绑定电脑的 Name 同步为空座位对应的姓名；若姓名为空则回退为该 Host，电脑编号与绑定不动。
- [ ] 确认 Veyon Host 始终是固定电脑名（如 PC-19）；Veyon Name 与学生姓名一致，空姓名时回退为 PC-19。
- [ ] 在可还原快照中将 Veyon Name 改成与学生姓名不同的值并刷新；确认出现按 UUID 确认同步方向的提示。单独修改 Host 时确认设备标为连接冲突且不能作为策略目标。

## G. 目录投影、冲突和只读回退

- [ ] 通过 Veyon 原生配置只修改 Name，再读取当前地点；确认出现 UUID 绑定差异，人工确认后 Campus 学生姓名更新且 Host/编号/座位绑定不变。单独修改 Host 时确认标为连接冲突，不能作为策略目标。
- [ ] 移动同一 UUID 到另一个地点后刷新；确认设备 UUID 保留并提示核对座位归属。
- [ ] 从 Veyon 删除一台测试电脑并刷新；确认旧投影标为缺失，座位资料没有自动删除。
- [ ] 清除一台设备的座位 UUID 绑定后重新读取完整目录；确认投影清除旧 SeatId/电脑编号/学生姓名关联，不影响其他设备。
- [ ] 制造重复 Host 或缺失父地点的测试数据；确认冲突设备不会成为策略目标；确认重复 Veyon Name 仅作为显示名，不触发身份冲突。
- [ ] 让投影中的设备分别发生外部 Name 修改、Host 修改和 UUID 不变的跨地点移动；每次刷新后确认该目标在姓名差异/连接/归属冲突被核对前不能用于策略或维护操作，解决冲突并重新完整读取后才恢复。
- [ ] 让 Veyon 完整读取失败并触发只读回退；确认界面提示回退，旧可信投影不被覆盖，也不能用回退结果执行关联/策略操作。

## H. 结果记录

请记录以下内容，便于修复未通过项：

- Windows 版本、Veyon 版本、Veyon Campus 版本。
- 新增前后的电脑数量，以及新设备 Name、Host、UUID、父地点 UUID。
- 管理员权限提示是否出现；每一步界面显示的成功/失败文本。
- 策略名单新增设备是否出现、已有选择是否保留、新设备是否未勾选。
- 是否有重名、重复 Host、遗漏绑定、错误重命名或错误成功提示。

任何一步出现重复创建、误删/移动既有对象、或新设备默认被选中，请立即还原快照并保留日志，不要在正式校区继续操作。
