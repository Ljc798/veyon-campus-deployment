## 文档维护约定

1. 项目级任务状态与验收证据以任务主表为准；专项规格可以维护细化子任务及其局部证据，但不替代 P0–P15 的项目验收结论。本页和架构页只写汇总结论并链接到权威证据。
2. 分开描述设计、代码实现、自动检查、线上部署和 Windows/手机实机效果。构建成功或 Agent 回执不能代替系统策略生效验收。
3. 记录某一日期的环境快照放入 `records/YYYY-MM/`，原始证据保留；后续变化更新现行指南和任务表，不覆写旧快照。
4. 过时方案和已替代指令移入 `archive/`；若用户仍需保留的视觉参考图，放在 `assets/` 并标明其不是实际产品截图。
5. 新需求先更新对应规格，再同步任务状态、架构边界和必要操作指南；不要在多份文档复制完整的发布状态流水账。
6. 根目录 `/artifacts/` 在 Git 中被忽略，属于本机生成或验证材料，不是共享仓库证据。若任务状态依赖某项检查，应把结论、版本、环境和命令写入受跟踪的 `records/`，可再链接本机 artifact；不能只留下无法随仓库访问的 artifact 链接。
