# 教师每日心跳触发与验收

本文按当前工作区代码说明 Teacher 校区每日心跳的初始化、触发、去重、重试和云端回执。它说明程序预期行为；CloudBase 端是否可用还要看文末部署状态。

## 触发方式一览

心跳由教师端桌面程序发起，不是 Windows 计划任务、系统服务或云端定时任务。程序只在 Teacher 窗口运行时进行本机调度：

| 事件 | 程序行为 |
| --- | --- |
| 第一次成功发布学生校区配置包 | 保存包 ID，安排在发布成功 60 分钟后发送第一次心跳。 |
| Teacher 启动 | 有待发送的首次心跳时恢复剩余等待时间；等待已结束则立即检查。之后的每日心跳仍在启动时检查。 |
| Teacher 窗口保持打开 | 启动一个每小时触发的计时器。每次只检查是否到新 UTC+8 日期或当天此前发送失败；符合条件才请求 API。 |
| Teacher 关闭 | 计时器停止，程序不在后台运行；若跨日时程序已关闭，会在下次启动时补发。 |

首次发布后的 60 分钟等待由单次计时完成；Teacher 保持打开时，到点就发送，不用等下一次整点检查。若 Teacher 关闭，程序不会在后台运行；再次启动时会恢复剩余等待，或在计划时间已过时立即尝试。之后“每小时触发”是一次到期检查，不代表每小时都发送。成功发送后，当天其余检查会被本机日期记录挡住。

## 第一次心跳是怎样发出的

1. **尚未发布配置包时不会发送。** 新安装的 Teacher 如果没有本机心跳状态文件，启动代码不会凭空创建一个有效包 ID，也就不会发心跳。
2. **发布成功后初始化状态。** 发布流程取得云端 `packageId`，再创建或更新本机状态。状态包含 `Enabled`、`PackageId`、随机生成并保存在本机的 `PublisherInstanceId`、`LastSentDay` 和首次发送的计划时间。新建状态的 `Enabled` 当前默认为 `true`，`LastSentDay` 初始为空。当前 Teacher 界面没有启停控件，只有发送状态显示。
3. **第一次发送延后 60 分钟。** 只有从未成功发布过配置包的本机才会写入 `FirstHeartbeatNotBeforeUtc`。Teacher 运行时到这个时间会读取 Veyon 当前配置并发送；后续更新同一校区配置包不会重置这次等待，也不会重复执行首次延迟。
4. **计算发送内容。** Teacher 读取本机 Veyon 网络对象中的配置目标，按电脑名忽略大小写去重，得到配置电脑总数；这不是当前在线电脑数，也不会逐台上报电脑名或学生姓名。延迟发送只让校区有时间完成电脑编号和配置，不会收集或关联学生个人资料。
5. **检查日期并调用 API。** 客户端以 UTC+8 日历日期检查是否到期，符合条件时向 `POST /v1/heartbeat/teacher` 发送一次请求，内容包括包 ID、随机本机标识、Teacher/Student 版本和配置电脑总数。目前客户端将运行中 App 的版本传作 Teacher 版本及 Student 版本的回退值；云端能读取发布目录时，会把数据库记录中的 Student 版本改用最新的 StudentSetup 发布版本。它不是逐台读取学生电脑当前安装的版本。
6. **收到成功回执才记为当天已发送。** 新版 API 成功返回 HTTP 200 和最新签名版本清单；客户端解析成功后，把当天日期写入 `lastSentDay`。旧版 HTTP 204 仍兼容为成功回执，但没有版本信息。HTTP 错误、网络错误或无效响应都不会更新日期。

## 之后每天如何触发

程序成功发送后，会把 `LastSentDay` 保存到：

```text
%LOCALAPPDATA%\VeyonCampus\Telemetry\teacher-heartbeat.json
```

Teacher 启动时和窗口每小时的计时器都会用当前 UTC+8 日期重新检查：

```text
Enabled 为 true
并且 PackageId 不为空
并且 LastSentDay 不等于今天的 UTC+8 日期
```

三个条件同时成立才会发送。日期按香港/中国标准时间的**日历日**计算，不按上一次发送后的完整 24 小时计算。因此，跨过 UTC+8 零点后可以触发新一天的心跳；如果 Teacher 当时开着，实际请求会在零点后的下一次每小时检查时发出，并非保证恰好 00:00 发送。如果 Teacher 关着，则要等下次启动。

如果一天内连续触发多个入口（例如启动、整点检查或再次发布配置包），`LastSentDay` 会挡住重复请求；同一程序实例还有并发保护，避免两个发送流程同时运行。发布包入口会发起尝试，但不会绕过每日去重。

## 失败重试与版本提示

请求失败时不会保存当天日期。Teacher 窗口仍开着时，计时器每小时会再次检查并重试；如果程序已关闭，下一次启动会再尝试。服务端的每日记录以 UTC+8 日期和校区身份为键执行 upsert，因此客户端重试不会造成同一校区同一天出现多条每日快照。

新版心跳响应还会携带 TeacherConsole 和 StudentSetup 的最新**签名**版本清单。客户端必须用固定在安装包中的 Developer Release 公钥验签，并确认发布角色后才比较版本；发现更新时只弹出版本提示，不下载、不安装。若客户端还没有固定公钥，或云端没有已发布版本，心跳本身仍可成功，但不会弹出版本提示。发布目录查询暂时失败时，云函数也会优先完成心跳，并在响应中返回空清单。

## 如何观察和复测

在 Teacher 的“首次设置”页查看“Teacher 每日汇总状态”：

- “正在读取……并发送”表示本机正读取配置电脑总数并请求 API。
- “服务已确认今日心跳发送”表示收到成功回执且 `lastSentDay` 已保存；后续当天显示跳过重复请求属于正常行为。
- “校区心跳未发送”及后面的错误说明请求未被本机记为成功；窗口保持打开时会在后续每小时检查时重试。

验收时建议用专用测试 VM：

1. 首次延迟：在没有旧心跳状态的测试 VM 上成功发布校区配置包。确认 Teacher 显示“首次校区心跳已安排”，且 60 分钟内云端没有该日回执；让 Teacher 持续运行到 60 分钟，到点后应收到成功回执并保存 `lastSentDay`。若中途关闭 Teacher，再次启动应恢复剩余等待。
2. 同日去重：重启 Teacher 或等待小时检查，确认状态提示跳过重复请求，云端当天仍只有一条校区快照。
3. 下一日发送：让 Teacher 保持打开跨过 UTC+8 零点，等下一次每小时检查；或关闭后在下一 UTC+8 日期重新启动。确认新的 `lastSentDay` 和当天快照。
4. 失败重试：只在测试环境暂时阻断 API 请求，确认失败时 `lastSentDay` 不变；恢复 API 后等下一次小时检查，确认成功并更新日期。
5. 版本提示：需先创建测试用 Developer Release 密钥、用公钥重建客户端、部署新版 API 并发布签名版本；然后从尚未发送当日心跳的测试快照启动。清单验签通过且版本较新才提示，提示窗口不执行下载或安装。

云端验收可在 `campus_daily_teacher_heartbeats` 表按包 ID 和 UTC+8 日期检查 Teacher/Student 版本、电脑总数和每日归组记录。心跳原始 Publisher ID 不写入该表；服务端只存按日 HMAC 摘要。

## 当前部署状态

首次发送延迟、每日去重和失败重试代码已部署到 CloudBase API；数据库迁移已应用至 `20261001110000`。`/health` 与部署包目录查询均返回 HTTP 200。签名版本仍需 Developer Release 公钥和对应发布记录；Teacher 首次心跳及回执需在专用 VM 中按上面的步骤端到端验收。部署细节见[CloudBase API 运行与验收](CloudBase%20API运行与验收.md)。
