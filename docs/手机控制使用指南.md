# 手机控制使用指南

手机端在同一校园 Wi‑Fi/LAN 内连接正在运行的 Windows 教师控制台。教师电脑负责签署和转发策略；手机只持有可撤销的访问凭据。教师控制台关闭或手机离开当前 LAN 后，手机无法操作。

## 首次连接

1. 在教师电脑打开正确校区的教师控制台，进入“手机控制”，点“启动服务”。窗口自动选择主用校园网地址，并显示 HTTPS 地址、根证书下载地址和 SHA‑256 指纹。教师控制台需要保持运行；活动课堂会自动启动服务。
   教师电脑和手机必须处于同一可互通的校园网。若教师控制台运行在虚拟机里，NAT 网络通常会挡住手机直连；请将虚拟网卡设为桥接，并确认手机能访问教师窗口显示的 LAN 地址。
2. 在手机浏览器打开下载地址获取教师根证书。下载使用 HTTP，但文件只是公开根证书；在安装前逐字核对 SHA‑256 指纹与教师窗口一致。指纹不一致时不要安装。
3. 在手机系统设置中安装根证书并启用信任。iPhone 还要到“设置 → 通用 → 关于本机 → 证书信任设置”启用该根证书的“完全信任”；Android 的菜单和浏览器信任行为会因系统版本、厂商策略而异。
4. 教师在桌面窗口点“生成二维码和一次性配对码”，再用手机相机扫码。二维码**先打开 HTTP 连接说明页**（39177），不会直接打开控制页。证书安装并信任后，回到说明页点“安装并信任证书后，打开安全连接”，进入 HTTPS 控制页（39176）；二维码中的五分钟配对码会随链接带入。也可手动打开教师窗口显示的 HTTPS 地址并输入配对码。
5. 手机填写设备名称并点“配对这部手机”。只有提交配对请求后，教师电脑“等待教师批准的手机”列表才会出现该手机；核对设备名称和来源 LAN 地址并批准后，手机才会出现在“已配对手机”列表中。扫码、下载证书、安装证书、刷新教师端列表都不会单独创建配对请求。若拒绝、超时或配对码已使用，请在教师电脑重新生成二维码和配对码。

### iPhone 页面无法打开时

按顺序分别打开教师窗口显示的两个地址，并记录哪一步失败：

- `http://教师机IP:39177/` 是连接说明页。它打不开时，问题还没到证书验证阶段；检查手机和教师电脑是否在同一可互通网段、教师服务是否运行、Windows 防火墙，以及校园 Wi‑Fi 是否启用了客户端隔离。虚拟机教师端使用 NAT 时通常不可从手机直连。
- 说明页能打开，但 `https://教师机IP:39176/` 打不开时，先确认 HTTPS 地址中的 IP 与说明页相同，且 iPhone 已对本次教师根证书启用“完全信任”。教师电脑可运行下面的只读 PowerShell 命令，确认安全端口已监听在教师窗口显示的 LAN 地址上：

  ```powershell
  Get-NetTCPConnection -State Listen -LocalPort 39176,39177 | Select-Object LocalAddress,LocalPort
  ```

  如果没有显示教师窗口的 IP 对应的 39176 监听项，停止并重新启动“手机控制”服务后再查；若 39176 正在监听而 iPhone 仍报安全连接错误，记录 Safari 完整错误和教师端版本，并确认教师机/iPhone 日期时间正确，再检查 Windows 防火墙或安全软件是否单独拦截 39176。重新扫码不会修复网络或证书信任问题。
- 已定位过一类“说明页可开、39176 监听但 HTTPS 握手失败”的教师端问题：Windows Schannel 无法使用仅驻留内存的服务器证书私钥完成 TLS 握手。Teacher 0.4.65 已把服务器证书重新载入到受进程生命周期管理的私钥容器；手机原有根证书不因此改变。安装 0.4.65 后重新启动手机控制服务并生成新二维码，再用真实手机验证；自动测试通过不代替 iPhone/Android 实机验收。
- HTTPS 控制页能打开但教师端列表没有手机时，在手机页面输入名称和配对码并点“配对这部手机”，然后查看教师端的“等待教师批准的手机”；尚未批准的设备不会出现在“已配对手机”列表。

如果仍失败，请记录两个 URL 各自的结果、iPhone Safari 显示的完整错误文字、教师机和 iPhone 的局域网 IPv4 地址（可遮住最后一段）及教师端版本。不要只写“网页打不开”，因为 39177 连接失败、39176 TLS 失败和配对请求未提交是不同故障。

## 查看和切换策略

首次操作每台学生电脑前，先在教师控制台的“读取并核对 Agent 身份”中逐台查看指纹，并与学生机部署记录核对后固定身份。首次信任或密钥变化须教师明确批准；密钥变化时先现场复核，不能直接沿用旧信任。

手机从教师电脑的 Veyon 机房目录读取目标，只能选择当前校区预先保存的网站、应用或长期系统策略。教师先在桌面编辑学生 SID 和系统开关，再通过“保存当前系统限制”建立手机预设；软件安装限制须先阅读影响说明并确认。先选预设和电脑，再读取状态；“签名身份已验证”只在学生 Agent 签名、校区/目标身份和本次状态随机数都通过核验后显示，并包含 Agent 版本、状态采集时间、策略模式、版本和到期时间。系统状态逐项显示六种设置及版本；无法连接、未固定身份或验签失败时显示未知/需复核，不推断限制效果。

六项长期系统策略为锁定 Windows 默认壁纸、禁止修改日期/时间/时区、限制网络设置、限制软件安装、禁止账户管理及本人改密、限制 Control Panel/Settings（按桌面当前开关，默认关闭）。系统策略不会自动到期；手机启用前会列出具体项目并要求确认，解除会请求学生机恢复本工具原先保存且仍由本工具拥有的设置。手机不能编辑学生 SID、策略内容或密钥。Agent 接受回执不代表系统效果已经实机验证。

启用或解除前手机会再次要求确认。应用“阻止”预设先推送审核模式并读取逐台统计；教师阅读统计后还要再次确认才会发送阻止策略。策略、审核和清单回执须由已固定身份的 Agent 签名，并匹配本次随机数、校区和请求正文摘要；不匹配时显示需复核。成功回执只证明该 Agent 接受了本次请求，不代表浏览器页面或应用启动效果已完成实机验证。部分电脑未确认时，可在结果区只重试未确认的电脑。

## 课堂求助

活动课堂期间，教师桌面和已配对手机都会自动显示学生 Companion 发来的求助，并可直接回复。学生只需按“需要老师帮助”；电脑身份、课堂和网络地址由 Teacher 与 Student Agent 自动确定。收到教师回复后，学生在原按钮位置按“标记已解决”，教师桌面和手机会同步显示“已解决”。消息只在校园 LAN 和当前课堂内暂存，不进入 CloudBase，也不保存为聊天记录。

## 全班通知

活动课堂期间，教师可在桌面或已配对手机的“课堂互动”区域输入一条通知并发送。系统自动使用当前课堂目标，不要求再选电脑或网络；在线学生端会显示通知。通知最多 500 字符、两分钟后失效，不提供回复和历史记录。页面报告已提交的目标数，不代表学生已读。

通知可包含一个完整的 HTTP(S) 网址。学生端显示“打开课堂网址”后，由学生点击并通过电脑默认浏览器访问；已配对手机的通知卡片也可直接点击链接。多个网址或无效网址仍按普通文本显示，不会自动打开。详见[课堂共享链接指南](课堂共享链接使用指南.md)。

## 课堂屏幕巡视

活动课堂期间，已配对手机可在课堂卡片点“查看屏幕”，查看最多 5 台课堂电脑的低清单帧概览。页面只刷新当前可见的画面，不录制或保存历史；点“停止巡视”、切到后台或结束课堂后会停止读取。此功能仍处于 PoC 阶段，首次使用前须在 Windows TeacherConsole、Student Veyon 和真实手机上完成现场验收。

## 手机策略范围

手机打开控制页后，如果活动课堂中的目标电脑与教师机 Veyon 清单逐台匹配，页面会默认选择本堂课电脑并收起范围列表。展开“更改电脑范围”后可自行调整。当前没有活动课堂，或目标与清单不能完整匹配时，系统不会代选电脑；请先核对范围再查看状态或启停限制。策略预设默认显示第一项，仍需教师确认启用或解除。

## 撤销和停止

教师可在桌面窗口撤销已配对手机、拒绝待批准请求、删除手机策略预设或停止服务。撤销立即使该手机的配对凭据失效。手机也可以点“退出”清除本机浏览器保存的凭据；退出不代替教师端撤销。

控制 API 只在教师电脑当前私有 IPv4 子网内提供，不使用 CloudBase 或公网中继。教师安装程序的 Windows 防火墙规则限定 LocalSubnet 与 Domain/Private 网络配置；若校园 Wi‑Fi 被 Windows 标为 Public，可能需要管理员按学校网络策略调整配置后再连接。请勿将服务端口转发到互联网。

手机控制记录保存在教师用户本机的 `%LOCALAPPDATA%/VeyonCampus/MobileControl`。教师根证书私钥保存在 Windows 当前用户证书存储关联的不可导出 CNG 密钥中；不要手动删除证书或密钥。根证书轮换后，所有手机都需要重新安装并信任新证书、重新配对。
