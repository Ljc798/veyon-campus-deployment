# Veyon Campus — 教师端 UI/UX 重构设计规范

**版本：** v1.0  
**日期：** 2026-10-22  
**适用范围：** TeacherConsole（Avalonia）、手机配对管理界面及相关桌面交互  
**设计基线：** `develop` 分支，TeacherConsole 1.1.32、Avalonia 12.1.3  
**目标：** 建立一致、轻量、专业的课堂控制界面，在低配置 Windows 教师机上保持良好的响应性。

---

## 1. 产品定位与设计原则

Veyon Campus 面向非技术背景的课堂教师。教师不应需要理解 Agent、证书、端口、签名策略或 Windows 注册表，才能完成日常课堂管理。

### 1.1 五项核心原则

1. **结果优先：** 优先展示设备状态、管控结果和下一步操作，技术细节按需展开。
2. **高频突出：** 课堂控制、查看异常、发送消息在一至两次交互内完成。
3. **状态可信：** 区分已验证、等待上线、同步中、需核对、失败、缓存和未知，绝不因为界面美化而误报成功。
4. **操作安全：** 任何具有系统影响的操作沿用现有确认、设备绑定、签名、租约和恢复机制。
5. **轻量一致：** 视觉效果以清晰布局、统一组件和适度动效实现，不依赖大量透明模糊或复杂动画。

### 1.2 非目标

- 不重写 Student Agent、InputGuard、网站策略、AppLocker 或更新器。
- 不更换 Avalonia，不为桌面端引入 Electron/WebView 前端。
- 不修改现有 REST、LAN、签名、身份固定或版本比较协议。
- 不在 UI 中新增未经后端支持的状态或操作能力。
- 不把设计稿中模拟的设备状态、姓名、在线数作为实际产品数据。
- 不承诺未经实测的性能、浏览器拦截或键鼠恢复效果。

## 2. 导航与信息架构

### 2.1 桌面端主要导航

按使用频率组织：

| 一级入口 | 核心用途 |
|---|---|
| 课堂控制 | 当前教室、课堂状态、快捷管控、学生消息与全班通知 |
| 设备健康 | 设备状态、异常处理、完整诊断与安全修复 |
| 策略与预设 | 网站黑白名单、软件执行限制、系统限制及预设管理 |
| 更新与运维 | 软件版本、更新部署、进度和诊断信息 |

低频入口：

- 手机配对与连接
- 教室与学生名单
- 首次设置向导
- 管理员工具
- 帮助与反馈

将后四项适当收进侧栏底部的「设置 / 帮助」区域。首次设置完成后隐藏日常入口，但始终允许重新进入，且不能因配置异常导致无法恢复。

**当前仓库已把「地点与学生名单」「首次设置向导」移入「遇到问题？」折叠区。第一阶段仅调整其视觉样式和可发现性，不擅自变更配置数据或可访问条件。**

### 2.2 左侧导航

- 标准展开宽度：224px。
- 窄窗口可收缩至 64–72px 图标导航，但必须提供 tooltip 和可访问名称。
- 深蓝灰背景，不使用大面积渐变。
- 当前页面：低饱和青绿背景、清晰左侧指示条。
- 单个项目高度：44–48px。
- 图标：20px，统一线性风格。
- 品牌图标保留，名称简化为「VEYON CAMPUS / 教师控制台」。
- 「遇到问题？」改为独立的帮助入口或可展开区，不显示突兀的灰色大按钮。

### 2.3 全局顶部区域

每个页面使用一致的页头：

- 左侧：页面名称、当前校区 / 教室。
- 右侧：通知入口、学生消息入口、必要的当前页主操作。
- 有多个教室时显示选择器；只有一个教室时显示纯文本名称，不展示无意义下拉框。
- 课堂状态由已有课堂会话确定，不与网站限制和键鼠锁定混为一谈。

## 3. 视觉设计系统

### 3.1 颜色 Tokens

| Token | HEX | 用途 |
|---|---|---|
| `Color.Background` | `#F5F7FA` | 页面底色 |
| `Color.Surface` | `#FFFFFF` | 一级卡片 |
| `Color.SurfaceSubtle` | `#F8FAFC` | 次级容器 |
| `Color.Sidebar` | `#112C3D` | 深色导航 |
| `Color.SidebarHover` | `#1C4251` | 侧栏悬停 |
| `Color.SidebarActive` | `#19665F` | 当前导航 |
| `Color.Primary` | `#1769C2` | 主按钮、链接与强调 |
| `Color.PrimaryHover` | `#12569F` | 主按钮悬停 |
| `Color.TextPrimary` | `#172D3E` | 主要文字 |
| `Color.TextSecondary` | `#617487` | 辅助文字 |
| `Color.Border` | `#E1E8EE` | 分割线和边框 |
| `Color.Success` | `#14805D` | 经过验证的正常状态 |
| `Color.Warning` | `#AB610E` | 等待和需关注 |
| `Color.Danger` | `#C13434` | 失败及需人工处理 |
| `Color.Info` | `#1769C2` | 同步中、执行中 |
| `Color.Unknown` | `#64748B` | 未知、未读、缓存 |
| `Color.Focus` | `#257BD8` | 键盘焦点 |

状态卡片可使用与状态色对应的淡色底，但不使用大面积高饱和背景。

**状态不能只靠颜色表达**，必须同时使用文字、图标或形状。特别注意已响应但需要核对，不等于正常。

### 3.2 文字规范

优先使用 Windows 系统原生字体栈，例如 Segoe UI，并使用系统中文字体回退。不通过安装包分发第三方字体。

| 层级 | 建议字号 | 字重 |
|---|---:|---|
| 页面标题 | 24–26px | Bold |
| 区块标题 | 17–18px | SemiBold |
| 组件标题 | 15–16px | SemiBold |
| 正文 | 14px | Regular |
| 次要说明 | 12–13px | Regular |
| 状态数字 | 24–30px | SemiBold |

禁止将关键状态、失败原因或可点击文案压缩至 10–11px。只对非关键元数据使用小号文字。

### 3.3 间距、圆角与尺寸

统一使用 4px 基础尺度：

- 页面水平间距：24px，窄窗口可降至 16px。
- 页面区块间距：20–24px。
- 卡片内边距：16–20px。
- 同组控件间距：8–12px。
- 按钮高度：40–44px；主要操作优先 44px。
- 卡片圆角：12–14px。
- 输入框 / 按钮圆角：8–10px。
- 标签圆角：胶囊形。
- 设备列表基础行高：56–64px；展开后按内容增长。

阴影只应用于浮层、抽屉和关键悬浮面板。常规卡片优先使用浅边框，不要每张卡片都叠加阴影。

## 4. 统一组件规范

所有页面优先组合以下基础组件：

| 组件 | 行为规范 |
|---|---|
| `AppPageHeader` | 页面标题、教室上下文、可选操作区 |
| `AppSidebarItem` | 统一图标、选中、悬停和焦点状态 |
| `SectionCard` | 一致的留白、边框、标题和操作区 |
| `StatCard` | 大数字、状态标签、简短说明 |
| `StatusChip` | 正常、需关注、需人工处理、未知、执行中、缓存 |
| `ActionButton` | Primary / Secondary / Ghost / Danger 四种层级 |
| `ModeChoiceCard` | 课堂快捷管控中的网站限制和键鼠锁定模式选择；普通网站策略页独立于键鼠状态 |
| `DeviceRow` | 姓名、可选设备编号、状态、摘要、操作 |
| `EmptyState` | 未配置、无消息、无搜索结果、未开始课堂 |
| `LoadingState` | 不抹去旧数据的读取态；必要时显示局部骨架 |
| `ConfirmDialog` | 风险操作、目标范围和预期影响 |
| `SideDrawer` | 聊天、设备详情、低频辅助信息 |
| `Toast` | 非阻断性操作反馈，支持进一步查看详情 |

优先通过 Avalonia `Styles`、`ControlTheme`、`DataTemplate`、`UserControl` 和资源字典复用，不为每种卡片新写一个复杂控件类。

禁用按钮必须在视觉上区别于可点击的次级按钮，且保留简短禁用原因。Hover、Pressed、Focused、Disabled 的效果须分别设计，不得使用一个全局模板覆盖而破坏特殊按钮样式。

## 5. 课堂控制页设计

### 5.1 页面结构

从上到下分为：

1. 页面标题与课堂状态操作。
2. 紧凑课堂概览。
3. 课堂快捷管控。
4. 逐台执行进度。
5. 课堂互动相关入口。

取消当前上下重复出现的教室和设备数量说明。

### 5.2 课堂概览

建议使用一行四个紧凑指标：

- 课堂状态：未开始 / 进行中。
- 本堂课设备总数。
- 管控已核验设备数。
- 等待上线 / 需要核对设备数。

对于尚未取得可信设备状态的目标，必须显示等待或未知，不可简单归为正常或离线。

### 5.3 快捷管控

主要内容分为三个层级：

**当前网站预设**

展示：
- 当前保存的网站名单。
- 禁止条数、允许条数。
- 「管理规则」入口。

**管控方式**

两个尺寸一致的 `ModeChoiceCard`：
- 网站限制。
- 锁定键盘与鼠标。

视觉选择必须与实际执行状态分开：卡片被选中只是待操作选择，不代表 Agent 已执行。现有仓库中两种方式是直接操作按钮，因此第一轮可只统一视觉，不强制改为“先选择、后启用”的双步骤，除非在独立交互任务中完成确认逻辑与测试。

**执行操作**

- 启用所选管控。
- 解除本工具拥有的课堂管控。
- 当前阶段 / 结果摘要。

现有试点构建功能开关必须继续有效。普通构建不得因按钮重绘意外开放危险操作。

### 5.4 逐台执行进度

采用紧凑的表格 / 可展开列表：

| 学生 | 当前状态 | 简短说明 | 操作 |
|---|---|---|---|
| 小子 | 待核对 | 等待可信状态 | 查看 |
| 也一样 | 等待上线 | 尚未收到 Agent 响应 | 查看 |
| 12321 | 已读回 | 网站策略已由 Agent 报告 | 查看 |

- 正文优先显示学生姓名。
- 维护视图和详情内保留设备编号及位置，以便未填写姓名时定位。
- 显示信息来源及更新时间。
- 对超过有效期的状态明确标识“旧状态”或“本地缓存”。
- 同一设备多个异常不互相覆盖。
- 不因自动刷新重置滚动位置、选中项或展开状态。

### 5.5 空状态

- 未开始课堂：显示开始课堂引导，快捷管控不可执行。
- 无设备：显示教室/名单设置入口。
- 没有网站规则：显示管理名单入口，不发送空规则。
- 设备都未响应：保留设备行并提示未取得可信状态。
- 普通构建禁用试点：显示简短说明，保留安全解除入口。

## 6. 设备健康页设计

### 6.1 布局

1. 标题与「读取完整诊断」。
2. 五个等高的轻量概览卡片：正常、需关注、需人工处理、未收到回执、等待读取。
3. 一条读取进度栏。
4. 异常摘要（有异常时优先）。
5. 搜索、筛选与设备列表。
6. 单机详情或按需完整诊断。

将以下内容移入“诊断详情”或开发者信息：
- 单轮耗时细项。
- 并发上限说明。
- 超时与退避实现细节。
- Agent 协议与版本内部描述。

### 6.2 状态语义

- **正常：** 有新鲜可信回执且检查通过。
- **需关注：** 有可信回执，但有尚待处理问题或数据不完整。
- **需人工处理：** 存在身份、事务或其他不能自动修复的问题。
- **未收到回执：** 已符合现有失败判定条件；不得直接显示“电脑关机”。
- **等待读取：** 尚无足够信息形成结论。
- **本地缓存：** 仅用于显示上次记录，不能作为当前在线或健康结论。

这些标签必须复用现有业务状态，不要从 UI 颜色反推业务结论。

### 6.3 列表

设备列表优先为行式布局，而不是一个设备套一张很高的卡片。

每行包含：
- 学生姓名。
- 设备编号/座位位置（详情或维护模式）。
- 主要状态。
- 最多一行异常摘要。
- 最近有效状态时间。
- 查看详情操作。

多项异常、版本明细、恢复条件、原始诊断都放入展开区域。

### 6.4 自动刷新

现有轻量签名健康轮询逻辑保持不变，UI 必须做到：
- 保持当前列表和行的稳定身份。
- 只更新有变化的内容。
- 暂时失败不清空设备行。
- 缓存数据与新鲜回执视觉区分。
- 不因为每轮刷新重新创建所有卡片。
- 不在窗口最小化或页面不可见时引入额外 UI 读取负载。

## 7. 学生聊天与全班通知

### 7.1 学生一对一聊天

取消现在课堂页底部的大块常驻聊天卡片，改为全局右侧聊天抽屉。

主要入口：
- 顶栏消息图标。
- 未读数提示。
- 有新的学生消息时显示非阻断提醒。

聊天抽屉分为：
1. 标题和关闭按钮。
2. 学生搜索/切换。
3. 学生姓名、座位及可信连接状态。
4. 消息时间线。
5. 底部消息输入和发送操作。

交互原则：
- 跨页面切换保持打开状态。
- 切换学生保留各会话未发送草稿。
- 断线时保留草稿，但不能显示已成功发送。
- 空会话显示小型空状态，不出现巨大灰色占位区域。
- 沿用 Enter 发送、Shift+Enter 换行以及中文输入法候选确认逻辑。
- 不重新设计聊天通信协议。

### 7.2 聊天抽屉尺寸

- 大窗口（建议 ≥1500px）：可使用右侧停靠面板，宽 340–380px。
- 中等窗口（约 1100–1499px）：覆盖式右侧抽屉，避免压缩主要管控区。
- 小窗口：宽度取窗口允许的合理范围，至少保留显著关闭操作和键盘焦点管理。
- 允许 Esc 关闭，关闭后焦点返回原按钮。
- 不遮挡安全确认对话框。

### 7.3 全班通知

不再常驻整张大型消息编辑卡片。

改为课堂工具区「发送全班通知」入口，点击后打开简洁编辑弹窗：
- 文字内容。
- 受影响的当前课堂目标。
- 有效期说明。
- 发送确认。
- 逐台交付结果摘要。

沿用现有通知有效期和学生端显示逻辑，不修改通知传输机制。

## 8. 手机配对与连接

### 8.1 推荐页面结构

将原独立窗口的内容重新设计为：

**上方：连接状态**
- 已启动 / 未启动 / 故障。
- LAN 连接状态。
- 停止服务、刷新等操作。

**左侧：连接新手机**
- 二维码。
- 8 位连接码。
- 过期时间和刷新。
- 简短连接指导。

**右侧：配对请求**
- 设备名称。
- 请求时间和来源提示。
- 允许 / 拒绝。

**下方：已配对设备**
- 已批准的设备列表。
- 连接记录、撤销入口。
- 可展开的证书和高级诊断信息。

### 8.2 迁移策略

第一阶段优先美化现有 `TeacherMobileControlWindow.axaml`，保留独立窗口、DataContext、配对管理器和事件调用。

第二阶段才考虑将同样的页面内容作为主窗口设置页或抽屉宿主。迁移前必须验证证书展示、配对批准、服务停止和窗口关闭时的生命周期。

不通过样式重构改变 HTTPS、证书信任、配对凭据、审批和撤销安全边界。

## 9. 策略与预设页

保持三个主要分区：
- 网站限制。
- 应用限制。
- 系统限制。

视觉调整：
- 一级策略导航清楚。
- 当前生效策略、待处理状态和编辑区分开。
- 长说明改为就近提示或折叠说明。
- 软件运行保护单独突出，不要求教师先扫描程序。
- 应用目录读取、手工 SID、哈希规则等进入高级区域。
- 启用与解除长期策略继续显示账户范围和影响确认。

不得把课堂快捷解除按钮扩展为解除 AppLocker 长期基线或学校其他策略。

## 10. 更新与运维页

建议使用：
- 当前教师端版本。
- 学生端版本摘要。
- 更新可用性 / 兼容状态。
- 当前批次进度。
- 逐台结果列表。
- 失败项和诊断入口。

原则：
- 进度实时变化，但列表稳定。
- 区分准备、传输、校验、安装、完成与失败。
- 把详细耗时、日志和环境信息放在展开详情。
- 不把“更新命令已受理”当作更新安装完成。

## 11. 动画与交互反馈

设计目标，而非框架性能保证：

| 交互 | 建议时长 |
|---|---:|
| 按钮悬停 | 100–140ms |
| 卡片选中反馈 | 120–160ms |
| 抽屉展开/关闭 | 180–220ms |
| 页面局部切换 | 120–180ms |
| 状态变化 | 优先即时更新，不做复杂动画 |

规则：
- 动画仅作用于局部属性，避免整个 70 台设备列表参与动画。
- 设备状态数字更新不反复弹跳。
- 页面切换不使用大幅平移。
- 遵守系统减少动画偏好；无法可靠取得偏好时允许产品配置关闭动效。
- 低性能环境优先关闭阴影动画、模糊与非必要过渡。

## 12. 响应式布局与可访问性

必须验收：
- 1024×768 及更宽的实际工作区。
- 1366×768、1920×1080。
- Windows 100%、125%、150% 显示缩放。
- 窗口非最大化时的滚动、抽屉、确认框和导航。
- Windows 高对比度及键盘焦点可见性。
- Tab / Shift+Tab、Enter、Esc 基本行为。
- 长中文姓名、长错误文本和较大的系统字体。
- 空状态、加载中、失败、离线、部分成功、旧缓存。

任何危险操作都必须能通过键盘完成确认或取消，并保留醒目的返回路径。

## 13. 性能与资源约束

目标硬件包含 8GB 内存 Windows 教师机，并需要支持 10–70 台学生设备。

建议验收指标：

- 静态界面不发生持续高 CPU 使用。
- 课堂页、健康页正常滚动时无明显卡顿。
- 自动状态刷新时不重置滚动位置。
- 聊天抽屉反复打开/关闭没有明显内存持续增长。
- 70 台设备展示保持有界视觉元素和 UI 更新负载。
- 切换页面不触发与页面无关的网络请求。
- 不因为动画或样式引入高频 Dispatcher 工作。

需要实测 UI 线程耗时、布局/绘制负担、GC 和整体内存。具体数值基线由 Phase 0 在真实教师电脑采集，不预先虚构。

列表实现要点：
- 优先使用支持虚拟化的列表控件和有界滚动宿主。
- 不把需要虚拟化的长列表直接放在无界高度 `StackPanel` 或外层纵向 `ScrollViewer` 中。
- 使用稳定设备身份作为逻辑键。
- 仅更新变化的设备项。
- 页面不可见时暂停纯视觉计时器，保持既有必须运行的业务循环。

## 14. 技术边界

保留：
- `TeacherMobileControlManager` / `TeacherMobileControlServer`。
- `TeacherClassroomQuickControlService`。
- 现有签名状态与设备健康聚合服务。
- InputGuard 租约及恢复逻辑。
- 网站规则、应用规则及长期系统策略的真实所有权和版本语义。
- 当前课堂会话固定目标集合。
- 手机 HTTPS、配对与证书信任架构。
- Classroom Quick Control Pilot 构建门。

UI 重构不得新增自动锁定、新的离线重放行为、新的“已生效”判定或不受已有校验的恢复按钮。

## 15. 视觉验收标准

达到以下条件才算 UI 重构完成：

1. 四个主页面采用同一设计系统。
2. 教师能在课堂首页快速识别当前教室、课堂状态、主要管控方式和异常数。
3. 不再出现无内容的大面积聊天容器。
4. 聊天通过抽屉使用，课堂管控操作始终可见或可快速返回。
5. 健康列表在读取、刷新、缓存、断网时保持稳定。
6. 所有状态颜色与用词语义一致。
7. 所有主要按钮具有默认、悬停、按下、聚焦、禁用状态。
8. 桌面 1366×768 可以正常完成课堂操作，不存在控件重叠或关键按钮被裁切。
9. 最新版业务行为、协议检查、课堂模式互斥与安全解除均未退化。
10. 经过实际 Windows 教师机和学生测试机验收，才能标记为可发布。
