# Windows 安装包与下载分发

## 给测试者的下载方式

教师电脑和学生电脑各有一个 ZIP。下载时按电脑角色选择对应包；不要把两个角色的安装包互换。

解压 ZIP 后会看到“安装前请阅读.md”和一个中文命名的 EXE。先读说明，再双击 EXE。Windows 如果询问是否允许应用更改设备，请确认安装包来自学校提供的下载页；不确定时选择“否”并联系管理员。不要关闭 Windows 安全防护。

## 文件放在哪里

- GitHub Release 是源文件和应用内更新下载入口，保存角色 ZIP、原始 EXE 和 `SHA256SUMS`。
- GitCode/AtomGit Release 只镜像两个 ZIP 和 `SHA256SUMS-BUNDLES`，供大陆用户优先尝试手动下载。它目前是待实测的镜像，不承诺速度或附件大小上限。
- 不使用 COS/CloudBase 存放这些面向用户的下载文件。

ZIP 只把安装器和说明放在一起，不会显著缩小约 128–145 MB 的安装器。GitHub Release 的单个附件上限足够容纳这些文件。GitCode/AtomGit 文档支持 Release 附件，但没有找到可据此确认本项目文件大小的公开上限，所以需要先上传实际文件并校验。

## 首次启用 GitCode 镜像

在 GitHub 仓库的 **Settings → Secrets and variables → Actions** 中设置为仓库级配置：

| 类型 | 名称 | 值 |
| --- | --- | --- |
| Variable | `GITCODE_OWNER` | GitCode/AtomGit 用户或组织名 |
| Variable | `GITCODE_REPO` | 对应仓库名 |
| Secret | `GITCODE_TOKEN` | 有权通过 API 创建 Release/Tag、上传附件和读取附件的个人访问令牌 |

`GITCODE_OWNER` 和 `GITCODE_REPO` 建在 **Repository variables**，`GITCODE_TOKEN` 建在 **Repository secrets**。不要只放在 `production-release` Environment：Beta 发布作业不引用该 Environment，仓库级配置才能供各个镜像工作流共同读取。

### 这三个值从哪里找

- 打开 GitCode 上准备存放镜像的仓库。仓库地址 `https://gitcode.com/<owner>/<repo>` 中，`<owner>` 填入 `GITCODE_OWNER`，`<repo>` 填入 `GITCODE_REPO`；两项都只填路径名称，不要填完整网址。测试者要免登录下载时，仓库需要设为公开。
- 创建令牌：GitCode 右上角头像 → **个人设置** → **访问令牌** → **新建访问令牌**。给令牌授予访问目标仓库及执行 Release 写操作所需的权限，并设置合理有效期。官方文档没有列出单独的 Release 附件权限名称；创建后令牌只显示一次，立即复制到上面的 GitHub `GITCODE_TOKEN` Repository secret。
- 不要把令牌放进代码、`.env` 文件或聊天消息中。

不要把访问令牌提交到仓库或粘贴到聊天中。保持这些配置全部为空时，常规发布只提供 GitHub 下载，不会尝试发布 GitCode 镜像；配置不完整时，工作流会在发布前停止。GitCode 上传或读回失败时，GitHub Release 可能已经创建，Actions 会标记失败，修复配置后可重跑。

为现有 `beta-v1.0.3` 补发时，在 GitHub Actions 中运行 **Mirror existing Beta download bundles**，选择 `beta-v1.0.3`。工作流会从已发布的 GitHub Release 下载原 EXE，先核对原有 SHA-256，再生成 ZIP；不会修改已发布的 GitHub Beta Release。成功后会把 ZIP 上传到 GitCode、读回并比对文件大小和 SHA-256，并在 Actions 摘要中给出 GitCode Release 链接。

第一次实际使用时，应在至少一个大陆网络环境分别下载教师包和学生包，并用 ZIP 内的 EXE 与 GitCode 附件列表确认下载完整。确认成功后再开始分发测试包。如果 GitCode 附件上限或速度不合适，GitHub ZIP/EXE 仍可用，但暂时没有国内镜像。

## 后续版本

推送 `vX.Y.Z` 或 `beta-vX.Y.Z` Tag 后，Windows 打包工作流会生成两个角色 ZIP，并在 GitHub Release 发布 ZIP、EXE 和对应校验值。配置了 GitCode 后，工作流会通过 Release API 在相同源提交创建 Tag/Release，上传两个 ZIP 和 `SHA256SUMS-BUNDLES`，再读回校验。新版本的 ZIP 校验值会同时列在 GitHub 的 `SHA256SUMS` 和 GitCode 的 `SHA256SUMS-BUNDLES` 中。CloudBase 应用内更新仍从 GitHub 下载 EXE。
