# Windows 安装包与下载分发

## 给测试者的下载方式

Teacher 版用于教师电脑，Student 版用于学生电脑。请从同一版本的 Release 下载对应 EXE 和 SHA256SUMS，按文件名核对 SHA-256；不要交换两个角色的安装器，也不要把 GitHub 的源码 ZIP 当成安装包。

[GitHub Releases](https://github.com/Ljc798/veyon-campus-deployment/releases) 是正式发布页。维护者也会把两个 EXE 和 SHA256SUMS 上传到 [GitCode Releases](https://gitcode.com/ljc_1126/veyon-campus-deployment/releases)，供用户手动下载。GitCode 附件不会由 GitHub Actions 自动同步；应用内更新经 CloudBase 验签后跳转到 GitCode Release 下载 EXE。GitHub Release 保留构建资产，并作为本机 GitCode 上传器的文件来源。

## 本地推送 GitCode 源码

先把本机 develop 分支推到 GitHub 和 GitCode。GitCode 源码推送从维护者本机执行，不经过 GitHub Actions。请使用已配置凭据的 Git，不要用 --force 覆盖远端历史：

~~~powershell
$gitCodeRepo = 'https://gitcode.com/ljc_1126/veyon-campus-deployment.git'
git push origin develop
git push $gitCodeRepo HEAD:refs/heads/develop
~~~

发布 tag 后，也要从本机把同一 tag 推到 GitCode，使 GitCode Release 关联到相同源提交：

~~~powershell
$tag = 'vX.Y.Z'
git push origin $tag
git push $gitCodeRepo "refs/tags/$tag:refs/tags/$tag"
~~~

如 GitCode 拒绝快进推送，应先拉取并检查两个分支的差异；不要强制覆盖。

## 发布 GitCode 安装器附件

将稳定版 vX.Y.Z tag 推送到 GitHub 后，Windows installers 工作流会在 Windows runner 上构建 Teacher/Student 安装器、运行 API/.NET 检查和安装卸载冒烟测试，然后将 EXE 与 SHA256SUMS 发布到 GitHub。CloudBase 发布器会校验 GitCode 公共下载 URL 的附件字节后再发布签名版本元数据；因此先等 GitHub Release 可下载，再由本机上传 GitCode 附件。GitHub Actions 不推送 GitCode 源码，也不上传 GitCode 附件。

确认 GitCode 已有指向相同提交的 tag 后，在本机仓库根目录运行：

~~~powershell
./scripts/upload-gitcode-release.ps1 -Tag vX.Y.Z
~~~

脚本会从 GitHub Release 下载两个 EXE 和 SHA256SUMS，在本机核对摘要，再提示输入 GitCode personal access token（输入隐藏）。随后脚本在 GitCode 创建或更新对应 Release、上传三个文件，并重新读取远端附件验证文件大小和 SHA-256。若 GitHub tag 工作流的 publish-release job 已先因 GitCode URL 返回 404 失败，完成本机上传后只重跑失败的 publish-release job；CloudBase 会在这次重试中校验 GitCode 文件后写入签名版本元数据。请勿把 token 写入仓库、脚本或共享文档。

### Windows 凭据管理器中的 GitCode 凭据

本机 GitCode 凭据已保存在 Windows 凭据管理器的“普通凭据”中，目标为 `git:https://gitcode.com`。运行发布命令时先确认使用的是保存该凭据的同一个 Windows 账户；`$env:GITCODE_TOKEN` 为空只表示当前进程没有设置环境变量，不能据此判断凭据管理器里没有凭据，也不要再次向维护者索要凭据。应先通过已配置的 Git Credential Manager 读取凭据，并把 password 字段只保存在当前 PowerShell 进程内传给上传脚本，不要打印或写入文件。例如：

~~~powershell
$credentialLines = "protocol=https`nhost=gitcode.com`n`n" | git credential fill
$passwordLine = $credentialLines | Where-Object { $_.StartsWith('password=') } | Select-Object -First 1
if (-not $passwordLine) { throw '当前 Windows 账户未能从 Git Credential Manager 读取 GitCode 凭据。' }
$env:GITCODE_TOKEN = $passwordLine.Substring('password='.Length)
Remove-Variable credentialLines, passwordLine
try {
    ./scripts/upload-gitcode-release.ps1 -Tag vX.Y.Z
}
finally {
    Remove-Item Env:\GITCODE_TOKEN -ErrorAction SilentlyContinue
}
~~~

如果 Git Credential Manager 未返回凭据，先核对 Windows 凭据管理器条目和当前 Windows 账户，再判断是否需要其他处理；不要仅检查环境变量或换到另一个账户后就报告凭据不存在。

脚本支持稳定版 vX.Y.Z 和预发布 beta-vX.Y.Z。下载文件保存在被 Git 忽略的 artifacts/gitcode-upload/<tag>/；上传失败时可复用该目录重新运行，脚本会先验证本地文件。若远端已有不同内容的附件，脚本会停止，不覆盖该附件。

## 发布前后检查

- GitHub 与 GitCode 的 tag 指向同一个提交。
- GitHub Release 包含 Teacher EXE、Student EXE 和 SHA256SUMS。
- GitCode Release 同样包含三个文件，上传后读回的 SHA-256 与 GitHub 清单一致。
- GitHub Actions 的 build、安装卸载检查和 CloudBase 签名元数据步骤均成功。
- 真实 Windows 设备上的策略、证书、局域网行为和更新恢复仍需单独验收；自动构建通过不代表课堂实机验收通过。
