# Windows 安装包与下载分发

## 给测试者的下载方式

教师电脑和学生电脑各有一个 ZIP。下载时按电脑角色选择对应包；不要把两个角色的安装包互换。

解压 ZIP 后会看到“安装前请阅读.md”和一个中文命名的 EXE。先读说明，再双击 EXE。Windows 如果询问是否允许应用更改设备，请确认安装包来自学校提供的下载页；不确定时选择“否”并联系管理员。不要关闭 Windows 安全防护。

## 文件放在哪里

- GitHub Release 是源文件和应用内更新下载入口，保存角色 ZIP、原始 EXE 和 `SHA256SUMS`。
- GitCode/AtomGit Release 只镜像两个 ZIP 和 `SHA256SUMS-BUNDLES`，供大陆用户优先尝试手动下载。它目前是待实测的镜像，不承诺速度或附件大小上限。
- 不使用 COS/CloudBase 存放这些面向用户的下载文件。

ZIP 只把安装器和说明放在一起，不会显著缩小约 128–145 MB 的安装器。GitHub Release 的单个附件上限足够容纳这些文件。GitCode/AtomGit 文档支持 Release 附件，但没有找到可据此确认本项目文件大小的公开上限，所以需要先上传实际文件并校验。

## 首次启用 GitCode 镜像

在 GitHub 仓库的 **Settings → Secrets and variables → Actions** 中设置为仓库级配置：

| 类型 | 名称 | 值 |
| --- | --- | --- |
| Variable | `GITCODE_OWNER` | GitCode/AtomGit 用户或组织名 |
| Variable | `GITCODE_REPO` | 对应仓库名 |
| Secret / 本地环境变量 | `GITCODE_TOKEN` | 自动同步源码时用于推送 `develop`；本机 Release 上传脚本需具备目标仓库 Release 附件读写权限的令牌；网页手动上传不需要此令牌 |

`GITCODE_OWNER` 和 `GITCODE_REPO` 建在 **Repository variables**。源码镜像工作流使用 `production-release` Environment；建议把该工作流所需的 `GITCODE_TOKEN` 放在 Environment secrets 中。仓库级 secret 也可供该工作流读取。本机运行 Release 上传脚本时，则把同名变量设置在当前 PowerShell 进程中；网页手动上传不需要 token。

### 这三个值从哪里找

- 打开 GitCode 上准备存放镜像的仓库。仓库地址 `https://gitcode.com/<owner>/<repo>` 中，`<owner>` 填入 `GITCODE_OWNER`，`<repo>` 填入 `GITCODE_REPO`；两项都只填路径名称，不要填完整网址。测试者要免登录下载时，仓库需要设为公开。
- 若要自动镜像 `develop` 源码分支，令牌需有目标仓库代码推送权限并保存为 GitHub `production-release` Environment secret。若要由本机脚本上传 Release 附件，令牌还需有目标仓库 Release 创建/更新、附件上传和读回权限；脚本运行时从当前 PowerShell 进程的 `GITCODE_TOKEN` 读取。
- 不要把令牌放进代码、`.env` 文件或聊天消息中。

不要把访问令牌提交到仓库或粘贴到聊天中。GitHub 工作流只镜像源码分支，不会向 GitCode 转发安装包。需要发布 GitCode Release 附件时，可由维护者在网页手动上传，也可从本机运行后文脚本上传本地 ZIP 并自动读回校验。

为现有 `beta-v1.0.3` 准备 GitCode 附件时，**Mirror existing Beta download bundles** 工作流会从已发布的 GitHub Release 下载两个 EXE 和 `SHA256SUMS`，先核验原文件摘要，再生成 Teacher/Student ZIP 与 `SHA256SUMS-BUNDLES`。它只把这些文件保存为 GitHub Actions artifact，**不会上传到 GitCode，也不会创建 GitCode Release**。如果工作流手动触发入口不可用，可在仓库根目录用 `scripts/create-windows-download-bundles.ps1` 本地生成两个 ZIP，再计算 `SHA256SUMS-BUNDLES`。当前该手动工作流尚未注册到默认分支 `main`；入口不可见时使用本地脚本即可。

该工作流还要求原始 `SHA256SUMS` 恰好有两个记录（Teacher/Student EXE）。如果清单还包含其他资产记录，工作流会报错；下面的本地流程只按文件名核对这两个 EXE，适用于包含更多记录的清单。

本地生成现有 Beta 包示例。先用已安装并登录的 GitHub CLI 下载 GitHub Release 里的原始安装器与摘要文件：

```powershell
$bundleDir = 'artifacts\gitcode-v1.0.3'
New-Item -ItemType Directory -Force -Path $bundleDir | Out-Null
gh release download beta-v1.0.3 -R Ljc798/veyon-campus-deployment `
  --pattern 'VeyonCampus-Student-Setup-1.0.3-win-x64.exe' `
  --pattern 'VeyonCampus-Teacher-Setup-1.0.3-win-x64.exe' `
  --pattern 'SHA256SUMS' `
  --dir $bundleDir
```

逐一比对 `SHA256SUMS` 中这两个 EXE 的命名记录；忽略清单里其他资产的记录：

```powershell
$expectedNames = @(
  'VeyonCampus-Student-Setup-1.0.3-win-x64.exe',
  'VeyonCampus-Teacher-Setup-1.0.3-win-x64.exe'
)
$records = @{}
foreach ($line in Get-Content -LiteralPath (Join-Path $bundleDir 'SHA256SUMS')) {
  if ($line -match '^([0-9a-fA-F]{64})  (.+)$') {
    $records[$Matches[2]] = $Matches[1].ToLowerInvariant()
  }
}
foreach ($name in $expectedNames) {
  if (-not $records.ContainsKey($name)) { throw "SHA256SUMS 缺少记录：$name" }
  $actual = (Get-FileHash -LiteralPath (Join-Path $bundleDir $name) -Algorithm SHA256).Hash.ToLowerInvariant()
  if ($actual -cne $records[$name]) { throw "原始安装器摘要不匹配：$name" }
}
```

随后生成 ZIP 和 `SHA256SUMS-BUNDLES`：

```powershell
$bundleDir = 'artifacts\gitcode-v1.0.3'
./scripts/create-windows-download-bundles.ps1 `
  -Version '1.0.3' `
  -StudentInstallerPath "$bundleDir\VeyonCampus-Student-Setup-1.0.3-win-x64.exe" `
  -TeacherInstallerPath "$bundleDir\VeyonCampus-Teacher-Setup-1.0.3-win-x64.exe" `
  -OutputDirectory $bundleDir `
  -Beta

$zipNames = @(
  'VeyonCampus-Student-Setup-1.0.3-win-x64.zip',
  'VeyonCampus-Teacher-Setup-1.0.3-win-x64.zip'
)
$sumLines = foreach ($name in $zipNames) {
  $hash = (Get-FileHash -LiteralPath (Join-Path $bundleDir $name) -Algorithm SHA256).Hash.ToLowerInvariant()
  "$hash  $name"
}
[IO.File]::WriteAllLines(
  (Join-Path $bundleDir 'SHA256SUMS-BUNDLES'),
  $sumLines,
  [Text.UTF8Encoding]::new($false)
)
```

上传步骤：

1. 确认目标 GitCode 仓库为公开仓库，并确认仓库里已有对应 tag，且它指向与 GitHub Release 相同的源提交。GitCode 创建 Release 前要求该 tag 已存在；当前源码镜像工作流只推送 `develop`，不会同步 Beta tag。若 GitCode 尚无 `beta-v1.0.3`，在本地仓库运行以下命令把 GitHub 上的同一 tag 推过去（把地址替换成自己的 GitCode 仓库；不要用 `--force`）：

   ```powershell
   $gitCodeRepo = 'https://gitcode.com/你的用户名/你的仓库名.git'
   git fetch https://github.com/Ljc798/veyon-campus-deployment.git tag beta-v1.0.3
   git push $gitCodeRepo refs/tags/beta-v1.0.3:refs/tags/beta-v1.0.3
   ```

   现有测试包使用 `beta-v1.0.3`；稳定版只能使用已经核准的 `vX.Y.Z`。
2. 在 GitCode 仓库的 **发行版/Releases** 页面创建对应 Release，上传两个角色 ZIP 和 `SHA256SUMS-BUNDLES`。GitCode 只放 ZIP，不必重复上传原始 EXE。
3. 保存后从 GitCode 页面重新下载两个 ZIP，用本地 `SHA256SUMS-BUNDLES` 核对 SHA-256；再用未登录浏览器确认公开下载可用。记录 GitCode Release 页面链接，供网站下载按钮使用。

网页附件大小限制尚未由本项目实测。如果 GitCode 拒绝约 128–145 MB 的 ZIP，先停止分发并确认平台实际限制，再确定分卷或替代下载方案；不要把未验证的附件链接放到网站。

第一次实际使用时，应在至少一个大陆网络环境分别下载教师包和学生包，并用 ZIP 内的 EXE 与 GitCode 附件列表确认下载完整。确认成功后再开始分发测试包。如果 GitCode 附件上限或速度不合适，GitHub ZIP/EXE 仍可用，但暂时没有国内镜像。

## 从本机上传正式版 GitCode Release

以下示例适用于本地已构建的稳定版。脚本直接读取本机 ZIP，不从 GitHub 下载资产；它会校验源 tag/提交、创建或核对正式 Release、上传附件，并逐个读回比对文件大小和 SHA-256。

在仓库根目录使用 PowerShell 7：

```powershell
$version = '1.0.5'
$tag = "v$version"
$releaseDir = "artifacts\release-local-$version"
$env:GITCODE_OWNER = '你的 GitCode 用户名或组织名'
$env:GITCODE_REPO = '你的仓库名'

# GitHub Desktop 自带的 Git 通常不在 PATH 中；需要时将其 cmd 目录加入当前进程 PATH。
$gitExe = Get-ChildItem -LiteralPath (Join-Path $env:LOCALAPPDATA 'GitHubDesktop') -Filter 'git.exe' -File -Recurse |
  Where-Object FullName -Match '\\cmd\\git\.exe$' | Select-Object -First 1
if (-not $gitExe) { throw '找不到 GitHub Desktop 自带的 git.exe。' }
$env:PATH = "$(Split-Path -Parent $gitExe.FullName);$env:PATH"

$commit = (& $gitExe.FullName -C $PWD rev-parse "$tag^{commit}").Trim()
if ($LASTEXITCODE -ne 0) { throw "找不到本地稳定标签 $tag。" }

$secureToken = Read-Host 'GitCode Release 上传令牌' -AsSecureString
$tokenPointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secureToken)
try {
  $env:GITCODE_TOKEN = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($tokenPointer)
  node scripts/publish-gitcode-release.cjs `
    $tag $version $commit `
    "$releaseDir\release-notes.md" `
    "$releaseDir\VeyonCampus-Student-Setup-$version-win-x64.zip" `
    "$releaseDir\VeyonCampus-Teacher-Setup-$version-win-x64.zip" `
    "$releaseDir\SHA256SUMS-BUNDLES"
  if ($LASTEXITCODE -ne 0) { throw 'GitCode Release 上传或读回校验失败。' }
}
finally {
  Remove-Item Env:GITCODE_TOKEN -ErrorAction SilentlyContinue
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($tokenPointer)
}
```

在 GitHub Actions 发布稳定版之前，应先将本地 `develop` 提交推到 GitCode 源码仓库，使 Release API 能解析目标提交。上传完成后检查脚本输出的 GitCode Release 页面和两份 ZIP 的 SHA-256；官网链接应在公开下载验证通过后再更新。

## 后续版本

推送 `vX.Y.Z` 或 `beta-vX.Y.Z` Tag 后，Windows 打包工作流会在 GitHub Release 发布角色 ZIP、原始 EXE 和 `SHA256SUMS`。GitCode Release 需另行创建并人工上传两个 ZIP 与 `SHA256SUMS-BUNDLES`；上传后应读回校验。CloudBase 应用内更新仍从 GitHub 下载 EXE。
