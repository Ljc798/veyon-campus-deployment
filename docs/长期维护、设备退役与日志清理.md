# 长期维护、设备退役与日志清理

本文记录当前代码支持的升级、密钥、设备退役和资料清理边界。部署规模扩大前，校区负责人还需确定未设定的保留期限，并由学校 IT 核实 CloudBase 日志策略。代码已有某项机制，不代表已完成 Windows 或线上验收。

## 1. 应用升级与断网维护

### 有网络时

- TeacherConsole 与 StudentSetup 的应用内更新只查询 CloudBase `veyon-api`。客户端先用安装包固定的 Developer Release 公钥验证 RSA-PSS 清单，再核对角色、版本、文件名、大小和 SHA-256；更新需教师确认，不自动降级。
- CloudBase 是应用内更新源。GitHub 与 Gitee Release 是相同安装器和 `SHA256SUMS` 的人工下载镜像；客户端不会在 CloudBase 不可用时自动切换到镜像。
- 下载并安装前记录角色、版本和 SHA-256。更新失败时保留错误证据并按更新助手的恢复结果复核；不要删除恢复区或手动清理暂存目录。

### 目标电脑断网时

离线导入校区配置包与离线升级 TeacherConsole/StudentSetup 是两件事。StudentSetup 可从本机磁盘导入已验证的校区配置文件夹；这不会更新 StudentSetup、TeacherConsole 或 Veyon。

教师控制台更新页现有离线包流程代码：联网时检查已签名的 TeacherConsole 发布，在导出目录同时写入安装器和 `.release.json`；目标教师机用已安装程序内嵌的 Developer Release 公钥验证签名、角色、版本、API 来源、文件名、大小和 SHA-256，再将包复制到本机更新暂存区。只有高于当前版本的包可交给更新助手；启动前助手会再次验证，失败时按更新助手恢复结果复核。工作区便携检查覆盖成功暂存、重复安全重跑、摘要不符拒绝和不覆盖现有文件；Windows 导出、U 盘转移、UAC 安装与失败回滚尚未实机验收，因此仍不能作为已支持的正式操作流程。

实际操作时，必须在目标机保留此前已信任的 TeacherConsole 安装，并确保它嵌入的生产公钥与发布清单签名密钥匹配。联网教师端在“更新”页检查版本并导出到学校批准的加密介质；安装器和同名 `.release.json` 必须一并转移且不得改名。目标机从 `Program Files` 中启动已安装 TeacherConsole，在“更新 → 离线安装器验证”选择 EXE；验签成功后核对界面显示的版本与摘要，再明确点击安装按钮。该入口目前只支持 TeacherConsole 自身更新。StudentSetup 离线升级入口和整条 Windows 现场流程仍未验收。生产 Developer Release 公钥尚未配置到发布构建前，应继续使用测试版本/隔离环境，不要把测试签名包投入正式机房。

没有完成上述验证时，保持已验收版本；如安全更新必须上线，先安排目标电脑的受控联网窗口，使用内置更新流程。GitHub/Gitee Release 页面可用于人工取得同版本文件，但不能替代签名验收。

## 2. 教师密钥保管与迁移

项目涉及的密钥用途不同，不能互相替代：

| 密钥 | 当前存放与代码行为 | 维护要求 |
| --- | --- | --- |
| 校区 Veyon 身份密钥 | Veyon 管理的密钥库。教师学生包生成器复用已有密钥，只导出公钥；私钥不进入学生包或部署快照。 | 教师电脑迁移前保留原电脑、Windows 用户和 Veyon 密钥库。项目尚无受保护的私钥导出/导入和恢复验收；不要通过复制未受保护文件、普通共享盘或配置包迁移私钥。 |
| 教师网站策略签名密钥 | 当前 Windows 用户的 `CurrentUser\My` 证书库；RSA CNG 私钥创建为不可导出，并在当前用户注册表记录固定证书指纹。学生包只带公钥。 | 目前没有应用内备份/恢复能力。不要删除原教师用户配置或在新电脑自动创建替代密钥。若原密钥不可恢复，须显式轮换，并重新向学生设备分发含新公钥的校区包后再推送策略。 |
| Developer Release 发布密钥 | Release 私钥只供受控发布任务签署版本清单；它与校区教师密钥、CloudBase 服务密钥不同。 | 仅保存在批准的密钥库/受保护发布环境中；不得提交 Git、放入安装器、浏览器变量或 CloudBase。正式公私钥和恢复备份配置完成前，不发布生产 tag。 |

学生端执行前状态快照使用创建快照的 Windows 用户 DPAPI 保护，可能包含原 Veyon 配置；它不是教师私钥备份，也不能用于另一用户或另一台电脑恢复教师身份。快照只用于查看和人工恢复核对。

### 教师电脑更换/退役的临时规则

1. 在原教师电脑上继续工作；在学校 IT 完成独立的密钥恢复方案前，不卸载 Veyon、不删除原 Windows 用户配置、不清空设备。
2. 由学校 IT 核实 Veyon 私钥与网站策略签名证书的备份/恢复能力，并比较恢复后的公钥指纹；普通磁盘镜像或用户目录复制尚不等于已验证的 CNG 私钥恢复。
3. 若没有可验证的密钥恢复方式，先保留原电脑作为唯一签名设备。需要换钥时按密钥轮换安排，在测试学生机验证重新部署信任后，才退役原设备。
4. 设备退役前撤销该设备上的学校账号/远程管理访问，按学校 IT 的资产处置、磁盘擦除或重灌流程处理。项目没有远程擦除或逐机 CloudBase 资产注销功能。

## 3. 学生设备退役

Teacher/Student 安装器卸载的是 App 文件，不会自动撤销此前对 Windows 账户、电脑名、Veyon 或网站策略 Agent 所做的系统修改。

1. 若设备继续使用 Windows，先以管理员身份打开 StudentSetup 的“管理员维护”，载入匹配的校区配置，并使用应用提供的 Agent 单独卸载/策略清理入口。让程序核验任务、文件、ACL、防火墙和策略归属；如果检测到未知或外部管理状态，停止并交由 IT 复核。
2. 重启 Edge、Chrome 和 Firefox 并确认本工具拥有的策略已解除；另外按 Veyon 自身维护流程从教师端机房列表移除退役主机。项目的校园 Veyon 密钥是校区级信任，不要仅为退役一台学生机而轮换全校区密钥。
3. 如果设备要重灌或转交，按学校 IT 的设备擦除/重灌和账户回收流程处理。不要只卸载 StudentSetup 就把旧系统交给下一位使用者。
4. 项目遥测是按日聚合数据，不是逐台资产清单；退役一台设备不会生成可按电脑名查找的云端记录。不要为单机退役删除整个校区配置包或心跳历史。

## 4. 已有保留期限与尚未设定的期限

| 数据 | 当前已知行为 | 清理或复核方式 |
| --- | --- | --- |
| 全站/部署范围逐日遥测 HMAC 摘要 | PostgreSQL RPC 删除早于 UTC+8 当日 90 天的逐日摘要；原始安装标识不入库。 | `telemetry_hkt_retention_state.last_cleanup_hkt` 记录上次清理日。清理在该日首次成功调用遥测心跳 RPC 时触发，不是独立定时任务；检查状态表和旧记录是否符合预期。 |
| 每日遥测汇总 | PostgreSQL RPC 删除早于 UTC+8 当日 400 天的汇总。 | 同上。该期限由迁移 `20260929140000_add_daily_campus_version_telemetry.sql` 的清理函数实现。 |
| 已撤回的校区配置包 | 撤回会把目录记录标为 `withdrawn`，阻止后续搜索/下载；当前撤回 API 不删除目录行或私有 ZIP 对象。 | 保留期限未设定。由 owner/admin 先按业务/隐私要求决定留存，再从私有对象存储单独清除对象；不要直接删数据库行，以免丢失撤回记录。 |
| 应用 Release 清单与安装器对象 | 仓库没有按年龄自动删除 Release 记录或私有安装器的清理流程。 | 保留期限和旧版回滚窗口未定；正式发布前需确定负责人、保留周期和删除审批/证据。 |
| 管理资料、教师发布者姓名及 CloudBase 执行/网关日志 | 业务资料没有统一到期删除规则；日志保留受 CloudBase 配置/平台策略影响，当前仓库没有可证明其期限的配置。 | 由授权管理员在 CloudBase 控制台核实访问权限、保留设置和删除能力，并记录实际值。2026-10-02 前的一次发布响应曾包含发布者姓名，后续代码已移除该字段；旧平台日志是否过期或已删除尚未核实。不要把相关日志原文贴入工单或聊天。 |
| StudentSetup 本机运行记录和部署前快照 | `%LOCALAPPDATA%\VeyonCampus\runs\<运行编号>\` 下的 `run.jsonl` 和 `pre-change-state.vcbak`。没有按天清理；读取历史时最多扫描最近 256 个运行目录，单条记录读取上限为 128 KiB/2048 行。DPAPI 快照可能包含敏感 Veyon 配置。 | 只有在运行已结束、没有“需核对”事项且学校批准的保留期已届满后，才删除对应运行编号子目录。删除会同时删除该次 DPAPI 快照；不要删除整个 `VeyonCampus` 目录。 |
| 教师网站策略推送历史 | `%LOCALAPPDATA%\VeyonCampus\WebsitePolicy\push-history.json`，按数量保留最近 50 次，文件上限 4 MiB；不按日期到期。 | 超出数量时程序自动移除最旧记录。若按学校政策提前清理，先关闭 Teacher App 并确认无待处理故障，只删除该历史文件；不要触碰 Windows 证书库中的签名密钥。 |
| 网站策略 Agent 诊断日志 | `%ProgramData%\VeyonCampus\WebsitePolicy\<校区摘要>\agent-startup.log` 和 `agent-runtime.log`；追加内容到达 64 KiB 上限时文件会重写为最新记录。 | 不要手动删除活动 Agent 配置目录。先用 StudentSetup 的受控卸载入口；保留故障证据时只导出经授权且已脱敏的日志。 |
| 更新助手/安装清理日志 | `%LOCALAPPDATA%\VeyonCampus\Updates\update-helper.log` 与 `%TEMP%\VeyonCampus-setup-cleanup.log`；代码未设年龄清理期限。 | 更新/清理故障结案且保留期届满后，可删除对应日志文件；先关闭相关 App，并勿在故障仍需排查时清理。 |

项目目前没有为本地运行日志、发布包/发布者资料、管理员资料或 CloudBase 平台日志规定统一的保留天数。将这些数据称为“匿名”或“已撤回”不表示其已物理删除。负责人需与学校 IT/隐私责任人确定期限后，补上定时清理或受控人工清理、执行人、审计证据和恢复窗口。

## 5. 日志处理原则

- 先处理并记录当前故障，再按学校批准的期限清理。未完成运行、状态“需核对”、正在更新或 Agent 异常诊断期间，保留对应证据。
- 日志、运行摘要和错误截图仍可能包含电脑名、校区标识、文件路径、异常详情或目标设备名。分享前先检查并脱敏；不要分享密码、私钥、完整配置、教师手机号后四位或未脱敏平台日志。
- 学生部署快照可能包含 Veyon 配置，只通过批准的加密介质/系统交接渠道保存。不要把它当普通日志附件或长期异机备份。
- 删除云端文件前先确认 packageId/releaseId、状态、对象 SHA-256 和批准记录；删除对象与删除数据库目录/审计行是不同操作。

## 6. 完成 P11-06 前仍需处理

- 实现并在 Windows 验收教师 Veyon 与网站策略签名身份的受保护导出、导入、指纹核对和恢复；或正式批准由旧设备继续持有密钥的替代运维方案。
- 验收教师端更新页新增的离线包导出、固定 Developer Release 公钥验签和更新助手安装入口；在可恢复 Windows VM 上验证加密介质转移、UAC、安装失败恢复及旧版回滚。StudentSetup 离线升级入口仍需另行实现或由负责人正式确定运维方案。
- 由负责人/学校 IT 确定本机日志、配置包和 Release 文件、发布者资料、CloudBase 平台日志的保留期限，并在控制台确认平台实际策略。
- 为应自动清除的数据实现并验证定时或受控清理；目前只有遥测 RPC 内的 90/400 天清理和教师推送历史的 50 次数量上限。
