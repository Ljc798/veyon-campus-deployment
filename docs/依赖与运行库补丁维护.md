# 依赖与运行库补丁维护

## 自动检查

`.github/dependabot.yml` 每周一 02:00（香港时间）检查以下更新，并创建待审查的 PR：

- `global.json` 中固定的 .NET SDK；SDK 补丁会带来用于自包含发布的 .NET 运行库更新。
- `src/`、`tests/`、`tools/` 下的 NuGet 直接与间接依赖及锁文件。
- CloudBase API 与静态网站的 npm 依赖、根目录 Dockerfile 的基础镜像，以及 GitHub Actions。

`.github/workflows/dependency-audit.yml` 每周运行并在依赖文件变更时运行。它先以 `--locked-mode` 还原，再检查整个解决方案的直接与间接 NuGet 漏洞；发现漏洞会使工作流失败，并保存 JSON 报告供复核。另一个 job 按 `website/package-lock.json` 和有依赖时的 Cloud Function 锁文件，向 npm 官方 Bulk Advisory 接口查询所有锁定的生产与开发包版本；发现公告或接口失败会使工作流失败，并保存单独的 JSON 报告。2026-10-03 本机核对网站 121 个锁定版本，无匹配公告；Cloud Function 当前未声明 npm 依赖。

2026-10-03 使用 x64 .NET SDK 10.0.401 本机复跑 NuGet 直接/间接依赖扫描，未发现漏洞；报告见 `artifacts/dependency-audit/dotnet-vulnerability-report.json`。这只记录当前锁定依赖的扫描结果，不表示默认分支上的周期工作流已生效。

本机 npm 10.9.2 的 `npm audit` 在 Bulk 请求失败后回退到已退役的 Quick Audit 端点，返回 HTTP 400，因此 CI 使用官方 Bulk Advisory 接口，避免旧回退端点影响扫描。Bulk API 的请求和响应格式见 [npm Registry Audit API](https://api-docs.npmjs.com/#tag/Audit) 与 [npm audit 文档](https://docs.npmjs.com/cli/audit.html)。

## 审查和发布步骤

1. 检查 Dependabot PR 中包／SDK 变更及对应安全公告；不要自动合并重大版本升级。
2. 确认 Windows App checks 与 Teacher、Student 安装器的构建、安装和卸载 smoke 全部通过。SDK 或运行库变化时还要检查两种产物确为 `win-x64` 自包含发布。
3. 合并依赖更新后，更新 `src/VeyonCampus.App/VeyonCampus.App.csproj` 的产品版本，并按正式发布流程创建新的稳定版本 tag。现有安装包内的运行库不会由目标电脑上的 .NET 更新自动替换。
4. 对新发布包核对版本、SHA-256、签名清单与更新流程，然后再分发给学校；依赖更新 PR 本身不会发布或覆盖已有 release。

### 2026-10-03 发行说明与已知问题审阅

- 4.11.3 发行说明列出翻译更新、Core 的 FQDN 解析错误处理、Configurator/Master 缩略图可见模式调整、截图插件 framebuffer 有效性修复，以及 Windows 依赖 OpenLDAP 2.6.15 和 QCA 3.2.12。官方 x64 安装器资产列出的 SHA-256 为 `6acad4fc310e915a631477373f7649d51b74fbe8c41c5b0ab38d2fa852876b73`。该上游摘要尚未由本项目下载、Authenticode 验证或纳入信任基线；发行说明没有明确列出安全修复，不能据此推断不存在其他安全变化。
- 上游仍有未关闭的 [Windows 11 登录崩溃问题 #1165](https://github.com/veyon/veyon/issues/1165)：报告针对 Windows 11 Education 24H2/build 26100 上的 4.11.2，称 `veyon-server.exe` 在交互用户登录时崩溃，并报告也在 4.11.0 重现。4.11.3 发行说明没有提到该问题；因此不推断其已修复，也不推断它必然影响 4.11.3。评估新版时必须实测 Windows 11 登录、服务启动和恢复。
- 当前项目仍只嵌入并固定 4.11.2.0；本轮没有下载或安装 4.11.3，也没有改动 `VeyonInstallerTrust`、项目资源或支持版本。结论：保留现有基线，4.11.3 仍为“未验证、不支持”，直至完成来源/签名审查及 Windows 10/11、CLI、密钥、服务、Teacher/Student 连接和回滚验收。

### 纳入新版本前的检查顺序

1. 阅读[Veyon 官方该版本发行说明及 Windows 资产](https://github.com/veyon/veyon/releases)，确认受影响的 CLI、AuthKeys、Master、Configurator、服务和打包依赖。
2. 由受控下载流程取得 x64 安装器，核对官方摘要、Authenticode 结果与发布者身份；经项目安全审查后才更新文件名、大小、SHA-256、证书指纹和嵌入资源。不要仅因版本号更高而改代码常量。
3. 在可还原 Windows 10 与 Windows 11 测试环境分别安装/升级；检查 VeyonService、CLI 版本、教师 Master、Veyon 公钥指纹和学生端连接。
4. 验证 StudentSetup 的首次安装、密钥导入、Agent 部署、重启读回、失败回滚和已安装未知版本阻断；确认 TeacherConsole 的密钥复用与配置读取。
5. 所有目标环境验收通过后，才把矩阵状态改为“验证通过”，更新固定版本和任务表证据，并发布新的 App 版本。旧版及升级失败恢复包在批准的回滚期内保留。
