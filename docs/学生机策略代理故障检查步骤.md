# 学生机策略代理故障检查步骤

适用于学生端提示“HTTP 监听地址已被其他账户保留”、`clretwrc.dll` “访问被拒绝”、无法设置或读回 SYSTEM 代理任务安全权限，或教师端推送超时的情况。

> 2026-09-28 学生虚拟机反复启动失败的时间线、`0x80070005` 读回结果和 0.4.22 路径尝试见[学生虚拟机网站 Agent 启动失败排查记录](学生虚拟机网站Agent启动失败排查记录.md)。该问题仍未闭环；本文件下面保留此前版本的现场资料和通用检查步骤。

## 在学生机运行检查

1. 到出现报错的**学生电脑**上操作，不是在教师电脑上操作。
2. 打开开始菜单，搜索 **Windows PowerShell**。
3. 右键选择 **以管理员身份运行**。
4. 复制下面整段命令，粘贴到 PowerShell 窗口后按 Enter。
5. 等命令执行完，把窗口里的**全部输出**复制发回，或拍照发回。红色错误信息也请保留。

```powershell
$agentDir = Join-Path $env:ProgramData 'VeyonCampus\WebsitePolicyAgent\0.4.19'
$agentFile = Join-Path $agentDir 'clretwrc.dll'

'=== PowerShell 是否以管理员身份运行 ==='
([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole(
    [Security.Principal.WindowsBuiltInRole]::Administrator
)

'=== 新端口 39174 的 HTTP URL ACL ==='
netsh http show urlacl url=http://+:39174/

'=== 旧端口 39173 的 HTTP URL ACL ==='
netsh http show urlacl url=http://+:39173/

'=== 39174 是否有程序正在监听 ==='
Get-NetTCPConnection -LocalPort 39174 -State Listen -ErrorAction SilentlyContinue |
    Select-Object LocalAddress, LocalPort, OwningProcess

'=== 后台代理目录与文件是否存在 ==='
Get-Item -LiteralPath $agentDir, $agentFile -ErrorAction SilentlyContinue |
    Select-Object FullName, Length, Attributes

'=== 代理目录权限 ==='
icacls $agentDir

'=== clretwrc.dll 文件权限 ==='
icacls $agentFile
```

## 检查 SYSTEM 代理任务权限

如果部署结果提示“无法设置或读回 SYSTEM 网站代理任务的安全权限”，请在**学生电脑**上用管理员身份打开 PowerShell，运行下面的只读检查。它不会更改任务或权限；请把全部输出追加到本文件末尾，或发回截图。

```powershell
$taskName = 'VeyonCampus-WebsitePolicyAgent'

'=== 任务计划程序摘要 ==='
& schtasks.exe /Query /TN $taskName /V /FO LIST
"schtasks exit code: $LASTEXITCODE"

'=== 任务 XML ==='
& schtasks.exe /Query /TN $taskName /XML
"schtasks exit code: $LASTEXITCODE"

'=== COM 读回的身份、启动项和任务安全描述符 ==='
try {
    $service = New-Object -ComObject 'Schedule.Service'
    $service.Connect()
    $folder = $service.GetFolder('\')
    $task = $folder.GetTask("\$taskName")
    $definition = $task.Definition
    $action = $definition.Actions.Item(1)
    [pscustomobject]@{
        TaskPath = $task.Path
        State = $task.State
        UserId = $definition.Principal.UserId
        LogonType = $definition.Principal.LogonType
        RunLevel = $definition.Principal.RunLevel
        ActionPath = $action.Path
        Arguments = $action.Arguments
        SecurityDescriptor = $task.GetSecurityDescriptor(7)
    } | Format-List
} catch {
    $exception = $_.Exception
    [pscustomobject]@{
        ErrorType = $exception.GetType().FullName
        HResult = [string]::Format('0x{0:X8}', $exception.HResult)
        Message = $exception.Message
        InnerException = $exception.InnerException
    } | Format-List
}

'=== 任务文件 ACL（只读）==='
$taskFile = Join-Path $env:windir 'System32\Tasks\VeyonCampus-WebsitePolicyAgent'
if (Test-Path -LiteralPath $taskFile) {
    icacls $taskFile
} else {
    "任务文件不存在: $taskFile"
}
```

请保留任务摘要、XML、COM 输出中的 `UserId`、`ActionPath`、`Arguments`、`SecurityDescriptor`，以及任何 `HResult` 和错误文本。不要手动创建、删除任务或修改 ACL；拿到读回结果后再决定修复方式。

## 检查学生端防火墙规则

TCP 39174 的规则必须允许当前 Windows 网络配置。虚拟机网卡可能被 Windows 识别为 Public；旧版本只允许 Domain/Private 时，教师端即使能解析学生机，也无法连接代理。0.4.21 起学生端安装会自动把本工具管理的规则更新为 Profile Any，0.4.24 进一步将程序过滤从 Agent EXE 修正为 HTTP.sys 对应的 `System`，仍限制 TCP 39174 和 `LocalSubnet` 来源。旧 EXE 规则可能使本机健康检查成功而教师端超时。

在**学生电脑**的管理员 PowerShell 中读取规则：

```powershell
'=== 学生端网络类别 ==='
Get-NetConnectionProfile | Select-Object InterfaceAlias, NetworkCategory, IPv4Connectivity

'=== 网站策略代理防火墙规则 ==='
$agentRule = Get-NetFirewallRule -DisplayName 'VeyonCampus Website Policy Agent' -ErrorAction SilentlyContinue
$agentRule | Format-List DisplayName, Enabled, Profile, Direction, Action
if ($agentRule) {
    $agentRule | Get-NetFirewallPortFilter | Format-List Protocol, LocalPort
    $agentRule | Get-NetFirewallAddressFilter | Format-List RemoteAddress
    $agentRule | Get-NetFirewallApplicationFilter | Format-List Program
}
```

升级到 0.4.24 后重新运行学生端配置部署即可修复旧规则；不需要删除 Veyon 密钥或配置。如果仍需临时手动添加规则，应在学生端管理员 PowerShell 执行，并把输出与上述检查结果一起保留。

## 如果 39174 正在监听且进程号是 4

在同一个管理员 PowerShell 窗口运行下面命令，并把输出一并发回：

```powershell
netsh http show servicestate view=requestq verbose=yes | Select-String '39174' -Context 3,8
```
