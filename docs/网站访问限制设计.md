# 网站访问限制设计

学生机上的 SYSTEM Agent 为 Edge、Chrome 和 Firefox 写入机器级浏览器策略。教师输入域名或 HTTP/HTTPS 网页地址；系统将域名规范化为小写 IDNA 主机名，再分别编译为三种浏览器的 URL 规则。黑名单封锁名单中的域名，白名单模式先封锁普通网页再放行名单域名，综合模式同时封锁黑名单并放行白名单例外，名单外网站照常访问；综合模式至少填写一份名单。当前规范化需求、组件设计和子任务见[网站限制专项规格](../specs/website-policy/requirements.md)；项目级完成状态仍以[路线任务主表](开发路线与任务清单.md) P12 为准。

Edge 和 Chrome 的 URL-list filter 均使用裸主机名匹配根域名和子域名；前导点表示精确主机名。Chrome 通用 Enterprise URL pattern 的 `[*.]` 写法不适用于 `URLBlocklist`/`URLAllowlist`。Firefox Enterprise `WebsiteFilter` 使用 `*://*.example.com/*`。Firefox 的黑名单写入 `WebsiteFilter\\Block`，白名单例外写入 `WebsiteFilter\\Exceptions`，白名单模式的全局拒绝规则为 `*://*/*`。Edge、Chrome 和 Firefox 均支持白名单作为黑名单例外。每份名单最多 1000 条。

教师可以把手动看到或复制的网页地址加入黑名单或白名单；应用只提取主机名，不读取学生浏览器地址或历史。教师端明确提供“阻止指定网站”“只允许指定网站”和“阻止指定网站并放行例外”三种方式，并按校区保存当前方式与两份名单。只允许模式会阻止名单外网站。

常见娱乐网站和学习网站名单可在教师端展开编辑并保存到教师电脑；这些名单只作为后续导入的起始内容，保存不会自动推送给学生。教师也可编辑已导入的校区名单，校区名单自动保存在本机，并由配对手机读取和更新当前模式及名单。

三个浏览器的规则共用签名、校区绑定、版本、防重放、到期清理和注册表事务恢复。Agent 保存策略所有权副本；若发现已有外部策略或策略值被管理员、组策略或其他程序修改，就停止覆盖。策略应用、解除或到期后，Agent 发布本机重启请求；登录中的 Student Companion 会尝试通过浏览器内置重启页重启已打开的 Edge/Chrome 并恢复标签页，Firefox 仍需手动重启。代理回执只证明策略已写入并发布重启请求，不证明 Companion 已收到或网页已被拦截。

Agent 启动时会把本工具拥有的旧 Chrome `[*.]domain` URL-list 值通过同一 Pending 事务迁移为裸域名，保留策略版本、期限和其他浏览器值；已是新格式时无操作。混合或未知格式、所有权不一致或事务期间出现外部改写时保留原现场并记录失败，不强行覆盖。

当前支持 Edge、Chrome 和 Firefox 的正式机器级策略。便携浏览器、其他浏览器、非浏览器应用、DNS 和全设备网络流量过滤不在范围内；这不是系统级网络防火墙。Windows 注册表读回、Firefox 策略页、浏览器重启、黑白名单实际匹配和卸载清理仍须在 Windows 实机验收。

规则依据：[Microsoft Edge URL-list filter format](https://learn.microsoft.com/en-us/deployedge/edge-learnmmore-url-list-filter-format)、[Chrome URLBlocklist filter format](https://support.google.com/chrome/a/answer/9942583)、[Mozilla Firefox WebsiteFilter policy](https://firefox-admin-docs.mozilla.org/reference/policies/websitefilter/)、[Mozilla Match Patterns](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Match_patterns)。
