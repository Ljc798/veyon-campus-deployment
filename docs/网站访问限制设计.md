# 网站访问限制设计

学生机上的 SYSTEM Agent 为 Edge、Chrome 和 Firefox 写入机器级浏览器策略。教师输入域名或不带路径的 HTTP/HTTPS 地址；系统将域名规范化为小写 IDNA 主机名，再分别编译为三种浏览器的 URL 规则。黑名单封锁名单中的域名，白名单封锁普通网页 URL 后放行名单中的域名。当前规范化需求、组件设计和子任务见[网站限制专项规格](../specs/website-policy/requirements.md)；项目级完成状态仍以[路线任务主表](开发路线与任务清单.md) P12 为准。

Edge 的 URL-list filter 裸主机名会匹配根域名和子域名；Chrome 需要 `[*.]example.com` 才能匹配这两种主机；Firefox Enterprise `WebsiteFilter` 使用 `*://*.example.com/*`。Firefox 的黑名单写入 `WebsiteFilter\\Block`，白名单放行项写入 `WebsiteFilter\\Exceptions`，白名单全局规则为 `*://*/*`。这些策略最多各含 1000 条，和本应用名单上限一致。

三个浏览器的规则共用签名、校区绑定、版本、防重放、到期清理和注册表事务恢复。Agent 保存策略所有权副本；若发现已有外部策略或策略值被管理员、组策略或其他程序修改，就停止覆盖。用户收到确认后仍需手动重启浏览器。代理回执只证明策略写入成功，不证明网页已被拦截。

当前支持 Edge、Chrome 和 Firefox 的正式机器级策略。便携浏览器、其他浏览器、非浏览器应用、DNS 和全设备网络流量过滤不在范围内；这不是系统级网络防火墙。Windows 注册表读回、Firefox 策略页、浏览器重启、黑白名单实际匹配和卸载清理仍须在 Windows 实机验收。

规则依据：[Microsoft Edge URL-list filter format](https://learn.microsoft.com/en-us/deployedge/edge-learnmmore-url-list-filter-format)、[Chrome Enterprise URL pattern format](https://chromeenterprise.google/intl/en_ca/policies/url-patterns/)、[Mozilla Firefox WebsiteFilter policy](https://firefox-admin-docs.mozilla.org/reference/policies/websitefilter/)、[Mozilla Match Patterns](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Match_patterns)。
