### 下载与配置下发的目标分工

分发按三类资料处理，不能把“App 下载”“校区配置包”和“课堂策略”混成同一种分发：

1. **正式 App 发布页**：同一发布页提供教师控制台和学生专用部署工具两个不同交付物，并标明版本、适用角色、来源校验和已知问题。负责人已决定公开 GitHub/Gitee 发布；仓库许可、Veyon 源码义务、两个 CloudBase npm 包许可及 Inno Setup 商用适用性仍待核实，生产 Environment 和发布凭据也尚未配置。公开发布物不得包含校区公钥配置包、教师私钥、管理员密码或学生设备清单。打包脚本现按 `-Role StudentSetup`／`-Role TeacherConsole` 生成不同 Setup EXE；当前源码尚未在 Windows 实机验收。
2. **校区配置包**：Teacher App 无需登录，教师填写校区名称、姓名和手机号后四位，生成并校验 schema v6 包后发布到 CloudBase 私有对象存储；对象键和下载文件名以该校区名称开头，并加 packageId 以区分每次发布，不附加电脑名前缀；StudentSetup 按校区名称搜索，输入手机号后四位校验后下载并导入。schema v5 的策略公钥和 Agent 兼容门槛由 v6 保留，v6 另增加首次部署建议字段；相关迁移及 API 已部署到预备份的共享体验环境。线上 v5/v6 E2E runner 已有本机服务 API key 配置和交互式 CloudBase Auth 登录，并会先验证撤回权限；发布/搜索/下载/撤回/对象删除链路仍待在本机终端输入管理员登录信息后运行。当前工作区已移除 UNC/SMB 配置分发入口；保留从本机磁盘导入，供断网恢复和管理员维护。
3. **课堂黑白名单策略**：学生 Agent 安装并取得校区公钥后，教师端直接向各 Agent 推送签名策略并收逐台回执。这条策略推送已有代码切片，Windows 网络实测未完成。让 Agent 定期从局域网服务器自行拉取策略是另一种协议，当前没有实现；首版先验收现有直接推送，需要实际需求支持后再增加拉取模式。

公开下载地址本身不能充当教师权限：教师签名私钥仍需仅由授权教师 Windows 用户持有，策略 Agent 只信任首次校区配置中的公钥。即使教师 App 可以公开下载，也不能只靠文件名、默认页面或隐藏按钮隔离角色；须保留学生专用交付物和签名密钥权限边界。

学生交付物需按角色裁剪。学生端默认路由或隐藏按钮不能代替权限边界；教师端私钥、教师 Master 和教师管理功能不得随学生交付。Student GUI 保留给管理员查看状态、修复和卸载本工具拥有的策略；关闭窗口不会卸载 Veyon、Agent 或移除 GUI。若用户不使用网站策略，可通过学生端单独确认入口卸载 Agent，并只清除可确认归属的浏览器策略；该修改需要管理员权限，Windows 实机验证仍待完成。

## 3. 任务执行与完成规则

- 任务 ID 固定，例如 P3-04；问题反馈、实现记录、测试记录引用 ID，避免只说“安装部分”。
- `[ ]` 表示未达到完整验收条件，不区分“还没写”或“写了没测”；在任务后追加实际状态和证据。
- `[x]` 只在任务的交付物和验收证据齐备后勾选。部分完成时拆分任务，不把整阶段提前勾完。
- 每项任务记录负责人、开始日期、完成日期、关联提交、验证环境和未解决问题。负责人初始为“待分配”，不虚构团队成员。
- 下阶段准备工作可以提前开展，但不得绕过前一阶段的系统修改、凭据或发布门槛。
- 每次实现控制范围：一个可验证行为、一组相关变更；先验证单机，再扩大设备范围。
- 本文以验收条件安排顺序，不在 Windows 测试条件未知时承诺具体发布日期。
- UI、架构、数据协议、运行产物和文档版本同步更新；新产物使用新补丁版本，避免不同代码一直叫 0.1.0。

任务记录模板：

```text
任务 ID / 标题：

前置任务：
本次变更与不包含的内容：
代码、文档、产物位置：
验证环境 / 步骤 / 结果：
关联提交 / 缺陷：
下一步或阻塞条件：
```
