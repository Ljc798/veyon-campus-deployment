# Veyon WebAPI 单设备屏幕截图可行性验证（2026-11-23）

> 目标：只验证「教师端本地 WebAPI 能否取到学生电脑真实屏幕并显示在 Avalonia 界面」这一条链路。
> 本阶段未改动 `src/` 任何业务代码，未引入云服务，未开发屏幕墙。

## 一、结论

**可行，且明显优于当前 CLI 截图方式。** 单台学生机 PC-01 实测：

| 环节 | 实测 | 说明 |
| --- | --- | --- |
| 查询认证方式 | 102–190 ms | 首次；纯本地请求 |
| 密钥认证（含 VNC 建链） | 257–2049 ms | 冷连接波动大，典型 300–800 ms |
| 认证后首帧可用 | 240–3308 ms | 需要重试，期间返回 503（code 10） |
| 稳定刷新（960×540 JPEG q80） | HTTP 1.9 ms 均值 / 解码 3.6 ms | 15 s 内 136 帧、0 错误 |
| 极限吞吐（同连接压测） | 201 帧/秒，4.4 ms/帧 | veyon-service 单核约 55% |
| 10 fps 常态轮询 | 服务端 CPU 约 2%（单核） | 每帧 24.6 KB |
| 关闭连接 | 1–7 ms | DELETE 释放 |
| 对照：`veyon-cli feature start … Screenshot` | 1165–1720 ms/次 | 每次都要新开进程 + 新建 VNC 连接 + 落盘 |

结论要点：WebAPI 走的是**常驻 VNC 连接 + 按需取帧**，认证一次后每帧只要 2–6 ms；CLI 每次截图约 1.2 s。
若做屏幕墙，WebAPI 是唯一能撑住多设备刷新的路径；CLI 只适合单次抓图。

## 二、环境与配置核查（本机教师端）

- **Veyon 版本**：`veyon-cli --version` → `4.11.2`；`plugins/webapi.dll` 程序集版本 `4.11.2.0`。
- **插件在位**：`plugins/` 下有 `webapi.dll`、`screenshot.dll`、`authkeys.dll`、`builtin-ultravnc-server.dll` 等 19 个插件。
- **监听端口**：`VeyonServerPort=11100`、`VncServerPort=11200`、`FeatureWorkerManagerPort=11300`、`DemoServerPort=11400`；WebAPI 端口 `11080`。
- **认证方式**：`Authentication/Method=1`（密钥文件认证）；密钥目录
  `C:\ProgramData\Veyon\keys\{private,public}\CDPPLHAJJHEOHFJOGOJCGFKGIDKJOKNCA\key`（RSA，PKCS#8 PEM）。
- **WebAPI 初始状态**：`WebAPI/HttpServerEnabled=false`（插件装了但 HTTP 服务默认关闭），`HttpServerPort=11080`，`HttpsEnabled=false`，`ConnectionLifetime=3`（小时），`ConnectionIdleTimeout=60`（秒），`ConnectionLimit=32`。
- **访问控制**：`AccessControl/AccessControlRulesProcessingEnabled=false`，即不做来源限制。
- **学生机**：Veyon 目录中 `测试 / PC-01`，解析到 `172.30.114.159`（Hyper-V Default Switch），11100 端口可达；桌面 960×540。

> 为完成验证，临时执行 `veyon-cli config set WebAPI/HttpServerEnabled true` 并重启 `VeyonService`；**验证结束后已改回 `false` 并重启，11080 端口已关闭**。

## 三、接口契约（4.11.2 实测确认）

- 会话头：`Connection-Uid: <uuid>`（认证响应 JSON `connection-uid` 同值）。
- `GET  /api/v1/authentication/{host}` → `{"methods":["0c69b301-81b4-42d6-8fae-128cdd113314"]}`（该 UUID 即密钥文件认证）。
- `POST /api/v1/authentication/{host}`，body 必须是**嵌套**的 credentials：
  ```json
  {"method":"0c69b301-81b4-42d6-8fae-128cdd113314",
   "credentials":{"keyname":"CDPPLHAJJHEOHFJOGOJCGFKGIDKJOKNCA","keydata":"-----BEGIN PRIVATE KEY-----\n…"}}
  ```
  注意：把 `keyname/keydata` 平铺在顶层会返回 400 / code 4。私钥 PEM 需原样带入。
- `GET /api/v1/framebuffer?width=&height=&format=&compression=&quality=` → 图像二进制；`width/height` 省略即原始分辨率。
- `GET /api/v1/session`、`GET /api/v1/feature`、`PUT /api/v1/feature/{uid}`、`DELETE /api/v1/authentication/{host}`（关连接）。

帧体积实测（PC-01 静态桌面）：

| 输出 | 体积 | 耗时 |
| --- | --- | --- |
| 320×180 JPEG q60 | 3.8 KB | 5 ms |
| 640×360 JPEG q80 | 14.2 KB | 6 ms |
| 960×540 JPEG q80 | 25.8 KB | 6 ms |
| 1280×720 JPEG q85 | 52 KB | 12 ms |
| 原分辨率 960×540 JPEG q80 | 38.3 KB | 6 ms |
| 原分辨率 PNG | 273 KB | 71 ms |

## 五、异常与边界（实测）

| 场景 | 返回 | 备注 |
| --- | --- | --- |
| 伪造 `Connection-Uid` | 401 / code 2 Invalid connection | 已关闭或过期的连接 |
| 密钥名不存在 | 401 / code 6 Authentication failed | |
| 私钥 PEM 损坏 | 400 / code 4 Invalid or incomplete credentials | 认证前即拒绝 |
| 学生机不可达（192.0.2.10） | 408 / code 8 在 15.0 s 返回 | 单次阻塞 15 s，UI 必须异步 |
| 不支持的图像格式 | **503** / code 9 UnsupportedImageFormat | 见下 |
| 首帧未就绪 | **503** / code 10 Framebuffer not yet available | 见下 |
| 连接空闲 65 s | 401 / code 2 | 对应 `ConnectionIdleTimeout=60` |
| 服务未开启 | 连接被拒（11080 无监听） | 默认状态 |

两个必须记住的坑：

1. **503 语义重载**：格式错误和首帧未就绪都是 503，只能靠 `error.code` 区分；只判断状态码会把格式错误当成「再等等」无限重试。
2. **认证与首帧是两段延迟**：认证成功不代表有画面，首帧需要 0.2–3.3 s 的重试窗口（本次观测到最多 7 次、每 200–250 ms 一次）。

## 六、风险

1. **私钥随请求体传输**：keyfile 认证要求把私钥 PEM 放进 POST body；`HttpsEnabled=false` 且 HTTP 服务监听 `0.0.0.0:11080`，同网段嗅探即可拿到教师端私钥。做产品前必须收敛：防火墙只放行本机、或启用 HTTPS（`TlsCertificateFile`/`TlsPrivateKeyFile`）、或改由本机受控进程代理。
2. **日志卫生**：请求体含私钥，任何中间层日志、异常回显都不能带上 body（本次探针已避免打印 keydata）。
3. **首帧延迟不可预测**（0.24–3.3 s），且每次重连都会重来，UI 必须占位 + 超时（建议 10 s）。
4. **连接会过期**：空闲 60 s、寿命 3 h，长跑的屏幕墙需要 ≤55 s 保活与到期重认证。
5. **`ConnectionLimit=32`** 同时约束 HTTP 线程池与并发连接数，40 台以上机房会被顶住，需要评估调大。
6. **访问控制未启用**：任何持有私钥的 Veyon 主控都能连，现网需确认是否符合管理要求。

## 七、对多设备阶段的启示（仅规划，未实施）

- 每台设备一条常驻连接（认证一次），**不要**每帧重新认证；错误 401 时按需重认证。
- 轮询预算（基于单设备 4.4 ms/帧、201 fps 上限、10 fps 时 2% 单核）：
  - 30 台 × 2 fps ≈ 60 请求/秒，服务端约 25% 单核，网络 30 × 2 × 25 KB ≈ 1.5 MB/s；
  - 30 台 × 5 fps ≈ 150 请求/秒，已接近压测上限（单设备 201 fps 时单核 55%），不建议作为默认。
- 缩略图用 320×180（3.8 KB、5 ms），选中放大时才取 960×540/1280×720，可把 CPU 与带宽降一个数量级。
- 解码（3.6 ms/帧 @960×540）不要放在 UI 线程串行执行；30 台 × 2 fps ≈ 216 ms/s 的 UI 线程占用会明显掉帧。
- 首帧/离线状态必须有独立状态机（连接中 / 首帧等待 / 在线 / 离线），离线单次等待已是 15 s。
