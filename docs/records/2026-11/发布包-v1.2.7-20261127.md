## 本版内容

1.2.7 只改教师端的「一键静默更新」：

- 等待学生回包的上限 15 分钟 → 8 分钟（现场 21 台里 900 秒全花在这条等待上）。
- 到期后不再直接判「需人工核对」，再读一次签名事务状态：已提交按成功、已回滚按恢复、仍在进行才待核对。
- 电脑名解析失败改为「未找到 pc-xx：可能已关机或未接入校园网」，不再说成身份核验失败。
- 修掉时钟回拨（NTP 校正）导致的「状态历史不连续」永久 Failed：新的状态时间至少与上一条相同。

学生端 Agent 仍为 `0.4.76`，本次没有学生端功能改动；学生端安装器只因同工程版本号升到 1.2.7，已装 1.2.6 的机器功能等同，可不重装。

## 首次构建失败的原因（已修）

第一次 tag 构建（运行 45949761094）在「Run .NET application checks」失败：

```
Unhandled exception. System.InvalidOperationException: 不允许维护状态从 ManualRequired 转换到 Failed。
  at MaintenanceModelChecks.Run() line 134
```

新增的时钟回拨回归走了 `Discovered → ManualRequired → Failed`，而状态机不允许 `ManualRequired → Failed`，整个检查套件在断言之前就中断。改为从新建的 run 直接 `TransitionTo(Failed, …)` 并把时间戳放在五分钟前（正是夹逼规则要处理的情形），提交 `5cebfa5` 后重打 tag，构建全绿。

教训：新增检查必须先在本机把该分支跑通；`StudentApplicationUpdateChecks` 内部会调用 `MaintenanceModelChecks`，一个非法转移会让后面所有检查都不再执行。

## 打包与验证命令

CI 侧由 tag 触发，无需人工干预；本机离线包必须带固定公钥：

```powershell
pwsh -File scripts/package-windows-offline.ps1 -Role TeacherConsole -Clean `
  -ReleasePublicKeyPath artifacts/veyon-campus-release-public.pem
```

GitHub 侧资产已用 `api.github.com/repos/.../releases/assets/<id>` 下载到 `artifacts/release-1.2.7/`，`sha256sum -c SHA256SUMS` 两个安装器均 OK。
