## 诊断结论与实机边界

image-83/84 中的退出代码 1 只说明 Windows AppLocker 调用失败，旧版本日志没有保留底层错误。0.4.71 会显示更完整的 Windows 错误；在学生虚拟机实际运行后，才能判断是系统组件、策略冲突、权限还是旧策略状态造成。若仍无法核实策略归属，卸载器会保留恢复文件并停止，避免造成不可恢复的系统策略。

image-85 显示任务和防火墙规则已读回，但 Agent 没有健康响应，也没有启动异常日志。这不足以判断虚拟机是否真的恢复到了干净快照：计划任务可能未成功启动进程，或 Agent 进程可能在写日志前失败。0.4.71 增加任务上次结果和进程读回，供下次运行区分这些情况。本轮没有在用户的学生虚拟机安装、卸载或修改 AppLocker/系统策略，也没有运行会注册 SYSTEM 任务和防火墙规则的 `AgentReconfigurationChecks`。

旧的 iOS 主屏图标可能仍持有修复前的站点数据。建议在 0.4.71 下从旧图标内配对一次，或在手机浏览器完成配对后重新添加主屏图标。WebKit 说明添加主屏图标时会复制网站 Cookie 数据：[WebKit Features in Safari 17.2](https://webkit.org/blog/14787/webkit-features-in-safari-17-2/)。

## 建议的学生虚拟机复测顺序

1. 先用 Student 0.4.71 覆盖安装存在旧 Agent/旧策略的测试快照。查看维护记录中的完整 AppLocker 错误；若恢复失败，保留 Agent 和策略数据，把完整错误文本回填 issue，不要手工删除 `ProgramData\VeyonCampus`。
2. 在同一快照通过“应用和功能”卸载学生端，观察卸载器是否先停止学生组件并移除 Agent。卸载成功后检查学生程序目录、`ProgramData\VeyonCampus` 和当前用户 `LocalAppData\VeyonCampus`；若同机保留 Teacher，教师信任资料会保留。
3. 恢复到记录清楚的干净快照后全新安装 Student 0.4.71。若页面报告 Agent 无健康响应，请把显示的计划任务上次结果、Agent 进程读回结果和启动日志信息一并记录，再判断快照状态。
4. Teacher 安装 0.4.71 后完成一次手机配对和教师批准；配对成功后重新添加主屏图标，再从桌面图标打开，确认直接进入控制页。退出后重新打开验证恢复，教师撤销该手机后验证恢复凭据失效。
