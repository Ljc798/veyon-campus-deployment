# 课堂屏幕巡视实现与验收边界更新

日期：2026-10-17（Asia/Hong_Kong）

## 当前实现

本记录更新 2026-10-10 的首版 PoC 记录。相关代码按用户要求拆成独立提交：

- `4dbbd2f`：把屏幕巡视目标限制为当前课堂的活动座位，并仅向手机暴露不透明目标 ID 和座位/学生/电脑名称。
- `b73d4f6`：加入服务端三档 JPEG 尺寸/质量映射、刷新档位、限速、并发和内存预算。
- `3f7a3d5`：加入手机端画质、自动更新间隔和开始/停止控制。
- `83603f1`：修复截图进程失败、超时或取消后的安全清理边界。
- `4fa9fe9`：课堂/租约生命周期结束、配对撤销或服务停止时取消进行中的画面读取。
- 2026-10-17 后续：普通巡视扩展为本堂全部已关联座位，最多 150 个；手机按座位排序显示所有卡片，只采集可见区域，并从对应卡片开启单座 Veyon 实时画面。移除手机端搜索、批量选中五台和独立实时画面入口。

普通巡视通过 Veyon `Screenshot` 取得单帧；唯一匹配且通过文件指纹校验的原始 PNG 会在教师端缩放成 JPEG 后清理，无法安全确认身份的文件保留。JPEG 经配对 HTTPS 返回并短期缓存在内存中；一部手机的普通巡视租约覆盖本堂全部已关联座位，最多 150 个。手机一次提交全部目标，无需教师分批选择；页面依座位顺序展示所有卡片，并只采集屏幕上可见的画面。教师机仍最多并发采集两路，每目标最短间隔和设备/全局请求限流不变。学生姓名和电脑名称用于卡片显示，IP 形式的名称不会显示，缺少可显示名称时回退到座位号。手机使用三档画质（省流/标准/清晰）和 3/5/10/15/30/60 秒刷新选择，默认省流、10 秒。

单座位还有独立的 Veyon 手机实时画面模式，由教师电脑 Veyon 监看窗口提供，约每秒把 JPEG 更新传到手机；它不沿用普通巡视的画质和刷新设置。教师电脑单独打开 Veyon 窗口的操作仍只在桌面显示。

## 启动期间取消与互斥（2026-10-17）

- 普通巡视和单座实时画面正在启动时，手机不再允许启动另一种画面或切换另一台电脑；切离巡视页、进入后台、课堂结束或座位绑定变化时会取消启动请求。
- Veyon 实时画面启动请求现在带取消信号；若响应在切页后才返回，手机会立即撤销新租约。服务端请求取消路径负责停止新开的 Veyon 窗口，避免手机已经离开但教师电脑仍保留监看窗口。
- 本次完成源码路径复核和 `git diff --check`；未运行测试、构建、浏览器或 Windows 实机验收。原有任务 9 现场验收仍开放。

服务端使用 GUID 目标 ID，并在启动租约与每次读图时重新解析当前活动课堂座位映射。普通巡视输出上限为 1280×720 母图和 1 MiB JPEG，内存缓存总预算 10 MiB、采集最多并行 2 路；每设备 120 次/分钟、服务全局 600 次/分钟，单目标采集最低间隔 3 秒。图片响应 `no-store`，审计只写座位标签，不写目标 ID、主机地址、画面或屏幕文字。停止、配对撤销、课堂或座位变化、教师服务关闭时，教师端撤销租约并取消进行中的采集；手机页面转后台或离开巡视页时会发送停止请求，若请求未送达则租约在 60 秒无有效读图后过期。

完整路由、JSON 字段、响应头及错误状态见[屏幕巡视 API 契约](../../../specs/classroom-screen-preview/api.md)；使用步骤见[手机控制使用指南](../../手机控制使用指南.md#课堂屏幕巡视)。
