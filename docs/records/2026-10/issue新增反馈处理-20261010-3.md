# 0.4.64 第七轮新增反馈处理与实机复测

处理 `artifacts/assets/issue.md` 最新新增四项：学生端覆盖安装的重启提示、教师策略标签选中态仍发黑、证书/配对码变化规律、手机已安装证书仍无法连到教师端。

## 处理结果

1. **学生端是否每次更新都需重启**：不是。0.4.63 安装器加入 `restartreplace` 后，若某个目标文件仍被占用，Inno Setup 会将替换延至下次 Windows 启动，并提示重启（见[Inno Setup 官方文件标志说明](https://jrsoftware.org/ishelp/topic_filessection.htm)）。image-66 的安装过程已经安排了至少一个延后替换；为了确认所有更新文件已生效，本次应重启后再测试。以后未出现重启提示的安装无需为该更新重启；选择稍后重启则被延后的替换不会立即完成。
2. **标签文字发黑**：之前把选中态颜色设在 `ContentPresenter` 上，实际内容是字符串时无法可靠保证生成的文字控件继承。现在为 `policy-tab` 使用明确的 `TextBlock` 内容模板，文字前景和字重直接绑定所属 `RadioButton`。Debug 构建无警告。此 Windows 环境未提供可启动原生桌面窗口的界面自动化入口，尚无目视截图验收。
3. **证书与配对码生命周期**：手机下载安装的是根证书 `.cer`，根证书存于教师当前 Windows 用户证书库，指纹由 HKCU 注册表固定。普通应用更新会复用相同根证书；服务重启会新建 HTTPS 服务器证书，但仍由该根证书签发。若用户手动移除根证书/记录或证书到期，则需人工处理，不会静默换成手机不信任的新根证书。每次手动生成邀请会产生新的随机 8 位码，5 分钟有效、成功提交后即消费；教师应用/服务重启后旧邀请不保留。
4. **手机无法打开安全页且教师端没有设备**：Teacher 安装器之前只为 Domain/Private 防火墙配置开放 TCP 39176（HTTPS）和 39177（HTTP 说明页），Windows 若将校园 Wi-Fi 标记为 Public，可能导致访问受阻。0.4.64 会先用 `netsh set rule` 更新已存在的同名规则，首次安装时才用 `add rule` 新增；两个规则均为 `profile=any` 并限定 `remoteip=LocalSubnet`，服务本身也只接受私有 IPv4 同网段访问。规则在 Inno Setup 的安装完成阶段更新（见[官方事件说明](https://jrsoftware.org/ishelp/topic_scriptevents.htm)）。教师端和说明页增加错误分层提示，并说明扫码/装证书本身不产生待审批手机，手机须在 HTTPS 页面提交配对码。

若手机说明页能打开、HTTPS 仍打不开，按以下顺序核对：

1. 教师电脑安装 Teacher 0.4.64；在“手机控制设置”生成新码和二维码。
2. 手机与教师电脑连接同一个可互通的校园 Wi-Fi。手机先打开窗口中的 `http://教师IP:39177/` 说明页。
3. iPhone 在“通用 → VPN 与设备管理”安装描述文件后，再到“通用 → 关于本机 → 证书信任设置”开启根证书完全信任；Android 按系统界面完成 CA 信任。确认页面显示的 SHA-256 与教师窗口相同。
4. 打开 `https://教师IP:39176/`。若此页可打开，填手机名称后点“配对这部手机”；教师端收到待审批项后核对设备名和 IP 并批准。
5. 若 39177 可打开但 39176 不可打开，保留手机浏览器完整错误、教师机与手机 IPv4（最后一段可遮盖），并核查 Windows 防火墙规则和校园 Wi-Fi 是否隔离客户端。手机实际连通尚未验收。
