# 教师端 1.1.41 名单、更新与重启恢复修正

基线：已在线拉取 `origin/develop`，提交 `ddef8d0`。拉取前的本地改动保留在 stash 中；重复改动采用远端版本，包括保留远端的 `PackageBuilder.cs`。

## 在线更新服务

- 公开 `/v3/releases/latest` 返回 HTTP 503。进一步只读核对发现，现有 `veyon-api` HTTP 云函数的 `CloudBase__ApiKey` 已无法访问数据库，上游返回 `401 INVALID_CREDENTIALS`。
- 工作区配置的服务凭据通过只读验证后，以合并方式只更新该函数的这一项环境变量，保留其余配置和函数代码。
- 修复后 `/health`、TeacherConsole 和 StudentSetup 的 v3 更新查询均返回 HTTP 200。目录目前返回版本 `1.1.40`；没有在此次修复中发布新版本或安装器。
- 客户端保留现有诊断码，同时区分服务端 HTTP 错误、访问拒绝、DNS、TLS 和代理故障，避免将服务端 503 提示为用户网络故障。异常原文、凭据和响应正文不会进入用户提示。

## 本地代码

- 当前教室恢复、切换和档案刷新时同步策略页与设备页共用的学生名单；两页都提供教室选择，并显示目录读取错误。
- 启动时先从本机活动课堂记录读取管控归属与原始 UTC 截止时间，再启动连接和设备核对；读取时验证课堂、校区、教室和目标集合。没有将未经重新核验的状态显示为“已应用”。
- 倒计时按保存的截止时间继续，设备处于未知、冲突或等待连接时不会隐藏或重置。临时连接提示也不会清空当前课堂的记录。
- 逐台状态、网站/键鼠状态、汇总和徽标依据持久化阶段显示；重试时间到达不再把“需核对”改成“待同步”。真实的等待连接状态仍会显示。
- 自定义网站名单目录同时用于限制方式的读写，保证回归检查隔离。
