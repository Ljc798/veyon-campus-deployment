不需要每次 App 补丁更新都重新发布校区配置包：既有协议、密钥和设置保持兼容时复用旧包即可。真正增加必要信任公钥、换校区密钥、变更配置或升级到不兼容协议时，才需要重新生成、发布和部署。当前旧包兼容适配不修改原包及其摘要；未来 0.5／新 schema 不自动放行。Veyon 仍固定为经过信任校验的 4.11.2.0，不能把 App 的补丁兼容扩大成任意 Veyon 版本兼容。

权限设计按本次用户要求改变：启动授权一次，Worker 仍为每次一个操作的短时进程，没有添加常驻代理，也没有绕过 Windows UAC。跨账户输入管理员凭据时，应用使用该管理员账户的档案及签名证书库；应继续用持有原校区教师签名密钥的账户，不能为恢复列表随意更换密钥。测试版仍未进行 Windows Authenticode 签名；Developer Release 清单签名不能消除“未知发布者”。

Veyon 读回依据固定 [4.11.2 BuiltinDirectoryPlugin 源码](https://github.com/veyon/veyon/blob/v4.11.2/plugins/builtindirectory/BuiltinDirectoryPlugin.cpp)、[数字对象类型](https://github.com/veyon/veyon/blob/v4.11.2/core/src/NetworkObject.h)、[JsonStoreArray 导出结构](https://github.com/veyon/veyon/blob/v4.11.2/core/src/Configuration/JsonStore.cpp)。安装后启动的权限继承依据 [Inno Setup Run flags](https://jrsoftware.org/ishelp/topic_runsection.htm)。

## 实机复测顺序

1. 关闭旧程序，在教师机装 Teacher 0.4.54、学生机装 Student 0.4.54；从各自快捷方式启动，确认版本。启动时同意一次管理员授权；安装后勾选启动应正常打开，后续导出／添加／部署不应再弹 Worker 授权。不要执行 obsolete 目录里的旧包。
2. 学生先重新下载或载入原有 0.4.52／0.4.53 校区包，确认兼容错误消失。使用原校区、原公钥，不为本轮测试更换密钥；不需要仅因补丁版本重发云端包。
3. 只选择“配置 Veyon”，完成第三步检查；返回第二步不改选项，再进入第三步，应复用结果。点击确认进入第四步立即执行完整流程。已有固定 Veyon 应跳过安装器，然后仍导入和验证公钥，并安装／修复 Agent；不应出现动态磁盘文字导致的预检不一致。改变选项或超过五分钟时应要求重新检查。
4. 成功结果应包含公钥配置及代理步骤。打开 Veyon Configurator 的验证密钥列表，核对本校区公钥；管理员维护里的只读部署检查应确认认证方式、公钥指纹和服务。再查看任务计划程序中的 `VeyonCampus-WebsitePolicyAgent` 和运行结果、Agent 配置及启动日志。原“仅安装完成”记录不能代替这些证据。需要重启时先重启，再重查继续，不跳过状态核对。
5. 教师生成同校区配置包，首次密钥准备期间进度提示应持续可见。校区下拉列表只显示实际名称。档案页确认没有内部 ID／CloudBase 实现说明；先点检查冲突，再一键添加。验证空机房可复用，添加结果与 Configurator 一致，再预览应保留已有电脑而不重复添加。
6. 网站策略先只测这台学生机。学生机 `ipconfig` 查看当前 IPv4，教师目标填写该 IP。在教师 PowerShell 执行 `Test-NetConnection <学生IPv4> -Port 39174`。若 `TcpTestSucceeded=False`，先查看 Agent 启动日志和任务状态，再核对同 LAN/VLAN、学生网络配置文件及本地子网防火墙规则，不通过时不要扩测。程序自动规则只覆盖 Domain/Private，Public 校园网络需由学校 IT 核对配置。
7. 端口通过后选同一签名校区，推送一条无害网站黑名单，确认单机回执；等待 15 秒，重启学生浏览器，验证访问与撤销。再换回电脑名测试：如果 IP 成功、名字失败，是现场名称解析问题，继续使用实际 IP 或学校 DNS 中可解析的主机名。PC-02 是编号，不能据此推断网络里已有同名设备；没有选电脑改名时，学生机名称不会自动改变。
8. 在 1024×768、100% 及较高 DPI 下检查学生窗口底部按钮和详情抽屉。最后重启学生机，再验证服务、公钥、Agent 和策略恢复。Windows 10/11、跨账户启动、正式签名及真实 LAN 测试仍列为未完成。

本轮没有还原学生机。若现场只是之前的 Veyon 安装缺公钥／Agent，保持同一校区载入后重新执行完整 Veyon 配置即可修复；如果此前已改账户、密码、电脑名或下发策略，是否恢复整机须以实际系统读回和测试前基线判断。
