# 0.4.65 第八轮新增问题处理

处理 `artifacts/assets/issue.md` 新增的学生端预检停滞问题，并继续解决手机无法完成 Teacher HTTPS 连接的问题。

## 问题与修复

### Teacher 手机 HTTPS 握手失败

手机能打开 HTTP 39177 说明页，但无法打开 39176 HTTPS 控制页；教师端也没有待批准设备。现场教师机检查表明，39176 正在监听、防火墙规则已启用、TCP 连接成功，失败发生在 TLS 握手期间。手机尚未提交配对请求，因此教师端没有设备条目符合现有流程。

服务器证书由内存中的 RSA 私钥生成并直接交给 Kestrel。Windows Schannel 需要可用的密钥容器，无法用原来的内存私钥完成服务端 TLS。现在将服务证书临时导出为 PKCS#12 后重新载入，让证书私钥具有受对象生命周期管理的容器；临时 PFX 字节会在使用后清零。教师根证书、根证书指纹和已配对手机的信任不变。

### StudentSetup 无法继续

image-68 的 StudentSetup 版本为 0.4.63，结果是 12 项通过、2 项提示、0 项未通过/需核对；页脚“本机最近运行记录：待重启”对应上次执行记录处于 `RequiresReboot`。应用在用户查看并确认上次结果前，故意阻止启动新部署。旧页面只显示历史状态，按钮旁没有明确说明，也缺少检查页上的复核入口。

保留该安全门槛，不允许跳过未完成部署复核。现在检查页标题会显示“需先核对上次运行”，说明文字会指向上次执行结果；页面内新增“查看上次结果”按钮。用户核对历史步骤和当前设备状态后，在结果页点“已核对，返回第 1 步”，旧预检会失效，必须重新生成计划并检查。若历史结果显示改名待重启，应先重启学生机，再重新打开应用核对状态。
