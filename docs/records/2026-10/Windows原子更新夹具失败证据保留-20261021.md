# Windows 原子更新夹具失败证据保留

日期：2026-10-21（Asia/Hong_Kong）

## 变更

- 将学生端原子存储夹具的结构化报告放入顶层 `try/catch/finally`，通过检查逐项记录结果。
- 成功报告继续记录 Windows、显式 opt-in、管理员权限、journal ACL 读回、陈旧记录拒绝、同卷旧目录保留、候选隔离与恢复、未知 journal 拒绝和恢复材料保留。
- 失败报告增加失败阶段、异常类型和 HRESULT，不收集绝对路径或设备身份。
- Windows workflow 即使夹具进程未输出结构化报告，也会写入启动失败兜底报告；非零退出状态仍使 workflow 失败，并由 `if: always()` 上传 JSON artifact。
- 报告仍固定为 `g0Acceptance=false`，此夹具不覆盖 SYSTEM 恢复任务、完整安装器故障注入、重启或真实设备。

## 验证状态

- 本次变更后尚未在 Windows runner 执行；工作流 artifact 结果仍待首次运行后审阅。
- macOS 可验证源码编译与工作流 YAML 语法，但不能验证 NTFS ACL、任务计划程序或 SYSTEM 执行。

## 后续门槛

- 审阅 Windows artifact 中的成功或失败报告，并解决实际失败阶段。
- 继续完成 10.7/G0 规定的 Windows 10/11 完整失败注入、开机恢复和教师—学生双机验收；此记录不关闭 G0。
