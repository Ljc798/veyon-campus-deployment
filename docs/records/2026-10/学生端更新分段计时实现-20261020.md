# 学生端更新分段计时实现记录

日期：2026-10-20（Asia/Hong_Kong）
范围：下一阶段开发规划 M0 的源码观测部分
状态：源码和 macOS Release builds 完成；Windows 原子更新验收与性能基线待现场执行。

## 已完成

- TeacherConsole 将签名发布查询与学生安装包缓存准备分开计时。缓存准备显示命中/下载、签名清单中的包大小、耗时；实际下载时额外显示平均吞吐。
- Student Agent 在有效命令通过验签后记录命令排队、预检、局域网传输、摘要计算、准备与备份、StudentSetup 安装、Agent 暂存/切换、健康检查/提交和回滚阶段。
- 局域网传输记录已接收字节数、耗时和由两者计算的平均吞吐；下载失败也会记录实际接收字节数与失败耗时。完整包摘要不匹配会单独将完整性阶段标记为失败。
- UpdateHelper 接续同一 `commandId` 记录 Agent 激活、健康提交和回滚。TeacherConsole 每台设备的更新行可展开查看阶段耗时和结果；终态签名确认作为单独阶段展示。
- 学生端阶段计时落在 SYSTEM 保护目录下的独立 sidecar，最多 16 个阶段/命令、32 KiB/记录、128 条记录；不修改事务 journal，不存校区名、设备名、IP、文件路径、URL 或令牌。写入、清理失败均不影响更新事务。
- Agent 仅接受带新鲜 nonce、校区签名和本次 `commandId` 的 v4 请求读取计时；响应由当前固定 Agent 身份签名。Teacher 校验 nonce、校区、命令编号和已固定身份后才更新 UI。旧 Agent 的 404 不影响原有状态/更新路径。

## 当前链路的源码事实（不代表速度基线）

- Teacher 在一次 rollout 中验证并准备一份签名 StudentSetup 完整安装包，再由本机 LAN endpoint 供目标设备读取；本地缓存命中要求已缓存包与当前签名清单/签名信封完全匹配。
- 目标下发并发上限当前为 8；LAN 文件服务最多接受 24 个并发连接。
- Student 端使用普通完整 GET，没有 HTTP Range/断点续传；Teacher 发布下载路径也没有断点续传。
- StudentSetup 共享 .NET Runtime 满足要求时，安装脚本可跳过 Runtime 安装。是否有其他重复 I/O 或体验瓶颈，须用 Windows 阶段数据确认。

这些数字和行为来自源代码读取，不能代替有线/Wi-Fi、不同机器规模和真实安装耗时的测量。
