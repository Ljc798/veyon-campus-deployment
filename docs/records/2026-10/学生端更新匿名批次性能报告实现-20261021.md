# 学生端更新匿名批次性能报告实现

日期：2026-10-21（Asia/Hong_Kong）

状态：代码与文档实现完成；Windows 现场基线和原子更新验收仍待完成。

## 目标

为 M0 现场测量补齐可携带的整批性能证据。教师端之前能显示单台阶段耗时，但没有批次 P50/P95、失败率和可人工保存的汇总文件。

## 实现

- TeacherConsole 在每批更新结束后只在内存保留一个匿名报告，提供“导出本次匿名性能汇总”JSON 按钮；开始下一批时清除上次报告。没有后台写盘或上传。
- 报告记录目标版本、随机批次 ID、批次 UTC 起止、完整包模式、已选/已是最新/预检失败/已尝试/成功/回滚/待核对/失败/未开始/未确认数量，以及发布查询、教师缓存准备、网络字节、教师下载耗时和可计算的吞吐。Teacher 进程最多暂存 128 个不含设备信息的批次观察值，按 1、2–9、10–19、20+ 分组计算缓存就绪和课堂总时长分布；进程退出后清空。
- 对已完成阶段、学生端安装提交时长和教师端终态签名确认时长计算最近秩 P50/P95 与最大值，并记录样本数、完成数和失败率。按批次规模带及学生端网络/Windows 版本类别聚合；另按 StudentSetup/Agent 源版本组合输出数量，不输出逐台明细。
- 性能 JSON 仅包含汇总、类别、阶段名、产品版本、时间和持续时间；不包含电脑名、地址、校区 ID、commandId、路径、下载 URL、密钥或逐台阶段记录。报告限制为 256 KiB，来源版本组合最多 32 组（其余合并为 `other`）。
- 学生端根据已验证的局域网下载 URI，在内存中匹配实际路由的网络接口类型，只保留 `wired`、`wifi`、`other` 或 `unknown`；无法唯一确定时使用 `unknown`。Windows 类别只保留 `windows10`、`windows11`、`other` 或 `unknown`，不保存注册表产品名、网络名或地址。
- 新增 `/v2/update-timings` 签名响应以返回环境类别；查询使用新鲜的校区签名 v4 nonce 和 commandId，Teacher 按已固定 Agent 身份校验。旧 `/v1/update-timings` 请求和响应字段保持不变；只有 v2 路径明确返回 404 时，Teacher 才回退到 v1。v2 超时或签名无效时丢弃该次计时样本，不再额外请求 v1，避免拉长终态确认等待。计时和报告错误不会改变安装、提交、回滚或恢复结果。
- 更新要求和设计写入 `specs/cloud-updates-and-installers`，实现进度写入学生端更新可靠性计划和安全增量更新系统设计。
