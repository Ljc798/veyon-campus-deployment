# 教师端更新后仍驻留托盘的修复

日期：2026-10-17（Asia/Hong_Kong）

## 问题与原因

用户从 TeacherConsole 1.0.16 下载 1.0.18 后，主窗口消失，但仍能从通知区域重新打开旧版。更新助手启动后等待教师程序退出；超过两分钟仍未退出就会记录“等待应用退出超时；未启动安装器”。

TeacherConsole 在 Windows 上使用 `ShutdownMode.OnExplicitShutdown`，并把普通窗口关闭解释为“隐藏到托盘”。在线和离线更新成功启动助手后只调用窗口 `Close()`，因此触发隐藏逻辑，教师进程没有退出。截图中的 Veyon Campus 通知区域图标与该行为一致。

## 修复

- 新增统一的应用退出路径，释放 Teacher 托盘图标并调用桌面应用生命周期的 `Shutdown()`。
- 在线及离线更新助手启动成功后均使用完整应用退出路径；普通关闭窗口仍按原行为驻留托盘。
- tray 菜单中的“退出 Veyon Campus”复用相同的退出方法。

## 验证边界

- 本次未运行自动化测试或 Windows 实机更新。
- 仍需在 Teacher 1.0.16 → 1.0.18（或后续带修复发行版）实测：窗口关闭后进程结束、UpdateHelper 开始安装、UAC 流程正常、新版读回与重启成功；另测离线更新路径。

## 后续更新方向

当前安装器可按完整包下载。未来可设计带签名文件清单的增量包，仅下载变化文件，并由更新助手在程序退出后验证、落盘、切换和回滚。运行中的 .NET 桌面代码仍需短暂退出并重启，因此这属于增量更新，不是严格意义的运行中热补丁。
