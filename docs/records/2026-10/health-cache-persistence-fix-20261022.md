# 设备健康列表本机缓存与稳定显示（1.1.32）

日期：2026-10-22  
版本：TeacherConsole / StudentSetup 1.1.32  
状态：双端 Windows x64 测试安装器已构建；应用未启动，现场验收待用户进行。

## 查询机制与问题

教师端打开设备健康页后，每 5 秒向所选学生电脑的 Agent 发起轻量状态读取。请求带校区签名；每台目标超时为 1.5 秒，最多 12 台并发。教师端校验 Agent 签名、请求随机数和已固定的设备身份。完整健康诊断仍由教师手动点击读取，不参与每 5 秒轻量轮询。

1.1.31 的查询结果只放在教师端进程内存里。选择校区/学生名单变化时，或完整诊断遇到读取异常时，旧逻辑会清空列表；应用关闭后也没有状态摘要可恢复。轻量读取的初次失败还会立即落入“未收到回执”，没有等待连续失败阈值。

## 本轮修正

- 按“校区 + 规范化电脑目标”保存当前状态摘要到 `%LocalAppData%\VeyonCampus\Teacher\device-health-cache.json`。使用原子写入；缓存最多 30 天、最多 2048 条。
- 缓存只包含学生显示名、上次状态类别和简短摘要/时间，不保存签名密钥或完整诊断内容。
- 应用重开、目标重新选择或读取过程发生选择变化时，匹配的缓存行显示为灰色“本地缓存 · 待更新”，并保留到实时状态更新。缓存不会被当成在线/正常状态，也不能作为设备修复操作的依据。
- 读取失败和选择变化不再清空整个健康列表；当前页面提示最近发生的选择变化原因。校区变化只恢复该校区对应缓存。
- 轻量读取前两次失败保持待确认，连续 3 次失败后才显示“未收到回执”；不推断学生电脑已经关机。

## 现场复测

1. 在教师电脑安装 TeacherConsole 1.1.32，使用已有校区和学生名单打开设备健康页；确认首次读取期间行持续可见。
2. 等待至少 30 秒，确认连续轮询不清空行；前两轮失败为待确认，连续 3 次失败后才显示“未收到回执”。
3. 读取到状态后关闭并重新打开教师端；确认同一校区/名单先恢复灰色缓存行，再更新成当前 Agent 签名状态。
4. 临时断开一台测试机网络或停止其 Agent，确认列表仍留在本机、缓存明确标记待更新且修复按钮不可用；恢复连接后确认状态更新。
5. 切换到另一校区或调整所选学生，确认不串用另一校区的同名电脑缓存；若选择发生变化，页面应说明原因而不是空白。
6. 复测课堂聊天 Enter 发送，确认此轮健康缓存改动没有影响已确认的聊天行为。
