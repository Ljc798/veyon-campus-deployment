# 学生端更新重试遥测 v3 实现

日期：2026-10-21（Asia/Hong_Kong）

## 目标

路线图要求 `LanTransfer` 记录下载重试次数，便于判断局域网丢包/断线与下载吞吐的关系。新增此观测不改变重试策略、校验方式、更新事务或恢复行为。

## 实现

- 下载器统计首次请求之后实际发出的额外 HTTP 请求次数，写入 `LanTransfer.retryCount`。成功与失败路径都会报告计数；命中最多三次请求上限时，`retryCount` 的最大值为 2。网络字节数仍包含失败片段和重传数据。
- SYSTEM 私有计时 sidecar 保存重试字段，并限制该字段只能出现在 `LanTransfer` 阶段、数值为 0–2。计时写入失败仍不会中断安装或改变回滚结果。
- 新增绑定 commandId 的签名接口 `/v3/update-timings`。v3 保留校区 ID、随机 nonce、已固定 Agent 身份、收集时间与计时字段验证，并携带已有环境分类。Teacher 首先请求 v3；只有服务端返回 404 才回退到 v2，再在 v2 也不支持时回退到 v1。网络错误、签名错误或回执验证失败不会降级成未经核验的数据。
- 对旧 Teacher 请求 v1/v2 的情况，Student Agent 仍按原结构返回响应，主动移除新的重试字段；新 Teacher 收到旧 Student 的 404 时继续使用已有兼容路径。
- Teacher 的逐台 LAN 阶段耗时显示重试次数。匿名性能导出 schema 升为 v2，在网络类型和 Windows 版本分组内记录重试计数的样本数、总次数、P50、P95 和最大值；报告仍不含设备名、地址、校区身份、commandId、路径或 URL，也不自动上传。

## 验证

- HTTP 续传 fixtures 验证一次中断后重试计为 1、忽略 Range 的完整重下计为 1、连续服务不可用时最多发出 3 次请求并记录 2 次重试。
- 签名协议 fixtures 验证 v3 能携带并验证重试次数；非法阶段和超出边界值被拒绝；v1/v2 响应省略 `retryCount`，序列化结构保持兼容。
- Teacher 界面夹具确认逐台阶段显示“重试 N 次”；匿名汇总夹具确认 schema v2 统计值和导出脱敏边界。
