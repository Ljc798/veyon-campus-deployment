# 学生端更新下载请求身份绑定实现

日期：2026-10-22（Asia/Hong_Kong）

## 目标

让新版本 Student Agent 的 Teacher LAN 下载请求证明请求者持有本机已固定 Agent 身份私钥，并将每次请求限制到教师签发的校区、更新命令和完整包摘要。完整签名安装包、Range 续传、最终 SHA-256 校验及原子更新事务保持原有顺序。

## 实现

- Teacher 为每个目标和 commandId 创建独立随机 LAN 路径，并保存短时授权：校区、commandId、签名发布摘要、过期时间，以及该目标已固定的 Agent 公钥。多个学生不再共用一个下载 URL。
- 支持下载请求协议 v1 的 Agent 使用 SYSTEM 持久身份私钥签名每次 HTTP GET。请求正文包括校区、commandId、发布 SHA-256、请求路径、Range、If-Range、UTC 签发时间和 128 位随机 nonce；完整下载与每次续传重试都会重新签名。
- Teacher LAN 服务在发送文件前校验请求签名对应本次固定 Agent 公钥，并逐项匹配下载授权的校区、commandId、摘要和路径；Range/If-Range 必须与签名内容一致。请求需在短时窗口内签发、早于命令过期时间，nonce 在该授权内只能使用一次。单条授权最多接受 32 次有效请求，重放或超限请求被拒绝。
- 新增签名的 `/v1/student-update-download-capabilities` 探测端点。Teacher 用新鲜校区签名 nonce 请求，Agent 使用固定身份私钥签名能力回执；新 Teacher 只在回执与当前校区、随机数和已固定 Agent 身份匹配后启用签名下载。旧 Agent 对该新端点返回 404 时，Teacher 才选择迁移授权。原有状态协议 v4 保持原样，防止新 Agent 增加字段后被旧 Teacher 的严格 JSON 反序列化拒绝。
- 已支持原子更新但尚未支持下载签名的旧 Agent，继续走每设备、每命令独立且随命令过期的随机 URL，以便先更新到带新协议的完整安装包。这个迁移路径仍以 URL 保密性作为下载门槛，不能证明 Agent 身份；下载包仍须通过开发者签名清单和 SHA-256 校验。之后由新 Agent 的签名请求保护后续更新。
- 事务创建、StudentSetup 安装、Agent 暂存/切换、健康确认、提交、回滚、更新并发数和文件包大小均未调整。Teacher 每次仍只推完整签名 StudentSetup 安装包。
