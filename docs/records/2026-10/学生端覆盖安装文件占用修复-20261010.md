# 0.4.62 / 0.4.63 新增问题修复与实机复测

日期：2026-10-10

## 本轮修复

1. **教师策略页选中项仍发黑**：策略分类和应用步骤使用自定义 `RadioButton` 模板。模板内部 `ContentPresenter` 现在对选中、悬停和按下状态明确设为白色，避免只设置外层 `Foreground` 时被内容模板里的文本颜色覆盖。
2. **手机扫码无法建立安全连接**：原二维码直接打开 HTTPS，未信任教师根证书时手机浏览器可能在页面载入前拒绝连接。新二维码先打开教师机的局域网连接说明页；说明页提供根证书下载、SHA-256 指纹和 iPhone/Android 信任步骤。安装并信任后再打开 HTTPS 页面，二维码中的一次性配对码会继续保留。证书仍须在可信校园网内安装，并与教师设置窗口中的指纹核对。
3. **课堂页没有当前 Veyon 机房**：Teacher 打开课堂管理时读取 Veyon 内置目录。唯一机房自动选用并保存到教师机本地课堂档案；多个机房时要求选择。网站/应用/系统共用的策略页在目标名单为空时也自动读取唯一机房；已有手动目标不会被覆盖。读目录只更新教师机本地档案，不写回 Veyon。教室名单限定 1–150 台；开始课堂仍需选择与学生配置包匹配的校区签名密钥。
4. **StudentSetup 覆盖安装 `Avalonia.Controls.dll` 被拒绝访问**：Windows 错误代码 5 只说明访问被拒绝，截图无法单独证明具体占用者。Student Companion 仍在后台运行并持有自身程序目录 DLL 是最可能的原因。学生安装器现在使用 `CloseApplications=force`，Companion 通过 `RegisterApplicationRestart("--startup", 0)` 注册后台恢复，安装器设为 `RestartApplications=yes`。Inno Setup 说明了[关闭占用文件的应用](https://jrsoftware.org/ishelp/topic_setup_closeapplications.htm)和[重启已注册应用](https://jrsoftware.org/ishelp/topic_setup_restartapplications.htm)的行为。

## 实机复测步骤

1. **学生覆盖安装**：若旧安装器仍显示文件占用，点击“取消安装”，不要跳过 `Avalonia.Controls.dll`。保留当前安装状态，运行 `artifacts/VeyonCampus-Student-Setup-0.4.62-win-x64.exe` 覆盖安装，观察安装器是否关闭后台 Companion、替换 DLL 并在安装后重新启动 Companion。核对 StudentSetup 与 Companion 文件版本为 0.4.62、快捷方式和登录启动均有效。若仍出现错误，记录当时 Companion 是否运行并保留 Setup 日志；随后再手动结束 `VeyonCampus.StudentCompanion.exe` 重试，作为进程占用诊断。
2. **教师页签文字**：安装 Teacher 0.4.62，在教师策略页分别选择“网站/应用/系统”，并在应用页选择“账户/软件/应用”；检查深色选中底上的字全部清楚，鼠标悬停和按下也可读。
3. **单机房默认读取**：教师机已安装 Veyon 且内置目录只含一个机房时，打开“课堂管理”，检查校区/机房自动选择、电脑数和预期一致；开始课堂前选定同学生配置包匹配的签名校区。确认仅教师本机课堂档案被更新，Configurator 中目录保持不变。
4. **多机房保护**：准备两个 Veyon 地点，进入课堂管理后应要求选择，不能自动把第一间机房当成目标。选定后确认电脑名单与所选机房一致。
5. **手机二维码**：在 Teacher 0.4.62 启动手机服务、生成二维码；手机扫码应先显示 HTTP 说明页。核对页面与教师窗口中的 SHA-256 指纹，按手机系统安装并完整信任 CA，再点安全连接。提交配对请求并在教师电脑核对设备名和局域网地址后批准。若仍无法打开，记录二维码使用的教师 IP、手机网络、VM 网络模式及浏览器完整错误信息；虚拟机 NAT 通常无法被手机直连，应桥接到可互通的校园网。

## image-64/65 后续：0.4.62 仍无法覆盖安装

学生端 0.4.62 在 `StudentCompanion\Avalonia.Base.dll` 再次报 DeleteFile 错误 5；用户确认安装器曾提示自动关闭运行中的软件。由此可知 Restart Manager 的常规关闭流程仍不够，错误码仍不能区分残留文件锁、ACL 拒绝或安全软件拦截，不能继续断言单一根因。

StudentSetup 0.4.63 的 `[Files]` 规则增加 Inno Setup `restartreplace`。如果目标 DLL 在安装时仍被锁定，安装器会安排在 Windows 下次启动时替换，并在结束时要求重启。当前包仍启用 `SetupLogging=yes`：按 Win+R，输入 `%TEMP%` 并回车，按修改时间排序，复制最新的 `Setup Log ... .txt`。若要采集关闭应用的细节，从命令行运行安装包并附加 `/LOGCLOSEAPPLICATIONS`；Inno Setup 支持该参数写入 Restart Manager 诊断。

使用 StudentSetup 0.4.63 覆盖安装 0.4.61/0.4.62 时，不要点“跳过此文件”。若安装器提示需要重启，按提示重启后再核对 StudentSetup、Companion 的版本和托盘状态。若仍失败，保留日志；特别记录失败文件路径、错误码，以及安装器是否要求重启。该修复目前仅源码和打包规则已调整，须由实机确认后才能关闭。

## iPhone 证书与配对说明更新

0.4.63 Teacher 的连接页把 iPhone 的“安装描述文件”与“启用 SSL/TLS 完全信任”分成两步，并提供静态 HTTPS 地址作为按钮失效时的备用入口。Apple 的[描述文件安装说明](https://support.apple.com/en-gb/guide/iphone/iph6c493b19/ios)指出下载的描述文件在“设置 → 通用 → VPN 与设备管理”安装；[手动安装证书的信任说明](https://support.apple.com/en-us/102390)指出 SSL/TLS 完全信任需在“设置 → 通用 → 关于本机 → 证书信任设置”启用。进入 HTTPS 页面后，手机还须点“配对这部手机”并提交；扫码本身不会在教师端创建待审批记录。

Teacher 与 Student 0.4.63 都通过 Windows x64 发布打包；完整自动检查 76/76 通过，Debug 构建 0 警告、0 错误。这些结果不代替在用户的 iPhone、教师主机和学生虚拟机上的真实网络/覆盖安装测试。
