# 2026-10-10 新增问题处理记录（0.4.66）

## 处理结果

- Teacher/Student 版本更新到 0.4.66。
- 教师待配对列表的时间显示中国标准时间 UTC+8；手机端到期时间和课堂时间也固定按 UTC+8 显示，服务端存储仍用 UTC。
- StudentSetup 发现上次运行要求重启时，会读取 Windows 启动时间。若系统在该运行结束后确实启动，历史改为“已完成”，部署不再被旧的“待重启”记录拦截；失败、中断和部分完成仍需复核。启动时间未知时继续保守拦截。
- 手机输入框字号提高到 16px，避免 iOS Safari 聚焦放大页面。控制页拆成“课堂 / 电脑策略”两个页签；待恢复项折叠，课堂消息限制在独立滚动区。
- 手机端刷新/临时断网时不删除本地配对凭据。仅服务器返回 401/403 才进入重新配对；其他连接失败保留控制页和凭据，可点“重连”。
- 配对后提供添加到主屏幕指引；同一浏览器配置下通常可以免扫码。Safari/桌面模式的存储隔离因系统版本而异，首次可能要在图标模式重新配对一次。
- 删除手机端重复的证书/网络排查说明、教师手机设置页的冗长背景文字，以及教师包发布页“仅发布已校验的配置包（ZIP 不超过 64 KiB）”说明。
- 座位功能改名为“座位排序”，控件标为“列数”。它是教师程序保存并供手机求助显示位置的本地数据，不是服务或 daemon。当前仅支持规则行列布局；原数据保留。
- 课堂策略模板可通过网站 API 分发。建议使用签名、版本、校区范围、教师预览/确认、设备回执和课堂结束回滚；0.4.66 不会自动读取云端模板或静默下发策略。

## 实机复测

1. 教师机覆盖安装 0.4.66，确认安装器和“关于”页版本一致；学生机先重启后打开 StudentSetup，确认旧“待重启”不再阻止生成新计划。若历史记录是失败或中断，仍应先人工复核。
2. 手机打开现有安全连接地址，刷新页面；断开 Wi-Fi 后刷新应保留控制页和配对状态并显示“重连”。恢复 Wi-Fi 后点“重连”，不应要求重新扫码。撤销配对后应回到配对页。
3. 在 iPhone/Android 分别聚焦输入框，确认页面不自动放大；按页面指引添加到主屏幕，再从图标打开并确认是否需要在该模式首次配对。
4. 检查教师端待批准请求时间和手机端策略到期/课堂消息时间均显示为 UTC+8；切换课堂/策略页签，确认长消息只在消息区域内滚动。
