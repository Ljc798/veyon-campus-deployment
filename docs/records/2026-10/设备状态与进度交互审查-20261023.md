# 设备状态与进度交互审查（2026-10-23）

本轮依据 `docs/ui_rule.md`、`docs/ui_design.md` 和 `docs/image.png`，审查教师端名单选择、设备健康读取、课堂逐台进度与失败重选的调用链。范围不等同于全应用、真实机房验收。

## 已修复的交互问题

| 问题 | 修复后的行为 |
| --- | --- |
| 设备健康使用网站策略复选框范围；全不选、失败重选会删除健康设备行并使页头变成 0 台 | 健康页监控当前完整名单。网站策略仍只对勾选学生操作；健康批量维护的确认文案明确对应当前名单，仍只发送给满足原有可信状态和修复条件的设备 |
| 全选、全不选和失败重选逐项触发完整状态重算 | 复选框各自更新，相关策略属性在批量选择结束后统一通知一次；勾选不再使健康快照失效 |
| 完整诊断先清空并重插设备行 | 按目标复用原行，不清空集合，保持展开状态和行身份；名单真正变化时移除对应设备 |
| 已发出的轻量查询可能晚于完整诊断返回并覆盖新结果 | 完整诊断开始时提升查询版本号，旧轮询结果按既有版本检查被丢弃 |
| 校区切换沿用上个校区同一地址的退避时间 | 切换校区时清除旧轮询排期，新范围重新读取 |
| 课堂进度随状态优先级重新排序，使正在看的学生跳动 | 保留已有目标顺序，只更新状态并追加新设备；保留展开状态 |
| 网站名单签名写入回执与浏览器实际执行混在绿色状态中 | 写入回执显示“已写入 · 待核对”；浏览器报告应用后才显示“策略已应用” |
| “重试失败设备”实际上仅改变名单选择，且重复追加说明 | 按钮改为“选择失败设备”，保留成功设备但取消勾选，并明确下一步点击“应用限制”；反馈不再逐次累加 |
| 切换校区或名单后，旧失败历史仍能影响新范围的勾选 | 仅允许选择同一校区且仍在当前名单中的失败设备；不存在交集时按钮隐藏，调用也不会改变选择 |

## 界面变化

- 两处灰色嵌套 Expander 改为统一的白底列表、细分隔线、状态标签与轻量展开箭头。姓名、简短说明和记录时间在行内展示，技术原因在详情中展示。
- 设备健康分为状态概览、异常摘要、学生电脑、折叠维护工具；缓存说明、采集耗时和批量修复不再挤在主视图中。
- 缓存记录保留只读语义，不增加修复权限。未核验的浏览器效果没有包装成执行成功，键鼠状态仍不限制网站操作。
- 只读或不适用的异常操作不再展示成一排灰色按钮；仍保留重新检测和查看设备。
- 健康页没有名单时提供配置入口；无筛选结果和无名单分别提示；只有多页数据时显示翻页按钮。
- 概览卡文字在较窄宽度下不再被图标挤掉。逐台进度使用有界 ListBox，实现实际虚拟化。
