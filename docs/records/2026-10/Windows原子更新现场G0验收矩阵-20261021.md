# Windows 原子更新现场 G0 验收矩阵

日期：2026-10-21（Asia/Hong_Kong）

状态：执行表已准备；所有案例默认 `Not run`。这份表定义如何采集证据，不表示任何 Windows 场景已经通过。

## 1. 验收边界

本矩阵执行《学生端更新可靠性计划》的 G0 门槛。至少需要 Windows 10 和 Windows 11 两类学生机、一个教师端、可恢复的隔离测试环境，以及固定的完整签名 StudentSetup 包。CI 中的存储/SYSTEM 夹具只作补充证据；真实设备更新、受控失败、恢复后读回和 Teacher 新鲜签名回执必须分别记录。

只在专用测试机或可还原快照的虚拟机上注入故障。不要在正在授课、承载生产数据或无法重装的机器上制造磁盘不足、任务 ACL 破坏、helper 终止或中途重启。需要替换安装器、签名、任务计划或进程行为的场景，必须使用隔离测试构建/测试密钥或明确的测试夹具；不得修改正式发布包或校区生产私钥来造故障。

任一场景出现 `needsReview`、版本/配置/身份无法读回、旧版任务动作不明或证据互相矛盾时，立即停止后续更新测试，在恢复材料未核清前不要重试或手工删除 journal、旧目录和恢复任务。

## 3. 正常更新与耗时基线

先完成 Win10、Win11 各一台的正常完整包更新和恢复证据审查；之后再采集批量基线。每项性能运行均冻结目标版本、源版本集合、网络类型、Teacher 缓存状态和并发设置。不要在同一组数据中混入首次外网缓存下载与学生机局域网安装时间。

| 编号 | 场景 | 必须记录 | 结果 |
|---|---|---|---|
| `G0-SUCCESS-W10` | Windows 10 单台，Teacher 缓存已命中，完整签名包更新 | 更新前/后快照；StudentSetup、Agent 任务动作和健康版本；配置/身份标签；Teacher 同一命令的签名终态 | Not run |
| `G0-SUCCESS-W11` | Windows 11 单台，Teacher 缓存已命中，完整签名包更新 | 同上；另记录 OS build 和卷剩余空间 | Not run |
| `G0-CACHE-MISS` | 单台首次外网获取目标包 | `time_to_teacher_cache_ready`、下载字节/耗时/吞吐、缓存 miss；与学生机安装阶段分开 | Not run |
| `G0-CACHE-HIT` | 同一不可变发布摘要再次更新/部署 | 缓存 hit、缓存准备耗时、实际外网字节；不得把签名/摘要校验省略 | Not run |
| `G0-BATCH-10-SAME` | 10 台同源版本同时更新至同一目标 | 批次准备时间、每台阶段分布、局域网总字节/吞吐、失败/未确认数量、课堂总时长 | Not run |
| `G0-BATCH-10-MIXED` | 10 台混合源版本直接更新至同一目标 | 每个源版本样本数、缓存复用、成功/回滚/需处理计数及同上耗时 | Not run |
| `G0-BATCH-20-PLUS` | 20 台及以上更新 | 明确目标台数、在线/跳过数、缓存准备、P50/P95/最大值、失败率、课堂总时长 | Not run |
| `G0-NETWORK-WIRED` | 受测有线网络 | 网络类别、批次规模、教师缓存状态、阶段耗时 | Not run |
| `G0-NETWORK-WIFI` | 受测 Wi-Fi 网络 | 与有线组使用相同版本和规模；记录实际分组，不推断原因 | Not run |
| `G0-SLOW-STORAGE` | 仅在可还原测试机上测慢磁盘/低空间边界 | 操作前后卷空间；预检/备份/安装/Agent staging 阶段；不在共享机填满系统盘 | Not run |

必须单独保留以下时钟口径：

- `time_to_teacher_cache_ready`：Teacher 外网查版/下载/验签/缓存准备。
- `time_to_student_installed`：单台学生机从接收局域网更新开始到本机事务终态。
- `time_to_teacher_confirmed`：Teacher 收到并验证同一 commandId、设备身份和目标版本的新鲜签名回执。
- `classroom_rollout_duration`：一次批次从发起到每台设备均处于明确终态。

每份统计都带样本数。样本少时将 P95 标记为初步结果，不用它单独决定扩大并发、缩短 timeout 或删除校验步骤。

## 4. 失败注入与恢复矩阵

每次失败注入从已记录的稳定旧版本开始；每个案例使用独立恢复点。前置快照需显示旧版本、主 Agent SYSTEM 任务动作、配置/身份 HMAC 标签和卷余量。完成故障操作后先等待有限时间并检查 Teacher 终态，再采集后置快照。

| 编号 | 注入场景与安全方式 | 预期学生端结果 | 必需读回与证据 | 结果 |
|---|---|---|---|---|
| `G0-REJECT-SIGNATURE` | 通过隔离测试签名/自动化夹具提供无效命令签名或发布清单 | 在创建恢复点、启动安装器前拒绝；旧目录和主任务不变 | 前后版本、任务动作、journal/恢复目录状态、Teacher 拒绝终态 | Not run |
| `G0-DOWNLOAD-INTERRUPT` | 更新下载期间断开测试机到 Teacher 的 LAN 连接，然后恢复网络 | 下载失败，不报告安装成功；旧版本与主任务保持可用 | 失败阶段、收到字节数、暂存清理状态、旧 Agent 健康读回、Teacher 终态 | Not run |
| `G0-DOWNLOAD-TRUNCATE` | 在隔离测试夹具中让下载流短于签名包大小 | 摘要/大小检查失败；不得运行 StudentSetup 安装器 | 安装器未启动证据、旧版本/任务、残留暂存状态 | Not run |
| `G0-DISK-PREFLIGHT` | 使用可还原的小容量虚拟磁盘或测试预检注入；不填满生产系统盘 | 空间预检失败；不得改变安装目录或 Agent 任务 | 操作前后卷余量、journal/恢复目录、旧版本及 Teacher 失败终态 | Not run |
| `G0-INSTALLER-FAIL` | 仅用隔离的测试包/故障夹具使 Inno 返回非零或超过有界等待 | 旧 StudentSetup 恢复，旧 Agent 任务/健康状态恢复；恢复失败则 `needsReview` | Previous/FailedCandidate 状态、journal、进程退出确认、setup 版本、任务动作、健康、Teacher 终态 | Not run |
| `G0-TASK-ACL-FAIL` | 通过测试夹具让恢复任务 ACL 读回失败；不手工改正式设备任务 DACL | 在活动目录改动前停止；若在激活阶段注入，必须恢复旧任务或保留材料进入 `needsReview` | SYSTEM 主任务动作、恢复/watchdog 注册与 ACL 读回、旧 Agent 健康、Teacher 终态 | Not run |
| `G0-AGENT-START-FAIL` | 仅用隔离测试包/夹具使候选 Agent 无法启动或健康指纹不符 | 恢复旧任务、StudentSetup 与旧 Agent；不得报告成功 | 目标/旧版本、健康版本与配置匹配、两个连续性标签、journal 终态和签名回执 | Not run |
| `G0-HELPER-EXIT` | 夹具只终止本案例已确认路径与 PID 的 UpdateHelper；禁止按进程名盲杀 | 恢复入口幂等处理：候选不健康时回滚；候选健康时允许提交；期间 Teacher 不应提前成功 | helper PID/退出时点、journal、任务动作、health、恢复任务清理顺序和 Teacher 终态 | Not run |
| `G0-REBOOT-PREPARED` | 在 `Prepared` journal 已落盘后，使用虚拟机控制重启测试机 | 启动恢复后旧版可用，事务有明确回滚终态 | journal、旧目录、旧任务/ACL、健康、配置/身份标签、Teacher 终态 | Not run |
| `G0-REBOOT-SETUP` | 分别在旧目录保留、安装器待运行/运行中、StudentSetup 已读回阶段重启 | 按 journal 幂等恢复或安全回滚；不得删除仍可能被安装器使用的暂存文件 | 每个阶段单独一份前后快照、安装器退出证明、恢复材料和 Teacher 终态 | Not run |
| `G0-REBOOT-AGENT` | 分别在 AgentStaged、ActivationPending 阶段重启 | ActivationPending 下只有候选 Agent 与配置指纹均健康才提交，否则恢复旧版；其他未完成阶段按规则回滚 | SYSTEM 任务路径/ACL、候选和旧 Agent 健康、journal、setup 版本、签名读回 | Not run |
| `G0-RECOVERY-REQUIRED` | 在隔离故障夹具中再让一项恢复步骤失败 | 标记 `RecoveryRequired/needsReview`；保留全部可识别的旧版、journal、暂存和恢复任务，不清理、不报告成功 | 故障阶段、恢复失败类别、材料仍在、教师端需处理终态 | Not run |

没有对应的测试构建或受控注入钩子时，将该项标记 `Blocked` 并写明缺失工具，不通过人工“模拟成功”替代证据。所有重启场景必须有可还原快照；每个 stage 单独记录实际持久化状态，不能用更新时间推断当前操作已经完成。

## 6. G0 关闭判定

只有在 Win10 与 Win11 正常更新都完成，规定的失败/重启注入都有可核对的旧版或候选提交终态，所有配置/身份/任务读回符合预期，Teacher 新鲜签名回执与学生 journal 对应，且性能报告提供缓存准备、学生端更新、教师确认和批次总耗时的真实样本时，才可以申请关闭 G0。任何 `Blocked`、`RecoveryRequired`、未知状态或缺少回执都意味着 G0 未通过。

托管 Windows CI artifact、PowerShell 语法解析、代码构建、离线夹具都不能单独关闭 G0。文件级增量仍须在 G0 和 M1 完成后才进入发布路径。
