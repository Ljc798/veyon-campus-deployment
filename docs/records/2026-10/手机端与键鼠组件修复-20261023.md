# 手机端与键鼠组件修复（2026-10-23）

## 范围与结果

按 `docs/ui_rule.md`、`docs/ui_design.md` 统一手机端课堂、设备、网站策略和消息界面。教师端、学生端试用安装包已构建；未发布或部署。仍需手机视觉验收和真实学生机键鼠验收，不能据此宣布正式 rollout 完成。

### 手机端

- `MobileWeb/index.html`、`styles.css`：统一浅色卡片、细分隔线、图标、触摸尺寸及窄屏排版；课堂进度采用紧凑列表，设备目录增加姓名搜索。
- 消息从课堂页移到顶部全局弹层，学生姓名在对话上方；底部为紧凑输入框与 SVG 发送按钮。按学生保留草稿，发送中禁止切换学生，保留 Enter / Shift+Enter / 输入法判断。
- `app.js`：复用进度行并保持展开状态；保留成功设备，区分签名写入与浏览器执行确认。接受合法的 `websiteAndInputLocked` 组合状态。
- `TeacherMobileControlServer.cs`、`TeacherViewModel.cs`：手机读取和保存名单时保留教师端的明确网站模式，推送时携带模式。避免名单中同时有黑白条目就擅自转换成组合模式；兼容没有模式字段的旧请求。
- 样式和脚本版本改为 v40，service worker 命名空间同步更新；原有配对、审批、认证、签名、租约与试点门控保留。

### 键鼠组件

用户截图显示 supervisor 多次记录 Started，另有 StartExited / ExitCode=1。能够确认发生过启动退出，但旧日志不足以确定最终原因。

- `WindowsProcessImagePath.cs`：采用 `PROCESS_QUERY_LIMITED_INFORMATION` + `QueryFullProcessImageNameW` 查询 IPC 对端路径，替换需要更多进程访问权限的 `MainModule`。仍严格校验安装路径和会话。
- `StudentInputGuardServer.cs`：单次连接被拒绝、断开、读取异常或超时只结束该连接，不退出整个 Guard；连接事务设置三秒超时。
- `GuardDiagnostics.cs` / `Program.cs`：在当前学生用户的 `%LOCALAPPDATA%\VeyonCampus\InputGuard\guard-server.log` 记录退出或拒绝连接原因、异常类型和 Win32 错误码，限制日志大小。
- 没有放宽管道 ACL、对端身份检查或锁定租约；没有提高进程权限，也没有把无法确认的状态改成成功。
