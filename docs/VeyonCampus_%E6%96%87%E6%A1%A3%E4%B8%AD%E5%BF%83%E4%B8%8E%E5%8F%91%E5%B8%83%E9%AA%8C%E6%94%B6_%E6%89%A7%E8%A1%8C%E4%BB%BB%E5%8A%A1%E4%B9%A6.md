- 根因不是排序而是**召回**：Pagefind 对空格分隔的词用 AND 语义，整句中文问句里任何一个词没在同一篇里共现就整体归零。直接探测索引可见 `安装` 命中 16 篇，而 `学生电脑安装之前要准备什么？` 命中 0 篇；失败项中有 14 条返回"无"。
- 修复一（查询松弛）：新增 `relaxQuery()`，用 `Intl.Segmenter` 分词后去掉疑问/语气脚手架再以空格重新拼接，作为第二个变体参与合并；没有可丢弃的词时返回空，避免浪费变体槽位。实测 27/47 → 33/47。
- 修复二（目录召回兜底）：新增 `catalogFallbackResults()`，仅在**所有** Pagefind 变体都无命中时，用文章目录的标题/错误码/别名/关键词/摘要做加权打分（权重与 Pagefind metaWeights 对齐），保证"搜不到"只发生在语料真的没有时。首版条件写成 `list.length === 0` 无效，因为排名循环会 push `null` 占位，改为按条目判断后才生效。实测 33/47 → 46/47。
- 修复三（别名补录）：为"学生电脑怎么装 Veyon Campus"这类自然问法补入安装文章别名，最后 1 条从第 4 名进到前 3。
- **修复后实测：前 3 名 47/47（100%，目标 ≥90%）；关键问题 28/28（100%，要求 100%）；MRR 0.943（关键问题 0.940）；P95 255 ms；首次查询读取 Pagefind 资源约 24.4 KB / 2 个文件。评测状态 `pass`。**
- 评测方法：无头 Chrome 通过 CDP 打开本地评测页，按真实时间轮询到 `#evaluation-summary[data-state]` 结束，再逐行导出结果；未使用 `--virtual-time-budget`，因为它会把 15 秒超时快进而真实索引请求尚未完成，导致全部查询误报超时。
- 仍未做：CloudBase Preview/深链接、移动端、键盘与屏幕阅读器人工验收；上述数字是本机静态构建的检索质量，不等于生产环境验收结论。

## 0. 最终决策（不可误解）

**第一优先级是官网知识库，不是继续增加教师端内部页面。**

1. 官网 `/docs` 升级为真正的**文档中心和问题搜索页**，支持浏览、分类、中文问题搜索、FAQ、分步骤教程、故障处理。
2. **教师端只增加一个“帮助与文档”入口。** 点击后使用操作系统默认浏览器直接打开 `https://kidscode.fun/docs`；**不内嵌 WebView、不建立第二套本地搜索、不缓存文档、不维护离线文档副本**。打不开浏览器或网页时显示简明提示并允许复制网址。官网是唯一文档发布来源。
3. 对仓库资料进行**审阅、筛选、整合、重写**，不是将 `docs/` 下所有文件不加处理地公开；面向教师和学校管理员的内容必须是“大白话”，必要时才解释专业词汇。开发内参、安全敏感资料和历史废弃说明不得进入公开索引。
4. 初版采用**纯静态搜索，优先 Pagefind + 中文内容优化**。不部署 Meilisearch/Elasticsearch、独立搜索 API、向量库或付费大模型，不把“问问题”误写成“AI 自动回答”。先返回有证据的文章和匹配片段；AI 问答是未来可选功能。
5. 本阶段**不把 Schema 3 或旧 Agent 0.4.55/0.4.56 全量历史升级矩阵作为稳定版阻塞项**。现有校区已升级到 1.1.6x；但仍需实测**当前已装 1.1.6x 的最低实际版本**升级到目标版本，验证密钥不变化、设备身份和课堂功能不回归。
6. 公开网站文档中心与教师端入口优先交付；正式版升级按独立验收门槛推进。**Commit 数多不是完成的证据。**

## 4. 中文搜索引擎决策：先做可测量的静态搜索

| 方案                                | 优势                                                                                                    | 限制                                                                                     | 决策                               |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ---------------------------------- |
| **Pagefind（优先）**                | 可直接索引静态 HTML，构建期生成分块索引；支持中文断词、多语言、摘要、过滤和权重；静态托管、无查询服务器 | 当前 SPA 动态拼接内容不能自动进入索引，必须先静态生成文档 HTML；需要实测中文自然语言查询 | **P0 采用**                        |
| MiniSearch                          | 小型 JS 方案，可自定义 `tokenize`、权重与查询逻辑                                                       | 默认以空白/标点切词；中文需自定义分词与索引构建，维护成本由自己承担                      | 仅当 Pagefind 质量明显不达标时备选 |
| FlexSearch                          | 灵活索引与自定义 CJK 编码，前端性能好                                                                   | 中文切词、语义召回、数据与索引管理仍需自定义                                             | P2 备选                            |
| Meilisearch/Typesense/Elasticsearch | 提供服务端搜索、高级过滤与动态数据管理                                                                  | 多出服务器、成本、运维、安全、限流和部署依赖                                             | 当前文档量不值得                   |
| 向量搜索/AI 问答                    | 对口语化问题和语义相似度更强                                                                            | 费用、幻觉、引用溯源、数据治理复杂；不应该让老师把搜到的文字误认为已验证事实             | 未来独立评估                       |

- Pagefind 中文分词：https://pagefind.app/docs/multilingual/
- Pagefind 运行与构建：https://pagefind.app/docs/running-pagefind/
- Pagefind 内容范围：https://pagefind.app/docs/indexing/

### 4.1 技术陷阱：Vite SPA 文档无法直接被 Pagefind 搜到

当前 `website/app.js` 的 `docsPage()` 在浏览器执行后才生成文章内容。Pagefind 默认索引**构建完成后 HTML 文件里真实存在的文本**，不是在浏览器中运行页面、等待 JS 渲染。**不能简单安装 `pagefind` 然后对 `website/dist` 建索引就声称完成**。

推荐的最小改造：

1. 新建一套经审核的公开文档源文件（建议 `website/content/docs/**/*.md`），不直接把开发仓库全量当作公开文档。
2. 在现有 `vite build` 流程后运行 `scripts/render-public-docs.mjs`：将文章 Markdown 转为**真正的独立静态 HTML 页面**，生成 docs 首页所需的分类索引/文章元数据，输出到 `website/dist/docs/articles/*.html`。页内统一 `lang="zh-CN"`、`title`、`description`、`canonical`、`article`、导航和站点样式。
3. 再执行 `pagefind --site dist`，只索引带 `data-pagefind-body` 的公开文档正文；站点后台、站点选择器、下载页版本弹窗及敏感数据不得进入索引。
4. `/docs` 页面加载 Pagefind 的浏览器搜索 API，使用统一 UI 包装，确保中英文混合搜索（如 `HTTP 409`、`Agent`、`PC-01`）可用。
5. 静态部署前对 `dist/docs/`、`dist/pagefind/` 进行存在性、HTML 链接、XSS 安全与中文检索检查；失败即禁止部署。**先在 Preview 环境验证，再改生产托管。**

示意构建命令（不是现成可运行的仓库命令，待 Codex 接入）：

```sh
cd website
npm ci
npm run build
node scripts/render-public-docs.mjs --output dist
npx pagefind --site dist
```

正式落地时应固定 Pagefind 依赖版本和 lockfile；将上述步骤合并为可重复的 `build:docs` 脚本，避免每次依赖 `npx` 在线临时获取最新版。

### 4.2 排序与“搜问题”体验

P0 召回逻辑：**中文断词 + 英文小写规范化 + 精确短语/标题高权重 + 维护的同义词/常见别名 + FAQ 问句多样化**。Pagefind 内置标题权重，优先按内容结构改善结果；对症状/错误码使用结构化 `aliases`、`keywords`、`errorCodes`，而不是在 JS 里写成百上千条 `if`。

示例同义词：

- `location` ⇄ `地点` / `机房` / `教室`（注意这三个业务含义不完全相同，需结合上下文）
- `maintenance` ⇄ `维护服务` / `后台维护` / `静默更新`
- `离线` ⇄ `连不上` / `不在线` / `无法连接`
- `409` ⇄ `信任根不匹配` / `身份不一致`（HTTP 409 也可有其他原因，不能写死等号）
- `座位表` ⇄ `座位图` / `打印编号`。

不要把 `409` 自动解释成某一个唯一根因；结果列表应展示多个可能文章，并按实际错误信息进一步排查。拼音、错别字纠正、智能推荐列为 P2，只有 P0 搜索评测失败且有真实需求时才实施。

### 4.3 搜索验收指标

建立 `website/tests/docs-search-queries.json`，**至少 30 条真实、口语化的中文提问**，每条标注标准结果 URL、可接受替代结果和版本范围（见 §10 示例）。

- P0 搜索成功率：目标文章在**前 3 条**中的比例 ≥ 90%；关键安全问题和安装问题必须 100% 可命中。
- 错误码、版本号和组件名如 `HTTP 409`、`1.1.77`、`Maintenance`、`PC-01` 可精确检索。
- 100 篇以内中文文档、常见手机与低配电脑上实测首屏、搜索响应和资源加载，不先承诺未测的毫秒级 SLA。约束：预估实际索引资源、首次查询资源体积与静态流量，并在 CI 记录。
- 搜不到问题时提供“换个说法试试”和问题反馈入口；绝不展示编造的 AI 答案。
- 键盘操作、焦点管理、Enter/ESC、无障碍标签、搜索框防抖、加载/错误/空状态、移动端均通过手动验收。

本地浏览器排名评测：在 `website/` 执行 `npm run build`、`npm run prepare:search-evaluation`、`npm run preview`，然后打开 `http://127.0.0.1:4173/docs/__search-evaluation.local.html`。评测页面会逐条触发真实 `/docs` 搜索并统计前 3 名；完成后停止 Preview 并执行 `npm run clean:search-evaluation`，避免将仅供本地验收的评测页带入其他发布操作。

## 5. 内容整理：从开发文档转成“老师能直接照做”的操作知识

### 5.1 内容来源审计

把仓库资料分成四类，建立 `docs-site-source-inventory.csv`（或者 JSON）：

| 来源                                                                 | 公开策略       | 处理方式                                                      |
| -------------------------------------------------------------------- | -------------- | ------------------------------------------------------------- |
| `README.md`、产品功能介绍                                            | 可公开部分     | 压缩产品术语，转为“这是什么”“老师能做什么”                    |
| `website/app.js` 旧 `/docs`                                          | 可公开部分     | 拆成快速开始系列，保留旧页面链接                              |
| `docs/` 中用户指南、发布/分发说明、FAQ                               | **人工筛选**   | 去重、更新截图和按钮名，按当前功能实测编写                    |
| `docs/maintenance/`、设计文档、`specs/`、测试脚本、CI/CloudBase 内参 | **默认不公开** | 只提取对用户有帮助且无敏感风险的结论；工程细节保留内部        |
| Release Notes、历史问题清单                                          | **谨慎公开**   | 只把适用当前版的常见故障转成帮助文章；历史 Bug 不等于当前 Bug |

**不允许出现在公开正文、搜索索引、静态 JS/JSON 或截图中**：签名私钥、Token/密码、API 凭据、内部证书材料、真实学校/机房及学生姓名、设备指纹、实际校园 LAN IP、未获授权的设备截图、管理员内部部署细节、校区配置包内容、可用于绕过安全校验的操作说明。必要的日志示例用合成数据并脱敏。

### 5.2 每篇文章统一格式

建议 frontmatter（仅作规范，最终解析器需白名单校验）：

```yaml
---
id: troubleshoot-student-offline
slug: student-offline
title: 学生电脑显示“离线”，怎么办？
summary: 先检查电脑有没有开机、是不是在同一个网络，再看教师端的连接提示。
category: troubleshooting
audience: [teacher]
keywords: [离线, 不在线, 连不上, 找不到学生电脑, Veyon]
verifiedFor: ["1.1.77"]
verificationStatus: needs-field-test
lastReviewed: 2026-11-07
sourceRefs:
  - docs/maintenance/classroom-feature-acceptance.md
---
```

文章正文固定为：**一句话结论 → 适用条件 → 按编号操作 → 如何判断成功 → 不成功怎么办 → 相关问题**。只有复杂步骤才使用截图或短视频；每一张图必须有中文替代文字与脱敏检查。

### 5.3 语气风格（强制）

**不推荐：**“请验证 Student Agent 维护通道的签名身份，并检查 Desired/Reported revision。”  
**推荐：**“先看学生电脑是否在线，再在‘设备与更新’里点‘重新检查’。如果系统提示‘校区身份不匹配’，说明教师端使用的校区配置和学生电脑原来的配置可能不同。先核对校区，不要反复创建新的配置包。”

第一次出现术语时，写成：**“维护服务（Maintenance）：安装在学生电脑后台的程序，负责接收更新和处理恢复。平时不用手动打开。”** 不应在没有证据时承诺“永远自动成功”。

**操作按钮名称**必须与当前实测 UI 一致。对未验证的功能，应写“部分版本可能提供 / 请以实际界面为准”或暂不公开相应教程，不应写成已正式上线。

### 5.4 内容验收与维护机制

- 一篇文章至少核对 `sourceRefs`、实际 UI、适用版本、最后审校人和文档状态。
- `draft` 不参与公开构建；`published` 才进搜索索引；`obsolete` 保留内部历史，旧公开 URL 需重定向或显示替代文档。
- 默认优先更新**常见问题、部署操作、紧急恢复**，而非开发架构长文。
- 软件发布时，只有涉及用户可见流程的改变才触发文档审查；文档发布不触发软件版本号升级。
- 文章改动至少经一次非开发者视角校对：老师可以只照文章完成操作，不需要知道 Git、PowerShell、Schema 等细节。

## 6. 教师端入口（此项已经按用户最新决定收敛）

### 6.1 功能定义

- 显示文字：**帮助与文档**；配书本或问号图标，与教师端现有导航视觉规范一致。
- 位置：教师端左侧导航靠底部的帮助/辅助区域（如现有布局更合适，也可在“设置/关于”区域）；不得再增加一个完整顶级页面或复杂工作区。
- 点击行为：调用系统默认浏览器打开 **`https://kidscode.fun/docs`**。**不是应用内浏览器、不是内嵌网页，也不是本地离线文档**。
- 遇到浏览器启动失败：显示“未能自动打开网页，请复制地址后在浏览器中访问”，并提供复制链接操作。
- 不依赖教师登录、校区身份、学生 Agent 或 Maintenance 服务；点击不会写入校区/设备配置。
- URL 固定 HTTPS 域名与路径，不能让校区配置或网络响应替换成任意网址；不能携带教师密钥、身份指纹、学生名或其他敏感数据作为 query 参数。
- 同时兼容 Windows Teacher Console 和已有 macOS Teacher Console。若 macOS 构建不在本轮交付范围，则仍需确保编译无平台专属 API 错误。

### 6.2 .NET 实现建议（示意）

```csharp
private const string DocumentationUrl = "https://kidscode.fun/docs";

private static void OpenDocumentation()
{
    var info = new System.Diagnostics.ProcessStartInfo(DocumentationUrl)
    {
        UseShellExecute = true
    };
    System.Diagnostics.Process.Start(info);
}
```

以上只是简化示意：真实实现需复用项目已有的 URL 启动/外链处理能力、捕获平台异常、向 UI 提示错误，并通过测试验证默认浏览器调用；不要在未核对现有 UI 架构时复制黏贴一个新的帮助窗口。

### 6.3 验收

- Windows：点击一次，仅打开一个默认浏览器标签页，目标为 `/docs`；不弹新内嵌窗口。
- macOS：验证同样的行为，失败不会导致教师端崩溃。
- 断网：浏览器可能显示网络错误，但教师端不会卡死；不引入“离线文档中心”。
- 从课堂页面、座位图、维护页进入，原页面状态不丢失；文档入口不会启动/中断课堂、变更策略或触发更新。

先审查现有 `website/app.js` 的站点选择、历史 `/docs` 路由和 CSS 设计系统；**只抽离文档功能，不要借机大规模重写全站**。支持电脑与手机阅读；不要为文档中心安装复杂的 UI 组件库。

### 7.2 安全控制

- Markdown 渲染处理原始 HTML、链接协议与嵌入内容：严格限制脚本、事件属性、`javascript:` URL 和不安全 iframe，避免静态文档带来 XSS。
- 外部链接默认 `rel="noopener noreferrer"`，必要时 `target="_blank"`；站内链接统一检查有效性。
- 对公开稿全文、生成 HTML、搜索索引和静态资源执行敏感信息扫描；**部署包/签名根材料、校园配置、真实学校学生信息必须排除**。
- 建议 CSP、依赖固定、禁止第三方追踪默认收集用户搜索内容；若需要搜索分析，先做隐私评估，只保留聚合指标，不记录原始 IP 或包含个人信息的查询。
- 扫描许可证：Pagefind、Markdown 解析库、图标与截图的授权范围。未经确认不得复制第三方手册整篇正文。

### 7.3 SEO / 可用性

- 文章为独立可访问 HTML，title/description/canonical/OG/站点地图明确；`lang="zh-CN"`；主内容有结构化标题层级。
- 文档移动时保留旧链接重定向或对应替代页；文章 URL 尽量永久稳定。
- 搜索失败时分类导航仍可使用；禁用 JS 时，静态文章仍可阅读（搜索可不可用）。
- 页面不因索引加载而阻塞首屏；针对 CloudBase 静态托管文件/缓存行为验证，避免旧索引指向新文章而造成 404。
- 上线前在预览托管验证直接访问 `/docs/articles/xxx.html`，刷新仍能返回文章，`/docs` 不误入 KidsCode 旧站选择器。

### 8.1 基线与范围

- 用户已确认：**现在没有需要从 Schema 3 或古老 Agent 0.4.x 起步迁移的校区**，现有校区均已升级到 `1.1.6x`；因此旧基线大矩阵不阻塞本轮发布。

### 8.2 发布阻塞项清单

| 编号  | 场景                          | 必须看到的结果                                                                                                             |
| ----- | ----------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| RC-01 | 最新 Commit 对应的 Windows CI | 编译、测试、安装器、签名/哈希检查完成，日志可追溯；不能用旧 SHA 的绿灯冒充最新 SHA                                         |

### 8.3 发布建议

- 官网文档中心可先独立预览和上线，不等 Maintenance 完成所有路线图功能；但未验收功能不应该写成稳定可用。

## 11. 第一批 FAQ 示例：给 Codex 的文案风格样本

### 学生电脑显示“离线”，怎么办？

先别急着重新安装软件。通常需要先确认电脑有没有开机、是不是连上学校网络，以及教师端能不能找到它。

1. 在那台学生电脑上看一下：能不能正常开机并进入桌面？
2. 检查教师电脑和学生电脑是否连接学校允许互通的网络。
3. 返回教师端，打开设备状态，重新检查这台电脑。
4. 如果仍然离线，记下界面提示的完整文字，再打开对应的“连接问题排查”教程。

**怎样才算恢复？** 教师端能看到学生电脑当前状态，并且能正常读取它的连接信息。仅看到“电脑名字在列表里”，还不能说明电脑已经在线。

### 为什么修改机房或校区名字后，更新失败？

学生电脑会记住最初安装时信任的校区身份。教师端如果换成了另一套校区身份，学生电脑可能拒绝更新请求。这是安全保护，不是简单的网络故障。

先打开教师端的校区身份诊断功能，核对学生电脑实际信任的校区。**不要反复创建新的校区配置包或密钥。** 如果提示仍然无法解决，请保存完整错误文字交给管理员处理。

### 电脑编号和学生姓名有什么区别？

**电脑编号是座位上的位置标记，学生姓名是坐在这里的人。** 比如座位一直叫 `PC-03`，原来坐张三，后来换成李四，只需要改学生姓名；电脑换了，也应先重新绑定新电脑，而不是把所有座位重新编号。软件识别电脑还会使用内部的设备标识（UUID），它和打印的编号不是一回事。

## 12. 完成定义（Definition of Done）

**只有同时满足下列条件，才称“官网文档中心上线完成”：**

- 现有 `/docs` 进入搜索型文档中心，稳定 URL 可直接访问；25–40 篇首批文章有审校记录。

- CloudBase 静态托管上直接访问文章 URL 正常；站点选择与管理员后台、下载页回归通过。
- 搜索索引不包含敏感材料、工程内参、未授权截图和真实学生信息。
- 教师端**仅增加一个外链入口**，默认浏览器跳转官网，断网不会导致应用故障。
