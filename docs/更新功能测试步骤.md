# 更新功能测试步骤

当前版本没有固定 Developer Release 公钥，CloudBase release API 和相关迁移也尚未部署，因此更新检查会安全失败关闭；此时不能做有效的在线更新测试。

开始验收前：

1. 在受控密钥库或 CI 中创建**测试专用** RSA 密钥对。私钥不得放进仓库、`artifacts`、安装包或日志；只有公钥可用于构建客户端。生产发布另用独立密钥。
2. 使用 `scripts/package-windows-offline.ps1 -ReleasePublicKeyPath <公钥 PEM 路径>` 构建 Teacher 和 StudentSetup 测试安装包，安装较旧版本。
3. 按[网站与云端指南](网站与云端指南.md)先部署并核对 release 数据库迁移、API 和路由；用对应测试私钥签名较新版本的发布清单，再发布测试安装包。

验收顺序：

1. 在专用测试 VM 发布校区配置包并发送每日 Teacher 心跳；确认心跳响应附带 TeacherConsole 与 StudentSetup 的最新签名清单。没有比本机更新的版本时不弹窗。
2. 发布高于本机版本的测试清单后，从尚未发送当日心跳的快照启动 Teacher，确认只弹出版本提示且显示角色、当前版本和最新版本；关闭提示后不应自动下载或安装。签名无效的清单不能触发更新提示。每日心跳本机按 UTC+8 去重，重复验收请还原该快照或使用独立测试配置。
3. 云端最新 TeacherConsole 版本与本机相同或更旧时，点击“检查更新”，确认提示当前已是最新版本。
4. 发布同一角色的更高版本，确认清单签名、版本、大小和 SHA-256 验证通过，再安装并核对重启后的版本。
5. 分别用错误签名、错误角色、被修改的安装包和不匹配的摘要测试，确认客户端拒绝安装且当前版本仍可启动。
6. 在可还原的学生测试机上测试 Agent 推送：核对校区命令签名、版本、有效期、TCP 39175、安装后版本读回及失败回滚。

Teacher 的“检查更新”面向本机控制台；“检查最新版本并对所选电脑静默更新”面向学生机。两条路径都依赖已固定的公钥和已部署的 release 服务。不要用真实机房做首次测试。
