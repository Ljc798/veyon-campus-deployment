# 学生端首次部署与恢复指南

适用源码版本：Veyon Campus 0.4.54 学生部署工具（StudentSetup）。本文按当前源码和窗口流程编写，供 Windows 验收时逐步核对；Windows 实机验收仍未完成。

> 这是操作草案，不代表 Windows 10/11 已通过实机验收。首次操作先用可还原的测试电脑；生产机房须等一教师一学生验收完成后再逐步扩大。

## 1. 开始前

### 需要准备

- 从可信渠道取得 **学生部署工具** Windows x64 Setup EXE，并核对发布版本和 SHA-256／签名信息；安装后从开始菜单启动 StudentSetup。不要把教师控制台安装器发给学生。校区配置包是另一份小型 ZIP，不能用它代替 App 安装器。
- 从教师端取得目标校区的配置包。配置包中的校区、电脑名前缀、公钥和策略公钥都必须来自该校区的授权教师；不要自行编辑包内文件。
- 两端启动时统一请求管理员权限；已授权的应用启动短时 Worker 会继承权限，不应在各步骤重复弹窗。安装结束后启动继承安装器权限；以后从快捷方式启动时可能再要求一次确认。取消启动授权不执行部署。测试包仍未做 Windows Authenticode 签名。跨账户输入管理员凭据时，档案及教师签名证书使用该管理员账户的数据，不能据此认为原账户密钥被删除。
- 在待部署电脑上确认有可用的本地管理员账号，并以管理员身份运行 StudentSetup。当前版本要求管理员进程执行 Windows 系统修改。
- 确认电脑可回滚或重装，并记录 Windows 版本、构建号、架构、Veyon 状态和恢复办法。域、组策略或 MDM 管理状态未知时先请学校 IT 核实。
- 先用一台测试电脑确认流程，再做小批测试。不要把第一次执行安排在无法恢复的课堂电脑上。

### 当前云端状态

StudentSetup 已有“从云端获取”入口。CloudBase `veyon-api` HTTP 云函数和默认 API 路由已部署；健康与目录查询均返回 HTTP 200，目录已有记录。一次合成教师发布已成功，数据库中存在配置包记录和私有对象；学生下载、撤回清理、真实限错和 Teacher 心跳仍未完成端到端验收。首次试用请继续使用合成配置包；需要离线时，可复制配置文件夹到学生电脑本机磁盘后导入。最新状态见[网站与云端指南](网站与云端指南.md)。

## 2. 选择并核对配置来源

StudentSetup 的第一步是“配置来源”。可选择：

1. **从云端获取**：输入校区名称或电脑名前缀，按 Enter 或点击“搜索”，选择教师发布的版本，输入发布教师手机号后四位，再选“下载并使用”。下载后工具会验证 ZIP、manifest 和文件摘要。
2. **导入本地配置**：先把教师提供的整个配置文件夹复制到学生电脑本机磁盘，再用文件选择器选择该文件夹。UNC 路径和映射网络盘已停用；不要直接从 `\\server\share` 或网络盘导入。

载入后检查校区和电脑名前缀，并打开“配置校验详情”查看清单、公钥和路径检查结果。出现校验错误时停止操作，请教师重新生成或提供匹配配置；不要通过删除清单、替换公钥或跳过校验来继续。

## 3. 选择部署操作

第二步“部署内容”提供四项独立操作。逐项勾选，并核对右侧“总结果预览”。只运行明确勾选的项目；未勾选的账户、电脑名或 Veyon 设置不应随其他操作隐式更改。

| 操作 | 实际范围 | 执行前应确认 |
| --- | --- | --- |
| 配置 Veyon | 使用 App 内嵌的固定版本离线安装学生组件（未安装时），设置密钥认证并导入已校验的校区公钥；若配置包包含网站策略公钥，也会安装独立的网站策略 Agent。 | 校区配置必须匹配本机所属校区。已有 Veyon 若版本或安装状态无法确认，程序会停止，先由管理员核对。 |
| 修改电脑名称 | 按配置中的前缀和 1–150 编号形成目标名，例如编号 3 会格式化为 `03`；新名称必须符合 Windows 名称规则和长度限制。 | 核对前缀、编号及最终名称。改名通常要重启后才生效。域成员、域状态未知或检查失败时，包含改名的整个组合计划会被阻止。 |
| 创建学生账户 | 创建本地标准用户，不赋予管理员组权限。若已存在符合条件的普通账户，保留原密码并跳过创建。 | 核对账户名。初始密码可按本地要求填写两次；两栏均留空时会按无初始密码路径创建，使用前应确认学校账户策略允许。 |
| 修改管理员密码 | 给指定的本地管理员账户设置新密码。程序会再次核对目标账户身份（SID），并要求新密码输入两次。 | 确认账号确实是本机要修改的管理员，并通过学校批准的方式保管新密码。旧密码不可读取，也不能由 App 自动恢复。 |

### 单项操作

- **只配置 Veyon**：载入匹配的校区配置包，勾选“配置 Veyon”。该操作不会重命名电脑或创建／改动账户。若电脑已装固定版本 Veyon，安装步骤会跳过，后续配置和验证仍按结果页显示。
- **只改名**：勾选“修改电脑名称”，填编号并确认预览；不需要配置包。若处于域管理环境或域状态未知，停止并联系 IT。
- **只创建学生账户**：勾选“创建学生账户”，核对用户名和两次初始密码；不需要配置包。已有合格普通账户不会重建或重置密码。
- **只改管理员密码**：勾选“修改管理员密码”，核对本地账户名并两次输入新密码。建议单独运行，确认新密码已经安全交接后再继续其他部署步骤。

### 组合操作

可同时明确勾选多项。当前计划的执行顺序是：创建学生账户 → 安装／配置并读回 Veyon（包括包内网站策略 Agent）→ 修改管理员密码 → 修改电脑名称。管理员改密不能自动恢复旧密码，因此放在 Veyon 成功之后、可能要求重启的改名前。若 Veyon 安装要求重启，本轮计划会停止，改密和改名均不会开始；重启后先检查 Veyon 实际状态，再重新预检并生成新计划。

组合操作不是事务，也没有通用的自动回滚。特别是管理员密码变更后，后续改名失败时新密码仍已生效；Veyon 失败或待重启则会在改密之前停止。因此，对账户身份或恢复方式不确定时，先拆成单项执行；涉及密码更改时建议单独操作。每轮只使用一台测试电脑，确认读回结果后再扩大。

## 4. 环境检查与执行

1. 转到第三步“环境检查”，点击“重新检查”。这会按本次已选操作读取账户、权限、Veyon、配置资料及其他前置条件。
2. 打开有提示、未通过或未知的项目详情。处理问题后重新检查；不要忽略阻断项，也不要在输入或配置变更后沿用旧检查结果。
3. 全部条件允许后进入第四步“执行部署”。逐项再核对操作、电脑名、账户和不可自动恢复项。
4. 确认后开始执行。执行中等待当前步骤结束，不要关闭程序、强制结束进程或关机。状态会分别显示成功、跳过、失败、部分完成、待重启或需核对。
5. 到第五步查看结果和每一步详情。只有页面显示的成功步骤才可记作完成；“列表已写入”“安装器已退出”或单一 Agent 回执不能代替实际系统读回。

运行事件记录按当前 Windows 用户写入 `%LOCALAPPDATA%\VeyonCampus\runs\<运行编号>\run.jsonl`。重新打开 StudentSetup 后，可在第一步点击“查看最近部署结果”查看最近一次摘要；摘要只恢复状态码和记录时间，不代表当前电脑状态。若上次运行没有正常结束标记，结果会显示“需核对”，先做只读检查再决定是否重试。记录文件不保存自由格式步骤详情、账户名或密码；它是本机事件摘要，不是完整诊断日志。分享给他人前先检查并按学校要求脱敏。

## 5. 结果复核与恢复

| 页面结果 | 处理方式 |
| --- | --- |
| 检查阻断／暂时无法部署 | 尚未开始部署修改。查看详情，确认目标电脑与账户后处理原因并重新检查。未知状态应由管理员或 IT 核实。 |
| 已完成 | 在“管理员维护”中运行只读部署检查，并查看 Veyon 详细状态。再从教师端单独验证连接。若配置了网站策略，教师还需检查逐台推送结果；策略写入后在学生机手动重启 Edge、Chrome 和 Firefox，并检查实际浏览器策略和访问结果。 |
| 待重启 | StudentSetup 会明确提示保存工作并重启。按学校维护安排手动重启；程序不会自动重启。重启后重新打开 StudentSetup，以管理员身份只读复查电脑名、Veyon 和 Agent 状态；改名要在重启后核对活动名称。 |
| 部分完成／失败 | 已成功的早先步骤可能仍然生效。按逐步结果确定已发生的修改，再读回真实系统；不要把失败理解为所有修改已撤销，也不要直接盲目重跑整套组合。 |
| 需核对 | 常见于异常、中断或系统状态无法确认。先保留结果详情和事件记录，核对账户、活动／待生效电脑名、Veyon 版本／服务／公钥指纹及 Agent 任务。确认系统事实前不要重试可能重复或不可逆的步骤。 |
| 取消 | 取消只会在安全步骤边界处理；查看哪些步骤已完成，再逐项复核。不要假定正在运行的外部安装器已被强行终止。 |

### 常见故障处理

- **配置无法载入**：检查是否选择了教师生成的完整文件夹、文件是否复制完整、路径是否在本机磁盘。保留原包，向教师索取重新导出的包；不要手工编辑 manifest 或公钥。
- **云端搜索失败／没有结果**：云端 API 已部署；默认域名的搜索接口可正常返回空目录。HTTP 200 且结果为空表示当前没有已发布包，教师发布流程仍待合成数据验收。HTTP 错误时先检查本机网络/DNS，再记录错误码并查看[云端 API 状态与验收步骤](CloudBase%20API运行与验收.md)；离线时使用本机磁盘导入。
- **公钥已存在或 Veyon 失败**：通过详细状态核对现有公钥指纹。只有指纹与本校区配置一致时才继续；不同或无法确认时停止，不删除密钥来“试试看”。
- **Agent 未安装或状态异常**：管理员重新载入同一校区配置，在“管理员维护”中运行只读检查；只有界面允许时才用“安装 / 修复网站策略 Agent”。不要手工删除计划任务、目录、注册表值或防火墙规则。
- **教师端无法连接**：先分别核对学生机 Veyon 服务、公钥认证、主机名解析和网络／防火墙，再做教师连接测试。StudentSetup 的本机检查不能证明网络可达。
- **网站策略回执成功但网页效果不符**：手动重启 Edge、Chrome 和 Firefox，检查浏览器策略页与目标访问，并确认是否有组策略覆盖。教师端回执只说明代理接受了策略。
- **管理员维护不可用**：关闭程序，使用 Windows“以管理员身份运行”重新启动。不要用普通学生账户尝试系统修改。
- **出现异常或疑似误改**：保留运行编号、版本、截图和脱敏后的步骤详情，联系校区管理员；不要清理现场或同时手工改多个系统设置。

管理员维护页提供只读部署检查、Veyon 状态读取、单机部署工具更新，以及网站策略 Agent 的安装／修复和单独卸载入口。顶部不再提供“软件更新”按钮；备用入口是“管理员维护 → 更新学生部署工具…”，用于管理员单机维护或离线更新。日常从教师端批量推送：学生 Agent 校验教师命令和开发者清单后运行 StudentSetup 安装器，并在需要时切换后台 Agent；因此教师批量更新包含两者。更新成功仍须以安装版本和 Agent 签名状态读回为准。Agent 卸载不会卸载 Veyon 或修改账户；卸载策略仍须在浏览器重启后验证。关闭 StudentSetup 窗口只关闭窗口，不会卸载程序或后台 Agent。

## 6. 教师端迁移与密钥保护

### 当前支持边界

同一台教师电脑继续使用原校区时，应保留稳定的校区 ID、Veyon 密钥和网站策略签名身份；教师端代码会尝试复用已有密钥。不要仅为更换输出目录而删除或重新生成密钥。

**教师端换机的受控迁移目前尚未实现，暂不提供可安全照做的自动迁移步骤。** 负责人已确认网站、应用和系统策略 CNG 私钥保持不可导出，换机时重新生成并轮换学生端公钥信任；该方案仍需实现并在 Windows 验收。教师 Veyon 私钥另走认证加密备份/导入流程；手机控制 TLS 根证书换机后要让已配对手机重新核对指纹并配对。学生配置包只含策略公钥，不能据此恢复教师签发能力；Student Agent 身份密钥属于单台学生机。不要把私钥、证书备份或整份教师配置通过聊天、邮件、普通共享盘或学生包传送；不要在旧教师机尚未备份／核验时重建同名校区密钥。

需要更换教师电脑时：

1. 保留旧教师电脑及其可用登录环境，不卸载 Veyon、不删除密钥、不重置证书。
2. 暂缓在新电脑创建同名／同 ID 新密钥，也不要撤销旧密钥。
3. 由学校 IT 使用其批准的加密备份介质和账号恢复流程，先确认能分别保护并恢复 Veyon 私钥、网站策略签名身份、Veyon 配置／机房目录及所需的教师账户权限。
4. 若目前没有经过验证的安全恢复流程，继续在旧教师电脑签发和管理；P7-12 的策略密钥决策已确认，但须等 Veyon 私钥保护、新公钥信任轮换、指纹验收和手机重新配对流程实现并验证后再切换。
5. 切换前需在新教师机读回两种签名身份并匹配原校区公钥指纹，以日常教师账户验证 Veyon 权限，再对一台可恢复学生机做连接和策略推送验收。

该限制不是通过重新生成密钥就能解决的问题；轮换密钥需要单独计划学生端信任更新和恢复。

离线应用升级、设备退役、数据保留和日志清理的完整边界见[长期维护、设备退役与日志清理](长期维护、设备退役与日志清理.md)。

## 7. 首次小范围验收收尾表

每台试点机记录：

- [ ] StudentSetup 安装器版本、来源、文件 SHA-256；校区配置包 SHA-256；Windows 版本／构建／架构和运行账户类型。
- [ ] 是否可恢复、恢复方法、Veyon 原始状态和校区配置包来源；配置包指纹与校区／前缀核对结果。
- [ ] 明确勾选的操作及计划预览；未勾选的账户、密码、Veyon 和电脑名保持原样。
- [ ] 预检各项状态；执行逐步结果、运行编号和是否需要重启。
- [ ] 重启后本机读回；教师端连接结果；如涉及网站限制，再记录浏览器策略与解除结果。
- [ ] 失败／未知项、恢复证据和待办。未完成或未实际执行的项目记为“未验收”，不要记作通过。

一台通过后按 5–10 台小批继续；每一阶段都先看故障和恢复结果。未经验收，不扩大到完整机房。学生部署闭环、发布与 CloudBase 云端分发状态分别记录，不能互相替代。

相关状态和完整验收矩阵见[开发路线与任务清单](开发路线与任务清单.md)、[测试验收与发布清单](测试验收与发布清单.md)和[开发与部署指南](开发与部署指南.md)。
