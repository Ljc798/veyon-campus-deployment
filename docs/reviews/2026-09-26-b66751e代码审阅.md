## 审阅结论

发现 8 项问题，建议修复后再开放新增部署功能。P1 表示应优先修复，P2 表示一般缺陷。

### 1. [P1] 公钥快照没有用于实际导入

位置：[MainViewModel.cs](../../src/VeyonCampus.App/MainViewModel.cs)，约第 647 行。

每步验证的是快照，但 `ConfigureVeyonOnly` 仍接收原始 `frozenPackage`，CLI 最终读取原始 `PublicKeyPath`。源文件在冻结后被替换时，快照校验仍通过，却可能导入未经确认的公钥。

建议：让实际导入命令直接消费已验证的快照文件，并验证源文件替换不会改变 CLI 消费的内容。

### 2. [P1] 最终验证失败也可能显示部署成功

位置：[MainViewModel.cs](../../src/VeyonCampus.App/MainViewModel.cs)，第 672 行起。

本次删除了将验证异常加入汇总的逻辑，并在验证前写入最终日志。即使公钥未确认、服务停止，整体仍可能是 `succeeded`；当前调用的 `WindowsVeyonAdapter.Verify` 的 `KeyImported` 实际始终为 `false`。

建议：先验证，再统一计算界面和日志的最终状态；未能确认预期公钥、版本或服务状态时，应保留 `NeedsReview` 等相应状态。

### 3. [P1] 改名使用了错误的 Windows 命令

位置：[WindowsRenameAdapter.cs](../../src/VeyonCampus.Core/WindowsRenameAdapter.cs)，第 60 行。

`net computer <目标名> /domain` 不会重命名本机。该命令用于增删域计算机记录，仅支持 `/add`、`/del`。本机执行 `net help computer` 的结果与[微软文档](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-server-2012-r2-and-2012/cc730899%28v%3Dws.11%29)一致。

建议：改用有效的本机改名接口，并读回待生效名称；重启后再确认活动名称。

### 4. [P1] 从 net user 输出解析 SID，导致账户流程无法正常完成

位置：[WindowsAccountAdapter.cs](../../src/VeyonCampus.Core/WindowsAccountAdapter.cs)，第 33 行起。

本机只读验证确认：`net user` 查询成功，但输出不含 SID。因此已有账户无法正常识别，新建账户后会返回 `NeedsReview` 并阻断后续步骤，管理员改密也被拒绝。对输出全文搜索 SID 格式的正则表达式不能代替账户身份查询。

建议：使用能返回真实本地账户 SID 的接口，并明确区分账户不存在、读取失败及读取成功。

### 5. [P1] 创建学生账户时没有设置初始密码

位置：[WindowsAccountAdapter.cs](../../src/VeyonCampus.Core/WindowsAccountAdapter.cs)，第 79 行。

执行的是 `net user <name> /add`，代码提到的“后续独立步骤”并不存在。允许空密码的机器会留下空密码账户；要求密码的机器则创建失败。

建议：在创建前完成密码输入和校验，准备完整之前阻止执行；创建后的结果应如实反映账户及密码设置是否完成。

### 6. [P1] 管理员改密入口固定传入空密码

位置：[MainViewModel.cs](../../src/VeyonCampus.App/MainViewModel.cs)，第 662 行。

`ChangeAdminPassword(..., "")` 必然无法通过适配器的密码长度检查。即使修好 SID 读取，此功能仍无法成功。

建议：接入真实密码输入及执行前校验，或暂时禁用该操作。密码不应写入执行日志。

### 7. [P2] 非零退出码被标记为进程成功

位置：[DeploymentRunLog.cs](../../src/VeyonCampus.Core/DeploymentRunLog.cs)，第 57 行。

`ProcessRunner.Run` 不会因非零退出码抛异常，但包装器无条件返回 `ProcessOutcomeKind.Success`。依赖 `outcome.Ok` 的域检查因此可能把失败且无输出的查询解释为工作组机器。

建议：按退出码区分 `Success` 和 `Failed`；域状态字段缺失或无法解析时保持未知，不应默认判断为工作组。

### 8. [P2] 新增测试无法在 Windows 正常运行

位置：[Program.cs](../../tests/VeyonCampus.Checks/Program.cs)，第 254 行。

测试直接启动 `echo`，但它是 Windows shell 内置命令；当前 `UseShellExecute=false` 会抛出 `Win32Exception (2)`。已实际复现，后续检查全部中断。仓库现有 CI 使用 `windows-latest`。

建议：使用跨平台测试子进程，或按平台选择明确的可执行文件，并覆盖非零退出码及启动失败的情况。
