## 产品意见与下一里程碑

保留离线、教师／学生角色、四项独立操作和先本地后分发的产品方向。状态应明确区分“已编码、可预览、可执行、已验收”。

下一里程碑：一台教师机生成安全资料，一台学生机完成 Veyon 配置，拔除部署介质、双方重启后，日常教师账号仍可连接；失败能明确已修改内容及后续处理。

实施顺序：恢复构建并关闭严重缺陷 → 补执行前复核、失败停止、日志和异步执行 → 一教师一学生闭环 → 独立改名／账户与完整教师配置 → 5–10 台试点 → 单机房 → 局域网分发。

## 架构意见

保留 App/Core 分离、集中命名规则、包摘要、公钥解析和显式进程参数。让 ExecutionPlan 成为唯一执行输入，由应用服务协调预检、受限执行器和结果记录；ViewModel 只负责交互状态。不要在日志、权限和恢复基础建立前继续加入账户与密码修改。

具体约束见 [架构与实现约束](../架构与实现约束.md)；本报告不要求一次创建所有空项目，而要求实际系统修改必须经过同一条可验证执行链路。

## 2026-09-25 安装器与 CLI 后续核对

- 官方 Veyon 4.11.2.0 x64 资产名称、大小和 Release API SHA-256 已固定；下载资产的实际摘要与上游值一致。安装器证书 SHA-256 已固定，Windows 侧新增 WinVerifyTrust + 发布者证书双重校验，并在预检与启动安装器前各执行一次。
- 官方 v4.11.2 NSIS 源码已核对 `/S`、`/NoMaster`、`/NoInterception`、`/NoStartMenuFolder` 和非管理员错误码 740。官方 CLI 手册确认 `authkeys import <KEY> <FILE>` 形状；校区 CampusId 现在映射为确定性 ASCII 字母 KeyId，再导入 `<KeyId>/public`。
- 移除旧实现中把可移除部署介质 `PublicKeyPath` 写入 `Authentication/KeyFile` 的命令；只用 `authkeys import` 将公钥导入 Veyon 配置的密钥目录，避免配置继续引用 U 盘路径。
- Release build 0 warning / 0 error，19 组本地检查通过。WinVerifyTrust 互操作、签名链、真实静默安装退出码、服务状态与密钥库读回仍未在 Windows 10/11 验收；P0-04/05 继续开放。
- 后续执行边界修订：`sc.exe` 服务状态使用数值状态解析；服务未注册或状态不可读的已有 Veyon 安装进入未知并阻断；重启流程有界等待并读回停止/运行状态。预检现将普通权限标为阻断，身份未知虽保留未知状态也不允许进入执行；执行前会比较新旧预检的逐项事实。当前仍需管理员手动启动 App，受限 UAC 执行器和 Windows 实测尚未完成。
