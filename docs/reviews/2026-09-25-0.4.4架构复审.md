# 0.4.4 架构复审（2026-09-25）

## 结论与范围

项目已经从计划预览发展到可执行的本地离线实验版。规则与资料校验基础较扎实，P3 的计划协调已有进展，P4 学生 Veyon 与 P7 教师准备各有切片；**下一步应收敛统一执行边界和一教师一学生闭环，暂不扩大账户修改或网络分发范围。** 当前不具备正式机房试点交付证据。

本轮检查 App/Core、检查程序、打包脚本、CI 配置及 docs。源码版本 0.4.4；直接读取 `.git/HEAD` 与分支引用得到 `develop` / `b39a394edd17f25690b3bd524deb576357ddaa0a`。本机未找到可用 Git 命令，未核实索引及工作区相对 HEAD 的差异，结论针对读取到的工作区，不能宣称该提交可独立重建全部结果。

本轮 Release 构建 0 警告、0 错误，21 组本地检查全部通过，并复核已有 0.4.4 ZIP 摘要。未安装软件、修改 Veyon 配置、账户、电脑名或服务；未做 UI、Windows 10/11 矩阵及教师学生连接验收。详见 [验证记录](2026-09-25-验证与变更记录.md)。

## 建议实施顺序

1. **统一执行入口。** 先落实 AR-01/02/05：应用服务、任务租约、类型化步骤结果与可注入进程接口。补运行记录与未知状态，避免继续增加独立按钮调用链。
2. **建立可恢复执行边界。** 完成 Worker、受控资源副本、修改前备份和失败后核对；恢复读取真实系统，不直接重放未完成命令。
3. **闭合单项 Veyon。** 处理 AR-04，在可恢复 Windows 10/11 环境验证离线安装、CLI、密钥库、公钥读回、服务、重启。教师用日常账户连接学生，拔除介质后仍可工作。
4. **再扩展功能与规模。** 在 P3 门槛通过后接入改名／账户，再完成完整教师目录和 5–10 台试点；正式离线核心版完成后再做分发。

保持 App/Core、统一命名、显式参数和固定资源基线。优先让一条系统修改链路可解释、可验证、可恢复；项目拆分应服务于实际权限与测试边界。
