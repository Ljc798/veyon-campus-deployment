# 教师端网站访问控制与角色隔离

更新日期：2026-09-28。此功能由本项目自研，免费，不继承、不调用、不打包 Veyon 商业 Add-ons。教师签名推送、独立学生 Agent、SYSTEM 计划任务 ACL、过期解除、教师／学生 App 分角色构建与部署后清理已有代码；真实 Windows 学生机部署仍需按[自测验收单](Windows学生端黑白名单与后台代理自测验收单.md)核验。

## 当前功能流程

1. 教师在 Windows 教师端生成新的学生校区配置包。程序在当前 Windows 用户的个人证书库创建或复用校区网站策略 RSA 签名证书；私钥不写入配置包。配置包 schemaVersion=3，携带教师公钥、网站策略公钥、校区 ID 和 SHA-256 清单。
2. 学生端载入新包，在“配置并部署”中安装 Veyon 学生组件、配置 Veyon 校区公钥，再安装网站策略代理。旧版 schemaVersion=1/2 包可以继续配置 Veyon，但没有网站策略公钥，代理会跳过。
3. 学生代理现为独立 `VeyonCampus.Agent.exe`，是无 UI 的 Windows GUI 子系统程序，不含 Avalonia 程序集。0.4.22 起，Agent 安装在 Program Files 的版本目录；配置放在 ProgramData，由 SYSTEM 开机计划任务启动；任务 ACL 只允许 SYSTEM 和本机 Administrators 完全访问。学生端只拿到教师网站策略公钥。
4. 教师在“学生网站黑名单 / 白名单”填写校区 ID 和网站域名，选择模式与时长后签名推送；目标可手动输入，也可从 Veyon 内置网络对象目录读取。只有一个机房时自动填入该机房电脑；有多个机房时，教师先选择一个机房再填入目标。导入优先使用 Veyon 主机地址，地址为空时使用电脑名。也可一键解除所选设备限制。默认 60 分钟，支持 45/60/90/120 分钟或不自动到期。教师端使用当前用户证书库私钥签名；学生 Agent 验签、核对校区和递增版本后应用策略，并返回逐机状态。
5. 部署完成后可做只读核验。只有 Veyon、公钥、Agent、SYSTEM 任务、健康响应和任务 ACL 均确认后，清理入口才会退出并按本次发布 manifest 删除便携 GUI 文件；它不会删除 Veyon、Program Files 中的 Agent、ProgramData 中的代理配置或课堂策略。

单次最多推送到 150 台学生机；域名条目最多 1000 个，自动去重、转为小写 ASCII/IDN punycode。输入裸域名或根路径 HTTP/HTTPS 地址；不支持 IP、端口、URL 路径、通配符或任意协议。名单按浏览器 URL 模式匹配网站域名。

机房读取通过 `veyon-cli networkobjects export` 只读导出 Veyon 内置网络对象目录，不修改 Veyon 配置。LDAP 或网络发现等动态目录不由此接口读取；此时教师可手动填写目标或在 Veyon 中改用内置目录。

## 浏览器策略与冲突处理

- Edge 使用 `HKLM\SOFTWARE\Policies\Microsoft\Edge\URLBlocklist` 和 `URLAllowlist` 列表策略子项；Chrome 使用 `HKLM\SOFTWARE\Policies\Google\Chrome\URLBlocklist` 和 `URLAllowlist`。每项以子项下的 `1`、`2` 等 `REG_SZ` 值写入。
- 黑名单将域名放入 `URLBlocklist`。白名单将 `*` 放入 `URLBlocklist`，允许域名放入 `URLAllowlist`；允许项作为阻止规则的例外。
- 停用时，代理只删除与上次记录完全相同、且确认由本工具写入的策略值。首次应用若机器已有这两个浏览器策略之一，或之后检测到管理员/组策略改变本工具值，代理拒绝接管、覆盖或清除。
- 教师和学生代理之间用 RSA-PSS/SHA-256 签名，不依赖网络传输保密。名单内容通过 HTTP 在受限局域网传输，不含口令或私钥。TCP 39174 入站规则适用于任意 Windows 网络配置，以兼容被识别为 Public 的虚拟网卡；规则仍限定学生 Agent 可执行文件、TCP 端口 39174 和 `LocalSubnet` 来源。

官方浏览器文档确认 Edge 的 `URLAllowlist` 可作为 `URLBlocklist` 例外，并列出 Windows 注册表路径与 1000 条上限；Chrome 文档确认 `URLBlocklist` 的编号字符串列表及 Windows 路径：[Microsoft Edge URLAllowlist](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/urlallowlist)、[Edge URL 过滤格式](https://learn.microsoft.com/en-us/deployedge/edge-learnmmore-url-list-filter-format)、[Google Chrome URLBlocklist（简体中文）](https://chromeenterprise.google/intl/zh_cn/policies/url-blocklist/)。本项目实现须在受支持的 Edge/Chrome 版本上读回并实测，不以文档描述代替现场验收。

## 角色与密钥隔离

| 项目 | 学生端 | 教师端 |
| --- | --- | --- |
| Veyon 组件 | Veyon Service/客户端；安装参数带 `/NoMaster` | 安装含 Veyon Master 的组件 |
| Veyon 认证密钥 | 只导入校区公钥 | 教师私钥由 Veyon 管理 |
| 网站策略密钥 | 只读网站策略公钥；SYSTEM 代理验签并改浏览器机器策略 | 私钥仅在当前 Windows 用户个人证书库；负责签名和推送 |
| 控制能力 | 无法签发有效策略；不安装 Master | 可向学生机发送本校区的新版本策略 |

教师和学生 App 现有两种独立构建：`VeyonCampus.Teacher` 只启动教师控制台，`VeyonCampus.StudentSetup` 只启动学生部署界面。项目文件在编译时移除对方的窗口和 ViewModel；学生构建不编译教师操作入口，教师构建不引用学生后台 Agent。`scripts/package-windows-offline.ps1 -Role StudentSetup` 和 `-Role TeacherConsole` 分别生成角色 ZIP；脚本检查角色专属入口及对方产物，学生 ZIP 的清理 manifest 仅列入学生包文件，并包含当前 `VeyonCampus.StudentSetup.exe`。旧 `VeyonCampus.exe` 学生包名仍可按清单清理。

这次拆分消除了学生部署界面中的教师控制台入口，但不是抵御本机管理员的安全沙箱。学生包内嵌固定 Veyon 安装器，学生部署流程使用 `/NoMaster` 安装客户端；教师私钥仍只保存在教师 Windows 用户证书库，不随学生包分发。学生部署后读回并清理只移除便携部署包，不能阻止有管理员权限的人自行修改本机组件。应由管理员执行学生部署，学生日常使用标准账户。Windows 角色包、运行界面、清理和普通用户权限仍需实测。SHA-256 只检测文件变化，不证明发布者；首次部署包仍须经学校可信渠道交付。教师证书库丢失或用户配置文件变化后需重新分发配置包；当前没有在线密钥轮换流程。

### 推荐的交付隔离方式

建议将日常教师控制台只交付教师机，将学生部署工具作为一次性管理员工具，并把常驻代理保持为独立无界面程序：

1. **教师控制台 ZIP**只部署在教师电脑。包含 Veyon Master 操作、学生包生成、网站策略签名和推送；网站签名私钥由教师专用 Windows 账户的个人证书库持有。教师日常账户不应与学生共用，也不应把私钥或教师配置包发到学生机。
2. **学生部署工具 ZIP**只执行学生端初始化所需操作，不含教师窗口和教师 ViewModel。完成部署并读回确认后，可以删除这个临时工具文件夹。
3. **学生常驻代理**只接收、验签和应用本校区网站策略，不带教师界面、包生成、密钥管理或任意命令执行功能；已拆为 `VeyonCampus.Agent.exe`，由 SYSTEM 计划任务启动，0.4.22 起安装在 Program Files。部署工具清理不会卸载代理。代理实际任务权限和学生普通账户无法停止须按自测验收单验证。
4. **操作系统权限作为第二道边界**：学生使用标准账户，不能持有本机管理员密码；教师控制台与签名密钥限制给授权教师 Windows 账户。学生若拥有本机管理员权限，能够停止或移除本机代理，任何纯本机过滤方案都不能把这一风险消除。

教师 App 的启动密码可以防止误打开，但教师权限仍由角色构建边界、教师用户私钥和 Windows 账户／管理员权限共同保护。若两个 ZIP 都放在任何人可访问的公开下载页，学生也可以下载并打开教师控制台；角色拆分保证学生部署包本身没有教师界面，公开下载不会授予学生签发被学生 Agent 接受的策略所需的教师私钥。若要求学生连教师控制台都无法下载或打开，还需由发布站点限制教师包访问，或增加学校管理员配置的教师身份授权。Windows Hello/PIN 或二次确认可作为教师签发策略时的额外保护。

部署结束后只移除学生部署工具；保留 Program Files 中的独立网站代理及 ProgramData 中的受保护配置、公钥和开机任务。当前有按发布 manifest 清理便携部署目录的入口；Agent 自动卸载、升级和回滚流程尚未实现。

代理目前按 Edge/Chrome 浏览器策略限制网页导航，不过滤 Firefox、便携浏览器、其他应用或任意网络流量。已有组策略、网络策略或教师机与学生机不在可达的本地子网时，不能假定推送或限制有效。
