# UI-05：设备健康页

## 本次调整

- 保留五项等高健康概览卡，将轻量状态与完整诊断压成一块状态栏；完整诊断仍由原按钮触发。
- 轮询状态改为一行结果摘要；耗时、通信、退避等内部采集指标移入折叠详情。
- 本机状态缓存升级到 schema v3，在设备摘要旁保存最多 8 条有长度上限的异常摘要、最近出现时间和恢复确认状态；仍可读取 v1/v2 缓存。
- 仅有缓存异常时未核实的记录显示“待核对异常”和“缓存待确认”，明确提示这不是当前状态；连续两次有效签名状态确认恢复后改为绿色“最近异常记录”，继续保存在本机供回看。缓存记录只允许重新读取/查看设备，不能标记已知悉或执行修复。
- 设备详情和告警诊断的展开值保存在原行/告警对象上，状态列表按既有稳定行对象更新。
- 修复告警卡片闪现：此前同一异常从实时状态转成本机缓存或已恢复记录时会更换卡片标识，刷新时旧卡片会被移除。本轮使用稳定异常标识并在原卡片上更新状态，未核实的本机异常也继续显示为“待核对异常”。
- 继续修复实时轮询中偶发的告警卡片消失：只要异常影响的设备仍在当前名单中，即使该轮实时结果和设备缓存都暂时没有对应异常，也保留原告警卡片并显示为“待核对异常”；后续可信状态回来后复用同一张卡片。切换校区仍清除旧校区告警，取消选择的设备也不会保留在当前卡片中。
- 修复扫描交接时设备行短暂缺席导致的告警盒子闪退：若该设备仍在选中名单，告警会降为只读“待核对异常”，并将旧行中的摘要写回本机缓存；设备行回来后继续显示同一告警，取消选择后才移除。
- 修复“需要处理”汇总框仍会短暂消失：只要原告警影响的学生仍处于选中状态，即使当前设备行和本机缓存本轮都没有带出该异常，也继续复用原告警并显示“待核对异常”；收到可信状态后再更新。
- 同一异常影响多台电脑而缓存里同时有待核对和已恢复记录时，告警摘要分别显示两类设备数量，避免把已恢复设备误显示为待核对。
- 完整诊断或轻量摘要没有提供对应字段、读取失败或只出现一次恢复状态时，历史记录仍保留为待核对；连续两次独立签名摘要或明确的详细诊断确认恢复后改标“已恢复”，不再伪装成待处理异常。

## 保留边界

- 没有改变轮询间隔、并发限制、超时退避、健康分类、修复白名单或修复前置条件。缓存异常摘要扩展到 v3，旧 v1/v2 文件仍可读取。
- 本地缓存仍不能作为在线证明或修复授权依据；已恢复记录只读、不可用于修复。
- 轻量摘要连续两次明确提供对应字段并证明恢复后，实时异常转入本地历史记录；摘要缺少字段、读取失败或只出现一次恢复状态时，仍标记为待核对。切换校区会移除旧校区的设备行和告警；同校区变更只会移除已取消选择设备的告警。
