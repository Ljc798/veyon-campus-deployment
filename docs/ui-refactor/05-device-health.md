# UI-05：设备健康页

## 本次调整

- 保留五项等高健康概览卡，将轻量状态与完整诊断压成一块状态栏；完整诊断仍由原按钮触发。
- 轮询状态改为一行结果摘要；耗时、通信、退避等内部采集指标移入折叠详情。
- 缓存摘要仍明确标记为本机缓存和待确认状态；搜索、筛选、分页与修复资格逻辑未改。
- 设备详情和告警诊断的展开值保存在原行/告警对象上，状态列表按既有稳定行对象更新。
- 修复“需要处理”卡片闪现：此前轻量运行摘要会直接覆盖完整诊断问题；摘要未包含某个诊断时，告警就从聚合列表中消失，后续完整读取又使其出现。现在完整诊断和轻量运行问题分开存储、合并显示；轻量轮询仅移除自己能明确判定已恢复的问题，完整快照类问题保留到下一次完整诊断。

## 保留边界

- 没有改变轮询间隔、并发限制、超时退避、健康分类、缓存格式、修复白名单或修复前置条件。
- 本地缓存仍不能作为在线证明或修复授权依据。
- 完整诊断告警可能在自动轻量状态显示恢复后继续保留；只有轻量摘要明确提供了对应字段并证明恢复时才会清除该问题。摘要缺少字段时，问题保留到下一次完整诊断，避免把“未提供”当成“已恢复”。

## 检查状态

- 教师端 XAML 通过 XML 静态解析；新增绑定对应已有或新增的显示属性。
- `git diff --check` 无空白错误；未运行测试套件、构建或窗口运行。
- 本机缺少仓库 `global.json` 指定的 .NET 10.0.100 SDK；自动刷新 30 秒稳定性、滚动/展开保持和 60–70 台性能仍待真实构建验收。

## 待人工验收

在至少一台存在完整诊断问题、且轻量摘要缺少对应字段的电脑上保持设备健康页打开 30 秒，确认“需要处理”卡不消失；下一次完整诊断明确恢复后确认卡片才清除。另检查缓存先显示、失败退避、设备列表搜索/筛选/翻页、打开行详情期间自动刷新、缓存状态下修复按钮禁用，以及 60–70 台教室的滚动与操作响应。
