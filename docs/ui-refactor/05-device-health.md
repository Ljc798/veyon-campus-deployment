# UI-05：设备健康页

## 本次调整

- 保留五项等高健康概览卡，将轻量状态与完整诊断压成一块状态栏；完整诊断仍由原按钮触发。
- 轮询状态改为一行结果摘要；耗时、通信、退避等内部采集指标移入折叠详情。
- 缓存摘要仍明确标记为本机缓存和待确认状态；搜索、筛选、分页与修复资格逻辑未改。
- 设备详情和告警诊断的展开值保存在原行/告警对象上，状态列表按既有稳定行对象更新。
- 修复“需要处理”卡片闪现：此前轻量运行摘要会直接覆盖完整诊断问题；名单刷新还会无条件清空聚合告警，即使设备行仍被保留。现在完整诊断和轻量运行问题分开存储、合并显示；同校区名单刷新会按仍选中的设备重建汇总，缺字段或读取失败时保留原告警，明确恢复需连续两次签名状态确认后才收起。

## 保留边界

- 没有改变轮询间隔、并发限制、超时退避、健康分类、缓存格式、修复白名单或修复前置条件。
- 本地缓存仍不能作为在线证明或修复授权依据。
- 完整诊断告警可能在自动轻量状态显示恢复后继续保留；轻量摘要连续两次明确提供对应字段并证明恢复后才会清除。摘要缺少字段、读取失败或只出现一次恢复状态时，问题继续保留，避免把“未提供”或单次抖动当成“已恢复”。切换校区会移除旧校区的设备行和告警；同校区变更只会移除已取消选择设备的告警。

## 检查状态

- 教师端 XAML 通过 XML 静态解析；新增绑定对应已有或新增的显示属性。
- `git diff --check` 无空白错误；未运行测试套件、构建或窗口运行。
- 本机缺少仓库 `global.json` 指定的 .NET 10.0.100 SDK；自动刷新 30 秒稳定性、滚动/展开保持和 60–70 台性能仍待真实构建验收。

## 待人工验收

在至少一台存在完整诊断问题、且轻量摘要缺少对应字段的电脑上保持设备健康页打开 30 秒，确认“需要处理”卡不消失；再观察单次和连续两次明确恢复的回执，确认单次恢复不会闪掉、第二次确认后卡片才清除。切换同校区名单后确认仍选中的异常继续显示，切换校区后旧告警清除。另检查缓存先显示、失败退避、设备列表搜索/筛选/翻页、打开行详情期间自动刷新、缓存状态下修复按钮禁用，以及 60–70 台教室的滚动与操作响应。
