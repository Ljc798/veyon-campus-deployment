# UI-05：设备健康页

## 本次调整

- 保留五项等高健康概览卡，将轻量状态与完整诊断压成一块状态栏；完整诊断仍由原按钮触发。
- 轮询状态改为一行结果摘要；耗时、通信、退避等内部采集指标移入折叠详情。
- 本机状态缓存升级到 schema v2，在设备摘要旁保存最多 8 条有长度上限的异常摘要；仍可读取 v1 缓存，旧版本只有分类时按分类显示待核对记录。
- 仅有缓存异常时卡片显示“上次异常记录”和“缓存待确认”，明确提示这不是当前状态；缓存卡片只允许重新读取/查看设备，不能标记已知悉或执行修复。
- 设备详情和告警诊断的展开值保存在原行/告警对象上，状态列表按既有稳定行对象更新。
- 修复“需要处理”卡片闪现：此前轻量运行摘要会直接覆盖完整诊断问题；名单刷新还会无条件清空聚合告警，即使设备行仍被保留。现在完整诊断和轻量运行问题分开存储、合并显示；同校区名单刷新会按仍选中的设备重建汇总，缺字段或读取失败时保留原告警，明确恢复需连续两次签名状态确认后才收起。
- 修复教师程序重启后告警卡片不保留的问题：写入缓存的异常码、标题、严重度和说明会在重新打开时恢复；当前 Agent 状态明确证实问题消失后才清除缓存记录。完整诊断或轻量摘要没有提供对应字段时继续保留。

## 保留边界

- 没有改变轮询间隔、并发限制、超时退避、健康分类、修复白名单或修复前置条件。缓存增加 v2 异常摘要字段，旧 v1 文件仍可读取。
- 本地缓存仍不能作为在线证明或修复授权依据。
- 完整诊断告警可能在自动轻量状态显示恢复后继续保留；轻量摘要连续两次明确提供对应字段并证明恢复后才会清除。摘要缺少字段、读取失败或只出现一次恢复状态时，问题继续保留，避免把“未提供”或单次抖动当成“已恢复”。切换校区会移除旧校区的设备行和告警；同校区变更只会移除已取消选择设备的告警。
