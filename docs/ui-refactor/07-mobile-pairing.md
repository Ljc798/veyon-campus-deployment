# UI-07：手机配对与连接

## 本次调整

- 保留独立窗口、原 `TeacherMobileControlManager` DataContext、HTTPS 服务和窗口生命周期。
- 按参考稿分成服务状态、扫码/连接码、待确认手机、已配对手机和高级连接信息。
- 二维码与 8 位连接码共用「连接新手机」主卡；没有连接码时显示短提示，不留空白区域。
- 待确认请求采用警示区、设备名称/来源/时间和原有允许/拒绝确认；已配对设备使用统一列表与原撤销确认。
- 地址、引导地址、证书指纹、自动恢复设置和操作审计移入折叠的高级区域。
- 明确显示「已配对」，不把配对授权误显示为手机当前在线。
- 为服务未启动、启动故障增加显示状态；启动异常仍沿用现有提示框，同时保留本窗口内的错误摘要。
- 窗口在屏幕允许时以宽布局打开；较窄工作区下扫码与连接码卡片自动折行，内容可滚动到达。

## 人工验收

1. 启动和停止服务；课堂进行时确认停止按钮仍禁用；触发启动失败后确认显示红色故障状态与错误摘要，重试成功后故障摘要清除。
2. 生成连接码，检查二维码内容和 8 位连接码对应同一次邀请；刷新连接码后确认二维码同步变化，核对到期时间。
3. 用手机提交配对申请，确认待确认列表显示名称、来源和时间；分别走允许、拒绝、过期和多条待确认的选择流程。
4. 确认允许后的手机出现在「已配对手机」，撤销前仍有确认，撤销后设备授权消失；列表不显示未采集的在线状态。
5. 在断网/无可用 LAN 地址时检查错误提示，不应显示已启动或可配对；检查高级区域地址、证书指纹和本机审计记录。
6. 在 1024×768 与更小工作区、不同缩放和窗口尺寸下检查扫码/连接码折行、滚动、关闭和对话框位置；关闭后重新打开确认管理器状态按现有服务生命周期呈现。
