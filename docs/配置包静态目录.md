# 配置包静态目录

配置包的“云端目录”不再依赖 CloudBase。目录和配置包都是版本库里的文件，学生端直接读取。

## 为什么改

CloudBase 环境被隔离（欠费）后，`kidscode.fun` 和云函数域名统一返回 `402 ENV_ISOLATED`。应用更新在 1.1.82 已经改成读 GitCode 的发布目录，配置包是最后一个还卡在云端的环节——它恰好也是新机房装机的必经之路。

配置包很小（≤ 64 KiB）、很稀疏（每校区一次）、内容可哈希，属于典型的“文件比数据库合适”。改成静态文件后：零成本、不会因为欠费停服、国内直连约 0.2 秒。

## 文件布局

```
packages/
├── deployment-catalog.json          目录索引，客户端唯一要读的文件
├── <packageId>.zip                  教师端生成的配置包原样字节
└── README.md
```

`deployment-catalog.json` 每条记录：

| 字段 | 说明 |
|---|---|
| `packageId` | 配置包 GUID，来自 `manifest.json`，同时是 zip 的文件名 |
| `campusName` / `computerPrefix` | 搜索匹配字段，大小写不敏感子串 |
| `sizeBytes` / `sha256` | 下载后逐字节校验 |
| `downloadUrl` / `mirrors` | 主地址与镜像，均为 HTTPS |
| `publishedAt` | 排序依据，倒序 |
| `status` | `published` 或 `withdrawn`；撤回的记录保留，客户端过滤 |

## 发布

```bash
node scripts/publish-deployment-package.cjs \
  --package-dir "D:\配置\春晓实验学校" \
  --output-dir packages \
  --display-name "春晓实验学校" \
  --mirror-owner Ljc798 --mirror-repo veyon-campus-deployment

git add packages && git commit -m "Publish 春晓实验学校 package" && git push
```

脚本不会重新实现校验：它调用 `cloudfunctions/veyon-api/package-validator.js` 的 `canonicalizeFolderFiles`，也就是原云函数用的同一个函数，所以同一个文件夹产出的 zip 字节与以前上传到云端的完全一致。

`--dry-run` 只校验并打印结果，不写文件。

## 撤回

```bash
node scripts/publish-deployment-package.cjs --output-dir packages --withdraw <packageId>
```

撤回只改 `status`，不删 zip。这样客户端能区分“被撤回”和“从来没有过”，历史也可追溯。

## 客户端行为

`DeploymentPackageCatalogClient` 的读取顺序：

1. `https://api.gitcode.com/api/v5/repos/ljc_1126/veyon-campus-deployment/raw/packages/deployment-catalog.json?ref=develop`
2. `https://raw.githubusercontent.com/Ljc798/veyon-campus-deployment/develop/packages/deployment-catalog.json`
3. 以上都不可用时，回退旧 CloudBase API（`VEYONCAMPUS_DEPLOYMENT_PACKAGES_API_BASE_URL`）

搜索在本地做：先按 `status=published` 过滤，再匹配校区名和电脑前缀，按 `publishedAt` 倒序分页（每页 20）。目录只要有一个源成功应答，就不再回退——否则撤回的包会被旧 API 复活。

下载按 `downloadUrl` → `mirrors` 依次尝试，每个地址都要满足：HTTPS、无凭据、无 fragment、主机在 `api.gitcode.com`/`gitcode.com`/`raw.gitcode.com`/`github.com`/`raw.githubusercontent.com`/`objects.githubusercontent.com` 之内。字节取回后校验长度与 SHA-256，通过才交给 `CampusConfigurationArchive` 解包。

### 环境变量

| 变量 | 作用 |
|---|---|
| `VEYONCAMPUS_DEPLOYMENT_CATALOG_SOURCES` | 覆盖来源，格式 `gitcode:owner/repo@ref;github:owner/repo@ref` |
| `VEYONCAMPUS_DEPLOYMENT_CATALOG_DISABLED` | 设为 `1` 时完全跳过静态目录，只走旧 API |
| `VEYONCAMPUS_DEPLOYMENT_PACKAGES_API_FALLBACK` | 设为 `0` 时关闭旧 API 回退 |

### 自检

```bash
dotnet run --project tests/VeyonCampus.Checks -- --deployment-package-catalog-fixtures
dotnet run --project tests/VeyonCampus.Checks -- --live-deployment-catalog-check
```

第二个开关打真实主机，验证三件固件测不出来的事：raw 端点返回的是字节而不是 HTML 预览、`?ref=` 的分支名正确、客户端算出的摘要与发布时写的一致。

## 与旧实现的差异

| 项 | 旧（CloudBase） | 新（静态目录） |
|---|---|---|
| 搜索 | PostgreSQL `search_deployment_packages` | 客户端本地过滤 |
| 下载鉴权 | 教师手机号后四位 | 不校验（静态文件无法逐人鉴权） |
| 下载计数 | 数据库累加 | 不统计 |
| 发布 | 后台/教师端上传 | git 提交 |
| 撤回 | 数据库改状态 | 目录里标记 `withdrawn` |

手机号后四位这条弱校验随之取消。配置包里只有 Veyon 公钥、策略基线和 Agent 地址，没有私钥或口令；如果确实需要限制分发，应该改成对 zip 加密，而不是靠一个 4 位数字。

## 还没做的

- 网站后台（登录、校区管理、数据库浏览）仍依赖 CloudBase，当前不可用。
- 心跳与遥测仍指向 CloudBase，会静默失败，不影响装机与课堂管控。
- 教师端“发布到云端”按钮保留，失败时会提示改用上面的脚本。

## 局域网分发（教室直发）

装机现场最稳的一条路：教师机把刚生成的配置包直接开在教室网里，学生端从教师机取，全程不碰外网。

### 教师端

「首次部署 → 生成配置包」完成后，选择配置包文件夹，点**开始分发**。教师机在 `39178` 端口起一个临时服务：

| 端点 | 用途 |
|---|---|
| `GET /v1/health` | 返回校区、packageId、大小、SHA-256，供学生端和扫描器确认“这是一台正在分发的教师机” |
| `GET /v1/catalog` | 目录 JSON，格式与云端 `deployment-catalog.json` 完全一致 |
| `GET /v1/packages/<packageId>.zip` | 配置包字节 |

目录里的 `downloadUrl` 按**请求实际到达的那张网卡**生成，所以双网卡机器（有线 + 无线）不会把学生指向一个不可达的地址。

**扫描教室机器**会扫本机所在的 `/24`（254 个地址，并发 48），同时探两个端口：`39174/health` 有 `X-VeyonCampus-Agent-Version` 头就是已装 Veyon Campus，`39178/health` 有响应就是正在分发配置包。用地址扫描而不是 Veyon 目录，是因为首次部署前教师机手里根本没有可信的学生地址。

### 学生端

打开「获取校区配置」窗口时**自动扫描一次**本网段：找到正在分发的教师机就直接填好并预选，技术员只需点「下载并使用」。没找到会提示改走云端搜索。

窗口里也有**局域网获取**按钮可以手动重扫；点「搜索」会取消正在进行的扫描、改走云端，避免两边结果混在一起。同一次会话里只自动扫一次，重复开窗直接复用上次结果。

### 端口

`39178`。已有的分配是：`39173`/`39174` 学生端策略代理，`39175` 教师端学生更新分发，`39176`/`39177` 手机控制。安装器会加一条入站规则（`VeyonCampusPackageShare`，TCP 39178，仅本地子网，域/专用网络）。

以前装过、没重装的机器没有这条规则，此时启动分发会报“端口无法监听”，需要管理员执行一次：

```cmd
netsh advfirewall firewall add rule name="VeyonCampusPackageShare" dir=in action=allow ^
  protocol=TCP localport=39178 remoteip=LocalSubnet profile=domain,private enable=yes
```

### 安全边界

- 服务只在教师点“开始分发”期间存在，停止或关窗即销毁监听。
- 只绑定私有 IPv4，只接受来自私有地址的连接；不接受公网地址，也不做端口转发。
- 下载的字节仍然要过 SHA-256 与长度校验，和云端路径同一套检查。
- 不经 git、不留仓库痕迹，包不会因为“发错了”而永久公开。

代价也说清楚：教室网内任何一台机器在分享期间都能取到包。这和“把包放在公开仓库”是同一个级别的暴露，只是窗口更短。
