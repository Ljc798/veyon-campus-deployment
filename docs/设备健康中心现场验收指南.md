# 设备健康中心现场验收指南

本指南用于在 Windows 10 和 Windows 11 学生电脑上验收教师端的设备健康读取和两种固定修复动作。代码检查或跨平台编译不能替代本指南中的 Windows 实机验收。

## 验收准备

- 准备教师机，以及至少两台学生机：一台 Windows 10、一台 Windows 11；记录 Windows 版本、Veyon 版本、教师端版本和学生 Agent 版本。
- 学生端使用本次构建的 Agent；Agent 以 SYSTEM 运行，受管计划任务路径和 ACL 正常。
- 教师端已选择对应校区和学生目标，且学生 Agent 身份指纹已由教师核对并固定。
- 另准备可恢复的测试设备，用于停止 Veyon 服务、阻断 TCP 端口和执行策略刷新场景。不要在正在上课或承担考试的设备上注入故障。
- 记录每个场景的时间、目标电脑名、结果、诊断编号和 `PASS / FAIL / NOT RUN / INCONCLUSIVE`。不要把私钥、完整策略名单或学生个人信息放入记录。

## 场景

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| H-01 | 在健康中心读取已配对的 Win10、Win11 设备 | 每台显示电脑名和学生名；签名状态通过身份固定验证；SYSTEM、计划任务路径与 ACL、Veyon 服务、策略和更新状态分别显示。 |
| H-02 | 暂停其中一台 Agent 或阻断教师机到 Agent 的 TCP 端口，再刷新 | 设备显示“未收到有效回执 / 状态未知”；不得显示“已关机”。恢复 Agent 或网络后可再次读到状态。 |
| H-03 | 在隔离测试机上撤销其已固定身份或使用不同 Agent 身份 | 显示身份需要教师核对；不得显示为健康，也不得开放自动修复。恢复原身份并重新核对后再继续。 |
| H-04 | 在测试机停止 VeyonService，然后读取健康状态并确认启动动作 | 服务显示已停止；按钮要求教师确认。确认后服务启动，并通过 Agent 签名回执和新一轮健康读取显示实际状态。 |
| H-05 | 在 VeyonService 正常运行时读取健康状态 | 显示服务正常；不得出现需要修复的误报。 |
| H-06 | 对未安装 VeyonService 或服务状态不可读的测试机读取状态 | 明确显示“未安装”或“未知”；不误报启动成功，也不循环尝试。 |
| H-07 | 在旧 Edge 注册表执行模式下对有未过期策略的测试机排入刷新 | 教师端只能显示“已排入刷新”；在学生已登录会话核对执行器结果后，才记录浏览器策略是否实际应用。队列回执本身不能算浏览器应用成功。 |
| H-08 | 在 Edge 实时扩展模式或网站策略已禁用/过期时尝试排入旧模式刷新 | 刷新动作不可用，或 Agent 返回不可用；策略版本不匹配时不得修改当前策略。 |
| H-09 | 让更新事务处于进行中或需要恢复的状态，然后尝试修复 | Agent 返回忙碌或需人工检查；更新锁和事务状态未恢复前不启动服务修复或策略刷新。不得触碰更新事务文件。 |
| H-10 | 对同一动作快速重复请求，并重放已处理的命令编号 | 冷却期内不重复执行；重复 nonce 被拒绝；重复 command ID 不产生第二次动作，并返回可验证结果或明确拒绝。 |
| H-11 | 修改校区或所选电脑后观察已有结果 | 旧健康行立即清除；新操作不能把旧校区结果用于新校区目标。 |

## 结果记录

每个场景分别记录 Windows 版本、目标电脑名、Agent 与 Veyon 版本、操作步骤、预期和实际结果、诊断编号、耗时及判定。更新锁场景如无法安全构造，应记为 `NOT RUN`；不要通过直接编辑 journal 来伪造更新事务。

在 Win10、Win11 两组都完成 H-01 至 H-11 后，再按项目发布清单评估是否关闭健康中心现场验收。已在 Agent 端排队的 Edge 刷新和浏览器实际应用必须分开记录。
