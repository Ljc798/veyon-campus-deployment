# Veyon Campus 1.1.84

**CloudBase 订阅恢复，云端能力重新接上**；同时修掉了局域网分发在真实教室里找不到教师机的问题。

**1.1.83 及更早的机器可以自动更新到 1.1.84。**

## 1. 云端更新通道恢复

上一版把更新来源整体挪到了签名静态目录，因为 CloudBase 环境当时返回 402 `ENV_ISOLATED`。订阅恢复后，云端不再只是"能访问"，而是重新参与更新：

- 客户端仍然**先读签名静态目录**——它是每次发布都会随包附带的那一份，也是断网机房唯一能读到的一份。
- 目录两个主机（GitCode、GitHub）都不可达时，**回退到 CloudBase `/v4/releases/latest`**，而不是把界面停在"版本目录暂时不可用"。
- 两处都失败时，报错会同时带上目录和云端的原因，现场能直接判断是该配代理还是该重装。
- 签名校验只在拿到清单之后发生，回退不会绕过它：云端返回的清单同样要过 RSA-PSS 校验。
- 需要纯离线验证时，设 `VEYONCAMPUS_RELEASE_API_DISABLED=1` 即可关掉回退。

配置包的 API 回退、遥测、校区心跳、维护服务分发本来就还指向云端，订阅恢复后无需改动即恢复工作。

## 2. 局域网分发：先问网关，再按真实掩码扫

原来的实现有两个假设，在真实环境里都不成立：

| 原假设 | 实际情况 | 现在的做法 |
|---|---|---|
| 本机第一个私有 IPv4 就是教室网卡 | 装了 WSL / Hyper-V / 虚拟机的机器，第一个常常是虚拟交换机 | 优先选**有默认网关**的真实网卡，虚拟网卡排后 |
| 教室一定是 /24 | 虚拟交换机常发 /20，学生可能在相邻的 /24 | 按**实际前缀长度**枚举；超过 /20 才退回本地 /24 |

扫描顺序也改了：**先探默认网关，再扫本地 /24，最后才展开大网段**。这一条直接解决了"教师机在宿主、学生端在 NAT 虚拟机里"测不通的问题——NAT 虚拟机的网关就是宿主，也就是教师机本身，第一跳就能命中。

学生端窗口新增**教师机 IP 输入框**：跨网段、双 VLAN、或者自动扫描被 AP 隔离挡住时，填地址即可直连，不用再开命令行。扫描失败时的提示也会列出**实际扫过哪些网段**，方便对着 `ipconfig` 核对。

**打开窗口不再自动扫描。** 上一版会在窗口弹出时立刻扫 254 个地址，把"我要按校区名搜索"变成了一次无声的局域网探测，状态栏还被扫描结果覆盖。现在只有点开折叠区里的"教室里直接获取"并按下"开始查找"，或直接填 IP 回车，才会发起探测；默认界面就是搜索框加"搜索"按钮。

## 3. 网站后台恢复

网站重新以带后台的模式构建（不再是 `build:static-only`）：

- `/admin` 登录与管理页恢复，接口直连 CloudBase（CORS 已放行 `kidscode.fun`）。
- 页面本身仍托管在 EdgeOne，**不需要把自定义域名绑回 CloudBase**，从而避开国内节点接入备案的问题。
- 打包脚本新增 `-WithAdmin`，两种产物分开命名，避免把后台代码误发到纯静态站点上：
  - `website-static-*.zip`：无后台，纯静态兜底
  - `website-with-admin-*.zip`：带 `/admin`

## 4. 升级说明

- 教师端、学生端均可从 1.1.83 直接更新。
- 教室首次部署仍可用局域网分发：教师端生成配置包 → 点"开始分发" → 学生端点"局域网获取"。
- 若学生端在虚拟机里测试，请确认虚拟交换机与教师机可达；不可达时直接填教师机 IP。
