# Veyon Campus 1.1.80

课堂管控不再只给一个灰按钮，静默更新不再丢失学生端托盘程序。不改协议、签名、身份固定与更新事务。

## 1. 课堂页直接说明按钮为什么不可用

课堂消息、全班通知、网站限制、键鼠锁定都要求「课堂已开始」且「当前教室的 Veyon 名单已成功核对」。条件不满足时按钮是禁用的，但界面此前不给任何说明，现场只能看到点不动的灰块。

现在按顺序给出第一个阻断项：

- 本机没有当前校区的签名身份，课堂无法开始 —— 需要先在一台教师机上生成含该校区的配置包；
- 课堂范围待确认 —— 教室或 Veyon 名单刚变化，需要重新核对；
- Veyon 设备名单没有读取成功 —— 服务未运行、密钥不匹配或端口不可达；
- 当前教室在 Veyon 里没有学生电脑 —— 地点为空或电脑未登记；
- 先在页面顶部点击「开始课堂」；
- 正在处理 / 时限无效。

提示条同时显示在快捷管控卡片上方，不再只有禁用状态。

## 2. 空闲徽标从「等待教室配置」改成「课堂未开始」

原来的措辞让人以为教室没配好，实际含义只是本堂课尚未开始。进度提示同步改为「点击开始课堂后可查看逐台进度」。

## 3. 静默更新后重新拉起学生端托盘程序

静默更新由维护服务以 SYSTEM 身份执行，安装脚本里带 `runasoriginaluser` 的启动项拿不到原始用户、带 `skipifsilent` 的启动项直接跳过，而「所有用户」启动快捷方式只在下次登录时才触发。结果就是：旧的学生课堂助手被替换、新进程没人启动，更新完成后教室里没有助手。

安装收尾阶段（`ssPostInstall`）在静默模式下调用 `ShellExecAsUser`，在当前活动会话中启动学生课堂助手与 Edge 策略执行器。非静默安装行为不变。

## 4. 新增只读连接诊断脚本

`scripts/diagnose-classroom-connection.ps1` 不修改任何系统状态，在教师机上输出：已安装版本、Veyon 服务与监听端口、防火墙规则、认证密钥、内置目录里的地点与电脑、逐台学生机的 DNS 与 11100 连通性、本机校区签名密钥、座位图、最近一次课堂会话，最后列出候选阻断原因。

```powershell
powershell -ExecutionPolicy Bypass -File .\diagnose-classroom-connection.ps1 -OutputPath .\课堂诊断.txt
```

- 未改动任何命令格式、签名校验、身份固定或事务状态机。
