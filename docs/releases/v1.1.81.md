# Veyon Campus 1.1.81

CloudBase 环境已过期隔离，原版本发现接口与下载页配置接口全不可用。这一版把更新来源整体迁移到仓库自己的发布页，客户端不再访问 CloudBase。

## 1. 更新来源改为发布目录

原来的 `/v4/releases/latest` 由 CloudBase 云函数提供，环境隔离后返回 402 `ENV_ISOLATED`，所有已安装的机器都无法再发现新版本。

现在每个 Release 额外携带一份 `release-catalog.json`，客户端按下面的顺序工作：

1. 读 GitCode 的 `releases/latest`（国内直连，302 到国内 CDN）；
2. 在资产里取 `release-catalog.json`，按角色取对应条目；
3. 用内置的 Developer Release 公钥校验清单签名（RSA-PSS-SHA256，与安装包同一把钥）；
4. 从清单的 `downloadUrl` 下载安装包，校验大小与 SHA-256；
5. 主地址不可用时依次尝试目录里的镜像（GitHub 同名资产），镜像同样要过摘要校验。

GitHub 的 `releases/latest` 作为第二来源。两个来源都不可用时明确报「版本目录暂时不可用」，不会误报「已是最新版本」。

`downloadUrl` 的校验从「必须与 API 基址同源、路径为 `/v1/releases/{id}/artifact`」扩展为「旧形态仍接受；或 GitCode / GitHub 的 `/{owner}/{repo}/releases/download/{tag}/{fileName}`，且文件名必须与签名清单一致」。签名覆盖完整的下载地址，因此限制仍然生效，只是允许的目的地随托管迁移。

## 2. 下载重试与镜像

`DownloadAsync` 新增镜像回退：主地址失败（网络、HTTP 状态、大小或摘要不符）时按顺序尝试镜像。所有来源都失败时：

- 若失败原因是摘要或大小不符，抛出完整性错误（不是网络错误），保持调用方原有的处理路径；
- 否则抛出带各来源原因的下载错误。

镜像不在签名覆盖范围内，但摘要被覆盖，所以镜像无法改变实际安装的内容。

## 3. 发版流水线

CI 在 GitHub Release 创建后自动生成并上传 `release-catalog.json`（`scripts/build-release-catalog.cjs`），覆盖教师端与学生端两个角色；学生端条目附带已签名的 Agent 目标版本 sidecar。

`scripts/publish-existing-cloudbase-release.yml` 重做为 `rebuild-release-catalogue.yml`：对已发布的版本重建目录并重新上传，学生端 sidecar 从旧目录继承（仅在安装包摘要与版本一致时）。

## 4. 网站下载页

下载页不再请求已下线的 `/v1/download-page-config`，改为直接读两个发布站的 `releases/latest`，任一可用即渲染；两个都不可用时回退到内置版本号。后台管理页面仍依赖 CloudBase 数据库，不在本次迁移范围。

## 5. 升级说明

**1.1.80 及更早的版本无法自动升级**：它们的版本发现地址在编译期写死为已隔离的 CloudBase 域名，只能手工安装一次 1.1.81。从 1.1.81 起恢复自动更新。

教师端生成/发布配置包、设备心跳、后台数据库依赖 CloudBase，环境恢复前相关功能不可用；课堂管控、策略分发、静默更新不依赖它们。
