# Veyon Campus 1.1.60

本版把 1.1.59 未发布的内容与「结束课堂点了没反应」一起发布。

## 修复一：结束课堂点了没反应

现象：顶栏「结束课堂」可以点、有按压反馈，但点完什么都不发生。

原因不是按钮被禁用，而是失败提示写进了一个**没有任何界面绑定**的属性：`EndClassroomSessionAsync` 返回 false 后只调用了 `SetClassroomQuickControlSessionNotice(...)`，它只更新 `ClassroomQuickControlProgressSummary`，而该文本位于课堂页下方的快捷管控区域，不在顶栏视野内；`ClassroomDeliveryStatus` 同样没有绑定。于是失败完全无声。

现在：

- 结束课堂失败会**弹出说明**，直接写出具体原因：课堂任务还剩几项、哪些电脑的策略（网站限制或键鼠锁定）未解除、课堂范围是否正在更新。
- **倒计时会自动结束**（纯本地写入，不涉及网络），不再因为一个已经跑完的倒计时挡住下课。
- 课堂任务未完成、策略未解除仍需要老师处理——这两类强行跳过会让学生机残留限制，所以只给明确指引，不静默吞掉。

## 修复二：注册表目录快照算「完整读取」

1.1.58 增加了「`veyon-cli` 无法启动时读 Veyon 注册表快照」的回退，但把结果标成了「部分读取」。而课堂开始/结束、座位绑定、策略推送都要求目录「完整可信」，于是出现一串看似无关的现象：

- 「结束课堂」状态异常
- 「重试 Veyon 同步」永远停在「名单未能通过完整读取与身份核对」
- 座位图显示 17 台已绑定，其余电脑加不进 Veyon

数据源本来就是 Veyon 自己的目录存储（`config export` 也从这里导出），UUID、父子关系、Host 全都在，因此它应当被视为完整读取。现在回退成功时 `PartialRead=false`，上述功能同时解锁。

## 修复三：写 Veyon 时自动「暂停课堂 → 写入 → 恢复课堂」

课堂进行中修改座位并同步，以前只会得到「请下课后重新添加电脑」。现在点「重试 Veyon 同步」会：

1. 先探测 `veyon-cli` 是否真的能启动；
2. 能启动时自动结束当前课堂，写入地点和电脑，然后**无论成功失败都会把课堂重新开起来**；
3. 结束课堂需要满足的条件（倒计时、未完成的任务、未解除的策略）会给出具体原因。

如果 `veyon-cli` 起不来（R6031），会在**暂停课堂之前**返回并提示修复 Veyon，避免老师白停一次课。

## 仍然存在的限制

写回 Veyon 目录必须经过 `veyon-cli`。它在这台机器上崩溃时，新增地点或电脑无法完成——这需要修复 Veyon 安装，或在 Veyon Configurator（GUI 正常）里手动补齐电脑；补齐后本程序按 Host 自动建立 UUID 绑定。
