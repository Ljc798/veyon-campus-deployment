# Veyon Campus 1.2.6

1.2.6 只修教师端的一个问题：一次点击里重复读回**同一份签名状态**时，整批「一键静默更新」会被判成「Maintenance journal 更新不是当前操作的单调延续」而中断。

## 变化

- 学生端给状态事实打的时间戳精度是秒，同一秒内对同一份签名状态读两次（更新结果核对完，紧接着核对配置阶段）很常见。journal 原来只允许「同一时间戳下 inProgress → committed」这一种推进，第二次读回相同事实（时间戳、组件版本、事务状态都相同）会被当成「改写历史」拒绝，异常直接冒到界面，整批设备一起失败。
- 现在允许**内容完全相同的重复记录**：时间戳相同、组件版本相同、事务状态相同即视为幂等重读，不再中断事务；不合法的时间戳回退、状态回退、计划/批次改写仍然照旧拒绝。
- 拒绝时的提示会带上具体是哪条规则被违反（例如「同一签名状态时间戳下改写了事务状态或版本读回」「签名能力集摘要与已记录的不一致」），不再是原来那句没有信息量的通文，现场可以直接照着判断。

## 说明

- **只影响教师端**，学生端 1.2.5（Agent 0.4.76）不用重装。
- 已经在 `pendingVerification` / `Updating` / `ConfigurationSyncing` 停住的设备，装好 1.2.6 后直接再点一次「一键静默更新全部学生端」即可续跑，不需要清 journal。
- 如果提示换成了别的括号内容，把它发回来就能定位到具体规则。
