# Veyon Campus 1.2.6

1.2.6 是 1.2.3 之后的第一个正式版，教师端与学生端**都要升级**：新增网络开关（关 WiFi、禁改网络设置），并修掉两个会直接影响课堂使用的问题——手机端单台定时锁键鼠必然失败、一键静默更新整批中断。

## 网络开关

- 教师端课堂设备卡片新增四个动作：**禁止修改网络设置**、**允许修改网络设置**、**关闭 WiFi**、**恢复 WiFi**。都走教师端签名指令，学生端验签后执行，回执带签名状态。
- 「禁止修改网络设置」把 `DisableControlCenter` 写到真正生效的位置（`HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\Windows\Explorer`，用户策略），并对每个已登录用户的配置单元写 `DisableControlCenter=1`、`HideSCANetwork=1`，任务栏和快速设置里的网络入口一并隐藏；同时清理旧版本写在从未生效位置上的残留值。
- 「关闭 WiFi」直接停用无线网卡，默认 10 分钟后由学生端按自己的时钟自动恢复；即使这期间教师端关闭或断线，机器也一定会自己恢复。
- 旧版学生端不认识这条协议时会明确回「此 Student Agent 尚不支持网络开关命令，请先更新学生端」，不会静默失败。

## 手机端键鼠锁定

- 定时锁定必须带 30–600 秒的重启宽限：桌面端一直传 45 秒，手机端只发时长、宽限留在 0，于是每次签名都被判「InputGuard 命令版本、身份、动作、租约或有效期无效」，单台锁在手机端必然失败。现在缺失或越界的宽限会被夹进合法区间，手机与桌面走同一套结果。
- 全班「限时锁定键鼠」本来就不走持久化租约，行为不变。

## 一键静默更新

- 学生端给状态事实打的时间戳精度是秒，一次点击里同一份签名状态常被读回两次（更新结果核对完，紧接着核对配置阶段）。journal 原来只允许「同一时间戳下 inProgress → committed」这一种推进，第二次读回相同事实会被判成「改写历史」，异常直接冒到界面，整批设备一起失败。
- 现在允许**内容完全相同的重复记录**（时间戳、组件版本、事务状态都一致）视为幂等重读；时间戳回退、状态回退、计划/批次改写仍然照旧拒绝。
- 拒绝时的提示会带上具体规则（例如「同一签名状态时间戳下改写了事务状态或版本读回」），现场可直接照着判断。
- 停在 `pendingVerification` / `Updating` / `ConfigurationSyncing` 的设备，装好 1.2.6 后再点一次「一键静默更新全部学生端」即可续跑，不需要清 journal。

## 升级说明

- 教师端与学生端均为 1.2.6，学生端内置 Agent `0.4.76`。只升教师端时，网络开关会回「尚不支持」，一键静默更新也拿不到可用的学生包。
- 本地临时构建、未嵌入固定签名公钥的包会出现 `UPDATE_CONFIGURATION: 更新配置不可用`，只能用本页正式安装包重新安装后才能走在线更新。
- 1.2.4 的 Agent 身份自动更新、1.2.3 的卸载与网络加固修复都仍然有效，不需要回退。
