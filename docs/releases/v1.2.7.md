# Veyon Campus 1.2.7

1.2.7 只改教师端「一键静默更新」的等待策略，学生端沿用 1.2.6（Agent `0.4.76`），不需要重装。

## 为什么之前一次要等十几分钟

学生端收到更新命令后会一直占着这条 HTTP 请求，直到本次更新事务进入终态才回包；教师端因此设了一个固定上限。1.2.6 及更早是 **15 分钟**，而现场 21 台里只有 3 台真正走到了下发阶段，剩下 18 台根本没开机（电脑名解析不出来），于是整批一直等到 15 分钟满才结束，最后什么结论也没有。

现场那份性能报告可以对着看：整个过程 939 秒，其中 900 秒就是这条 15 分钟的等待，检查 21 台设备只花了 39 秒。

## 变化

- 等待上限从 15 分钟收到 **8 分钟**（68 MB 局域网传输 + 静默安装，在较慢的机房里也够）。
- 等待到期后不再直接报「需人工核对」，而是**再读一次签名事务状态**：已提交就按成功收尾，已回滚就按恢复收尾，仍在进行才标记待核对。以前即使学生端其实已经装好，也会被记成「待验证」。
- 电脑名解析不出来时，提示改成「未找到 pc-xx：学生电脑可能已关机或未接入校园网（电脑名无法解析）。开机后重新执行即可」，不再说成「身份或签名能力未通过核验」——那是安全问题，和关机是两回事。
- 修掉一类会让设备永久停在 Failed 的问题：两次状态写入之间系统时钟被校正（NTP 或有人改了日期）时，新的状态时间早于上一条，之后每次读取都报「Maintenance run 状态历史不连续」，这台机器再也无法维护。现在新的状态时间至少与上一条相同。
