# Veyon Campus 1.2.4

1.2.4 只修一件事：整批重装学生端之后，教师端不再把全班挂成「身份需要核对」。

学生端完全卸载再重新部署会重新生成 Agent 密钥，每台机器的指纹都会变。1.2.3 虽然已经去掉了人工比对指纹，但健康页读取状态时仍然只把"指纹不符"记为拒绝，不下发更新，于是整批设备一直停在「Agent 身份指纹已变化；轻量状态被拒绝」，必须有人对每台机器跑一次维护操作才能恢复。

现在状态读取本身就带着证明：学生端回执是拿它出示的私钥，对教师端当场生成的随机数签名的。只要这个签名、随机数回执和时间窗口都通过，读取路径就地更新固定记录，不再要求任何人工步骤。

## 变化

- 健康页「重新检测」、课堂状态、InputGuard 状态读取：验签通过的新指纹自动写回固定记录，设备直接标记为正常，提示写成「Agent 身份已自动更新」。
- 首次固定的行为不变；关闭自动信任（无界面 / 检查夹具）时仍然保持严格拒绝，行为可复现。
- 更新、策略下发这类命令路径仍按原规则校验：它们在同一次传输里靠固定键判断中途是否被替换，不在这里放宽。

## 说明

- 只影响教师端。学生端不需要重新安装，1.2.3 的学生端可以直接配 1.2.4 的教师端。
- 如果设备离线，读取无法完成，健康页仍会显示未响应，这是网络问题而不是身份问题。
