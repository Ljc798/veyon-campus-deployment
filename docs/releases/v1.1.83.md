# Veyon Campus 1.1.83

这个版本换掉了两件事的底座：**配置包从哪里来**，以及**网站封禁靠什么生效**。

**1.1.82 及更早的机器可以自动更新到 1.1.83**（更新链路不经过已隔离的云端环境），但它们的配置包搜索仍是坏的，装上新版才恢复。

## 1. 配置包改为静态目录分发

CloudBase 环境隔离后，配置包的搜索接口和下载接口一起失效：新机房装不了机，重装也拿不到配置。

配置包数量少、体积小（单个上限 64 KiB），客户端本来就会校验下载内容的摘要，所以目录从一个数据库查询变成了一份随包提交的 JSON：

```
packages/
├── deployment-catalog.json
└── <packageId>.zip
```

- 客户端**先读静态目录**，失败才回退旧接口；只要有一个源正常应答就不再回退，避免已撤回的包被旧接口"复活"。
- 下载后校验长度与 SHA-256，任何不符直接丢弃。
- 只接受两个发布主机的地址，被篡改的索引无法把设备指向别处。
- 撤回是保留记录并置为 `withdrawn`，客户端过滤——这样"被撤回"和"从来没有过"可以区分。

发布不再是上传，而是一次提交：

```powershell
# 把配置包文件夹拖到 scripts\publish-package.cmd 上即可
```

校验用的是云函数同一个规范化函数，同一批文件产出的字节与旧上传完全一致。

## 2. 教室局域网直发

首次部署时，机器上什么都没有，而云端路径依赖公网。教师机是唯一同时拥有配置包和学生可达地址的地方，所以它直接把刚生成的包开在教室网里：

| 端点 | 用途 |
|---|---|
| `/v1/health` | 校区、packageId、大小、SHA-256 |
| `/v1/catalog` | 与云端同格式的目录 |
| `/v1/packages/<id>.zip` | 配置包字节 |

端口 `39178`（`39173`/`39174` 是策略代理，`39175` 是学生更新分发，`39176`/`39177` 是手机控制）。

学生端打开「获取校区配置」窗口时**自动扫描本网段**，找到正在分发的教师机就直接填好并预选，技术员只需点「下载并使用」。学生端与云端走同一个目录客户端，搜索、下载、摘要校验、解包一行没改。

装了旧版的机器没有 `VeyonCampusPackageShare` 防火墙规则，启动分发时会提示手动添加；本次安装会一并写入。

## 3. 网站封禁下沉到网络层

原来所有封禁都停在名字层：浏览器读机器策略，或程序问系统解析器拿 hosts 答案。下面三种情况两层都拦不住——地址栏直接输 IP、客户端自带 DNS、浏览器开启加密 DNS。

现在学生端 Agent 把黑名单域名解析成地址，通过 Windows 防火墙写出站阻止规则。它不解密、不看内容，只匹配目标地址，因此对所有进程一致生效。

四条边界是刻意设计的：

- **共享地址豁免**：被封站点与放行站点共用 CDN 边缘地址时跳过，否则封一个连带封掉另一个。
- **内网地址不封**：私有、回环、链路本地、CGNAT、组播、文档保留段在计划阶段就过滤，避免切断教室局域网与 Veyon 本身。
- **额外封 853**：DoT/DoQ；浏览器一旦启用加密 DNS，hosts 就完全失效。
- **不把"配置成功"当成"封禁成功"**：写完规则会尝试连接最多三个被封地址，**连得上**说明流量仍在走（可能被其他安全软件接管），报"未生效"；连不上不算证据，不上报。

解析在后台线程进行，同时只允许一个过程；启动刷新一次，之后每十分钟重解析——CDN 地址会漂移。

## 4. 关闭受管浏览器的加密 DNS

策略启用期间写入：

| 浏览器 | 位置 | 值 |
|---|---|---|
| Edge / Chrome | `Policies\...\DnsOverHttpsMode` | `off` |
| Firefox | `Policies\Mozilla\Firefox\Preferences` | `network.trr.mode` = 5 |

值与 URL 名单走同一个注册表事务，崩溃在两次写入之间也能恢复；所有权记在 `Managed\<浏览器>\SecureDns`，卸载、解除、到期只删自己写的那份。

学校自己固定了 DoH 的不覆盖：保留原值、不声明所有权、不抛异常，只在教师端提示"X 仍启用加密 DNS（hosts 在那失效）"。宁可承认缺口，也不报告策略完整。

## 5. 升级须知

- 更新本身可用：1.1.82 能正常发现并安装 1.1.83。
- 旧版的配置包搜索仍然请求已失效的接口，需要装到 1.1.83 才能从静态目录或教师机取包。
- 装了 360 等接管防火墙的机器上，网络层规则可能写入成功但不生效，教师端会显示"网络层封禁未生效"。这是已知场景，不是安装失败。
- 已撤回的配置包仍保留在仓库里可供追溯，客户端会拒绝；要彻底移除需同时删除文件与目录行。
