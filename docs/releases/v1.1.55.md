# Veyon Campus 1.1.55

## 一键静默更新学生端

- 「学生端维护」收敛为一个按钮「一键静默更新全部学生端」：自动选中当前地点全部学生电脑、自动核对身份、执行统一维护事务并静默推送更新，不再需要事先勾选或逐台操作。
- 移除了「高级维护操作」折叠区、逐台的「在此核对身份」、设备概览里的「核对并固定身份」与指纹展开/复制入口，以及各段冗长说明。教师不再需要寻找隐藏按钮或人工比对指纹。

## 学生端身份自动核对

- 教师端首次收到某台学生机有效的签名回执时，自动固定其 Agent 公钥（首次使用即信任），不再要求人工确认指纹。
- 已固定设备的密钥变化不会被静默替换；只有教师主动执行一键更新时才自动批准轮换，并同时批准 Maintenance 服务的密钥轮换。
- 身份信任记录写入增加进程内串行化，避免并发状态读取损坏记录。

## 维护事务

- 修复维护事务「证据」对象未按值比较的问题：journal 从磁盘重读后，连续推进两个状态会被误判为「不是当前操作的单调延续」而拒绝。
- 被学生端明确拒绝（4xx 且查不到该命令事务）的更新命令不再永久停留在「待验证」；判定为本次未开始，可在同一次点击内重新检查、重新规划并重新下发。
- 「需人工核对」不再被降级为「待验证」。界面会直接给出可执行结论，而不是一个永远不会自行结束的状态。

## 兼容旧版学生 Agent（0.4.55 / 0.4.56）

- 对受信任的历史 Agent 按 1.1.44 的精确 JSON 形状签发更新命令（7 字段命令 / 4 字段信封 / 10 字段清单），不再夹带旧版本会拒绝的新字段。这解决了 `HTTP 409：学生更新命令正文格式无效`。
- 回归检查使用一份严格模式的历史模型副本做反序列化与字节级重序列化比对，而不是靠推测兼容。

## 学生端更新可靠性

- 更新流程在重命名整个安装目录之前，先停止已安装的角色进程（学生端主程序、Worker、学生伴侣、Edge 策略执行器、输入守卫、Edge 原生宿主等），修复因目录被占用导致的
  `Access to the path 'C:\Program Files\Veyon Campus\Student' is denied.`。
- 目录重命名失败时会短暂等待后重试一次，仍失败则在错误中列出占用该目录的进程映像名与 PID。
- 回滚路径同样经由该封装，避免失败后恢复目录时重复撞同一堵墙。

## 升级说明（重要）

静默更新由**学生机上当前已安装的 Agent** 执行。因此：

- 1.1.44 及更早的学生机**第一次升级仍需手动运行一次 StudentSetup 安装包**，之后才能使用一键静默更新。旧版本在重命名安装目录前不会停止自身进程，`Directory.Move` 必然被拒绝，这不是权限或环境问题，教师端也无法远程代为完成。
- 手动安装完成后，请删除残留的失败事务记录，否则该机会一直报告「已有未结束的更新事务」：
  `C:\ProgramData\VeyonCampus\StudentUpdateTransactions\`。
- 从此版本起，后续版本迭代可以全部通过一键静默更新完成。

自动发布流水线负责正式安装包构建、完整性校验（SHA-256）和发布检查。**本版本未做 Windows Authenticode 代码签名**，首次运行安装包时 SmartScreen 可能提示「未知发布者」，需要点「更多信息 → 仍要运行」，这是预期行为，不是安装包损坏。自动检查不替代真实 Windows 设备上的课堂、同步和更新恢复验收。
