# Veyon Campus 1.1.66

## 变更

**修掉“一键静默更新全部学生端”把整批设备判成“需现场维护”。**

当一台学生机在教师端**已经固定过 Maintenance 身份**、但独立 Maintenance 通道当前不在线时，
巡检和更新都会直接停下并记为 `ManualRequired`（界面显示“需现场维护”），
完全不给已签名的 Agent 通道任何机会。1.1.6x 的安装器曾经在“启动 Maintenance 服务”这一步报错中止，
于是这批机器正好落在“身份已固定、服务没起来”的组合里：21 台里 17 台被拦在预检，
`Maintenance 已接管 0 · Legacy 0`，一台都更新不了。

本版改成：**通道不在线时退回已签名的 Agent 通道**（Agent 身份指纹在巡检里仍然逐台核对，
学生端的更新事务日志与机器锁仍会阻止并发安装）。只有“通道在线但身份未固定/不匹配”才继续拒绝。

**一次只更新一台的问题解决了。**

`TeacherMaintenanceCoordinator` 里学生更新是一个严格串行的 `for` 循环，一台装完才发下一台。
现在改成**每批 4 台并发**：

- 巡检同样从逐台串行改成 8 路并发（20 台机房不必先等几分钟才出现第一条更新）；
- 连续同因失败 3 次的熔断逻辑保留，只是在每一批开始前判定；
- 进度条按完成台数推进，`维护事务 N/M` 会按批推进而不是 1/2 卡住。

**“已等待 17 秒”不再每 5 秒跳一次。**

等待计时原本 5 秒才刷新一次（同一段代码里延时就写死 5 秒）。现在计时**每秒**刷新，
签名阶段快照仍按 5 秒读一次，避免给 Agent 增加 5 倍请求。

## 注意

- 本版只改教师端，学生 Agent 仍是 0.4.58；已是最新学生端的机器不需要重装。
- 并发 4 台是按机房局域网带宽估算的默认值：每台约 68 MB 安装包，4 台同时下载约 270 MB。
  带宽紧张时可先小范围试用。
- 1.1.65 的手机端改动（隐藏策略预设、首次推送不再被版本号卡死）也在本版内。
