# Veyon Campus 1.1.71

本版基于一次真实机房的逐台诊断（21 个目标、实际 7 台电脑）收紧“一键静默更新”的判定。
1.1.69 已经让导出文件逐台写出状态与原因，这次直接按原因修。

## 1. 配置同步收尾不再被当成“更新完成”

一台机器上如果还留着上一轮“教师连接配置同步”的维护事务，这次点“一键静默更新”会先把它恢复收尾。
原来的代码收到 `Completed` 就写进结果并结束，界面显示“已完成”——可它的 StudentSetup 仍然是旧版本。
也就是说：**看起来成功，其实一个字都没升级**。

现在：如果收尾的是 `ConfigurationSync` 计划，而本次请求包含软件更新，会在**同一次点击内**重新巡检、
重新规划并继续更新，而不是把配置同步的完成当成软件达标。

## 2. “未知的原子更新状态 unknown”不再终止整批

规划器收到的 `UpdateTransactionState` 在设备没有上报时被填成字面量 `"unknown"`，
于是每台这样的机器都被判成“暂停配置同步并保留设备待核对”，提示里还让人去“核对”，实际上无从核对。

- 教师端不再把“没有上报”写成 `"unknown"`，而是 `notFound`（即没有待处理事务）。
  真正的 `inProgress` / `needsReview` 仍然会阻止下发，规划器对任何其它未识别状态仍然
  按“需人工核对”处理，学生端的机器锁也仍然生效。

## 3. 身份核验失败时给出真实原因

以前这类设备只显示一句“学生 Agent 身份或签名能力未通过核验；需要重新核对”。
现在会把适配器的具体说明（例如签名状态读取失败、指纹不一致、缺少能力读回）附在后面，
逐台诊断里也能看到，不再需要猜。

## 4. 维护记录时间戳倒序不再卡死设备

`MaintenanceRun` 要求 `updatedUtc >= createdUtc`，系统时间被调整（虚拟机常见）时会写出一条
“更新时间早于创建时间”的记录，此后**每次读取该设备的维护记录都抛异常**，
表现为“只读设备检查失败”，只能手工删文件才能恢复。现在读取时把倒序钳到创建时间，
状态历史的连续性与单调性仍然照旧校验。

## 升级建议

- 教师端升到 1.1.70 后再点“一键静默更新全部学生端”；
- 学生端保持 1.1.68 及以上即可（安装器崩溃已修）。
- 若仍有失败，重新导出性能汇总：`devices` 里每台都会写明地址、状态、通道与原因。
