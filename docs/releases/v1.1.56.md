# Veyon Campus 1.1.56

## 修复：更新在移动安装目录前被无谓阻断

学生端在重命名安装目录之前，会校验「旧 SYSTEM Agent 是否可回滚」。这个校验本应只在**发布包确实要替换 Agent** 时才执行，但此前无论 Agent 版本是否变化都会执行：

- `currentAgentVersion = 0.4.57`、`targetAgentVersion = 0.4.57` 时，机器上根本没有需要保护的旧 Agent，却仍然要求 `/health` 在 **2 秒**内返回配置指纹与版本完全一致的响应头。
- 这个检查紧跟在停止学生端 UI / Worker / Edge 策略执行器 / 输入守卫 / Edge 原生宿主之后执行，此刻机器正处于终止进程、释放句柄的高负载瞬间，2 秒窗口会稳定超时，导致更新以
  `HTTP 409：旧 SYSTEM Agent 未通过移动 StudentSetup 前的版本、配置指纹与健康检查` 结束。

现在的行为：

- Agent 版本未变化时**不再执行**该回滚材料校验，因为它没有需要保证可回滚的对象。
- 该检查的超时从 2 秒放宽到 **20 秒**，与安装完成后的同类健康检查保持一致，避免在系统繁忙瞬间误判。

## 插件（Agent）版本

- 学生 Agent 版本提升到 **0.4.58**，以便「更新/修复 Student Agent」把新逻辑真正部署到 `WebsitePolicyAgent\0.4.58\` 版本目录。旧目录不会被原地覆盖，升级后可确定地知道自己在跑哪一份代码。

## 升级说明

- 1.1.54 的学生端**无法靠自身完成**本次升级：那次更新由 1.1.54 内的旧逻辑执行，会被上述 2 秒检查拦下。请手动运行一次 1.1.56 的 StudentSetup，然后在学生端点击「管理员维护 → 更新/修复 Student Agent」把 Agent 部署到 0.4.58。
- 1.1.46 及更早的学生端首次升级仍需手动安装一次（旧版本在重命名安装目录前不停止自身进程，`Directory.Move` 必然被拒绝）。
- 从 1.1.56 起，后续版本迭代可以完全通过教师端的「一键静默更新全部学生端」完成。

自动发布流水线负责正式安装包构建、完整性校验（SHA-256）和发布检查。**本版本未做 Windows Authenticode 代码签名**，首次运行安装包时 SmartScreen 可能提示「未知发布者」，需要点「更多信息 → 仍要运行」，这是预期行为，不是安装包损坏。
