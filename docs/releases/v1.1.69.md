# Veyon Campus 1.1.69

## 一键静默更新不再被“身份尚未固定”整批挡下

`TeacherMaintenanceWorkflow.MaintainAsync` 在真正联系设备之前，会先查本机保存的学生 Agent 身份固定记录：

```csharp
var pinnedPublicKey = _trustStore.FindTrustedPublicKey(campusId, target);
if (pinnedPublicKey is null)
{
    outcomes.Add(new TeacherMaintenanceTargetResult(target, null, MaintenanceRunState.ManualRequired,
        "学生 Agent 身份尚未由教师核对固定；未发送维护命令。"));
    continue;
}
```

也就是说：**凡是从未被教师端联系过的座位，一律直接判为“需现场维护”，一个数据包都不会发出去**。
新建座位表、重装过系统的机器、第一次点“一键静默更新”的教室，都会整批落在这里——
导出的 21 台里 18～19 台“预检失败”、只有 2 台被实际尝试，正是这条分支造成的。

现在改为：先对所有没有固定记录的学生机并发做一次**签名状态读取**，由第一次可信应答自动固定身份
（与网站策略通道用的 TOFU 策略一致），然后再走原有的巡检与规划。只有**确实没有任何应答**的地址
才会被跳过，并且提示改为可操作的说明：

> 该地址的学生 Agent 没有应答，无法核对身份；如果它只是 Veyon 目录里的历史电脑对象，请从地点中删除后再试。

## 性能汇总新增“逐台诊断”

以前的导出只有聚合数字（选中 21、预检失败 18……），无法判断到底是历史对象、离线机器还是回滚。
现在报告里多了一个 `devices` 数组，每台一条：

```json
"devices": [
  {
    "target": "192.168.1.23",
    "state": "ManualRequired",
    "attempted": false,
    "reason": "该地址的学生 Agent 没有应答，无法核对身份；……",
    "channel": null,
    "studentSetupVersion": null,
    "agentVersion": null,
    "updateTransactionState": null
  }
]
```

该块只写进**教师选择的本地文件**（不会自动上传），地址仅用于把失败行对应到具体电脑。

## 与 1.1.68 的关系

1.1.68 修的是学生端安装包在中途崩溃（`LocalFree` 导入错误）导致“装完了还弹 Maintenance 失败”、
以及更新事务回滚。两者叠加才表现为“整批更新失败”：18 台根本没有下发，2 台下发了又因为安装器崩溃而回滚。
建议教师端与学生端都升级到 1.1.69 后再点一次“一键静默更新全部学生端”。
