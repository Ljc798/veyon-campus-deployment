# Veyon Campus 1.1.64

## 变更

**修掉“课堂已开始，学生端却一直显示等待教师端连接、快捷管控推不动”。**

教师端的所有课堂动作（课堂在线状态、键鼠锁定、求助/私聊授权、设备运行摘要、健康修复）都走
`StudentAgentChannelHttpMessageHandler`。这个处理器只有在“学生 Agent 的教师端长连接在线”时才发送，
否则**直接抛错、根本不发请求**；而同一时刻“策略与预设”能推送，是因为它额外允许直连回退。
于是现场出现很反常的一组现象：

- 网站黑白名单能从“策略与预设”推下去（有直连回退）；
- 课堂在线状态推不下去，学生端两分钟后就回到“等待教师端连接”（没有回退）；
- 课堂快捷管控读不到状态 → 设备停在“待核对”，两个按钮点了没有效果（没有回退）；
- 键鼠锁定、求助/私聊、设备健康巡检同样受影响。

本版把教师端发起的课堂与设备操作统一成与策略推送一致的传输策略：
`allowLegacyDirectFallback: true, allowDirectFallbackWhenChannelOffline: true`。
直连同样要求教师私钥签名请求、Agent 私钥签名回执，长连接只是传输优化，不是信任边界；
长连接可用时仍然优先走长连接。

覆盖范围：课堂在线状态（`ClassroomStatusProtocol`）、课堂事件授权（`ClassroomEventGrantTransport`）、
键鼠 Guard（`StudentInputGuardTransport`）、设备运行摘要（`DeviceRuntimeSummaryProtocol`）、
健康修复（`StudentAgentHealthRepairProtocol`）、网站策略推送（`WebsitePolicyRuntime`）、
课堂状态读取与解除读回（`TeacherClassroomModes`、`TeacherClassroomQuickControlService`）。

**课堂在线回执改为首次使用即固定身份。**

学生 Agent 已经签名确认了课堂状态，但教师端本地没有该设备的身份记录时，旧代码会丢弃这份回执并记为“待核对”，
于是第一节课永远显示“已回执 0 / 待核对 1”。本版与网站状态读取一致：首次签名有效即固定身份，
之后仍要求指纹一致；指纹变化依然拒绝，并提示走“核对并固定身份”。

**课堂概览显示投递结果。**

`ClassroomDeliveryStatus`（例如“课堂状态确认：0/1 台 · 待核对 1 · 未响应 0”）以前从未绑定到界面，
出问题时界面上没有任何线索。现在显示在“课堂概览”卡片下方。

**设备健康页恢复“核对并固定身份”按钮。**

处理身份轮换的事件处理函数一直都在，但上一轮精简界面时把入口删掉了，
结果是学生端重装/换机、指纹变化后设备永久停在“需核对”，快捷管控永远发不出去。
现在设备行在存在待核对身份时重新显示该按钮，一次点击即可固定新指纹并重新读取状态。

## 注意

- 学生 Agent 版本仍为 0.4.58，本版只改教师端；学生端不需要重新安装。
- 已固定过身份的电脑不受影响；指纹变化的那台需要在“学生端维护 → 设备健康”里点一次“核对并固定身份”。
- 本版同时包含 1.1.62（旧更新事务自动收敛、Maintenance 服务误报修复）与 1.1.63（课堂名单 UUID 解析、
  学生配置包密钥提示）的全部内容。
