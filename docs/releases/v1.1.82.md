# Veyon Campus 1.1.82

修复 1.1.81 的更新发现缺陷。**1.1.81 无法发现任何更新，请直接安装 1.1.82。**

## 1. 目录资产的重定向

GitCode 的资产地址不是直接返回文件，而是 302 到 `file-cdn.gitcode.com` 并附带一次性的 `auth_key`。客户端的共享 `HttpClient` 有意关闭了自动重定向（安装包下载要逐跳校验），1.1.81 的目录读取沿用了它却没有自己跟随跳转，于是把 302 当成失败：

```
版本目录暂时不可用：gitcode:… 发布目录暂时不可用。；github:…
```

结果是 1.1.81 装上以后既不会提示新版本，也不会报“已是最新”，而是直接显示目录不可用。

现在元数据读取（发布索引与目录资产）单独走一条路径：最多跟随三次 HTTPS 跳转，拒绝带凭据、非 HTTPS 或带 fragment 的目标，超过次数直接失败。

## 2. 回归保护

新增的固件让目录资产先回 302、再由另一个主机返回 JSON，正是线上形态。去掉重定向处理，这个固件会立刻失败。

同时新增 `--live-release-check`：用真实网络走一遍“索引 → 目录 → 验签 → 下载 → 摘要校验”，需要构建时嵌入固定公钥（`-p:VeyonCampusReleasePublicKeyPath=…`）。本次发版前的检查结果：

```
TeacherConsole: latest=1.1.82 newer=True mirrors=1 host=gitcode.com
download: 71039543 bytes verified
StudentSetup: latest=1.1.82 newer=True mirrors=1 host=gitcode.com
notes: 1579 chars
```

## 3. 更新来源回顾

版本发现不再经过 CloudBase：读 GitCode 的 `releases/latest`，取该 Release 的 `release-catalog.json`，用内置的 Developer Release 公钥验签，再从清单里的 `downloadUrl`（GitCode 资产）下载并校验 SHA-256；主地址失败时依次尝试 GitHub 镜像。详见 `docs/更新来源与发布流程.md`。

## 4. 升级说明

- **1.1.81 必须手工替换成 1.1.82**，它自己发现不到。
- 1.1.80 及更早同样只能手工安装一次。
- 从 1.1.82 起恢复自动更新。
- 教师端生成/发布配置包、设备心跳、后台数据库仍依赖 CloudBase，环境恢复前不可用。
