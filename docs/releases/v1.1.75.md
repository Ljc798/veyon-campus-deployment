# Veyon Campus 1.1.75

这一版针对“一键静默更新报 HTTP 409：没有任何当前或过渡期策略信任根验证通过”，
把原因和修法直接放到界面上，不再让人靠猜。

## 1. 409 到底在说什么

学生 Agent 只认**一个**校区策略签名根：它安装时由学生配置包写入校区标识和网站策略公钥，
之后教师端所有签名请求（读状态、推策略、发更新）都必须用同一把校区私钥签名。
只要教师端换了校区标识（每个校区标识对应一把独立密钥），学生端就会用 409 拒掉，
正文就是这句“没有任何当前或过渡期策略信任根验证通过”。

在教师机上核对过：当前保存了 4 个签名校区（`智学前程-1019-1`、`-2`、`-3`、`智学前程-123`），
其中 `-2`、`-3` 是今天 22:04 和 23:25 新建的密钥 —— 每换一次校区标识就多一把根，
而学生机只认当初装包时的那个。

## 2. 新增“诊断学生端信任的校区”

“设备与更新 → 学生端维护”里，“一键静默更新全部学生端”旁边新增按钮
**诊断学生端信任的校区**：它用本机已固定的每个校区密钥，逐个对当前地点的学生机
发一次签名状态读取，谁读回签名回执就说明学生端认的是哪个校区。

- 命中一个且与当前不同：自动切换教师端校区标识，并提示“请再点一次一键静默更新”。
- 命中多个：列出来，让你固定在学生端实际使用的那个。
- 一个都不命中：说明学生端是用别的教师机/别的校区配置包装的，或两机时间差超过 2 分钟；
  界面会直接给这条结论和“用当前校区重新生成配置包并在学生机载入”的做法。

## 3. 409 提示带上了处置建议

更新前的“能力读取”被 409 拒绝且原因是信任根时，提示会补一句：

```
…：没有任何当前或过渡期策略信任根验证通过。 当前校区标识为“X”；学生端只认给它配置的那个
校区密钥。请在“设备与更新”点“诊断学生端信任的校区”，切到该校区后重试。
```

## 4. 没有改的部分

- 签名、协议、信任根校验逻辑一行没改：本版只增加“找出学生端认哪个校区”的动作和提示，
  不会放宽任何校验，也不会自动删除任何校区密钥。
- 学生端行为与 1.1.74 相同；1.1.71 起可直接升级到本版。

## 5. 如果诊断后仍然 409

按这个顺序处理：

1. 在学生机上看 `C:\ProgramData\VeyonCampus\WebsitePolicy\<哈希>\config.json` 里的 `campusId`，
   与教师端当前校区标识对齐；
2. 或直接用当前校区重新生成学生配置包，在学生机上运行 StudentSetup 载入该包（只更新配置，
   不重装 Agent），之后教师端再推更新；
3. 两机时间差控制在 2 分钟内（`w32tm /resync`）。
