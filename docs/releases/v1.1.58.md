# Veyon Campus 1.1.58

## 修复

**教师机上的 `veyon-cli.exe` 完全无法启动时，教师控制台不再丢失整份名单。**

现场表现：某台教师机上，Veyon 目录读取的三种方式全部失败，都返回退出码 255，并输出

```
runtime error R6031
- Attempt to initialize the CRT more than once.
This indicates a bug in your application.
```

结果是「地点与学生名单」读不到任何电脑，课堂控制与网站策略全部不可用。这不是权限问题，也不是 Veyon 配置损坏：`veyon-cli.exe` 在这台机器上每次启动都会 abort（常见原因是安全软件或课堂管控软件向子进程注入 DLL，导致 MSVC 运行时重复初始化）。同一台机器上 Veyon Configurator 和 Veyon 主控仍然工作正常。

本版新增只读回退：`veyon-cli` 无法完成 `config export` 时，教师端直接读取 Veyon 自己的注册表目录快照

```
HKLM\SOFTWARE\Veyon Solutions\Veyon\BuiltinDirectory\NetworkObjects
```

该值是 `@@JsonValue(<base64 UTF-8 JSON>)`，与 `config export` 输出的是同一份对象数组，因此地点、电脑、UUID、父子关系都一致。回退结果只用于读取与展示，指纹不会被当作写回依据。

同时修正了诊断文案：出现 R6031 时不再只显示裸退出码，而是直接说明原因（安全或管控软件向 `veyon-cli` 注入 DLL）和处理方式（修复安装 Veyon，或让安全软件不再干扰 `veyon-cli`）。读取失败时的空状态提示也不再让老师去「配置教室」——那会误导已经配好 30 个座位的学校。

## 影响范围

- 可以读取：地点列表、学生名单、电脑 UUID 与父子关系、座位图绑定、课堂控制、网站策略推送、设备概览、一键静默更新。
- 仍需要可用的 `veyon-cli`：向 Veyon 目录**写回**地点或电脑（「重试 Veyon 同步」仍会失败，并给出上述可执行提示）。写回不能直接改注册表——Veyon 自己维护这份目录，绕过它容易产生同名重复地点。

## 验证

- `--veyon-registry-snapshot`：在本机真实 Veyon 4.11 上直接读取注册表快照并解析，得到 `HKLM (64 位) 注册表目录快照，地点 1 个、电脑 1 台`，与 `config export` 结果一致。
- 新增回归断言：`@@JsonValue(base64)` 解码、裸 JSON 解码、非法形状必须 fail closed（不得产出空名单）。
- Core / App / Checks 编译 0 错误。
