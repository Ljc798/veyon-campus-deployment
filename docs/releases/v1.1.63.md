# Veyon Campus 1.1.63

## 变更

**修掉“生成学生配置包”失败时只报“不匹配的步骤标识；请核对本机状态”。**

教师端点“生成学生配置包”时，如果 Veyon 教师端密钥认证没有确认成功，`VeyonTeacherKeyProvisioner`
会把底层认证结果原样返回，而那条结果的步骤标识是 `teacher-auth`，与本次操作应有的 `veyon-teacher-key`
不一致。派发层随后把结果整条替换成“Worker 适配器返回了不匹配的步骤标识”，真正的原因被丢掉，
现场只能看到一句无法行动的提示。本版两处都改：

- 密钥配置器自己返回正确的 `veyon-teacher-key`，并把认证失败原因写进提示（含退出码和手工核对命令
  `veyon-cli config set Authentication/Method 1`）；
- `PrivilegedWorkerDispatcher.AlignStepResult` 遇到步骤标识不一致时不再丢弃诊断，而是保留适配器给出的原文，
  以“待核对”状态返回。

**课堂名单不再因为“先有课堂、后有 Veyon 目录”而丢失。**

上一版把座位解析改成“Veyon UUID 优先”后，在 UUID 目录存在之前开始的课堂（旧快照会话）里，
目标 ID 是随机 GUID，匹配不到任何座位，快速控制和举手求助都退化成“未填写姓名”。本版按身份强弱分三级解析：

1. 会话目标携带的 Veyon 对象 UUID；
2. 已记录的连接地址或 Veyon 计算机名；
3. 会话快照里的电脑编号，且**只用于还没有 Veyon 身份的座位**——已经绑定设备的座位绝不被旧会话改写。

第三级的编号来自会话快照（`MachineNaming.TryParseNumber`），不再依赖任何数组下标，
所以机房档案改动或网络目标顺序变化都不会错位。任一级出现两个座位同时命中时一律放弃，宁可不显示姓名也不张冠李戴。
`ReadActiveSeatLabels` 与显示名解析现在共用同一个解析器，读取路径上最后的位置耦合也去掉了。

**课堂目标改为按 Veyon UUID 目录建立。**

开始课堂时，目标集合来自已核对过的 Veyon 电脑 UUID 目录，而不是“机房档案里的电脑名列表”：

- 课堂目标 ID 就是 Veyon 电脑 UUID，座位、聊天、通知、快速控制都按同一身份对齐；
- 目录与进行中的课堂范围不一致时，界面明确提示“进行中的课堂旧范围 N 台 · 当前 Veyon M 台；请确认切换范围”，
  在确认之前禁止群发通知和聊天，避免把指令发到已经不在机房的电脑；
- 目标标签校验加严：非空、不重复、不超过 253 字符、无控制字符；连接地址必须是合法主机名且不重复。

## 注意

- 本地数据 schema 没有变化，仍是 1；已有的 `classroom-sessions.json`、`classroom-seat-grid.json`、
  以及此前用 schema 6 生成的部署包都可以继续读取，不需要迁移或重建。
- 旧课堂（随机目标 ID）在升级后仍然可用，学生姓名按上面第三级规则恢复；
  下次重新开始课堂时目标会自动切换成 UUID 形式。
- 密钥认证失败时“生成学生配置包”仍然会停下并给出原因，不会带着没生效的认证继续打包。
  如果你确认本机 Veyon 认证已手动配好，按提示核对后重试即可。
