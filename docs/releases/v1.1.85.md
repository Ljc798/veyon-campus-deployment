# Veyon Campus 1.1.85

修掉 1.1.84 留下的两个“能不能用”的问题：**打开配置窗口就被强制扫描**，以及**云端发布的配置包搜不到**。

**1.1.84 及更早的机器可以自动更新到 1.1.85。**

## 1. 打开窗口不再自动扫描教室

1.1.84 会在“获取校区配置”窗口弹出的瞬间扫 254 个地址。用户本来只是想按校区名搜索，却先被一次局域网探测挡住，状态栏还被扫描结果覆盖成“没有正在分发配置包的教师机”。

现在：

- 默认界面只有搜索框和“搜索”，打开窗口不发任何网络探测。
- 教室分发收进折叠区「教室里直接获取（教师机正在分发时）」，点“开始查找”或直接填 IP 回车才发起。
- 扫描失败时仍然会列出**实际扫过哪些网段**，方便对着 `ipconfig` 核对。

## 2. 云端发布过的配置包重新可搜

上一版把搜索完全切到仓库里的静态目录，而静态目录只要应答（哪怕是 0 命中）就不再问云端。结果是：教师机直接发布到 CloudBase 的包，客户端永远搜不到——云存储里明明有 `智学前程-测试-1119`，搜索却返回“没有找到”。

现在按 id 合并两个来源：

| 场景 | 行为 |
|---|---|
| 包只在云端 | 合并进结果，可下载（走云端 POST，需要教师手机号后四位） |
| 包在仓库目录 | 以目录为准，带公开下载地址与镜像 |
| 目录里已撤回 | **不会**被云端重新复活 |
| 云端不可达 | 只返回目录里的包，不报错 |

撤回仍然只有一处事实源，所以“撤回后又被云端带回来”不会发生。

## 3. 局域网发现按真实网段

延续 1.1.84 的修正，本次一并进入正式版：

- 优先选有默认网关的真实网卡，虚拟交换机的地址排后。
- 按接口实际前缀长度枚举（`/20` 不再只扫一个 `/24`）。
- 扫描顺序：先问网关，再扫本地 `/24`，最后才展开大网段。
- 跨网段时可直接填教师机 IP。

## 4. CloudBase 相关能力

订阅恢复后，1.1.84 起已经接回：

- 更新检查：签名目录优先，GitCode/GitHub 都不可达时回退 `/v4/releases/latest`。
- 配置包搜索：本版新增的云端合并。
- 网站后台 `/admin`：直连 CloudBase，页面仍托管在 EdgeOne。

## 校验

- `dotnet build`（StudentSetup / TeacherConsole）0 错误。
- 配置包目录固件：静态语义、撤回过滤、云端合并、下载路由全部通过。
- 局域网固件：`/24`、`/23`、`/20`、`/16` 回退与网关优先枚举断言通过。
