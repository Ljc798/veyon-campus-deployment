# Veyon Campus 1.1.74

这一版修的是机房地点：**在“开始编辑座位图”这一步就把地点写进 Veyon**，之后的加电脑、
同步设备名单才不会因为“Veyon 里没有这个地点”或“目录后端认不出来”而失败。

## 1. 先建地点，再加电脑

以前点“开始编辑座位图”只把校区和机房名称存进教师电脑，Veyon 目录里什么都没有，
必须等到“添加地点并同步电脑”时才第一次写 Veyon；那一步一旦失败，前面填的名称就白填，
界面还会停在“没有可识别的 Builtin Directory”。

现在的顺序是：

1. 填写校区名称、机房名称 → 点“开始编辑座位图”；
2. 程序以管理员权限调用 `veyon-cli networkobjects add location <机房名称>` 创建地点，
   再立刻重新读取 Veyon 目录，确认这个地点存在且 UUID 唯一；
3. 地点核对通过后才进入座位编辑，状态栏会明确写出“Veyon 地点已创建并核对”；
4. 之后“添加地点并同步电脑”只在这个已有地点下加电脑，用的就是第 2 步读到的地点 UUID。

地点已经存在时不会重复创建，只会核对；同名地点出现多个时报错并停下，不会猜一个来用。

## 2. 不再把“刚装好的空目录”当成外部目录

Veyon 全新安装、还没建过任何对象时，导出的配置里只有“当前选中的目录插件”，没有
`BuiltinDirectory\NetworkObjects` 段。旧代码把这种情况判成“可能是 LDAP 等外部目录后端”，
于是拒绝写入，界面报：

```
Veyon 配置中没有可识别的 Builtin Directory；可能使用外部目录后端，已拒绝将其误判为空目录。
```

现在按 Veyon 的目录插件 GUID（`14bacaaa-ebe5-449c-b881-5b382f952571` = BuiltinDirectory）
判断：该插件就等于内置目录，空目录是合法的首次状态；只有确实选了别的后端才会拒绝。

## 3. 加电脑不再顺手造出第二个同名地点

Veyon 4.11 的 `networkobjects import ... location <名字>` 在找不到父对象时会**追加一个新地点**，
而地点 UUID 是按名字派生的，于是 Configurator 里会出现两个一模一样的地点。
现在逐台执行 `networkobjects add computer <名称> <地址> "" <地点UUID>`，父对象按 UUID 精确匹配，
不会再生成重复地点。

## 4. 配置包支持 schemaVersion 7 / 8

客户端可以生成并校验带“教师通道根证书”（v7）和“策略信任根轮换”（v8）的校区配置包；
发布到云端仍需服务端同时接受 7/8（本次一并处理）。

## 5. 其它随版改动

- “设备与更新”页在有更新说明时显示“更新内容”，文字来自 `/v1/releases/notes`，
  读不到就不显示，不影响检查与下载。
- 学生端拒绝更新请求（HTTP 409）时，提示里会带出学生端给出的原因，不再只有状态码。
- 座位图单元格尺寸收紧，机房页新增“返回首次设置向导”。

## 6. 升级说明

- 教师端：直接安装本版即可，旧的 1.1.71/1.1.72/1.1.73 教师端无需先升级。
- 学生端：1.1.71 起可直接升级到本版；更新仍是整包替换，失败自动回滚。
- 已经在 Veyon 里手工建过地点、或已经存在重复地点的机器，本版不会自动删重复项，
  只会拒绝在“同名地点不唯一”时继续写入；请先在 Veyon Configurator 里清理后再操作。
