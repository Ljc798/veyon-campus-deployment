# Veyon Campus 1.1.79

只修「一键静默更新」的失败路径与结果判定，不改协议、签名、身份固定和更新事务。

## 1. 修掉「当文件已存在时，无法创建该文件」

批量更新按 4 台一波并发，教师端会同时为多台设备暂存同一个 StudentSetup 安装包。两个线程都通过了下载前的存在性检查后，先完成的一方把文件改名到目标位置，后完成的一方再改名就会撞上 Win32 183，命令因此没有发到学生端（`attempted=false`）。

现在暂存改名允许“抢输”：两个写入方都已按签名清单校验过同一个 SHA-256，目标位置存在同名文件时视为另一方已完成，删除自己的临时文件后继续；调用方随后仍会重新校验大小与 SHA-256，内容不符会照常失败。网络下载与本地测试包两条暂存路径都已覆盖。

## 2. 「未开机」不再算预检失败

地址无应答以前统一记为“需现场维护”，一次批量更新里十几台没开机的电脑会被算成失败，把真实成功率压得很低。

新增 `Unreachable` 结果状态：

- 推理为“学生电脑未开机或不在线（地址无应答）；开机后重新执行即可”，不再引导用户误删历史对象；
- 不计入 `preflightFailureCount`，改计入“未开始”，导出报告的逐台块里状态为 `Unreachable`；
- 界面状态列显示“未开机或不在线”，汇总行单独给出“未开机 N 台”。

## 3. 「已完成」必须版本一致

以前只要状态是 `Completed` 且本次没有尝试安装，就计入“已是最新”。只做了配置同步、Setup 版本仍停在上一个版本的设备（例如停在 1.1.66）也会显示完成。

现在要求**读回的 Setup 版本等于计划目标版本**才算已是最新：

- 版本不一致时，逐台结果标记为“待核对”，汇总给出“版本未达目标 N 台”；
- 导出报告里这类设备计为 `needsReview`，不再计入 `alreadyCurrentCount`；
- 目标版本未知时保持原行为，避免凭空判定。

## 4. 验证

- 教师端编译 0 错误；检查套件新增“已完成必须版本一致才算已是最新”，本机 PASS。
- 本机检查套件仍会在“Veyon 只读探测”处因安全策略禁止 `sc.exe` 而中止，该项由 CI runner 覆盖。
- 未改动任何命令格式、签名校验、身份固定或事务状态机迁移；`Unreachable` 只用于结果与报告，不写入维护事务。
